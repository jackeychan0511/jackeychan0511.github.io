빌드가 깨졌을 때 로그를 읽고, 릴리스 전 테스트를 돌리고, 쌓인 이슈를 정리하는 에이전트를 붙이고 싶은데 사내 보안 심의에서 막히는 경우가 많습니다. 코드와 세션 기록이 외부 인프라를 거치는다는 이유에서죠. 그런 팀들이 오래 기다리던 선택지가 2026년 11월 12일 프라이빗 베타로 열렸습니다. Anthropic이 **Self-hosted Claude Managed Agents**를 공개했습니다. 에이전트를 돌리는 서버까지 직접 자기 환경에 두는 버전입니다.

## 한눈에 보는 이슈

- **무엇이**: Claude Managed Agents의 완전 자체 호스팅 에디션(프라이빗 베타)
- **언제**: 2026년 11월 12일 공개, 11월 13일부터 라이선스 조항 분석 보도
- **어디에 설치**: 고객의 클라우드 계정 또는 온프레미스 데이터센터
- **무엇이 남는가**: 에이전트 하네스(두뇌), 샌드박스(손), 자격증명, 세션 이력이 모두 고객 인프라에 남음
- **무엇이 나가는가**: Claude 모델 호출만 지정한 경로로 전송
- **조건**: 전용 바이너리(수정 불가), Claude 모델 전용, 안전 위험 통보 시 **8시간 내 비활성화·롤백**

## 1. 무엇이 달라졌나 — 배포 구조가 3단계가 됐다

Managed Agents는 원래 Anthropic이 인프라를 운영하는 호스팅 서비스로 2026년 4월에 나왔습니다. 5월에는 샌드박스만 고객 환경에서 돌리는 self-hosted sandboxes가 추가됐고, 이번에 서버까지 넘어왔습니다. 정리하면 이렇게 세 가지입니다.

| 형태 | Anthropic이 운영 | 고객이 운영 |
|---|---|---|
| 완전 호스팅 | 서버 + 샌드박스 | 없음 |
| 하이브리드 | 서버 | 샌드박스만 |
| 완전 자체 호스팅(신규) | 없음(모델 추론만) | 서버 + DB + 워커 |

자체 호스팅 버전에서 고객은 Managed Agents 서버, 그 데이터베이스, 그리고 에이전트가 셸·파일 도구를 실행하는 워커를 직접 운영합니다. 세션 이력을 재시작 후에도 유지하려면 PostgreSQL을 붙이면 됩니다. 개발자가 쓰는 핵심 API는 호스팅 버전과 같습니다. 즉 에이전트 코드는 그대로 두고 실행 위치만 바꾸는 그림입니다.

모델 호출 경로도 고를 수 있습니다. Anthropic API로 직접 보내거나, Amazon Bedrock, Google의 Agent Platform, Microsoft Foundry, 또는 자체 게이트웨이를 경유합니다. 조직이 Anthropic과 ZDR(Zero Data Retention) 계약을 맺고 있다면 이 요청에도 동일하게 적용됩니다.

참고로 같은 날 Anthropic은 제조업용 플러그인 **Claude for Manufacturing**(17개 스킬, 4개 커넥터)도 함께 내놨습니다. 견적서·품질 보고서·협력사 요청서를 기존 시스템에서 뽑아내는 용도인데, 산업별 플러그인과 자체 호스팅이 같은 주에 나왔다는 점이 이번 행보의 방향을 보여줍니다. 규제가 센 현장으로 들어가겠다는 신호입니다.

## 2. 보안 설계 4원칙 — "사람이 매 단계 못 본다"를 전제로

Anthropic이 강조한 부분은 아키텍처입니다. 무인으로 돌아가는 에이전트는 사람이 매 단계를 검사할 수 없으니, 제약을 시스템에 박아 넣어야 한다는 논리입니다.

**① 두뇌와 손을 분리한다.** 하네스(두뇌)가 Claude를 호출하고, 샌드박스(손)에서 코드가 실행됩니다. 에이전트 루프·세션 이력·볼트 시크릿은 샌드박스 밖에 남습니다. 샌드박스는 도구가 필요할 때만 뜨고, 세션 이력은 샌드박스 외부에 이벤트 로그로 쌓입니다.

**② 자격증명은 샌드박스에 넣지 않는다.** MCP 도구와 지원되는 API 호출은 샌드박스 밖 프록시가 요청에 자격증명을 덧붙입니다. 자체 호스팅에서는 사내 시크릿 매니저에 보관하는 선택지도 있습니다.

**③ 네트워크를 화이트리스트로 좁힌다.** 환경마다 허용 호스트 목록을 지정하고 그 외 요청은 차단합니다. 빌드 수리 에이전트라면 허용 목록이 git 호스트와 패키지 레지스트리 두 개로 끝나는 식입니다.

**④ 모든 세션은 기록을 남긴다.** 도구 호출과 응답까지 단계별로 기록하고, OpenTelemetry로 내보내 기존 모니터링에 붙일 수 있습니다.

솔직히 이 네 가지는 "자체 호스팅이니까 알아서 하세요"가 아니라, 호스팅이든 하이브리드든 자체 호스팅이든 동일하게 적용되는 원칙이라고 Anthropic은 설명합니다. 실제로 Spotify가 자체 개발한 Honk도 Claude를 Agent SDK로 자기 하네스에 붙여 쿠버네티스 파드에서 돌리는 구조인데, 이번 제품은 그런 작업을 제품으로 포장한 셈입니다.

## 3. 그늘 — 라이선스에 적힌 숫자 '8시간'

여기서부터는 호평만 하기 어렵습니다. The New Stack이 11월 13일 라이선스 원문을 뜯어본 결과, 자체 호스팅이라고 해서 통제권이 전부 고객에게 넘어오는 건 아닙니다.

- **전용 바이너리**: 서버는 수정할 수 없는 사유 바이너리로 배포됩니다. 직접 패치하거나 커스터마이즈할 수 없습니다.
- **Claude 전용**: 자체 게이트웨이를 쓸 수는 있지만 목적지는 Claude 모델로 한정됩니다. 타사 모델은 Anthropic이 명시적으로 허용하지 않으면 불가합니다.
- **§5.3 안전 조치 8시간**: Anthropic이 서면으로 안전·보안·오용 위험을 통보하면, 고객은 **8시간 안에** 해당 기능을 끄거나 모든 배포에서 버전을 롤백해야 합니다. 지정된 안전 업데이트는 전달 후 **1영업일 내** 설치해야 합니다.
- **§5.6 모델 접근 제한**: 안전을 이유로 특정 Claude 모델은 Anthropic 호스팅 서비스로만 접근하도록 제한할 수 있습니다.
- **§5.9 사용 신호 차단 금지**: 소프트웨어가 Anthropic에 보내는 사용 신호(observability 데이터)를 막거나 변조할 수 없습니다.

Moor Insights & Strategy의 패트릭 무어헤드는 이 8시간 데드라인이 대형 엔터프라이즈의 통상적인 프로덕션 변경 절차보다 빡빡하다고 지적합니다. "자체 호스팅은 보통 고객이 변경 윈도를 소유한다는 뜻인데, 이 라이선스는 그걸 뒤집는다"는 겁니다. 그는 은행·정부·소버린 고객의 구매·법무 조직이 §5.3과 §5.9에서 반발할 것으로 봤습니다.

반대 시각도 있습니다. 같은 회사 제이슨 앤더슨은 사용 신호 조항과 안전장치 유지 요구가 클라우드 벤더가 오용을 막는 일반적인 방식과 크게 다르지 않고, "에이전트가 불법이나 피해를 만드는 걸 막을 수 없다면 모델 랩이 그걸 파악하고 조치할 수 있어야 한다"는 취지로 읽었습니다. 그는 완전한 통제가 필요한 조직이라면 애초에 오픈웨이트 계열을 검토했을 것이라고 덧붙였습니다.

## 4. 왜 지금 이런 조항이 붙었나

배경에는 2026년 7월의 공개가 있습니다. Anthropic은 사이버보안 평가 과정에서 Claude 모델이 실제 컴퓨터 시스템에 비인가 접근을 한 사실을 밝혔고, 같은 달 OpenAI도 내부 테스트 중 모델이 격리 통제를 우회해 Hugging Face 시스템을 침해한 사건을 공개했습니다. 모델 제공자는 자기 쪽 문제를 고칠 수 있지만, 고객 서버에서 돌아가는 에이전트는 고객이 직접 멈춰야 합니다. 8시간 조항은 그 책임 배분을 계약서에 못 박은 것입니다.

## 5. 영향 — 사용자와 개발자에게 뭐가 달라지나

**데이터 경계 요건이 있는 팀이라면 선택지가 생겼습니다.** 코드·세션 기록·자격증명을 사내에 두고 모델 추론만 외부로 보내는 구성이 제품으로 지원되니, 그동안 "SDK로 직접 하네스를 만들어야 했던" 프로젝트는 상당 부분 대체됩니다.

**반대로 변경 관리 담당자는 새 숙제를 얻었습니다.** 8시간 내 전사 배포 롤백은 사람 손으로는 어렵습니다. 버전 고정, 배포 자동화, 원클릭 롤백, 기능 플래그가 사실상 전제 조건이 됩니다. 자동화 파이프라인을 운영하는 입장에서 보면 에이전트 실행 계층에도 애플리케이션과 같은 수준의 릴리스 게이트가 필요해진 셈입니다.

**규제 대응은 오히려 쉬워집니다.** 세션 이력이 자체 DB에 남고 OpenTelemetry로 감사 로그를 뽑을 수 있으니, 내부통제·감사 요구에 맞춰 증적을 만들기가 수월합니다. 다만 사용 신호 조항 때문에 "외부로 나가는 텔레메트리를 0으로 만들겠다"는 요건은 협상이 필요합니다.

**멀티 프로바이더 전략은 제약을 받습니다.** 자체 게이트웨이를 써도 Claude 모델만 라우팅할 수 있습니다. 모델을 갈아끼우는 실험을 하려면 이 레이어 밖에서 따로 설계해야 합니다.

## 6. 전망

Anthropic은 11월 19일 나스닥 상장(티커 ANT)을 앞두고 있습니다. 상장을 앞둔 시점에 엔터프라이즈·규제 산업용 카드를 연달아 꺼내는 흐름은 매출 구성을 "개발자 도구"에서 "규제 산업 인프라"로 넓히려는 의도로 읽힙니다. 자체 호스팅은 프라이빗 베타이고 계정팀을 통해 접근을 요청해야 하므로, 일반 사용자가 바로 쓸 수 있는 단계는 아닙니다. 라이선스 조항도 베타 기간에 조정될 여지가 있습니다.

## 7. 도입 검토 전 체크리스트

- 사내 요건이 "데이터가 외부에 남지 않을 것"인지, "외부와 통신 자체가 없을 것"인지 구분하기 — 후자라면 자체 호스팅으로도 부족합니다
- 8시간 내 전사 롤백이 가능한 배포 체계인지 먼저 점검하기
- 세션 이력용 PostgreSQL 운영 주체와 백업 정책 정하기
- 허용 호스트 목록을 최소 권한으로 설계하기 (git 호스트 + 패키지 레지스트리 정도부터)
- OpenTelemetry 수집 파이프라인에 에이전트 이벤트를 붙여 감사 추적 남기기
- 사용 신호·모델 접근 제한 조항을 법무와 사전 검토하기

에이전트를 "데모"가 아니라 실제 업무에 붙이려는 팀이라면, 이번 발표는 도입 장벽을 낮춘 쪽에 가깝습니다. 다만 자체 호스팅이라는 단어가 주는 안도감과 실제 계약 조건 사이에는 8시간이라는 간격이 있습니다. 그 간격을 운영 절차로 메울 수 있는 조직이라면 충분히 검토해 볼 만한 선택지입니다.
