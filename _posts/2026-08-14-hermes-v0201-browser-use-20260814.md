요즘 저처럼 **오픈소스 AI 에이전트**에 관심 많으신 분들, 특히 **Hermes Agent**를 쓰면서 "요즘 뭐가 업데이트됐지?" 하고 매일 GitHub을 뒤적이시는 분들 많으시죠? 저도 이 블로그 포스팅을 **Hermes Agent 크론잡**으로 자동 발행하고 있어서, 릴리스와 커밋 소식을 거의 매일 같이 보고 있는데요.

어제(8/13) **Hermes Agent v0.20.1**이 조용히 배포됐습니다. 그런데 이번 패치, 숫자가 좀 무섭습니다. **v0.20.0(8/3) 이후 불과 10일 만에 1,444개 커밋·656개 PR**이 모였다고 하거든요. 솔직히 "패치 릴리스인데 이게 맞나?" 싶을 정도입니다.

그리고 그 사이 **브라우저 자동화의 판을 바꾸는 기능**이 기본 모드로 자리 잡았습니다. 바로 **Browser Use 모드**인데요 — 브라우저 도구 **12개가 '1개'로 통합**되는 변화라, 이번 글에서 **v0.20.1 소식 → Browser Use 모드 가이드 → 함께 보면 좋은 업데이트** 순서로 핵심만 정리해 드릴게요.

## 1. v0.20.1 배포 (8/13) — 10일 만에 656개 PR이 모인 '안정화 롤업'

8월 13일, Hermes Agent **v0.20.1 (v2026.8.13)**이 태그 릴리스로 배포됐습니다. 이번 릴리스는 신기능 대신 **v0.20.0 이후 쌓인 수백 개 PR을 한 번에 묶은 패치 롤업**이라는 점이 특징이에요.

- **1,444개 커밋 / 약 656개 머지 PR** / 2,172개 파일 변경 (+233,872 / −75,244줄)
- **약 481개 이슈 클로즈**
- 데스크톱 앱, 게이트웨이 플랫폼, 인스톨러, 툴 시스템, 프로바이더 카탈로그 전반의 **안정화·버그픽스**가 주를 이룸

재미있는 건 "이번 창의 **큐레이티드 릴리스 노트는 v0.21.0에 한 번에 공개**된다"고 공지되어 있다는 점입니다. 그러니까 지금은 `hermes update` 한 줄이면 받을 수 있는 **안정화 버전**이고, 이 기간의 하이라이트 정리는 다음 메이저 릴리스에서 나온다는 뜻이에요.

그래도 "10일 만에 656개 PR"이라는 숫자 자체가 **커뮤니티 기여가 얼마나 활발한지** 보여주는 지표라, 오픈소스 에이전트를 고르시는 분들이라면 눈여겨볼 만합니다. 참고로 현재 **GitHub 스타 23만 개(230,104) · 포크 4.5만 개**를 넘어섰습니다.

## 2. Browser Use 모드 — 브라우저 도구 12개가 'browser_exec' 1개로

이번에 가장 눈여겨봐야 할 변화는 따로 있습니다. Hermes는 원래 브라우저 관련 도구가 **12개**였는데, **Browser Use 모드**가 이걸 **단 하나의 도구(`browser_exec`)로 통합**했어요. Nous Research가 X(트위터)로 공식 발표한 내용이고, 핵심 PR(`feat(browser): Browser Use CLI 3.0 mode — one browser_exec driver over all CDP backends`, **#81958**)은 **8월 10일 머지**됐습니다.

### 2-1. 뭐가 어떻게 달라졌나?

기존 방식은 요청마다 **도구 12개의 스키마**를 싣고, 클릭 한 번 할 때마다 **도구 호출을 한 번씩** 해야 했습니다. Browser Use 모드는 여기서 완전히 다릅니다.

> **에이전트가 '브라우저를 조작하는 파이썬 스크립트'를 직접 작성하고 실행**합니다. 클릭, 타이핑, 드래그, 스크래핑까지 한 번에.

이 방식은 **browser_use의 CLI 3.0**이 구동하는데, 공식 문서 표현을 빌리면 **웹 태스크에서 SOTA(최고 수준)**로 평가받는 하네스라고 합니다. "도구 호출 한 번 = 동작 하나"에서 "스크립트 하나 = 작업 전체"로 패러다임이 바뀐 셈이죠.

### 2-2. 이제 '기본 모드'다

중요한 건 이 모드가 **기본값으로 자리 잡았다**는 겁니다. `browser.backend` 설정이 없고 `browser-use` CLI가 실행 가능하면(설치됐거나 `uvx`로 사용 가능), Hermes는 자동으로 **`browser_exec` 1개만** 제공합니다. CLI가 없으면 기존 내장 도구로 자동 폴백하니 "설정 잘못해서 브라우저가 아예 안 되면 어쩌지?" 하는 걱정은 안 하셔도 됩니다.

- **해제(기존 12개 도구 유지)**: `/browser use off` 또는 config에서 `browser.backend: "off"`
- **강제 활성화**: `browser.backend: "browser-use"`

또한 Browser Use 모드는 **설정된 브라우저 백엔드 위에서 동작**하는 드라이버라서, 로컬 Chrome은 물론 Nous 구독 클라우드, Browserbase, Firecrawl, Browser Use 클라우드 브라우저까지 **어떤 브라우저 소스와도 조합**됩니다. (예외는 Camofox뿐인데, CDP 엔드포인트가 없어서 자동으로 기존 도구를 유지합니다.)

### 2-3. 알아두면 좋은 주의점

솔직히 이 부분은 꼭 짚고 넘어가야 합니다. **Browser Use 모드는 모델이 작성한 파이썬을 내 컴퓨터에서 실행**하는 구조라, **터미널(terminal) 도구 권한이 있는 세션에서만 `browser_exec`가 제공**됩니다. 메신저처럼 터미널이 차단된 표면에서는 보안상 기존 브라우저 도구를 그대로 씁니다. "왜 나는 browser_exec가 안 보이지?" 하시는 분들은 이 조건부터 확인해 보시면 됩니다.

## 3. 로컬·클라우드 하이브리드 라우팅 — SSRF 걱정도 자동 해결

Browser Use 모드와 함께 공개된 **하이브리드 라우팅**도 꽤 유용합니다. 클라우드 브라우저(예: Browserbase)를 쓰고 있는데, 접속 URL이 **`localhost`·`127.0.0.1`·`192.168.x.x`·`10.x.x.x` 같은 사설 주소**로 바뀌면 어떻게 될까요?

Hermes는 이 경우 **로컬 Chromium 사이드카를 자동으로 띄워서** 사설 URL은 로컬에서 처리하고, 공개 URL은 계속 클라우드로 보냅니다. 같은 대화 안에서 **`http://localhost:3000` 대시보드 스크린샷 + `https://github.com` 스크래핑**이 동시에 되는 거죠.

- **기본값: 켜짐** (`browser.cloud_provider.auto_local_for_private_urls: true`)
- 클라우드 제공자는 사설 URL을 **절대 볼 수 없음**
- 공개 URL에서 사설 주소로 **리다이렉트되는 우회도 차단**

"로컬에서 개발 중인데 Browserbase를 쓰고 있어서 전환하기 번거롭다"는 워크플로우 고민이 싹 사라진다는 점이 마음에 들었습니다.

## 4. 함께 보면 좋은 최신 업데이트 (8/13 기준)

v0.20.1 창에서 쌓인 커밋 중 눈에 띄는 것들도 몇 개 추려 봤습니다.

- **MCP 추천 디렉터리 18개 공식 호스티드 리모트로 확장 (데스크톱)** — 데스크톱 앱에서 MCP 서버를 고를 때 추천 목록이 18개 공식 원격 서버로 늘어났습니다. MCP 처음 쓰시는 분들은 설정 삽질 대신 이 목록에서 골라 붙이는 걸 추천합니다.
- **`model_overrides` 설정 (모델별 메타데이터 오버라이드)** — 모델별로 메타데이터를 개별 덮어쓸 수 있는 단일 스키마가 정리됐습니다. "이 모델만 context 길이 다르게 잡고 싶다" 같은 커스텀이 훨씬 쉬워졌어요.
- **크론잡 `repeat` 지원** — `cron.manage add`에서 반복 실행 설정이 제대로 전달되도록 수정됐습니다. 저처럼 **크론잡으로 블로그 자동 포스팅**을 돌리는 분들께는 반가운 소식이에요.
- **비용 표시 정직성 개선** — 사용량 화면에서 1센트 미만 금액, 비용 버킷, 포함 내역을 솔직하게 표기하도록 바뀌었습니다. "이게 왜 이렇게 나오지?" 싶던 표시가 좀 더 투명해졌어요.
- **모델 카탈로그 새로고침 안정화** — models.dev 카탈로그의 ETag 조건부 GET, 네트워크 없는 환경 대응, 미러 URL 오버라이드까지 처리돼서 모델 목록 갱신이 훨씬 안정적입니다.

## 5. 마무리 — 업데이트는 'hermes update' 한 줄

정리하면, 이번 주 Hermes Agent의 핵심은 **"브라우저 자동화의 단순화"**입니다. 도구 12개가 스크립트 1개로 통합된 Browser Use 모드가 기본이 됐고, 그 위에서 로컬·클라우드를 자동으로 오가며 **속도와 보안(SSRF 가드)을 동시에** 챙기는 구조가 갖춰졌어요.

업데이트는 기존 설치자 기준 **`hermes update` 한 줄**이면 끝입니다. 새로 설치하시는 분들은 README의 인스톨러 원라인을 쓰시면 되고요.

솔직히 저처럼 **AI 에이전트로 반복 업무를 자동화**하시는 분들, 특히 "웹에서 정보 수집 → 정리 → 발행" 같은 파이프라인을 돌리시는 분들께는 **Browser Use 모드가 생각보다 큰 체감**을 주는 업데이트라고 봅니다. 브라우저 자동화가 필요한데 아직 Hermes를 안 써보셨다면, 이번 v0.20.1이 시작하기 좋은 타이밍입니다. 가성비 좋은 오픈소스 AI 에이전트 찾는 분께 추천드려요.
