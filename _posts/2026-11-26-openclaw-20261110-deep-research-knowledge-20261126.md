> **📌 한줄 요약:** 2026년 11월 25일 14시 42분(한국시간), OpenClaw **2026.11.10 정식판**이 올라왔습니다. 같은 날 오전에 나온 2026.11.9가 보안 유지보수 릴리스였다면, 이번 건은 **기능 릴리스**입니다. ① **딥리서치(Deep Research) 기본 탑재**, ② **로컬 지식 저장소(Knowledge) 플러그인**, ③ **에이전트 브라우저 인계(Browser handoff)** 가 간판이고, 여기에 ④ **`operator.cron` 권한 스코프** ⑤ **자동 업데이트 스케줄** ⑥ **자격증명·리다이렉트 보안 수정**이 함께 들어갔습니다. 규모는 **PR 7,671건, 기여자 349명**입니다.

## 유지보수 릴리스와 기능 릴리스가 하루에 겹쳤다

11월 25일은 OpenClaw 쪽에서 하루에 릴리스가 두 번 나온 날입니다. 오전 09시 47분에 **2026.11.9**(보안 하드닝 + 11월 29일 설정 만료 고지), 오후 14시 42분에 **2026.11.10** 정식판이 올라왔습니다. 앞선 글에서 2026.11.9를 따로 정리했으니, 이번 글은 2026.11.10만 봅니다.

숫자부터 정리하면 이렇습니다.

| 항목 | 내용 |
|---|---|
| 버전 | 2026.11.10 (정식) |
| 공개 시각 | 2026-11-25 05:42 UTC / 14:42 KST |
| 규모 | 커밋 8,309건 · PR 7,671건 · 기여자 349명 |

주의할 점은 **PR 7,671건이 전부 이번에 새로 만든 기능은 아니라는 것**입니다. 릴리스 노트 제목부터 "Changes included in this release"입니다. 즉 그동안 베타 채널(2026.11.10-beta.1~3)과 메인 브랜치에 쌓인 변경분이 정식 채널로 묶여 올라온 구조입니다. 그래서 "업데이트 한 번에 7천 건이 바뀐다"고 읽기보다는, **2026.11.5 이후 쌓인 변경분의 총결산**으로 보는 게 정확합니다.

## 핵심 1 — 딥리서치가 '기본 켜짐'으로 들어왔다

첫 번째가 가장 실무적인 변화입니다. **딥리서치(Deep Research)** 가 이번 릴리스부터 **기본 활성화** 상태로 들어갑니다.

기존에는 여러 웹 소스를 오가며 조사하는 작업을 만들려면 검색 툴과 요약 프롬프트를 직접 조합해야 했습니다. 이제는 채팅창에서 그냥 딥리서치를 요청하면 됩니다. 동작 방식은 이렇습니다.

- **포터블 엔진이 기본**입니다. 이미 연결해 둔 모델과 웹 도구를 그대로 씁니다. 별도 검색 API 계약이 필요 없습니다.
- 구글의 **관리형 리서치 엔진은 옵트인**입니다. 플러그인 설정에서 직접 켜야 합니다.
- 결과물은 **인용이 붙은 리포트**입니다. 출처가 서로 어긋나면 **인용문을 나란히 붙여** 보여주고, 근거가 비는 지점은 **Unresolved** 항목으로 따로 표시합니다.
- 웹 검색뿐 아니라 **로컬 파일·URL을 함께 넣을 수 있습니다.**
- 진행 상황은 채팅에서 실시간으로 보이고, **게이트웨이가 재시작돼도 작업이 이어집니다.**
- 저장된 리포트는 **7일간** 다시 열어볼 수 있습니다.

실무에서 체감이 큰 건 마지막 두 줄입니다. 조사 작업은 대개 오래 걸리는데, 그동안 창을 붙잡고 있어야 하거나 중간에 끊기면 처음부터 다시 시켜야 한다면 자동화에 넣기 어렵습니다. **재시작 후 재개 + 7일 보관**이 붙으면 "밤에 돌려 놓고 아침에 읽는다"는 흐름이 성립합니다.

다만 **"인용을 붙인다"와 "사실이 맞다"는 다른 문제**입니다. Unresolved 항목이 붙은 리포트는 그 자체로 "여기는 확정하지 못했다"는 신호이니, 그대로 사내 문서에 붙여 넣기보다는 그 목록을 먼저 확인하는 편이 안전합니다.

## 핵심 2 — Knowledge: 대화가 로컬 마크다운 저장소로 쌓인다

두 번째는 **Knowledge 플러그인**입니다. 성격을 한 줄로 말하면 **"흩어진 대화·회의·메모·파일을 로컬 마크다운 금고로 엮는 기능"** 입니다.

기본값은 **옵트인**입니다. 켜는 방법은 두 가지입니다. 설정에서 `plugins.slots.memory` 값을 `"knowledge"`로 바꾸거나, Settings의 메모리 제공자 목록에서 Knowledge를 고르면 됩니다. **게이트웨이 재시작 없이 핫리로드**되고, 기존 `memory-core` 데이터는 건드리지 않습니다.

동작에서 눈여겨볼 부분은 이렇습니다.

- 인물·프로젝트·결정 사항이 **서로 링크된 페이지**로 정리되고, Control UI 탐색기에서 훑을 수 있습니다.
- 프로젝트별 **타임라인**이 붙습니다. "이 결정이 왜 났는지"를 원문 발췌까지 거슬러 추적하는 구조입니다.
- **스크라이브(scribe)** 가 대화, Granola 회의록, 기존 메모/Dreams 일기를 읽어 페이지를 최신으로 유지합니다. 원본은 수정하지 않습니다.
- 수정·철회·병합이 가능하고, **로컬 Git 체크포인트**로 이전 버전을 남깁니다.
- 저장소는 **에이전트별**로 둘 수도, **여러 에이전트가 공유**할 수도 있습니다.

주의할 항목도 릴리스 노트에 명시돼 있습니다. **자동 리콜(auto recall)은 섀도 모드에서 시작**하는데, 이 섀도 모드의 키워드 스코어링은 **메시지 본문과 후보 발췌를 설정된 Decision 프로바이더로 전송**합니다. 로컬 저장소라고 해서 데이터가 기기 밖으로 전혀 나가지 않는 구성은 아니라는 뜻입니다. 민감한 대화가 섞이는 환경이라면 이 지점은 먼저 확인하고 켜는 게 좋습니다.

## 핵심 3 — 브라우저 인계: 로그인 벽에서 사람이 직접 받는다

세 번째는 **브라우저 인계(Browser handoff)** 입니다. 자동화를 오래 돌려 본 사람이라면 아는 장면이 있습니다. 결제·로그인·2단계 인증·CAPTCHA에서 에이전트가 멈춰 서고, 그 시점에 런 전체를 포기하거나 처음부터 다시 시켜야 합니다. 세션 상태는 날아가고, 앞서 채운 폼도 같이 사라집니다.

이번 릴리스는 그 지점에 **일시정지 버튼**을 넣었습니다.

- Control UI의 Browser 패널에서 **Take control** 을 누르면 에이전트의 클릭·타이핑이 멈추고, 그 사이 사람이 로그인이나 CAPTCHA를 끝냅니다.
- 끝나면 **Release control** 로 돌려주면 됩니다. **5분간 입력이 없으면 자동으로 반환**됩니다.
- 조작을 넘긴 상태에서도 에이전트는 **스냅샷·스크린샷을 계속 찍을 수 있고**, 다른 탭 작업도 유지됩니다.
- **Chrome 설정과 비밀번호 관리자**는 에이전트 손이 닿지 않는 별도 탭으로 열 수 있습니다.

제약도 분명합니다. **게이트웨이 호스트에서 도는 브라우저에만** 적용되고, 노드로 라우팅된 브라우저에는 없습니다. 그리고 툴바의 Take control을 실제로 눌러야 인계가 성립합니다. 화면을 그냥 클릭하거나 타이핑하는 것만으로는 넘어가지 않습니다.

## 업무 자동화에 직접 영향 있는 변경 3가지

간판 기능만 보면 "조사·기억·브라우저" 이야기로 끝나는데, 정작 매일 도는 작업에 영향을 주는 건 **Automations and Scheduling** 섹션입니다.

### ① operator.cron — 관리자 권한 없이 자기 작업만 관리

새 **`operator.cron` 스코프**가 생겼습니다. `operator.write`에 포함되는 범위입니다. 인증된 사용자가 **게이트웨이 관리자 권한 없이**, 자기 대화에 소유된 자동화를 에이전트 턴을 통해 만들고 관리할 수 있습니다.

여러 명이 한 게이트웨이를 쓰는 구성에서 의미가 있습니다. 지금까지는 크론 작업 하나 추가하려면 관리자 권한이 필요했고, 그 권한은 남의 작업까지 건드릴 수 있는 권한이었습니다. 이제 소유권과 호출자 권한이 **대시보드 대화 인계, 공유 대화, 채널 편집을 거쳐도 유지**됩니다. 신뢰 프록시 인증 환경에서도 마찬가지로, `allowUsers`에서 사용자를 빼거나 신원 스코프를 바꾸면 기존 작업은 거부되고, `trustedProxies` 같은 설정만 바꾸면 돌던 작업은 유지됩니다.

### ② 첫 실패에 소유 대화로 바로 알림

자동화가 실패했을 때 **첫 실패 시점에 소유 대화로 알림이 갑니다.** 지금까지는 실패가 며칠 쌓인 뒤에야 알아차리는 경우가 많았습니다. 조용히 죽는 자동화가 제일 나쁜데, 그 구간이 줄어드는 변경입니다.

함께 고쳐진 것도 실무형입니다. **이미지 생성 크론 실행**, 재시작·워커 복구, CLI 검증, 셀프 스크래치 접근 권한 문제가 이번에 정리됐습니다. 그리고 **동시 실행 슬롯 8개가 모두 차 있어도 조건 검사(condition check)는 응답**하도록 바뀌었습니다. 슬롯이 꽉 차면 조건 검사까지 줄을 서던 동작이 사라진 셈입니다.

### ③ 자동 업데이트에 스케줄이 생겼다

관리형 게이트웨이에서 자동 업데이트를 켜 둔 경우, **업데이트 캠페인이 시작되는 시점**을 고를 수 있습니다. Settings → Updates → Update schedule에서 **Hourly(기본) / Daily / Weekly / Custom cron** 중 선택하거나 `update.auto.schedule` 로 지정합니다. 시간은 **게이트웨이 호스트의 타임존**을 따르고, **게이트웨이 재시작 없이 적용**됩니다. 기존의 Hold 1시간, 수동 Update Gateway, 유휴 시 재시작 규칙은 그대로입니다.

업무 시간에 게이트웨이가 재시작되면 곤란한 환경이라면, 이 설정 하나로 새벽 시간대로 옮겨 둘 수 있습니다.

## 그 밖에 체감되는 변화

- **모델 카탈로그**: Gemini 4 Hydrogen이 카탈로그에 올랐습니다(컨텍스트 1,048,576 토큰, 기본 출력 65,536 토큰, thinking low/medium/high). Gemini 4 Carbon은 추천 목록에 추가됐고, 신규 Gemini 릴리스는 models.dev에서 자동 동기화됩니다. AI Studio 공식 엔드포인트의 Gemini 텍스트 모델은 **Interactions API가 기본**이고, `/fast on`은 이 경로에서 `service_tier=priority`로 매핑됩니다.
- **모델 카탈로그 v3 기본화**: 커스텀 프로바이더에 브랜드 표기가 붙고, Claude Code 웹 검색이 기본 활성화됩니다.
- **Control UI**: 툴 호출이 타임라인 형태로 정리되고, `/reasoning on`일 때 추론 단계가 얇은 한 줄 행으로 표시됩니다. 세션 메뉴에서 **Inline command trail** 을 켜면 셸 명령·파일 읽기·검색이 대화 순서대로 펼쳐집니다. Cmd+K 백그라운드 세션, Settings 레이아웃 개편, 카탈루냐어 추가도 포함됩니다.
- **Skills**: Skill Workshop이 번들 플러그인(`skill-workshop`)으로 편입됐고, `CLAW.md` 매니페스트 하나로 채팅에서 템플릿을 만들고 검토할 수 있습니다. 채팅 상세 화면에서 **어떤 스킬이 로드됐는지** 확인됩니다.
- **네이티브 앱**: macOS 앱에서 OpenClaw ID 로그인과 기기 등록이 가능해졌고, macOS·iOS에서 작성 중인 초안과 첨부가 앱 재시작 후에도 유지됩니다. Wear OS 앱에는 워치 어시스턴트 지원이 들어갔습니다.
- **PostgreSQL 운영**: 온라인 백업, 스테이징 복원 훈련, 멀티코어 아카이브 압축이 추가됐습니다.

## 솔직히, 아쉬운 부분

장점만 적으면 리뷰가 아니니 단점도 적습니다.

1. **옵트인 항목이 늘었다.** Knowledge는 기본 꺼짐이고, 관리형 리서치 엔진도 옵트인입니다. 기능은 좋아졌지만 **켜야 할 스위치가 늘어난 것**도 사실입니다. 릴리스 노트를 읽지 않으면 새 기능이 있는 줄도 모르고 지나갑니다.
2. **데이터 흐름을 따로 확인해야 한다.** Knowledge의 섀도 모드 리콜은 메시지와 후보 발췌를 Decision 프로바이더로 보냅니다. "로컬 마크다운 금고"라는 표현만 보고 내부망 전용이라고 단정하면 안 됩니다.
3. **브라우저 인계의 범위가 좁다.** 게이트웨이 호스트 브라우저에만 적용되고, 노드 라우팅 브라우저는 빠집니다. 노드로 브라우저를 몰아 쓰는 구성이라면 이 기능의 혜택은 없습니다.
4. **규모가 커서 회귀 위험이 남는다.** 7천 건 규모 변경분이 한 번에 정식 채널로 들어옵니다. 11월 중에도 2026.10.3 계열에서 회귀가 나온 전례가 있으니, 운영 게이트웨이는 바로 올리기보다 하루 이틀 관찰 후 올리는 편이 안전합니다.

## 업그레이드 전 체크리스트

업무 자동화를 굴리는 구성이라면 아래 순서를 권합니다.

1. **현재 버전과 자동 업데이트 스케줄 확인** — `openclaw --version`, Settings → Updates. Hourly 기본값이면 원치 않는 시간대에 재시작될 수 있습니다.
2. **`openclaw doctor` 실행** — 11월 29일 만료 예정 항목(2026.11.9 릴리스에서 고지된 deprecation)이 남아 있는지 확인합니다.
3. **크론 작업 소유권 점검** — `operator.cron` 스코프 도입으로 소유권 판정이 바뀝니다. 공유 대화에서 만든 작업이 있는지 봐 둘 것.
4. **Knowledge는 테스트 게이트웨이에서 먼저** — `plugins.slots.memory`를 바꾸면 핫리로드되므로, 운영 게이트웨이에서 바로 켜기보다 별도 프로필에서 먼저 확인하는 편이 안전합니다.
5. **백업** — PostgreSQL 구성이면 온라인 백업 기능이 새로 들어왔으니 이번 기회에 한 번 떠 두는 게 좋습니다.

## 정리

이번 2026.11.10은 **"에이전트가 조사하고, 기억하고, 막힌 지점에서 사람을 부를 수 있게 된"** 릴리스입니다. 세 가지 간판 기능이 각각 조사·기억·개입이라는, 자동화에서 실제로 발목 잡히던 지점을 하나씩 맡고 있습니다. 여기에 `operator.cron` 스코프와 자동 업데이트 스케줄이 붙어 **운영 권한과 유지보수 시간대**까지 손봤습니다.

반대로 옵트인 스위치가 늘고 데이터 흐름 확인 항목이 생겼으니, **"일단 설치하고 알아서 돌아가겠지"** 방식으로는 새 기능의 절반을 놓치게 됩니다. 릴리스 노트를 한 번 훑고, 자기 구성에서 실제로 켤 것만 켜는 방식이 이번 버전에는 더 맞습니다. 규모가 큰 업데이트인 만큼 운영 환경은 며칠 관찰 후 올리는 걸 권합니다.
