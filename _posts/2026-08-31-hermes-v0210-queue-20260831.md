## 1. 요즘 저처럼 "지난주 정리했는데 또 뭐가 달라졌지?" 하시는 분들

요즘 저처럼 **Hermes Agent로 블로그 크론잡(자동 예약 작업)을 돌리시는 분들**, 많으시죠. 지난주 금요일(8/29)에 **v0.20.6(v2026.8.27)** 업데이트를 낱낱이 정리해드렸는데, 솔직히 그 글을 쓰면서도 마음 한편이 편치 않았습니다. 왜냐하면 릴리스 노트마다 **"전체 큐레이티드 노트는 v0.21.0에서"**라는 문장이 붙어 있었거든요. **"그럼 그 사이에 또 뭐가 쌓이고 있는 거지?"** — 크론잡 운영자로서 이 궁금증을 못 참겠더라고요.

## 3. 핵심 테마 ① — 컴프레션 전쟁: "7~11분 멈추던 digest 스톨이 사라졌다"

### 어떤 변경인가

v0.20.6에서 **lean-tail 압축(문서 앞·뒤만 압축해서 담는 방식)이 기본값**이 된 건 지난주에 말씀드렸죠. 그런데 기본값이 되니 **실사용자들의 버그 리포트가 쏟아졌습니다.** 이번 주 머지 PR을 보면 그 수습 과정이 고스란히 보입니다.

> **"fix(compression): lean compaction is one auxiliary request again — 7-11 min digest stalls eliminated"**
> — Hermes Agent PR (2026-08-30 머지)

**압축을 실행할 때 보조 요청(auxiliary request)이 한 번 더 나가면서, 무려 7~11분 동안 대화가 멈추는(digest stall)** 문제였습니다. 크론잡을 돌리는 입장에서 7분 멈춤은 **"잡이 죽었나?"** 싶은 수준의 공포인데요, 이 PR이 **보조 요청을 다시 1회로 고정**하면서 스톨이 사라졌습니다.

같은 날 머지된 다른 컴프레션 PR들도 눈여겨볼 만합니다.

- **native compaction 핫-어플라이** — 컴팩션 설정을 바꾸면 **이미 열려 있는 세션에도 즉시 적용** (예전엔 재시작해야 반영)
- **시스템 프롬프트 커밋 경계 리빌드** — `feat(compaction): system prompt always rebuilds at the commit boundary` — 긴 세션에서 **업데이트가 끝까지 안 닿던 문제** 해결. 새 스킬·새 설정을 배워도 오래된 세션이면 계속 옛날 프롬프트로 돌던 버그였는데, 이제 커밋(체크포인트)마다 시스템 프롬프트를 다시 만듭니다
- **이미지만 있는 메시지 생존** — native compaction에서 **이미지 전용 메시지가 체크포인트 정리 때 사라지던 버그** 수정
- **Codex 세션 컴팩션 안정화** — 컴팩션만 하는 턴이 3회 연속 재시도 끝에 죽던 문제, 900K 창에서 200K 기본값으로 잘못 발화하던 문제 수정

### 실제 사용감/장점

솔직히 이번 주 컴프레션 PR들이 **제일 반가웠습니다.** 저는 크론잡이 매일 아침 여러 사이트를 읽고 요약하는데, **문서가 길어지면 예전엔 "응답이 5분 넘게 안 온다"** 싶은 순간이 있었거든요. 이제 digest 스톨이 사라졌으니 **길~고 긴 문서를 읽어도 대화가 멈추는 느낌이 확 줄었습니다.** 특히 **시스템 프롬프트 커밋 경계 리빌드**는 장수 세션(며칠째 이어가는 대화)에서 "왜 새로 배운 걸 자꾸 까먹지?" 하던 답답함을 해소해줍니다.

### 단점/주의

- 컴프레션 관련 PR이 **하루에 10개 이상** 쏟아지는 걸 보면, **아직 이 영역은 '안정화 진행형'**입니다. v0.21.0 정식 노트 전까지는 "압축 설정은 기본값을 믿고 가되, 이상하면 끄는" 전략이 안전합니다.
- 7~11분 스톨이 사라졌다고 해도, **초장문 컨텍스트의 근본적인 토큰 비용**은 그대로입니다. 컴팩션은 "멈춤"을 고쳤지 "비용"을 없앤 게 아니에요.

## 4. 핵심 테마 ② — 승인/보안: "무인 세션은 이제 기본으로 거부"

### 어떤 변경인가

이번 주 보안 쪽에서 **가장 의미 있는 변화**는 이것입니다.

> **"fix(approval): unattended webhook/API sessions no longer stall 300s on dangerous-command approval"**
> — Hermes Agent PR (2026-08-30 머지)

**웹훅(webhook)이나 API로 들어오는 무인(unattended) 세션**이 위험 명령어 승인을 기다리며 **300초(5분)를 멈춰 있던** 문제를 고치면서, 동시에 **이런 세션은 기본적으로 거부(deny by default)** 하도록 바꿨습니다. 그리고 같은 날 **"webhook 세션을 게이트웨이 승인 컨텍스트에서 제외"**하는 PR까지 붙었죠. 요약하면 **"사람이 없는 채널에서 위험한 명령은 그냥 안 된다"**가 기본값이 된 겁니다.

같은 날짜의 다른 보안 PR도 챙겨볼 만합니다.

- **세션 쿠키 권한 수정** — `fix(browser): copied session cookies are no longer world-readable` — 브라우저 세션 쿠키를 복사했을 때 **다른 계정도 읽을 수 있는 권한(0644)으로 저장되던 문제** 수정
- **환경변수 오탐 수정** — 변수명 중간에 API/KEY/TOKEN이 들어간 환경변수(예: `MY_API_URL`)가 **유출(exfiltration)로 오탐되던 문제** 수정. 크론잡에서 환경변수 다루는 분들께 반가운 소식

### 실제 사용감/장점

저처럼 **웹훅으로 크론잡 트리거를 받는** 사람에겐 이번 변경이 양날의 검입니다. 솔직히 **"기본 거부"는 살짝 불편할 수 있어요.** 하지만 생각보다 합리적인 이유가 있습니다. 무인 세션에서 위험 명령어가 **5분간 멈춰 있다가 타임아웃**되는 건 그냥 실패일 뿐인데, **거부(default deny)**는 "이 채널은 사람이 없으니 위험 명령은 아예 시도도 안 함"이라는 **명확한 계약**을 만들어줍니다. 보안 관점에선 오히려 예측 가능한 게 안전하죠.

### 단점/주의

- **웹훅/API 자동화를 많이 하는 분**은 "기본 거부"를 우회할 **명시적 허용 설정**을 확인해야 합니다. 승인 정책을 채널별로 어떻게 열어두는지는 **v0.21.0 정식 노트의 설정 문서**를 기다리는 게 정확합니다.
- 세션 쿠키 권한 수정은 **이미 복사된 과거 파일에는 소급 적용되지 않을 수** 있으니, 한 번쯤 `~/.hermes` 아래 쿠키 파일 권한을 확인해보시는 걸 추천합니다.

## 5. 핵심 테마 ③ — 스킬 시스템 슬림화: "활성화 로드 비용 -31%"

### 어떤 변경인가

Hermes Agent의 자랑인 **스킬 시스템**도 이번 주 대대적으로 다듬어졌습니다.

> **"fix: skill activation no longer repeats the absolute path on every supporting-file line (-31% load cost)"**
> — Hermes Agent PR (2026-08-30 머지)

스킬을 활성화할 때 **지원 파일(supporting file)마다 절대경로를 반복 출력하던 비효율**을 고쳐 **로드 비용을 31% 줄였습니다.** 숫자만 봐도 감이 오지만, 스킬을 여러 개 켜고 도는 크론잡 입장에선 **매 턴 컨텍스트 절약**이 쌓이면 꽤 큽니다.

같은 날 스킬 관련 PR이 유난히 많았습니다.

- **shipped-set 슬림** — 기본 번들 스킬 15개를 **optional(선택 설치)로 전환**, PDF 스킬은 OCR 흡수, 채널-게이트웨이 정리
- **skills-hub 설치 견고화** — dangling refs(끊긴 링크)·형제 링크·glob 문법·unpinned fetch 같은 **깨지기 쉬운 설치 케이스** 전부 수용
- **스킬 이름 해석 수정** — `skill_view`의 디렉터리 경로와 `skill_manage`의 분류 이름 해석 버그 수정

### 실제 사용감/장점

저는 블로그 크론잡에서 **blogger-style 스킬·이미지 리서치 스킬·최종 검증 스킬**을 매일 로드하는데, **로드 비용 -31%는 체감이 확실합니다.** 게다가 기본 번들에서 빠진 15개 스킬은 **필요할 때만 설치**하면 되니, "안 쓰는 스킬이 매 턴 컨텍스트를 먹던" 아까움이 줄었어요. **스킬 = 도구를 만드는 도구**라는 Hermes의 철학이, 이번 주엔 "가볍게" 방향으로 한 걸음 더 나갔다고 보시면 됩니다.

### 단점/주의

- **optional로 전환된 15개 스킬 중 일부를 이미 쓰고 있었다면**, 업데이트 후 **재설치가 필요할 수 있습니다.** 업데이트 전에 `hermes skills list`로 내가 쓰는 스킬이 뭔지 확인해두는 걸 추천해요.

## 6. 핵심 테마 ④~⑤ — 브라우저 헤드리스와 텔레그램 인라인 피커

### ④ 실제 프로필 브라우징, 이제 헤드리스로

지난주 v0.20.6의 스타 기능이었던 **동의 기반 실제 프로필 브라우징(consent-gated real-profile browsing)**이 이번 주에 **헤드리스(headless) 전환**됐습니다.

> **"fix(browser): real-profile browsing runs headless — no focus-stealing window"**
> — Hermes Agent PR (2026-08-30 머지)

지난주에도 **"브라우저가 독립 OS 창을 갖게 됐다"**고 말씀드렸는데, 그 **독립 창이 사용자가 다른 일을 하는 중에 갑자기 떠서 포커스를 뺏는(focus-stealing)** 문제가 있었나 봅니다. 이번 PR로 **실제 프로필 브라우징은 백그라운드(헤드리스)로 실행**되면서 **창이 튀어나와 작업을 방해하는 일이 사라졌습니다.** 자동화를 돌리면서 다른 작업을 하는 분께는 아주 반가운 수정이에요.

### ⑤ 텔레그램 @봇네임 인라인 피커

> **"feat(telegram): every command and skill is searchable via @botname — inline picker bypasses the menu"**
> — Hermes Agent PR (2026-08-30 머지)

텔레그램 게이트웨이에서 **모든 명령어와 스킬을 @봇네임 인라인 피커로 검색**할 수 있게 됐습니다. 슬래시 메뉴가 길어져서 **메뉴 한계(menu cap)에 걸려 못 보이던 명령·스킬도** 인라인 검색으로 바로 찾을 수 있고, 같은 날 **"pinned skill 명령이 메뉴 한계를 넘어도 살아남도록"** 하는 수정도 붙었습니다. 봇 모드(8/30 포스팅)와 합쳐지면 **"단톡방에서 봇에게 @멘션으로 일 시키기"**가 훨씬 유연해집니다.

## 7. 핵심 테마 ⑥~⑦ — 크론/터미널 운영 가시성

### ⑥ TUI 상태줄: cache-hit %·지연시간·t/s

> **"feat(tui): status rule shows cache-hit %, latency, and t/s with shared field toggles"**
> — Hermes Agent PR (2026-08-30 머지)

터미널 UI(TUI) 상태줄에 **캐시 히트율(cache-hit %)·지연시간(latency)·초당 토큰(t/s)**이 표시됩니다. 지난주 v0.20.6의 **TTL 웹검색 캐싱**과 맞물려서, **"지금 이 응답이 캐시에서 왔는지, 새 검색인지"**가 눈으로 보이는 거죠. 크론잡 운영자 입장에선 **"캐시가 실제로 작동하고 있다"**는 게 숫자로 확인되니 믿음이 갑니다.

### ⑦ 크론·게이트웨이 수정

- **`repeat='forever'` 수정** — 무한 반복 크론잡의 **업데이트가 깨지던 버그** 완결 (string-repeat 클래스 전체)
- **todo 스냅샷 정리** — stale todo 스냅샷이 쌓이거나 **완료된 계획이 부활하던 버그** 수정
- **게이트웨이 캐시 버스트** — 컴팩션 라우팅 설정 키 변경 시 **에이전트 캐시를 즉시 비우도록** 수정
- **모델 스위치 역량 보존** — 같은 공급자 내 `/model` 스위치·게이트웨이 재개 시 **네이티브 컴팩션 역량이 사라지던 문제** 수정, custom-provider `extra_body` 보존
