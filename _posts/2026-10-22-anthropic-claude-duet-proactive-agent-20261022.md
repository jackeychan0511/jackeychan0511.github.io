> **📌 한줄 요약:** 2026년 **10월 21일(미국 태평양시간)**, 앤트로픽이 **Claude Duet**의 리서치 프리뷰를 열었습니다. 이름 그대로 **"Claude가 먼저 말을 거는"** 구조입니다. **Opus 5.5**를 기반으로, **자체 브라우저가 설치된 클라우드 가상머신**에서 백그라운드로 일하고, **매일 아침 짧은 브리핑**을 보내며, **메시지 발송·결제·서명·삭제 같은 민감한 동작 앞에서는 반드시 승인을 기다립니다.** 배포는 **미국 Pro·Max 구독자 대상 대기명단**부터, 앱은 **iOS·안드로이드 독립 앱 + claude.ai**입니다.

지난 몇 달 Claude 쪽 소식은 신모델(Opus 5.5 → Sonnet 5.5 → Haiku 5.5)과 가격, 정책 이슈가 중심이었습니다. 이번 건은 결이 다릅니다. **모델이 아니라 '일하는 방식'이 바뀐 발표**입니다. 채팅창을 열어 질문을 던지는 쪽에서, 에이전트가 먼저 와서 "이건 지금 봐야 합니다"라고 말하는 쪽으로 무게추가 옮겨갑니다.

**무슨 일이 있었나 → Claude와 뭐가 다른가 → 실제 동작 방식 → 연결 범위 → 안전 설계 → 공개된 한계 → 경쟁 구도 → 영향(사용자/개발자) → 도입 체크리스트 → 전망** 순서로 정리했습니다.

## 1. 무슨 일이 있었나 — 10월 21일, 'Duet' 리서치 프리뷰

![Claude Duet 공식 대표 이미지](/assets/images/posts/anthropic-claude-duet-20261022/duet-hero.jpg)
*앤트로픽 공식 Claude Duet 제품 페이지의 대표 이미지. (이미지 출처: claude.com/duet)*

발표문의 첫 문장은 이렇습니다.

> "오늘 우리는 **Claude Duet**의 리서치 프리뷰를 연다. Claude가 **프로액티브 에이전트**로 일하는 새 앱이다. **주의가 필요한 것을 먼저 가져다주고**, 요청한 작업을 끝내고, **자리를 비운 동안에도 계속 일하며**, 사용자를 대신해 행동하기 전에 **확인을 받는다.**"

핵심 스펙을 표로 정리하면 이렇습니다.

| 항목 | 내용 |
|:---|:---|
| **발표일** | 2026년 10월 21일(미국 태평양시간) / 한국시간 10월 22일 오전 |
| **제품 성격** | 프로액티브 에이전트 앱 (**리서치 프리뷰**, 대기명단제) |

## 2. Claude와 뭐가 다른가 — '대화'가 아니라 '보고'

가장 궁금한 지점은 이겁니다. 이미 Claude가 있는데 왜 앱을 하나 더 만들었나. 앤트로픽이 FAQ에서 직접 답합니다.

| 구분 | 기존 Claude 앱 | **Claude Duet** |
|:---|:---|:---|
| **시작점** | 사용자가 채팅을 연다 | **Duet이 먼저 온다** |
| **작업 방식** | 함께 보면서 진행 | 위임 → 백그라운드 수행 → 결과 보고 |
| **스레드** | 대화별로 분리 | **하나의 이어지는 스레드** |
| **접점** | 열었을 때만 | 아침 브리핑 + 필요할 때만 알림 |
| **승인** | 해당 없음 | 발송·결제·서명·삭제 전 **필수 승인** |
| **기반 자산** | — | 기존 Claude의 **메모리·스킬·연결 앱** 승계 |

마지막 줄이 실무적으로 중요합니다. **기억(memory), 스킬(skills), 연결된 앱이 그대로 넘어옵니다.** 새 도구를 하나 더 배우는 게 아니라, 이미 쌓아둔 맥락 위에 "먼저 말 거는" 레이어가 얹히는 구조입니다.

발표문에 나온 내부 사용 사례도 이 방향을 보여줍니다. Claude Code 팀을 이끄는 Boris Cherny는 산책하면서 머릿속 할 일 목록을 Duet에게 말한다고 하고, 모델·제품 행동 설계 팀의 Chelsea Larsson은 아이들과 있으려고 자리를 뜨기 전에 할 일 목록을 넘기고 저녁에 결과 보고를 받는다고 합니다.

## 3. 실제 동작 — 아침 브리핑, 그리고 '조용히' 있는 시간

Duet의 하루는 대략 이렇게 흘러갑니다.

1. **매일 아침** — 연결된 앱들에서 중요한 항목을 뽑아 **짧은 브리핑**을 보냅니다.
2. **낮 동안** — 앱들을 **몇 시간 간격으로** 확인하고, 정말 주의가 필요할 때만 메시지를 보냅니다.
3. **작업 위임** — 짧은 메시지(텍스트 또는 음성)로 일을 넘기면, 어떤 앱을 어떤 순서로 쓸지 스스로 판단해 백그라운드에서 처리합니다.
4. **완료 또는 승인 요청** — 끝났거나 판단이 필요하면 알림이 옵니다.

여기서 눈에 띄는 문장이 있습니다. **"몇 시간마다 확인합니다. 끊임없이 확인하면 플랜 한도를 훨씬 빨리 소진하기 때문입니다."** 프로액티브 에이전트의 진짜 비용은 토큰이 아니라 **상시 감시**라는 걸 인정한 셈입니다. 그래서 "무엇을 얼마나 자주 알려줄지"를 사용자가 직접 조정할 수 있게 했습니다.

발표문이 든 업무 범위는 생각보다 넓습니다.

| 범주 | 예시 |
|:---|:---|
| **커뮤니케이션** | 놓친 Gmail·Slack 메시지 찾기, 답장 초안 작성 |
| **재무** | QuickBooks·Stripe에서 미수금 찾아 독촉장 초안, Gusto로 급여 준비(근무시간·보너스·경비 포함) |
| **채용·계약** | 채용 공고 초안 → 수정·승인 후 LinkedIn 게시, DocuSign으로 검토·서명 요청 |
| **영업** | HubSpot의 연락처·딜 이력으로 팔로업 메일 작성 |
| **마케팅·커머스** | Canva로 런칭 캠페인 제작, Shopify 스토어 설정·디자인·관리 |
| **분석** | 수십 개 도구를 엮은 대시보드, 재무·매출 예측, 프로토타입·웹앱 제작 |

결제도 됩니다. **Stripe의 디지털 월렛 'Link'** 로 물건을 사고, **가상 카드**로 결제해 실제 카드번호를 노출하지 않습니다. Shopify의 **Shop Pay**도 지원하고, **1Password에 저장된 로그인으로 사이트에 접속하는 기능**은 "곧"이라고 예고했습니다.

## 4. 안전 설계 — 승인 게이트가 제품의 절반

에이전트가 메일을 읽고 돈을 쓰는 순간, 위험은 기능이 아니라 **권한**에서 나옵니다. 발표문에서 이 부분이 가장 길게 설명돼 있습니다.

**① 사람이 최종 결정권자**
읽기·초안·준비는 스스로 하지만, **메시지 발송, 결제, 문서 서명, 삭제** 앞에서는 무엇을 하려는지 정확히 보여주고 기다립니다. 승인해도 **불가능한 동작**이 따로 있습니다. **증권 거래**와 **계좌 간 자금 이체**입니다. 연결된 앱은 언제든 해제할 수 있습니다.

**② 자격증명을 직접 보지 않음**
비밀번호·로그인 토큰 처리 방식은 **Claude Managed Agents** 설계를 따릅니다. 즉 Duet이 비밀번호 자체를 들여다보지 않는 구조입니다.

**③ 행동 승인은 분류기가 담당**
행동 실행 전 승인 판단에 **오토 모드 분류기(auto mode classifier)** 를 씁니다. Claude와 Claude Code를 "요청하지 않은 행동"에서 막는 것과 같은 장치입니다.

**④ 프롬프트 인젝션 방어**
숨은 지시·프롬프트 인젝션에 대한 방어는 **브라우저 사용 연구**에서 나온 것을 적용했습니다. 웹을 돌아다니는 에이전트에게 이건 선택이 아니라 전제입니다.

**⑤ 민감정보 전용 분류기**
메시지마다 검사하는 **전용 분류기와 안전 시스템 프롬프트**를 새로 붙였습니다. **신용카드 번호·정부 발급 신분증** 같은 최상위 민감 정보는 **공유 요청 자체를 거부**합니다. 건강·개인 재무 정보는 **사용자가 명시적으로 지시한 경우에만** 통과됩니다.

**⑥ 외부 검증**
레드팀과 **외부 업체의 침투 테스트**를 거쳤고, **공개 버그바운티 프로그램** 대상에 포함됩니다.

솔직히 말하면, 이 항목들은 "기능"이라기보다 **에이전트 제품이 갖춰야 할 최소선**에 가깝습니다. 앞으로 개인용 에이전트를 비교할 때 스펙표보다 먼저 봐야 할 것도 이쪽입니다.

## 5. 공개된 한계 — 여기가 실제 기대치 조절 지점

앤트로픽이 직접 밝힌 한계입니다. 오히려 이 목록이 도입 판단에 더 유용합니다.

| 한계 | 의미 |
|:---|:---|
| **스레드를 잘못 읽거나 긴급도를 오판할 수 있음** | 브리핑의 우선순위를 100% 신뢰하면 안 됨. 판단 튜닝은 진행 중 |
| **개인 잡무는 상대적으로 약함** | 항공권 예매 같은 개인 심부름보다 **업무** 중심으로 설계 |
| **자기 브라우저 화면을 아직 보여주지 못함** | 무슨 작업을 하는지 실시간 화면 확인은 제한적 (수행 이력은 확인 가능) |
| **당분간 별도 앱** | 기존 Claude 앱과 통합은 아직. 초기 사용자 피드백으로 방향 결정 |
| **사용 한도 공유** | Pro·Max 한도를 기존 Claude와 **나눠 씀**. 백그라운드 점검도 한도에 포함 |
| **큰 작업은 한도를 더 먹음** | 재무 모델·덱 제작처럼 모델 턴이 많이 필요한 작업은 체감 소모가 큼 |

특히 마지막 두 줄은 **요금 설계가 아직 미완성**이라는 신호로 읽힙니다. "프로액티브"와 "무제한에 가까운 사용"은 구조적으로 충돌합니다. 감시 주기를 몇 시간으로 두는 것도, 한도 정책이 아직 실험 단계이기 때문일 가능성이 큽니다.

## 6. 경쟁 구도 — 개인 에이전트 전쟁의 한가운데

Duet은 혼자 나온 제품이 아닙니다. 같은 주에 **Meta의 Muse**, **OpenAI의 Dots**가 이미 같은 카테고리를 차지하고 있고, xAI의 에이전트 계열도 거론됩니다. 외신들은 하나같이 "Anthropic이 Muse·Dots에 맞서는 에이전트를 냈다"는 프레임으로 보도했습니다.

세 제품의 공통점은 명확합니다.

- **먼저 말을 건다** (reaches out before you ask)
- **클라우드 가상머신 + 자체 브라우저**에서 백그라운드로 일한다
- **민감한 행동 전 승인**을 받는다

차이가 나는 지점은 **타깃과 유통**입니다. Duet은 처음부터 **전문직·소상공인**을 명시했습니다. 그 때문에 연결 목록이 QuickBooks·Gusto·DocuSign·HubSpot·Shopify처럼 **실제 업무 시스템**에 촘촘히 붙어 있습니다. 모델 성능 경쟁이 아니라 **업무 소프트웨어 생태계 장악** 경쟁으로 옮겨간 국면입니다.

## 7. 영향 — 누구에게 무엇이 달라지나

**① Claude Pro·Max 사용자 (국내 포함 관심사)**
현재는 **미국만** 대상입니다. 국내 계정은 대기명단 대상도 아니어서, 당장 쓸 수 있는 변화는 아닙니다. 다만 이번 프리뷰에서 검증된 **승인 게이트·자격증명 설계·한도 정책**은 이후 일반 플랜·타 지역 확장의 기준점이 됩니다. 한국어 지원 시점은 아직 공식 언급이 없습니다.

**② 업무 자동화 파이프라인을 운영하는 사람**
설계 패턴이 하나 더 표준이 됩니다. **"초안은 자유롭게, 실행은 승인 후"** 라는 분리입니다. 이미 크론잡과 에이전트를 굴리는 쪽이라면, 발송·결제·삭제 같은 지점에 승인 단계를 두는 것이 사실상 기본값이 되어가고 있다는 신호로 읽을 만합니다.

**③ 개발자·API 사용자**
당장 API로 Duet을 호출하는 제품은 아닙니다. 하지만 **커넥터 마켓플레이스(6,000개 이상)** 가 에이전트의 실질적 유통 채널이 되는 흐름은 분명합니다. 자사 서비스를 "에이전트가 쓸 수 있는 형태"로 노출하는 일이, 앱스토어 대응만큼 중요해지는 중입니다.

**④ 소상공인·전문직**
가장 직접적인 수혜층입니다. 다만 초기 버전 특성상 **미수금 독촉·급여 준비·계약서 발송**처럼 실수 비용이 큰 업무에 바로 붙이는 건 권하지 않습니다. 승인 게이트가 있더라도 **초안 검토 시간**은 사람 몫으로 남습니다.

## 8. 도입 전 체크리스트

- **대기명단·지역 조건 확인** — 미국 Pro·Max 대상. 승인 전에는 기능 문의보다 플랜 확인이 먼저입니다.
- **한도 소모 구조 이해** — 백그라운드 점검도 한도를 씁니다. 감시 주기를 짧게 잡으면 본 작업 몫이 줄어듭니다.
- **승인 지점을 먼저 정하기** — 발송·결제·서명·삭제 중 어디까지 자동으로 둘지, 업무별로 기준을 정해두는 편이 안전합니다.
- **민감정보 흐름 점검** — 카드번호·신분증은 차단되지만, 건강·재무 정보는 명시 지시 시 통과됩니다. 어떤 지시문을 쓰는지가 곧 정책입니다.
- **연결 앱 최소화** — 6,000개 커넥터가 매력적이어도, 처음엔 2~3개로 시작하는 편이 사고 반경이 작습니다.
- **개인 잡무는 기대하지 않기** — 업무 중심 설계입니다. 예약·티켓팅 같은 용도는 아직 약합니다.

## 9. 전망 — '반응형 AI'에서 '능동형 AI'로

이번 발표를 제품 하나 추가로만 보면 과소평가입니다. 최근 프런티어 랩들의 방향이 한 곳으로 모이고 있습니다. **사용자가 묻는 것을 잘 답하는 능력**에서, **무엇이 중요한지 스스로 판단해 먼저 개입하는 능력**으로 평가 축이 옮겨가는 중입니다. Managed Agents, 상시 실행 에이전트, 그리고 이번 Duet이 같은 줄기입니다.

앞으로 지켜볼 지점은 세 가지입니다.

1. **한도 정책의 진화** — 프로액티브 에이전트는 구조적으로 토큰을 계속 먹습니다. 별도 과금·전용 크레딧 체계가 등장할지
2. **지역·언어 확장** — 미국 프리뷰 이후 한국어·국내 업무 시스템(더존·네이버웍스 등) 연결이 언제 붙는지
3. **승인 UX의 표준화** — 승인 요청이 잦아지면 사용자가 승인 피로를 겪습니다. "무엇을 물어보고 무엇을 알아서 할지"의 기준이 제품 경쟁력이 될 가능성

생각보다 빠르게 온 변화입니다. 불과 한 달 전만 해도 Claude의 화두는 모델 버전과 가격이었는데, 이제는 **"이 에이전트에게 어디까지 맡길 것인가"** 라는 운영의 문제로 넘어왔습니다. 지금 필요한 건 새 기능을 쫓는 일이 아니라, **맡겨도 되는 경계를 정해두는 일**입니다.
