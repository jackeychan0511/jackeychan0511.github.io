> **📌 한줄 요약:** 2026년 11월 18일 13시 15분(한국시간), OpenClaw의 **LTS 대응 채널 `extended-stable` 태그가 2026.9.37 → 2026.10.33으로 이동**했습니다. **10월 말 코드에 2026.11.4 승인 베이스라인의 유지보수 수정과 보안 업데이트를 선별해서 얹은 게이트웨이 전용 릴리스**입니다. 실무적으로 눈에 띄는 건 **① 폴링 조건·MCP 이벤트에 반응하는 자동화**, **② 재시작·재연결을 넘어 살아남는 응답**, **③ 긴 대화·큰 세션 저장소에서의 OOM 감소**입니다. 대신 **네이티브 앱은 빠졌고, 버전 번호(10.33)와 실제 코드 베이스(11.4)가 어긋나는** 구조라 업데이트 전에 한 번 짚고 가야 합니다.

## LTS 트랙에 물려두고 쓰시는 분들, 이번 건은 그냥 지나치면 손해입니다

에이전트를 게이트웨이 서비스로 올려두고, 크론잡으로 반복 업무를 맡기고, 결과를 텔레그램이나 슬랙으로 받는 구성 — 이런 식으로 **한 번 붙여놓고 오래 굴리는 팀**이라면 채널 선택이 두 갈래로 갈립니다. 최신 기능이 먼저 들어오는 정규 안정판(2026.11.x)과, **한 달에 한 번 검증된 변경만 조심스럽게 얹는 확장 안정판(extended-stable)** 입니다.

솔직히 말하면 확장 안정판은 "조용한 게 미덕"인 채널입니다. 대부분의 달은 릴리스 노트가 밋밋하고, 뉴스로 다룰 일도 많지 않습니다. 그런데 이번 2026.10.33은 다릅니다. **9월 말 이후 두 달 가까이 쌓인 게이트웨이·코어 플러그인 변경이 한 번에 올라오는 릴리스**라, 2026.9.37에 머물러 있던 인스턴스라면 사실상 **한 세대를 건너뛰는 업데이트**가 됩니다. 반대로 2026.10.10처럼 10월 라인을 이미 쓰고 있었다면 "누적분 + 11.4 베이스라인 유지보수"가 얹히는 형태라 체감 폭이 훨씬 작습니다.

오늘은 **GitHub 릴리스 태그(v2026.10.33)의 릴리스 노트, npm dist-tags, 공식 릴리스 노트 페이지**를 기준으로 — 무슨 일이 있었는지, 무엇이 실질적으로 달라지는지, 어디를 조심해야 하는지 순서로 정리합니다.

## 1. 무슨 일이 있었나 — dist-tags가 2026.10.33으로

먼저 사실관계부터. npm 레지스트리에서 확인한 OpenClaw `dist-tags`는 이렇게 걸려 있습니다.

| 태그 | 이번 릴리스 전 | 현재 (2026.11.19 확인) |
|:---|:---|:---|
| `latest` | 2026.11.5 | **2026.11.5** |
| `beta` | 2026.11.5 | **2026.11.5** |
| `extended-stable` (LTS 대응) | 2026.9.37 | ⬆️ **2026.10.33** |

- **배포 시각:** 2026-11-18 **04:15 UTC** = 한국시간 **2026-11-18 13:15**
- **릴리스 성격:** 게이트웨이 전용(gateway-only) 확장 안정판. 공식 표현으로 "현재 LTS에 해당하는 릴리스"
- **코드 기준:** 2026년 10월 말 시점의 OpenClaw + **2026.11.4 승인 베이스라인의 선별 유지보수 수정** + 보안 업데이트
- **배포 범위:** 코어 npm 패키지, 공식 npm 플러그인, 게이트웨이 도커 이미지. **네이티브 앱(iOS/macOS/Android) 릴리스는 미포함**
- **릴리스 SHA:** `5196fbbf89838939b0c2e29c09b8829afbc0d415`
- **ClawHub:** 확장 안정판은 **ClawHub에 배포되지 않습니다** (스킬 마켓 기준이 아님)

여기서 한 가지 짚고 갈 부분이 있습니다. 이 릴리스의 **표시 버전은 2026.10.33인데, 플러그인 호환성 식별자는 2026.11.4 소스 베이스라인을 그대로 유지**합니다(#200302). 즉 "버전 번호는 10월 라인, 실제 코드는 11.4 계보"라는, 조금 헷갈리는 구성입니다. 플러그인 API 요구사항을 낮추지는 않았다는 뜻이라 **서드파티 플러그인을 쓰는 환경에서는 이 점이 가장 중요한 체크 포인트**가 됩니다.

## 4. 기능 변화 중 챙길 만한 것

'Changes' 절은 분량이 많아서, 실무에 닿는 것만 골라 정리했습니다.

- **세션 정리:** 대화 스누즈, 커스텀 기상 시간, 중첩 대화의 명시적 정리·아카이브 (#161960, #171255, #168076)
- **세션 컨텍스트:** Tasks 진행률을 Details에 표시, 헬퍼 대기 상태 표시, 헬퍼 수에서 서브에이전트 패널 열기 (#161674, #164190, #166142)
- **공유 대화:** 프롬프트·응답에 이모지 리액션, 세션의 송수신 시점 설정 (#161053, #162316)
- **워크스페이스:** 페어링된 기기의 기존 폴더에서 세션 시작, 호스팅 워크스페이스 선택 (#169722, #168259)
- **컨텍스트 관리:** 지원되는 OpenAI·Anthropic API 키 경로에서 **프로바이더 네이티브 압축**, ChatGPT 로그인 세션은 서버 측 압축, 컨텍스트 오버플로 복구 후 모델 폴백 (#168164, #168401, #170141)
- **음성 통화:** 통화별 브리프·리포트·실시간 스티어링·콜백·**보이스메일 감지**, OpenAI 실시간 음성에 커스텀 엔드포인트 (#165716, #165632)
- **Teams:** **다중 봇 계정** 지원 (#112811)
- **X 통합:** 멘션, GitHub 검증 저장소 작성자, 게스트 저장소 질문, **일·월별 API 비용 한도** (#165138, #168071, #165354, #165351)
- **MCP 앱:** 대화·워크스페이스 파일 전반에서 사용, 뷰가 열려 있는 동안 도구 접근 유지, principal 바인딩 릴레이 (#161747, #164496, #168233)
- **백업:** **외장 디스크·Cloudflare R2** 대상 지원, PostgreSQL 기반 저장소를 백업·업데이트 너머로 보존 (#161913, #170828)
- **Code Mode:** 셀·응답·재시작을 넘어 store/load 값 유지 (#164086, #164833)
- **Control UI:** 브랜딩·세션 배경 커스터마이즈, 유튜브 인라인 재생, diff 코드 접기, Nerd Font 터미널 폰트 (#168027, #168301, #164576, #172350, #166180)
- **설치:** 옵트인 고정 Bun 런타임, 독립 실행 파일 (#168832, #172384)

이 중에서 눈에 띄는 건 **백업 대상에 R2가 들어온 것**과 **X 통합의 비용 한도**입니다. 에이전트를 상시 굴리면 비용이 새는 지점이 늘 API 호출 쪽인데, 일·월 단위 상한을 걸 수 있게 된 건 운영자 입장에서 꽤 반가운 변화입니다.

## 5. 솔직히, 아쉬운 점도 있습니다

장점만 적으면 리뷰가 아니죠. 확장 안정판 2026.10.33에서 아쉬운 부분은 이렇습니다.

1. **네이티브 앱은 빠졌습니다.** 게이트웨이 전용이라 iOS·macOS·Android 앱 릴리스는 포함되지 않습니다. 데스크톱 앱을 주로 쓰는 환경이라면 "LTS로 올라갔다"는 말이 앱에도 그대로 적용된다고 오해하면 안 됩니다.
2. **버전 번호가 직관적이지 않습니다.** 표시는 2026.10.33인데 플러그인 호환성 식별자는 11.4 베이스라인입니다. 플러그인 개발자나 사내 포크를 유지하는 팀이라면 "내 코드가 어느 API 세대에 맞춰야 하는가"를 릴리스 노트로 확인해야 합니다.
3. **버전 스큐 검사가 양날의 검입니다.** 설치된 서비스가 쓰는 상태를 보호하려고 구버전 서비스의 간섭을 차단하는데, 오래된 서비스 유닛을 방치해 둔 환경에서는 업데이트가 예상과 다르게 막힐 수 있습니다.
4. **11.x 대비 지연은 남습니다.** 확장 안정판은 검증된 것만 얹는 채널이니, 11.5에서 자동 롤백이나 플러그인 API 파괴적 변경 같은 최신 처리가 필요하다면 결국 정규 안정판으로 넘어가야 합니다.
5. **ClawHub 미배포.** 확장 안정판은 ClawHub에 올라가지 않습니다. 스킬 마켓 기준으로 버전을 맞추는 팀은 이 점을 감안해야 합니다.

---

## 6. 올리기 전 체크리스트

바로 `npm i -g openclaw@2026.10.33`부터 치기보다, 아래 순서를 권합니다.

| 순서 | 확인할 것 | 이유 |
|:--|:---|:---|
| 1 | **백업** — 외장 디스크 또는 R2 대상 설정 | 이번 릴리스부터 백업 대상이 넓어졌지만, 업데이트 자체의 안전장치는 별개 |
| 2 | `openclaw doctor`로 현 상태 기록 | 업데이트 후 비교 기준점이 됨 |
| 3 | 도커라면 **이미지 태그를 2026.10.33으로 고정** | `latest`를 따라가면 정규 안정판으로 끌려감 |
| 4 | 플러그인 API 요구사항 확인 | 11.4 베이스라인 식별자 유지 (#200302) |
| 5 | 오래된 서비스 유닛 정리 | 버전 스큐 검사로 차단될 수 있음 |
| 6 | 업데이트 후 **텔레그램·왓츠앱·시그널 회귀 확인** | 응답 생존 계열 수정이 대거 포함된 영역 |
| 7 | 크론잡·시스템 이벤트 자동화 1회 수동 실행 | 완료 처리 권한·응답 보존 변경 확인 |

운영 중인 자동화가 많을수록 6·7번이 중요합니다. 응답이 조용히 사라지는 유형의 문제는 로그를 보기 전까지 모르는 경우가 많아서, 업데이트 직후 **한 번은 눈으로 확인**하는 편이 안전합니다.

---

## 7. 그래서, 누가 올려야 하나

정리하면 이렇습니다.

- **2026.9.37 LTS에 머물러 있던 환경** → 올릴 이유가 충분합니다. 두 달치 누적 개선이 한 번에 들어오고, OOM·업데이트 복구·응답 생존처럼 "조용히 터지는" 유형을 겨냥한 수정이 많습니다.
- **2026.10.10 등 10월 라인을 이미 쓰는 환경** → 급하지는 않습니다. 다만 11.4 베이스라인 유지보수와 보안 업데이트가 얹히므로, 다음 유지보수 창에 맞춰 올리는 걸 권합니다.
- **최신 기능이 필요한 환경** → 이 채널이 아니라 2026.11.5 정규 안정판이 답입니다.
- **데스크톱 앱 중심 환경** → 이번 릴리스는 해당 없음(게이트웨이 전용).

가성비로 따지면 이 릴리스의 값은 "무료"입니다. 오픈소스고, 추가 비용은 모델 API 호출과 호스팅뿐이죠. 대신 **업데이트 한 번 잘못 올려서 생기는 다운타임**이 진짜 비용입니다. 그 비용을 줄여주는 게 바로 이번 2026.10.33의 성격이라, **오래 굴리는 걸 우선하는 분들께 추천**하고 싶습니다.
