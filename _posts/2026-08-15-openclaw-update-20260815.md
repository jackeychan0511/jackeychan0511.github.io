요즘 저처럼 **오픈소스 AI 에이전트 OpenClaw**의 커밋 로그를 매일 아침에 한 번씩 훑어보시는 분들, 계시죠? 지난주 목요일(8/13) [v2026.8.1-beta.2 코드 프리즈 소식 글](/2026/08/13/openclaw-update-20260813/)에서 "다음 베타가 며칠 안에 나온다"고 말씀드렸는데, **오늘(8/15) 기준으로도 아직 정식 베타.2 태그는 안 찍혔습니다.** 대신 그 사이 메인브랜치에는 꽤 묵직한 기능들이 연달아 들어왔습니다.

솔직히 이틀 사이 커밋 수만 해도 **100건이 넘습니다.** 그중에서 제가 가장 눈여겨본 건 두 가지입니다. **① Codex 런타임에서도 클라우드 워커를 쓸 수 있게 된 것**, **② macOS에서 '컴퓨터 사용(computer.act)' v2가 네이티브로 자리 잡은 것**. 둘 다 지난주에 말씀드린 "내 기기들이 하나의 클러스터가 된다"는 방향의 연장선에 있는 기능들이에요. 오늘은 제가 GitHub 커밋과 PR에서 직접 확인한 **8월 15일자 OpenClaw 소식**을 정리해드립니다.

## 1. v2026.8.1-beta.2, 여전히 출시 대기 중 — 검증 라운드 후보만 계속 갱신

먼저 다들 궁금해하실 베타 소식입니다. 지난 글에서 "코드 프리즈 후 8번째 검증 라운드"라고 말씀드렸는데, **오늘 아침 확인 시점에도 npm 베타 태그는 여전히 `2026.8.1-beta.1`** 입니다.

- GitHub 릴리즈 피드에는 **`release-publish/...` 이름의 자동 검증 후보**가 8/13까지 세 차례 더 올라왔습니다. (한국시간 8/13 저녁이 마지막)
- 이건 "이 커밋 상태로 배포해도 되는가"를 자동 파이프라인이 검증하면서 찍는 후보 태그라서, **검증이 끝나고 정식 `v2026.8.1-beta.2` 태그가 찍히면 그때 배포**가 시작됩니다.
- npm 기준 현재 배포 상태: **최신 안정판 `2026.7.1-2` / 베타 `2026.8.1-beta.1` / 확장 안정판(extended-stable) `2026.6.34`**.

> 저처럼 베타 라인을 타시는 분은 `npm install -g openclaw@beta` 상태로 두시고 기다리시면 됩니다. 8/13 이후로 새 후보가 안 올라온 걸 보면, **검증팀이 마지막 정리를 하고 있는 게 아닌가** 싶어요. 출시는 이번 주말~다음 주 초 사이로 보고 있습니다.

## 2. ⭐ 이번 주 최대 신기능 — Codex 런타임용 클라우드 워커 (#123743)

어제(8/14, 한국시간 8/15 새벽) 메인브랜치에 합류한 **이번 주 최대 커밋**입니다.

- **`feat: cloud workers for the codex runtime (remote-exec placements)`** — 그동안 **클라우드 워커는 OpenClaw 런타임 전용**이었습니다. Codex 하네스(코드 에이전트)를 쓰는 환경에서는 Control UI의 클라우드 대상이 "클라우드 워커는 OpenClaw 런타임이 필요합니다"라며 회색으로 막혀 있었죠.
- 이번 변경으로 **Codex 앱서버에서도 일회용 클라우드 머신에 세션을 올려 실행**할 수 있게 됐습니다. Codex는 내부적으로 에이전트 루프·추론·인증을 자기 바이너리 안에 갖고 있어서 워커-턴 분할은 못 쓰지만, **네이티브 exec/fs/http가 샌드박스 exec-서버로 라우팅되는 구조**를 그대로 활용합니다.
- PR 설명을 보면 Codex 플러그인의 샌드박스 라우팅을 **원격 실행 배치(remote-exec placement)**에 연결하는 방식입니다.

솔직히 이게 왜 중요한지 한 문장으로 요약하면 — **"어떤 에이전트 런타임을 쓰든, 내 로컬 PC가 아니라 클라우드의 깨끗한 머신에서 AI가 작업한다"**가 기본 옵션이 되어가는 신호입니다. 지난주 [페어링 기기 워커 파운데이션](/2026/08/13/openclaw-update-20260813/)과 맞물려, OpenClaw가 "내 기기 + 클라우드 워커"를 하나의 실행 풀로 다루는 방향으로 확실히 가고 있어요.

## 3. macOS '컴퓨터 사용' v2 — Peekaboo로 네이티브 지원 (#123801)

맥 유저분들께 반가운 소식입니다. **macOS 컴퓨터 사용(Computer Use)의 새 버전(computer.act v2)이 네이티브 fulfill러인 'Peekaboo'를 통해 구현**됐습니다.

- 기존 Peekaboo는 **화면 좌표 기반의 v1 액션**만 지원했는데, 이번에 **v2 계약(정확한 창 관찰, 백그라운드 창·요소 입력, 생명주기, 구조화된 효과/에스컬레이션)**까지 지원하게 됐습니다.
- 구현 세부를 보면 **DesktopObservationService**(정확한 창 스크린샷 + AX 스냅샷), **UIAutomationService**(세대 고정 백그라운드 라우팅과 액션 결과), **ApplicationService·WindowManagementService·MenuService**(앱/창/메뉴 발견과 생명주기)가 묶여 있습니다.
- 보안도 꼼꼼합니다. **앱/창/관찰/요소 참조는 프로세스 로컬·실행 로컬**이고, 생명주기 세대가 바뀌면 무효화되며, **가장 최신 관찰 결과만 요소·픽셀 액션을 허가**합니다.

여기에 맞물려 **드라이버 엔드포인트를 비공개 환경변수 하나로 합친 보안 픽스(#123798, #123845)**도 함께 들어왔습니다. "맥에서 AI가 직접 화면을 보고 클릭한다"는 기능이 점점 실사용 가능한 수준으로 단단해지고 있다는 느낌입니다.

## 4. Slack·채널 소식 — 부재 시간(away duration) 전송 (#123805)

슬랙을 OpenClaw 게이트웨이로 쓰시는 분들께는 사소하지만 유용한 변경입니다.

- Slack에서 **away → active 전환 이벤트에 시간 메타데이터**(`observed_away_at_ms`, `observed_active_at_ms`, `observed_away_duration_ms`)가 추가됐습니다.
- 모니터가 **처음 감지한 away 시각을 다음 active가 감지될 때까지 보존**했다가 경과 시간을 함께 보고하는 방식입니다.
- "부재 중이었던 시간"을 에이전트가 알게 되면, **돌아온 사용자에게 "30분간 자리를 비우셨는데 그 사이 도착한 메시지부터 정리해 드릴까요?"** 같은 시나리오를 만들 수 있습니다. 저는 이거 다음 베타에서 바로 써볼 생각입니다.

## 5. 보안 강화 — 설치 경고 승인 제도, 출력 문자열 소독

8월 들어 계속 이어지고 있는 **보안 강화 흐름**도 이틀 사이 꽤 쌓였습니다.

- **설치 정책 경고 승인 제도 (#116489)** — 외부 `security.installPolicy` 명령이 `warn`을 반환하면, **의심스러운 플러그인·스킬 설치를 진행하기 전에 운영자가 검토 후 승인**하도록 바뀌었습니다. CLI 설치 시 사유와 조사 결과를 보여주고 **정확한 대상 이름을 입력해야** 계속됩니다. `--acknowledge-install-policy-warning` 플래그로 일괄 승인도 가능하고요.
- **승인 생성 경계 소독 (#123742)** — 플러그인 제목과 exec 경로를 승인 생성 시점에 정화(sanitize).
- **CLI 출력 문자열 소독 (#123797)** — `directory`, `cron show`, `agents`, `channels`, `sessions` 출력에서 저장된 문자열을 정화해 **터미널 출력 주입을 차단**합니다.
- **CUA 드라이버 엔드포인트 비공개화 (#123798, #123845)** — macOS 컴퓨터 사용 드라이버 소켓을 **버전 지정 JSON 하나로 합쳐 비공개 환경변수**로만 전달. 앞서 언급한 Peekaboo v2와 짝을 이루는 픽스입니다.
- **명시적 플릿 보안 (#123878)** — 명시적 플릿(explicit fleets)에서 쓰지 않는 기본 워크스페이스를 건너뛰도록 수정.

## 6. UI/UX — 랍스터를 이제 영구히 해제할 수 있습니다 (#123789)

재미있는 픽스도 있었습니다. 사이드바에 놀러 오는 **랍스터 마스코트를 이제 "이번 방문만 닫기"와 "앞으로 안 보이기" 중에 선택**할 수 있게 됐습니다. 기존에는 우클릭하면 바로 사라져서 "다시 보고 싶은데?" 하시는 분들이 있었거든요. 영구 해제 선택은 브라우저 로컬 설정(`lobsterPetVisits: false`)에 저장돼서 **외관(Appearance) 설정에서 언제든 되돌릴 수 있습니다.**

그 외에도 눈에 띄는 UI 개선들이 줄줄이 들어왔습니다.

- **활성 세션 포크 안정화 (#123718)** — 에이전트가 작업 중일 때 세션을 포크하면 거부되던 문제를 수정. 이제 **"마지막 완료 메시지 기준"으로 안정적인 경계를 잡아** 복사하고, 진행 중인 턴은 원본에 남깁니다.
- **게이트웨이 업데이트 후 낡은 탭이 계속 이벤트를 쏘던 문제 (#123882)**, **세션 생성 시간순 정렬 (#123828)**, **모바일 라이트박스 이미지 정리 (#123840)** 등.
- **자동 비활성화된 자동화를 '일시정지'로 숨기지 않고 그대로 표시 (#123769)** — 크론잡이 10회 실패로 꺼졌을 때 UI에서 안 보여서 헷갈렸던 분들께 반가운 변경입니다.

## 7. 안정성 픽스 — 메모리·워크스페이스·압축

## 9. 솔직한 단점 — 짚고 넘어갈 것들

좋은 점만 나열하면 솔직한 리뷰가 아니죠. 이번 주 기준으로 짚어야 할 것들입니다.

1. **베타.2는 아직 "출시 대기"** — 코드 프리즈 후 검증 후보만 갱신되는 상태가 8/13 이후로 멈춰 있습니다. 새 기능을 빨리 만져보고 싶은 분은 **메인브랜치 커밋을 직접 추적**하거나 베타.1을 쓰면서 기다려야 해요.
2. **신기능 대부분은 아직 메인브랜치** — 이번 글의 Codex 클라우드 워커, Peekaboo v2 같은 기능들은 **아직 어느 태그에도 실리지 않았습니다.** 베타.2에 들어갈지, 그다음 베타에 실릴지는 미정입니다.
3. **플러그인 SDK 이전 예고** — 2026.6.34 릴리즈에서 `before_agent_start`, 루트 `openclaw/plugin-sdk` 임포트, `providerAuthEnvVars`, `channelEnvVars`의 **제거 일정이 예고**됐습니다. 플러그인을 직접 만드시는 분은 공식 문서의 마이그레이션 가이드를 미리 확인하시는 게 좋아요.
4. **클라우드 워커는 여전히 진화 중** — Codex 런타임 지원이 막 합류한 만큼, 실사용 경험은 다음 베타부터 본격적으로 쌓일 전망입니다.

## 10. 마무리 — 추천 대상과 설치 방법

정리하면, **이번 주 OpenClaw의 키워드는 "어디서든 실행되는 에이전트"**입니다. Codex 클라우드 워커로 실행 환경의 선택지가 넓어졌고, macOS 컴퓨터 사용 v2로 맥에서의 자동화 범위가 한 단계 깊어졌습니다. 거기에 설치 경고 승인 제도·출력 소독 같은 **보안 레이어가 매 릴리즈마다 두꺼워지고** 있습니다.

설치는 아래 한 줄이면 끝입니다.

```
# 최신 안정판
npm install -g openclaw@latest

# 베타 라인 (신기능 체험)
npm install -g openclaw@beta
```

솔직히 저처럼 **메신저에서 바로 일하는 AI 비서**를 찾으시는 분, **Codex·Claude 같은 코딩 에이전트를 자기 PC 밖에서도 돌리고 싶은 분**이라면, OpenClaw의 다음 베타(8.1-beta.2)는 꼭 한번 타보시길 권합니다. 무료 오픈소스(MIT)에 38만 스타가 증명하듯 **가성비 좋은 AI 에이전트 찾는 분께 추천**드려요. 다음 베타가 찍히는 대로 다시 정리해서 찾아오겠습니다.
