요즘 저처럼 **"말로 입력하면 바로 글이 되는" 음성 AI**에 관심 있으신 분들 많으시죠? 솔직히 저도 회의록 정리할 때마다 "음… 그러니까… 그게…" 하며 더듬는 제 목소리를 받아 적다 보면, 그 필러 단어까지 그대로 텍스트로 남아서 일일이 지우느라 시간을 버리곤 했습니다. 그런데 지난 8월 26일, 구글이 이 고민을 정확히 겨냥한 모델을 내놨습니다.

바로 **'Gemini 3.5 Transcribe'**인데요. "음, 어" 같은 군더더기를 알아서 지워주고, 말하다가 고친 내용("화요일—아니, 수요일")까지 이해하는 구글의 **가장 정밀한 음성→텍스트(STT) 모델**입니다. 오늘은 이 소식을 **이슈 요약 → 상세 분석 → 영향(사용자·개발자) → 전망** 순서로 정리해 드립니다.

*Gemini 3.5 Transcribe — 구글 공식 블로그 'Introducing Gemini 3.5 Transcribe' (출처: Google 공식 블로그, 2026.8.26)*

## 📌 이슈 요약: "더듬는 말투까지 정리해 주는" STT 모델

- **8월 26일**, 구글이 공식 블로그를 통해 **Gemini 3.5 Transcribe** 발표 — "가장 정밀한(most precise) 음성→텍스트 모델"
- 기존 STT 모델(**Chirp 3**) 대비 **시간 대비 최종 텍스트 생성 속도 70% 개선**, 오류율(WER) 대폭 감소
- **핵심 기능 5가지**: ① 필러 단어("음·어") 자동 제거 ② 말하다 고친 내용(self-correction) 이해 ③ 전문 용어·고유 철자 인식(커스텀 어휘) ④ **85개 이상 언어** 자동 감지 ⑤ 녹음 파일에서 **최대 3명 화자 구분** + 단어 단위 타임스탬프
- **이미 실사용 중**: Android Gboard의 **Rambler** 기능, macOS **Gemini 앱** — **Chrome에도 곧 적용** 예정
- 개발자는 **Gemini API(공개 프리뷰)**에서 바로 사용 가능 — 실시간 스트리밍(Live API)과 녹음 파일(Interactions API) 두 가지 방식

> ⚠️ 본 글은 2026년 8월 30일 기준 Google 공식 블로그(8/26)·9to5Google(8/26)·Ars Technica·The Rundown 보도를 바탕으로 작성했습니다.

## 🔍 상세 분석: 무엇이 달라졌나

### 1. "받아쓰기"가 아니라 "정리된 문서"가 나온다

기존 음성 인식은 소리를 글자로 바꿔줄 뿐, 말투의 군더더기까지는 그대로 남겼습니다. Gemini 3.5 Transcribe는 **원시 오디오를 바로 '정확하고 다듬어진, 서식 적용된 텍스트'로 변환**합니다. 예를 들어 "화요일에 만나자—아니, 수요일"이라고 말하면 최종 텍스트는 **"수요일에 만나자"**로 정리되고, "음", "어" 같은 필러는 싹 빠집니다. 배경 소음이 많은 실제 환경과 우편번호·주문번호 같은 영숫자 조합에서도 강점을 보인다고 합니다.

### 2. 성능 지표: 숫자로 보는 '대형 업그레이드'

| 지표 | Gemini 3.5 Transcribe | 비고 |
|:---|:---|:---|
| 🎯 **WER(단어 오류율)** | 스트리밍 4.0% / 비스트리밍 2.6% | Artificial Analysis 측정, Chirp 3 대비 대폭 개선 |
| 🌍 **FLEURS 다국어 벤치마크** | 스트리밍 5.50% / 비스트리밍 5.04% | 주요 언어·로케일 기준 |
| ⚡ **최종 텍스트 생성 시간** | Chirp 3 대비 **70% 개선** | 실시간 감성 중요 |
| 🗣️ **언어** | **85개 이상** 자동 감지 | 지역 억양·방언 대응 |
| 👥 **화자 구분** | 최대 3명 + 타임스탬프 | 3명 초과는 실험적 지원 |

### 3. 개발자를 위한 두 갈래 API

- **실시간 스트리밍**: `gemini-3.5-transcribe-live` — Live API 기반, **양방향·서브초(1초 미만) 지연**으로 음성 에이전트·실시간 자막에 적합
- **녹음 파일 처리**: `gemini-3.5-transcribe` — Interactions API 기반, **최대 1시간 오디오**를 화자 속성·단어 단위 타임스탬프와 함께 처리 (회의록·통화 분석 파이프라인용)
- **함수 호출(Function calling)** 지원 — 다른 Gemini 모델에 이미지 생성·파일 분석 같은 작업을 위임 (macOS Gemini 앱에서 이미 활용 중)

## 👥 영향: 사용자와 개발자

### 일반 사용자
- **Gboard의 Rambler**(Android): 말한 생각을 바로 정리된 텍스트로. 음성으로 **편집·맞춤법 수정·문체 변경**까지 가능 — "받아쓰기 후 손으로 고치던" 습관이 바뀔 전망
- **macOS Gemini 앱**: 음성만으로 파일 요약·문서 재작성·이미지 생성까지 — 화면 컨텍스트와 연동된 복합 워크플로가 가능
- **Chrome**: "곧(coming soon)" — 웹의 **모든 입력 필드에서 말로 타이핑**할 수 있게 됨. 댓글·이메일·Gemini 프롬프트를 말로 입력하는 시대가 열립니다

### 개발자·스타트업
- **공개 프리뷰(public preview)** 상태로 Gemini API·Google AI Studio·Google Antigravity에서 바로 사용 가능
- **Agora, LiveKit, Pipecat, LangChain, Vercel** 등 주요 실시간 음성 플랫폼이 Gemini Live API 기반으로 3.5 Transcribe를 통합 지원 — **음성 에이전트 구축 비용·시간이 크게 줄어듦**
- vivo, Intellitek Health, Lingopal 등이 지연 시간·정확도·다국어 지원에 긍정적 피드백
- **기업**: Gemini Enterprise Agent Platform에서 프리뷰 제공, 곧 'Gemini Enterprise for Customer Experience'로 확대

### 경쟁 구도
- OpenAI(Whisper 계열)·AWS(Transcribe) 등 기존 STT 시장에서 **"말투 정리 + 실시간 스트리밍 + 멀티모달 함수 호출"** 조합으로 차별화
- 이미 Gboard·Gemini 앱·Chrome 등 **수십억 사용자 접점에 내장**되는 유통력이 최대 강점

## 🔮 전망

1. **STT의 기준선 이동** — "소리를 글자로"에서 "말을 문서로"로. 필러 제거·자동 서식이 기본이 되면 받아쓰기 앱 시장의 재편이 예상됩니다
2. **음성 에이전트 대중화 가속** — 서브초 스트리밍 + 함수 호출로 "말로 일 시키는" AI 비서가 현실적인 수준에 도달
3. **구글 생태계 전방위 확산** — Gboard·Gemini 앱·Antigravity에 이어 **Chrome·Docs·Gmail**까지 STT가 기본 기능으로 스며들 전망
4. **Gemini 3.5 Audio 패밀리 확장** — Live Translate(통역)·Transcribe(녹음)·Transcribe Live(실시간)로 나뉘는 오디오 모델 라인업이 본격화

## 💡 마무리: 지금 바로 써보는 법

- **일반 사용자라면**: Android Gboard 설정에서 **Rambler**를 켜고 메시지 앱에서 말해 보세요. "음…어…" 없이 정리된 텍스트가 나오는 걸 체감할 수 있습니다. macOS Gemini 앱(영어)에서도 음성 명령으로 파일 분석·이미지 생성을 시도해 보시길.
- **개발자라면**: Google AI Studio의 Build 모드에서 **Gemini 3.5 Transcribe**를 골라 음성으로 코드를 작성(vibe coding)해 보거나, Live API로 실시간 자막 앱을 만들어 보는 걸 추천합니다. 공개 프리뷰라 테스트 부담이 작습니다.
- 솔직히 "회의 녹음 → 정리된 회의록"까지 한 방에 나오는 날이 생각보다 가까워졌습니다. **음성 입력을 일상에 도입하고 싶은 분, STT API로 서비스를 만들려는 분** 모두에게 추천할 만한 업데이트입니다.
