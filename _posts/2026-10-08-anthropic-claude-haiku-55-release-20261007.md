> **📌 한줄 요약:** **2026년 10월 7일**, **Anthropic(앤트로픽)** 이 소형 모델 **'Claude Haiku 5.5'** 를 공개했습니다. **100만 토큰 컨텍스트**(기존 Haiku 4.5는 20만 토큰)에 **최대 12만 8천 토큰 출력**을 지원하고, **10만 토큰 이하 프롬프트 기준 입력 100만 토큰당 0.10달러·출력 0.50달러**로 **Haiku 4.5 대비 최대 90% 저렴**해졌습니다. 같은 날 **Sonnet 5.5의 캐시 읽기 가격 50% 인하**와 **Max·Team 구독자 대상 월 API 크레딧**도 함께 발표됐습니다. 한마디로 **"소형 모델이 이제 '싸구려 대충'이 아니라, 대량 작업의 실전 주력으로 올라온"** 사건입니다.

가벼운 작업은 가벼운 모델로 돌리는 게 맞다는 걸 알면서도, 막상 소형 모델을 붙이면 **"요약은 되는데 판단은 못 미더운"** 순간이 자주 옵니다. 그래서 결국 무거운 상위 모델을 계속 쓰게 되고, 비용은 생각보다 빠르게 부풀죠. 반복 작업·분류·서브에이전트처럼 **호출 수가 많은 구간**일수록 이 딜레마가 커집니다.

그 균형점을 다시 계산하게 만드는 발표가 나왔습니다. 이번 글은 **① 이슈 요약 → ② 상세 분석 → ③ 영향(사용자/개발자) → ④ 유의점 → ⑤ 전망** 순으로 정리합니다.

## 1. 이슈 요약 — 무엇이 나왔나

Anthropic이 **2026년 10월 7일**, Claude 5.5 패밀리의 마지막 퍼즐인 **Claude Haiku 5.5**를 출시했습니다. 회사는 이 모델을 **"지금까지 만든 것 중 가장 싸고, 가장 빠르며, 가장 유능한 소형 모델"** 이라고 소개합니다.

핵심 특징은 이렇습니다.

- **모델 ID:** `claude-haiku-5-5` (Amazon Bedrock에서는 `anthropic.claude-haiku-5-5`)
- **컨텍스트 창:** **100만 토큰** (Haiku 4.5의 20만 토큰에서 대폭 확대)
- **최대 출력:** **12만 8천 토큰**
- **가격(10만 토큰 이하 프롬프트):** 입력 **$0.10** / 출력 **$0.50** (백만 토큰당) → Haiku 4.5의 **$1.00 / $5.00** 대비 **최대 90% 인하**
- **가용 플랫폼:** Claude Platform(AWS·Google Cloud·Microsoft Azure 포함), Amazon Bedrock, Google Vertex AI, Microsoft Foundry, Claude Platform on AWS

특히 **"Haiku 클래스 최초로 adjustable effort(조절 가능한 추론 노력) 설정"** 을 지원한다는 점이 눈에 띕니다. Low·Medium·High·Xhigh·Max 다섯 단계로 **"돈을 아낄지, 똑똑함을 살지"** 를 작업별로 선택할 수 있습니다.

참고로 5.5 패밀리는 **Opus 5.5(9월 22일) → Sonnet 5.5(9월 28일) → Haiku 5.5(10월 7일)** 순으로 완성됐습니다. Haiku는 **4.5에서 곧바로 5.5로 건너뛰었고**, 5는 존재하지 않습니다.

## 2. 상세 분석 — 성능·가격·안전성

### 2-1. 성능: "소형"의 기준이 올라갔다

Anthropic이 공개한 주요 벤치마크입니다. Haiku 4.5와 직접 비교하면 상승폭이 상당합니다.

| 벤치마크 | Haiku 5.5 | Haiku 4.5 | GPT-6 Luna | Sonnet 5.5 |
|---|---|---|---|---|
| 지식 노동 (GDPval-AA v2.1) | **1620** | 735 | 1437 | 1840 |
| 지식 노동 (AA-Briefcase v1.1) | **1578** | 614 | 1336 | 1824 |
| 컴퓨터 사용 (OSWorld 2.1) | **72.4%** | 15.7% | 48.9% | 83.9% |
| Humanity's Last Exam (no tools) | 45.9% | 10.2% | — | 56.9% |
| Humanity's Last Exam (with tools) | 57.4% | 18.7% | — | 64.5% |
| 에이전트 코딩 (Terminal-Bench 4.0) | 39.2% | 0.0% | 16.4% | 70.6% |
| 에이전트 코딩 (FrontierCode 1.1, Main) | 46.4% | — | 42.4% | 52.1% |
| 시각 추론 (Chartography, no tools) | 46.4% | 6.4% | 29.1% | 61.6% |

가장 눈에 띄는 건 **컴퓨터 사용(OSWorld 2.1)** 입니다. 무려 **15.7% → 72.4%** 로 뛰었습니다. 화면을 보고 클릭·입력하며 여러 단계 작업을 수행하는 **에이전트형 작업**에서 소형 모델이 실사용 가능한 수준으로 올라온 겁니다. 서드파티 평가기관 **Artificial Analysis의 Intelligence Index도 43점**으로, 약 1년 전 Haiku 4.5보다 **26점 상승**했습니다.

반면 **복잡한 에이전트 코딩(Terminal-Bench 4.0)은 39.2%** 로, Sonnet 5.5(70.6%)와는 여전히 큰 격차가 있습니다. Anthropic도 공식적으로 **"복잡한 코딩은 Sonnet·Opus가 낫고, Haiku 5.5는 압축·요약·서브에이전트처럼 좁고 반복적인 작업에 최적"** 이라고 선을 긋습니다.

### 2-2. 가격: 두 개의 구간, 그리고 '100K 임계값'

가격표를 보면 **10만 토큰을 기준으로 요금이 뛰는 2단 구조**가 핵심입니다.

| 항목 (백만 토큰당) | Haiku 5.5 (≤100k) | Haiku 5.5 (>100k) | Haiku 4.5 | Sonnet 5.5 |
|---|---|---|---|---|
| 입력 | **$0.10** | $0.50 | $1.00 | $2.00 |
| 출력 | **$0.50** | $2.50 | $5.00 | $10.00 |
| 캐시 읽기 | $0.01 | $0.05 | $0.10 | $0.10 |
| 캐시 쓰기 | $0.125 | $0.625 | $1.25 | $2.50 |

Anthropic은 **기존 Haiku 4.5 요청의 약 90%가 10만 토큰 이하**였다며, 이 구간에서는 **Haiku 4.5보다 90% 저렴**하고 전체적으로는 **평균 약 75% 저렴**하다고 설명합니다. 다만 **10만 토큰을 넘기면 입력·출력 모두 5배**로 뛰니, 긴 문서를 통째로 밀어 넣는 워크로드라면 체감 단가가 달라집니다.

### 2-3. 같은 날 함께 나온 소식

Haiku 5.5 발표에는 **모델 가격만이 아니라 생태계 조정**이 같이 담겼습니다.

- **Sonnet 5.5 캐시 읽기 50% 인하:** $0.20 → **$0.10** (백만 토큰당). 캐시 읽기는 토큰 소모의 큰 비중을 차지하기에, **대부분의 에이전트 작업에서 Sonnet 5.5 비용이 약 20% 절감**됩니다.
- **Max·Team 구독자 월 API 크레딧:** 이번 주부터 **Max 5x $100, Max 20x $200, Team 최대 $500(사용자 풀링)**. API를 호출하는 도구·앱·에이전트를 실험하는 용도이며, **대화형 Claude Code 세션과 Bedrock 등 서드파티 클라우드는 제외**됩니다.
- **SDK 업데이트:** Claude Python·TypeScript SDK에 **컴퓨터 유즈·브라우저 유즈(베타)** 지원 추가. 빠르고 저렴한 Haiku 5.5와 궁합이 좋다고 강조합니다.

### 2-4. 안전성

Anthropic은 Haiku 5.5가 **Haiku 4.5 대비 거의 모든 정렬(alignment) 평가에서 개선**됐고, 오용 협조 성향이 줄었다고 밝혔습니다. 다만 **사이버보안 세이프가드는 Haiku 4.5보다 더 제한적**이며(방어 작업은 Sonnet 5.5보다 넓게 허용하되 침투 테스트 등은 차단), **생물학 세이프가드는 Sonnet 5·5.5·Opus 5와 동일**합니다. 폭넓은 생물·사이버 연구가 필요한 조직은 **Life Sciences·Cyber Verification Program**을 신청할 수 있습니다.

## 3. 영향 — 사용자와 개발자에게 무엇이 달라지나

### 👤 사용자 관점

- **"값싼 모델 = 못 미덥다"는 인식이 약해집니다.** 요약·분류·표 정리처럼 자주 반복되는 작업에서, 품질 손실을 크게 감수하지 않고도 비용을 낮출 여지가 생깁니다.
- **컴퓨터·브라우저 자동화의 문턱이 내려갑니다.** OSWorld 점수가 70%대까지 올라온 소형 모델이 초저가로 풀린다는 건, **화면 조작형 자동화**를 대량으로 돌리는 시나리오가 현실적인 단가로 계산된다는 뜻입니다.
- **Max·Team 사용자라면 월 API 크레딧**으로 개인 자동화 도구를 직접 실험해 볼 수 있습니다.

### 🧑‍💻 개발자 관점

- **서브에이전트·라우팅 설계가 유리해집니다.** 상위 모델이 큰 그림을 잡고, Haiku 5.5 서브에이전트가 **특정 구간(사내 문서에서 수치 하나 뽑기, 요약, 압축)** 을 맡는 구조가 비용 효율적으로 정당화됩니다.
- **100만 토큰 컨텍스트 + 조절형 effort** 조합은, 프롬프트·비용·품질을 동시에 튜닝할 수 있는 여지를 넓힙니다.
- 실사용 사례도 이미 나왔습니다. **Asana**는 AI 에이전트 제품에서 **지연 30% 이상 감소, 에이전트 턴당 최대 2.5배 빠른 추론**을 보고했고, **HubSpot**은 CRM 평가 스위트에서 **92.8%** 로 자사 최고 점수를 기록했습니다. **AlphaSense**(주 800만 회 호출 서비스)는 **0.84 대 0.76**으로 유의미한 개선을, **Box**는 **Haiku 4.5보다 11점 높은 점수를 약 절반 지연**으로 얻었다고 밝혔습니다.

## 4. 유의점 — 솔직히 봐야 할 부분

- **'100K 임계값'을 예산에 반영해야 합니다.** 10만 토큰 초과 시 단가가 5배로 뛰니, 긴 컨텍스트를 상습적으로 밀어 넣는 파이프라인은 헤드라인 단가와 실제 청구액이 크게 벌어질 수 있습니다.
- **토크나이저가 바뀌었습니다.** Sonnet 5.5·Opus 5.5와 유사한 토크나이저를 써서 **같은 작업에 토큰을 조금 더 소모**합니다. 순수 단가 인하폭(90%)이 곧 청구서 인하폭(약 75%)은 아닙니다.
- **복잡한 에이전트 코딩에는 부족합니다.** Terminal-Bench 4.0이 39.2%로, **다단계 코딩 자동화는 여전히 Sonnet·Opus의 영역**입니다. "가장 싼 모델"을 만능으로 쓰면 품질에서 손해를 봅니다.
- **사이버보안 세이프가드가 더 제한적**이라, 보안 관련 자동화를 소형 모델로 돌리려는 계획은 별도 검증이 필요합니다.

## 5. 전망

이번 발표는 **"프런티어 성능 경쟁"과 "단가 경쟁"이 동시에 소형 모델 구간으로 내려왔다**는 신호로 읽힙니다. Haiku 5.5는 **OpenAI GPT-6 Luna와 동일한 단가($0.10/$0.50, 100k 이하)** 를 책정하며 정면으로 맞붙었고, 그와 동시에 Sonnet 5.5의 캐시 가격 인하와 구독 크레딧으로 **모델 라인 전체의 '가성비 곡선'을 다시 그렸습니다.**

앞으로 주목할 지점은 셋입니다. **①** 저가·고성능 소형 모델이 보편화되면 **다중 에이전트(오케스트레이터 + 저가 서브에이전트)** 구조가 기본값이 될 가능성, **②** 100만 토큰 컨텍스트가 소형 모델까지 내려오며 **"긴 문서 통째 처리"** 워크로드의 설계가 바뀌는 흐름, **③** 10만 토큰 임계값 같은 **구간형 과금**이 업계 표준으로 자리 잡을지 여부입니다. Anthropic이 예고한 대로 컴퓨터·브라우저 유즈 SDK가 안정화되면, **저가 소형 모델 기반 화면 자동화**가 다음 격전지가 될 공산이 큽니다.

## 마무리 — 이런 분께 추천

정리하면, **Claude Haiku 5.5는 "요약·분류·압축·서브에이전트"처럼 호출은 많은데 판단은 단순한 작업**을 대량으로 돌리는 분들께 특히 잘 맞습니다. AI 에이전트를 실사용하고 있거나 자동화 파이프라인을 운영하는 입장이라면, **상위 모델은 큰 판단에만 쓰고 반복 구간은 Haiku 5.5로 내리는 라우팅**을 한번 계산해 볼 만합니다. 반대로 복잡한 코딩 자동화가 중심이라면, 저렴하다는 이유만으로 갈아타기보다 **Sonnet 5.5·Opus 5.5와 역할을 나누는 쪽**이 안전합니다.

무엇보다 **"소형 모델을 쓸까 말까"를 고민하던 단계에서, "어디까지 소형 모델에 맡길까"를 설계하는 단계로 넘어갔다**는 게 이번 소식의 진짜 의미라고 봅니다. 가성비 좋은 모델 조합을 찾는 분들께 추천할 만한 업데이트입니다.
