> **📌 한줄 요약:** 요즘 오픈소스 AI 에이전트를 업무 자동화에 붙여 굴리는 분들이라면, 이번 소식은 눈여겨볼 만합니다. **2026년 10월 11일**, OpenClaw가 베타 채널에 **`2026.10.5-beta.1`** 을 올렸습니다. 하루 전 정식판 `2026.10.1`이 나온 직후라 "또 업데이트?" 싶지만, 내용은 결이 다릅니다. 핵심은 **새 X(트위터) 멘션 채널 플러그인**, **음성 통화의 통화 브리핑·통화 리포트·실시간 개입·콜백·보이스메일 감지**, **게이트웨이 안에서 ClawHub 플러그인·스킬 탐색**, **워커 로컬 추론 런타임**, 그리고 **재시작을 넘어가는 대화·업데이트 안정성**입니다. 즉 "채널과 입력 경로를 넓히고, 런타임을 더 단단하게 만든 베타"입니다.

---

## 이 글을 읽으면 알 수 있는 것

- **2026.10.5-beta.1**이 하루 전 정식판(2026.10.1)과 무엇이 다른지
- **새 X(트위터) 채널 플러그인**이 자동화에 갖는 의미와 기본 안전장치
- **음성 통화 기능**(통화 브리핑·리포트·보이스메일 감지)의 실무 활용 포인트
- **게이트웨이 내장 ClawHub**와 **워커 로컬 추론**이 운영에 주는 변화
- **재시작 안전성·게이트웨이 성능** 개선이 왜 중요한지
- 지금 **베타를 올릴지, 정식판/LTS에 남을지** 판단하는 기준

## 도입: "채널이 하나 늘면, 자동화가 붙는 자리도 하나 는다"

업무 자동화 파이프라인에 AI 에이전트를 붙여 쓰는 분들이라면 아마 공감할 텐데, 실사용에서 판을 가르는 건 모델 성능보다 **"어디로 들어오는 요청을 잡을 수 있느냐"** 입니다. 메신저 하나가 늘고, 문의 채널 하나가 붙고, 전화 응대가 하나 생기는 순간마다 자동화로 흡수할 수 있는 일감의 종류가 달라집니다. 반대로 **업데이트 도중 게이트웨이가 멈추거나, 재시작 한 번에 대화 맥락이 날아가는 문제**는 가장 조용히 쌓이다 크게 터지는 유형입니다.

그래서 이번 **OpenClaw `2026.10.5-beta.1`** 은 성격상 눈여겨볼 만합니다. 겉으로는 "채널 하나 추가 + 통화 기능 확장"처럼 보이지만, 실제로 무게가 실린 곳은 **채널 확장(입력 경로)** 과 **재시작·업데이트 안정성(운영 기반)** 입니다. 오늘은 **GitHub 공식 릴리스 노트**와 **OpenClaw 공식 문서**를 기준으로, 꼭 알아야 할 것만 정리해 드립니다.

## 2. 핵심 변경 ① — X(트위터) 멘션 채널 플러그인

이번 베타에서 가장 눈에 띄는 건 **X(트위터)를 정식 채널로 붙이는 플러그인**입니다. 릴리스 노트 기준으로 이 채널은 **멘션을 에이전트 대화로 바꾸고, 에이전트의 답변을 공개 답글로 게시**합니다. 세부 사항이 실무적으로 꽤 촘촘합니다.

- **Activity API 스트리밍 + 백필**로 멘션을 수집합니다(#165138, #165337, #165354).
- 기본값은 **허용 목록(allowlist)에 있는 작성자만 응답을 트리거**하고, 그 외 작성자는 조용히 무시합니다. 게스트 모드를 켜면 저장소 관련 질문에 한해 응답 범위를 넓힐 수 있습니다.
- **GitHub 검증을 거친 저장소 작성자**만 쓰기 동작을 수행하도록 제한합니다.
- **일일·월간 X API 비용 한도**를 강제합니다(#165351, #168071).

자동화 관점에서 의미가 있는 지점은 명확합니다. **"외부에서 들어오는 공개 문의를 자동으로 받아 답하는 통로"** 가 하나 생긴 겁니다. 다만 릴리스 노트가 **비용 한도와 작성자 검증을 기본으로 깔아 둔 것**이 핵심입니다. 공개 채널은 잘못 열면 API 비용과 스팸이 같이 들어오는데, 그 두 가지를 플러그인 차원에서 먼저 막아 둔 셈입니다.

## 3. 핵심 변경 ② — 음성 통화에 "통화 브리핑·리포트·보이스메일 감지"

두 번째 축은 **음성 통화(voice call)** 입니다. 이번 판에서 통화 기능에 다음이 붙었습니다(#165716).

- **통화별 브리핑(per-call briefs)** — 이번 통화에서 무엇을 처리할지 미리 지정
- **통화 리포트(call reports)** — 통화가 끝난 뒤 무엇이 오갔는지 요약
- **실시간 개입(live steering)** — 통화 도중 방향을 바꿔 지시
- **콜백(callbacks)** 과 **보이스메일 감지(voicemail detection)**

공식 문서 기준으로 음성 통화 플러그인은 기본 **`sessionScope: "per-phone"`** 을 써서, **같은 발신자의 반복 통화가 대화 기억을 이어갑니다**. 업무 자동화 쪽에서 보면 **"예약·확인 전화를 에이전트가 받고, 요약을 남기고, 필요하면 다시 걸게 하는"** 흐름이 문서 수준에서 정리되기 시작한 겁니다. 다만 음성은 실패 모드가 많아서(끊김, 배경 소음, 보이스메일), **바로 프로덕션에 붙이기보다는 시나리오를 좁혀 검증하는 편**이 안전합니다.

## 4. 핵심 변경 ③ — ClawHub 내장과 워커 로컬 추론

### ① 게이트웨이 안에서 ClawHub을 탐색합니다
이번 판에서는 **게이트웨이에서 ClawHub의 플러그인과 스킬을 직접 검색·탐색**할 수 있게 됐고(#163459), **플러그인이 실행 중인 OpenClaw가 지원하는 최신 공식 릴리스판을 자동으로 고르도록** 개선됐습니다(#167485, #166588). 여러 대를 굴리면서 버전이 조금씩 다른 환경에서는 이 "알아서 맞는 판 고르기"가 은근히 체감이 큽니다.

### ② 워커 로컬 추론(worker-local inference)
**네이티브 워커 추론 런타임**이 추가되어, 게이트웨이가 작업을 배분하고 클라이언트가 **로컬 추론 위치를 지정**할 수 있게 됐습니다. 릴리스 노트에는 **필수 워커 정책과 목적지 검사, 실패 시 설명**까지 함께 들어갑니다(#158902, #163645~#163647, #166611 등). 요약하면 **"추론을 어디서 돌릴지"를 운영 정책으로 다룰 수 있는 문이 열린 것**입니다. 로컬 모델을 쓰거나 비용·데이터 위치를 통제해야 하는 환경에 의미가 있습니다.

### ③ 모델 픽커와 카탈로그 정리
- 각 제공자의 **권장 모델을 픽커 맨 앞에 노출**하고, **새로 등록된 Claude·ChatGPT·Ollama 모델을 OpenClaw 릴리스 없이도 표시**합니다(#167370, #166737, #167658).
- **카탈로그 v2**에 제공자별 추천 목록을 실어 보내고, **게이트웨이 재시작 없이 다운로드한 카탈로그를 적용**합니다(#167989, #158000).
- **Claude Haiku 5.5 지원**이 이 베타에도 그대로 들어와 있습니다(#166706).

## 5. 업데이트·재시작 안정성 — 이번 판의 진짜 무게

솔직히 말하면, 이번 판에서 가장 실무적인 변화는 신기능보다 **안정성 항목**일 수 있습니다.

- **더 안전한 업데이트:** 기기·파일시스템·Windows 권한 상승·중단된 활성화를 넘어 업데이트가 끝나고, **낡은 리스(lease)·바뀐 근거(evidence)에서 복구**해 설치를 방치하거나 이후 업데이트를 막지 않습니다(#164636, #166695, #168043 등).
- **재시작 안전 대화:** **중단된 턴, 작업 트리 준비 중 들어온 첫 메시지, 지연된 작업이 게이트웨이 재시작 후 이어집니다.** 사용자 입력과 커밋된 세션 데이터가 재시작·동시 쓰기·실패한 발행을 넘어 살아남습니다(#165333, #166042, #165502, #167570 등).
- **더 빠르고 안정적인 게이트웨이:** 세션·트랜스크립트·히스토리·메타데이터 읽기를 **워커 스레드로 옮기고 턴당 SQLite 작업량을 크게 줄였습니다**. 시작 유지보수도 준비 완료 이후로 밀어, 바쁜 게이트웨이가 멈추지 않게 했습니다(#164744, #165470, #167194 등).
- **턴·서브에이전트 신뢰성:** 멈춘 스트림, 재사용된 도구 호출 ID, 만료된 ChatGPT 웹소켓에서 턴이 복구되고, **서브에이전트 결과가 후속 턴·재시작·만료된 전달 창을 넘어 계속 반환**됩니다(#165983, #167013, #168068 등).
- **자동화 복구:** 실패한 자동화가 **알림 전에 소유자 대화에서 먼저 복구를 시도**하고, 오류가 바뀌면 두 번째 복구 턴을 줍니다(#161007, #162702, #162772).

솔직히 이런 항목들은 사용자 기능이 아니라서 체감이 잘 안 됩니다. 그런데 **"업데이트가 반쯤 멈추는 문제"와 "재시작하면 맥락이 날아가는 문제"는 프로덕션에서 가장 조용히 쌓이다 크게 터지는 유형**입니다. 이번 판은 그쪽에 무게가 실려 있습니다.

## 6. 보안·데이터 무결성 수정

릴리스 노트의 "Fixes"에서 자동화 운영에 직결되는 항목만 추리면 이렇습니다.

- **보안 경계:** 해결되지 않은 **A2A 피어 토큰 참조에 fail-closed**, 프로세스 목록으로 임시 루트 미사용을 증명하지 못하면 **fail-closed**, **호환되지 않는 워커 프롬프트 컨텍스트는 실행 전에 거부**(#165021, #165079, #166268)
- **세션 권한·프라이버시:** 압축을 위한 콜드 히스토리 복원 전에 **호출자 권한 확인**, 커밋된 세션 변경 후 권한 최신 유지, **잘못된 훅 세션 키 거부**(#166506, #167875, #166406)
- **데이터 무결성:** 검증 전에 **잘못된 UTF-8 백업 매니페스트 거부**, 잘못된 UTF-8·연결 대상의 뒤 공백 보존, 첨부 파일의 악센트 유지(#167389, #167399, #167116)
- **세션 데이터 안전:** 재시작 복구와 실패한 발행을 넘어 **사용자 입력과 커밋된 사실 보존**, 교차 스토어 워커 커밋 펜싱(#165502, #167570, #168018)

**보안·프라이버시 쪽 동작은 OpenClaw 공식 문서의 Security(감사·자동 수정) 절차와 함께 확인하는 게 좋습니다.** 공개 채널(X)과 음성 통화처럼 **입력 경로가 늘어나는 판에서는 이 경계 수정들이 특히 중요**합니다.

## 7. 지금 올려야 할까 — 베타 판단 가이드

**① LTS(extended-stable)나 정식판으로 운영하는 경우**
- 굳이 이 베타로 갈 필요는 없습니다. LTS 트랙은 별도로 관리되며 검증된 변경만 내려옵니다. (직전 LTS 대응 판은 2026.8.35)
- X 채널·음성 통화가 **업무에 곧바로 필요하지 않다면, `2026.10.1` 정식판에서 한 박자 쉬어가는 편**이 안전합니다.

**② 신기능을 먼저 검증하려는 경우**
- **별도 테스트 인스턴스에 베타를 올리고**, X 멘션 응답과 통화 흐름만 좁혀 리허설하는 방식을 권합니다. 특히 X 채널은 **API 비용 한도 설정값을 먼저 확인**하세요.
- 업데이트는 **한 대씩 순차적으로.** 한 번에 다 올리면 문제 원인을 못 찾습니다.

**③ 여러 대를 굴리는 경우**
- **핵심 업무 파이프라인은 LTS/정식판, 실험·신기능은 베타 채널**로 분리하는 구성이 여전히 실질적으로 유리합니다.
- 재시작 안전성·게이트웨이 성능 개선은 베타에 먼저 들어오므로, **"다음 정식판에서 내려올 항목 목록"** 으로 읽어 두면 계획을 세우기 쉽습니다.

## 8. 솔직한 장단점 정리

**좋았던 점**
- **X(트위터) 채널 플러그인**이 비용 한도·작성자 검증을 기본으로 깔고 들어온 게 반갑습니다. 공개 채널을 열 때 가장 무서운 두 가지를 먼저 막아 줍니다.
- **음성 통화의 통화 리포트·보이스메일 감지**는 "받고, 요약하고, 다시 걸기" 흐름을 문서 수준에서 다룰 수 있게 해 줍니다.
- **재시작을 넘어가는 대화·서브에이전트 결과**는 장기 실행 자동화의 체감 안정성을 확실히 올리는 방향입니다.
- **게이트웨이 성능(워커 스레드·SQLite 절감)** 개선은 대화가 길어지고 스킬이 많아질수록 차이가 납니다.
- **게이트웨이 내장 ClawHub**로 플러그인·스킬 탐색 동선이 짧아졌습니다.

**아쉬운 점**
- **베타**입니다. X 채널과 음성 통화는 실패 모드가 많은 영역이라, 프로덕션 투입 전 별도 검증이 사실상 필수입니다.
- 릴리스 노트가 **PR 목록까지 포함해 매우 방대**해서, 필요한 항목만 골라 읽는 데 시간이 듭니다.
- X API는 **비용이 외부 요인**이라, 한도 설정을 잘못 잡으면 자동화가 조용히 멈출 수 있습니다.
- **음성 통화는 통화 품질·언어·규제 이슈**가 겹치는 영역이라, 국내 환경에 그대로 얹기엔 확인할 게 남아 있습니다.

## 마무리 — "입력 경로를 넓히는 판"을 미리 보고 싶은 분께 추천

정리하면, **OpenClaw `2026.10.5-beta.1`** 은 화려한 단일 기능보다 **"채널을 넓히고(X·음성) 런타임을 단단하게(재시작 안전·게이트웨이 성능)"** 만든 베타입니다. X 멘션 채널과 음성 통화는 자동화가 붙을 수 있는 입력 경로를 늘려 주고, 재시작 안전성·자동화 복구 개선은 파이프라인이 조용히 멈추는 사고를 줄이는 방향입니다. 최신 기능을 당장 쓸 필요는 없지만, **다음 정식판에서 무엇이 내려올지 미리 가늠하고 싶은 분** — 그런 분께 추천합니다.

**활용 팁 하나.** 새 채널을 붙일 때는 **"응답 범위 → 비용 한도 → 실패 시 알림"** 순서로 좁혀서 여는 게 가성비가 좋습니다. 특히 X 채널은 기본이 허용 목록 기반이니, **먼저 자기 계정 하나로만 응답을 트리거해 보고** 범위를 넓히는 순서를 권합니다. 음성 통화는 시나리오를 하나(예: 예약 확인)로 정해 놓고 통화 리포트가 쓸 만한 수준인지부터 확인하는 편이 안전합니다.

> 다음 관전 포인트는 **X 채널과 음성 통화가 어떤 정식판으로 승격되는지**, 그리고 **재시작 안전성·워커 로컬 추론 개선이 LTS 트랙에 언제 내려오는지**입니다.
