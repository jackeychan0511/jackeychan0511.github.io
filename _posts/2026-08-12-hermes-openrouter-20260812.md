요즘 저처럼 **AI 에이전트를 실제 업무에 붙여 쓰는 분들**이라면, "이제 AI 에이전트가 그냥 유행이 아니라 인프라가 되어가고 있다"는 걸 체감하시는 분 많으시죠? 저도 이 블로그의 일부 자동 포스팅을 **Hermes Agent 크론잡**으로 돌리고 있는 입장이라, 최근 수치들이 나올 때마다 "생각보다 훨씬 빠르게 커지고 있구나" 싶습니다.

그런데 지난주, 이 오픈소스 에이전트의 **어마어마한 사용량 기록**이 공개되면서 해외 IT 커뮤니티가 한바탕 떠들썩했습니다. 바로 **OpenRouter에서 하루(주간 기준) 약 1.5조 토큰을 처리**하며, **플랫폼에 추적되는 다른 앱 49개의 합산 사용량과 맞먹는 수치**를 기록했다는 건데요. 솔직히 이 숫자는 "AI 에이전트 시대"가 실제로 열렸다는 걸 보여주는 가장 강력한 증거라고 생각합니다.

이번 글에서는 **① OpenRouter 토큰 기록 → ② GitHub 스타 22.9만 돌파와 커뮤니티 → ③ Block의 Buzz 통합 → ④ 공식 문서에 새로 추가된 실전 가이드** 순서로, 최신 소식을 꼼꼼하게 정리해 드립니다.

## 1. OpenRouter 1.5조 토큰 — "에이전트가 사람을 이겼다"

### 1) 하루(주간) 1.5조 토큰, 다른 앱 49개 합산과 맞먹어

IT 매체 **CryptoBriefing이 8월 7일 보도**한 내용입니다. OpenRouter는 여러 모델 제공자를 하나로 묶어주는 AI 추론 플랫폼인데, 이 플랫폼이 **앱별 토큰 사용량 랭킹을 공개**하고 있습니다. 그런데 8월 초 기준 **Hermes Agent가 약 1.5조 토큰**을 처리하며, **플랫폼에서 추적되는 다른 모든 앱(49개)의 합산 사용량과 거의 맞먹는 수치**를 기록했습니다.

### 2) 누적 33.1조 토큰, 사용 모델 407개

일회성 반짝 기록이 아닙니다. Hermes Agent는 올해 초 출시 이후 **누적 33.1조 토큰**을 처리하며 OpenRouter 글로벌 일일 랭킹 **1위를 꾸준히 유지**해 왔습니다. 추적 시점별로 보면 약 **6조 → 17조 → 33.1조**로 가파르게 증가했고, 출시 이후 **무려 407개의 서로 다른 모델**을 사용한 것으로 집계됐습니다. 작업별로 가장 적합한 모델을 골라 쓰는 구조라서, 단일 모델에 의존하지 않는 설계가 이 수치에서도 드러납니다.

### 3) "에이전트가 인간을 추월했다" — 구조적 변화

이 기록이 중요한 이유는 단순한 사용량 증가가 아니라 **토큰 소비의 주체가 바뀌었다**는 점입니다. OpenRouter에서는 **에이전트(에이전틱 워크플로)가 인간의 대화형 사용량을 추월**했습니다. 에이전트는 하나의 작업을 완료하기 위해 모델 호출·도구 사용·추론 단계를 연쇄적으로 반복하므로, 대화 한 번보다 훨씬 많은 토큰을 소모합니다. 즉, **AI 컴퓨팅이 '사람이 채팅하는 용도'에서 '에이전트가 일하는 용도'로 넘어가고 있다**는 구조적 신호인 셈입니다.

## 2. GitHub 스타 22.9만 돌파 — 가장 빠르게 성장한 오픈소스 에이전트

이 글을 쓰는 시점(2026-08-12) 기준, Hermes Agent의 GitHub 저장소는 **스타 약 229,005개, 포크 약 45,132개**입니다. 지난 4월 스타 10만 개를 돌파한 지 4개월도 안 돼 **두 배 이상** 성장한 셈입니다. 8월 3일 공개된 v0.20.0 '헤럴드 릴리스'에는 **약 3,650개 커밋, 약 1,400개 머지 PR, 650명 이상의 기여자**가 참여했을 만큼 커뮤니티 개발 속도도 무시무시합니다.

특히 눈에 띄는 건 **공식 문서에 새로 생긴 'User Stories & Use Cases' 페이지**입니다. X(트위터)·GitHub·Reddit·Hacker News·YouTube·블로그 등 11개 소스에서 수집한 **실사용 사례 262개**를 15개 카테고리로 정리해 둔 건데요. 몇 가지만 소개하면 이렇습니다.

- **개발 워크플로(65건)**: "에이전트가 검색하고, 랜딩 페이지를 만들고, SSH로 VPS에 업로드한 뒤 완료 문자까지 보내더라" (@emmagine79)
- **개인 비서(44건)**: "매주 평일 아침 9시에 받은 편지함을 요약해서 Slack에 올려줘" — 자연어 크론 사용 사례
- **거래·시장(5건)**: "자가학습 날씨 트레이딩 봇으로 48시간 만에 $100 → $216" (@DeRonin_)
- **프라이버시·자체호스팅(8건)**: 로컬 SearXNG 컨테이너를 여러 Hermes 에이전트가 공유하는 설정

솔직히 이 페이지를 훑어보면 "사람들이 이걸 이렇게까지 쓰고 있나" 싶을 정도로 활용 범위가 넓습니다. **에이전트를 어떤 식으로 쓸지 고민 중인 분**이라면 아이디어 얻기에 딱 좋은 자료입니다.

## 3. Block의 'Buzz' 통합 — Nostr 기반 워크스페이스에서 사람·에이전트 협업

7월 31일, **Block(블록)이 만든 오픈소스 워크스페이스 'Buzz'와 Hermes Agent의 공식 통합**이 발표됐습니다. Buzz는 Nostr(탈중앙화 네트워킹 프로토콜) 기반으로 사람과 AI 에이전트가 **공유 채널에서 함께 작업**하는 셀프호스팅 워크스페이스인데요. Nostr 특성상 각 AI 에이전트가 **고유 암호화 키페어를 갖고 독립적인 정체성**을 가질 수 있어, 봇 토큰이나 중앙화 계정 없이도 에이전트를 구성원으로 초대할 수 있습니다.

통합 경로는 환경에 따라 **3가지**로 나뉩니다.

| 통합 경로 | 대상 | 특징 |
|:---|:---|:---|
| **Buzz Desktop 매니지드 런타임** | 개인 개발자 | 로컬 Buzz 데스크톱 앱이 Hermes를 ACP 런타임으로 직접 실행 |
| **릴레이 브리지 (buzz-acp)** | 중간 규모·원격 환경 | WebSocket 릴레이로 원격 Hermes와 설정·상태 공유 |
| **네이티브 게이트웨이 플랫폼** | 엔터프라이즈·풀 기능 | Buzz를 Slack·Discord처럼 완전한 Hermes 메시징 게이트웨이로 변환 (NIP-42 인증 WebSocket) |

특히 네이티브 게이트웨이 경로는 **스킬 자동 생성, 장기 메모리, 승인 워크플로, 크론 예약 작업**까지 Hermes의 핵심 기능을 그대로 유지하면서 채널·DM·스레드에서 작동합니다. 자동화된 장애 기록, 코드 리뷰, 자율 워크플로 실행 같은 유스케이스가 타깃입니다. 두 프로젝트 모두 오픈소스(Buzz: Apache-2.0, Hermes: MIT)라서, **자체 호스팅 중심의 프라이버시 중시 팀**에게는 꽤 매력적인 조합입니다.

## 4. 공식 문서 대형 개편 — 복붙만 하면 되는 '자동화 블루프린트'

이번 주엔 **문서 쪽 업데이트**도 눈여겨볼 만합니다. 개인적으로 가장 유용하다고 생각하는 건 **Automation Blueprints(자동화 블루프린트)** 페이지입니다.

### 1) 세 가지 트리거 + 어디로든 배달

블루프린트는 크게 **① 스케줄(크론) ② GitHub 이벤트(웹훅) ③ API 호출** 세 가지 트리거를 지원하고, 결과물은 **텔레그램·디스코드·슬랙·SMS·이메일·GitHub 코멘트·로컬 파일** 어디로든 보낼 수 있습니다. 모든 블루프린트가 특정 모델에 종속되지 않아 어떤 모델과도 함께 쓸 수 있다는 점도 장점입니다.

### 2) 대표 블루프린트 예시

- **야간 백로그 트리아지**: 매일 새로 올라온 GitHub 이슈에 우선순위(P0~P3)·카테고리 라벨을 달아 팀 채널로 요약 전송
- **자동 PR 코드 리뷰**: PR이 열리면 웹훅으로 diff를 받아 보안·성능·코드 품질 리뷰 후 GitHub 코멘트로 게시
- **문서 드리프트 감지**: 주 1회 머지된 PR에서 코드가 바뀌었는데 문서가 안 바뀐 부분을 찾아 리포트
- **의존성 보안 감사**: 매일 `pip audit`·`npm audit`으로 CVSS 7.0 이상 취약점을 스캔해 알림

예를 들어 야간 백로그 트리아지는 아래 명령 하나로 끝납니다.

```bash
hermes cron create "0 2 * * *" \
  "You are a project manager triaging the NousResearch/hermes-agent GitHub repo. \
   Run: gh issue list ... Summarize: total open issues, new today, breakdown by priority. \
   If no new issues, respond with [SILENT]." \
  --name "Nightly backlog triage" --deliver telegram
```

### 3) 팁 모음도 새 단장 — AGENTS.md·SOUL.md

함께 새로 정비된 **Tips & Best Practices** 페이지에서는 실전 팁을 빠르게 얻을 수 있습니다.

- **AGENTS.md**: 프로젝트 규칙(코딩 컨벤션, 아키텍처, 금지사항)을 파일 하나에 정리하면 매 세션 자동 주입
- **SOUL.md**: `~/.hermes/SOUL.md`에 성격·말투를 정의하면 에이전트의 기본 톤이 고정됨
- **프롬프트는 구체적으로**: "코드 고쳐줘" 대신 "`api/handlers.py` 47행 TypeError — `parse_body()`가 `None`을 반환"처럼 파일 경로와 에러를 명시
- **CLI 꿀팁**: `Ctrl+C` 한 번으로 진행 중 응답 중단 후 방향 수정, `hermes -c`로 이전 세션 그대로 재개, `Ctrl+V`로 클립보드 이미지 바로 분석
- **`/skills`로 먼저 확인**: 긴 설명 대신 이미 만들어진 스킬이 있는지 `/skills`로 검색

## 5. 솔직한 시각 — 이 기록들, 어떻게 봐야 할까

### ✅ 긍정적으로 보는 이유

- **실사용량이 증명하는 성숙도**: 1.5조 토큰 기록은 마케팅 수치가 아니라 **실제로 에이전트가 일하고 있다는 증거**입니다. 크론잡으로 직접 돌려보는 입장에서도, "자율 실행"이 데모 수준을 넘어 일상 업무에 들어갔다는 걸 체감합니다.
- **생태계가 두터워지고 있음**: 262개의 실사용 사례, 650명+ 기여자, Buzz 같은 외부 플랫폼 통합까지 — 혼자 잘하는 도구가 아니라 **플랫폼으로 성장**하는 단계입니다.
- **무료로 시작 가능**: MIT 라이선스라 설치 비용이 없고, `hermes update` 한 줄이면 최신 버전으로 유지됩니다.

### ⚠️ 신중하게 볼 부분

- **토큰 기록의 의미 해석 주의**: 1.5조 토큰은 OpenRouter 한 플랫폼 기준이며, 에이전트 워크플로 특성상 토큰 소모가 많은 것은 자연스러운 현상입니다. "압도적 점유율"로 단순화해 읽기보다 **에이전트 트래픽 자체가 폭증하고 있다**는 추세 신호로 보는 게 정확합니다.
- **API 비용 관리 필요**: 에이전트가 열심히 일할수록 토큰이 쌓입니다. 개인 사용자는 무료 모델부터 시작하고, 비용 알림이나 사용량 점검을 설정해 두는 걸 추천합니다.
- **문서는 여전히 영어 중심**: 한국어 자료는 아직 부족한 편이라, 초보자는 공식 문서의 영어 가이드를 따라가는 데 시간이 걸릴 수 있습니다.

## 6. 마무리 — 어떤 분께 추천할까요

정리하면, 이번 주 Hermes Agent 소식의 핵심은 **"AI 에이전트가 실사용에서 검증된 단계"**라는 점입니다. OpenRouter의 토큰 기록은 에이전트 트래픽이 인간 대화를 추월하는 구조적 변화를 보여주고, GitHub 스타 22.9만·262개 실사용 사례·Buzz 통합은 생태계의 두께를 보여줍니다.

**이런 분께 추천합니다.**

- 반복 업무(보고서, 브리핑, 코드 리뷰, 백로그 정리)를 자동화하고 싶은 분
- 자체 호스팅으로 프라이버시를 지키면서 AI 에이전트를 쓰고 싶은 분
- 오픈소스라 비용 부담 없이 최신 AI 에이전트를 직접 만져보고 싶은 분

**이런 분은 신중하게.**

- "설치만 하면 바로 완벽한 비서"를 기대하시는 분 (초기 세팅과 문서 탐색 시간이 필요합니다)
- 채팅형 AI만 필요한 경우라면 굳이 에이전트일 필요는 없습니다

가성비 좋은 AI 도구를 찾는 분들께는 지금 가장 뜨거운 선택지 중 하나라고 자신 있게 말씀드릴 수 있습니다. 궁금한 점은 공식 문서와 GitHub에서 확인해 보세요.
