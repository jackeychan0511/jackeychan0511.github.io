> **📌 한줄 요약:** OpenAI가 2026년 8월 19일(미국 현지시간) 공식 블로그 **"Offering Zero Data Retention for frontier models"**를 통해, 기업용 API 고객의 **프롬프트·모델 응답을 전혀 보존하지 않는 '제로 데이터 보존(ZDR)' 약속을 유지하면서도** 여러 차례의 상호작용을 종합해 악용 패턴을 찾아내는 신규 안전 시스템 **'프라이빗 안전 처리(Private Safety Processing)'**를 공개했습니다. 기존 안전 시스템이 상호작용을 하나씩 평가했다면, 새 시스템은 **관련 상호작용들을 묶어** 반복적인 가드레일 탐색·계정 간 공조·에이전트의 권한 이탈 등을 탐지합니다. 고객 콘텐츠는 고객 통제 인프라(또는 고객 소유 암호화 키)에만 남고, OpenAI 직원은 **위험의 '유형'만 알려주는 제한된 신호(signal)** 만 받아봅니다. 현재 Glean·Databricks·Abridge·Microsoft 등 초기 고객과 테스트 중이며, **9월부터 본격 롤아웃과 기술 백서 공개**가 예정돼 있습니다.

## 이슈 요약 — "우리 데이터, AI 회사가 안 봐도 안전할 수 있을까?"

요즘 저처럼 AI 뉴스를 매일 챙겨 보시는 분들, 특히 **회사에서 API나 엔터프라이즈 AI를 도입하시는 분들**이라면 이런 고민 한 번쯤 해보셨을 겁니다. "프롬프트에 영업 기밀·환자 정보·금융 데이터를 넣어도 되는 걸까? AI 회사 직원이 우리 데이터를 볼 수도 있는 거 아니야?"

솔직히 말하면, 지금까지 AI 안전과 프라이버시는 **줄다리기**였습니다. "안전을 강화하려면 데이터를 좀 보관해야 한다"는 게 업계의 상식이었거든요. 그런데 지난 8월 19일(수, 미국 현지시간), OpenAI가 그 공식을 깨는 발표를 했습니다. **"데이터는 하나도 안 보관할 테니, 오용 여부는 자동 시스템이 패턴으로만 감지하겠다"**는 겁니다.

- OpenAI는 **'프라이빗 안전 처리(Private Safety Processing)'** 를 공개했습니다. 이름 그대로, **프라이버시를 지키면서(private) 안전 처리를 하는(safety processing)** 시스템입니다.
- 대상은 **제로 데이터 보존(ZDR, Zero Data Retention)** 을 선택한 기업용 API 고객. OpenAI는 이 고객들의 프롬프트와 모델 응답을 **요청 처리 후 보존하지 않습니다.**
- 기존 ZDR 안전 시스템은 상호작용을 **하나씩** 평가했지만, 새 시스템은 **관련 상호작용들을 묶어 패턴**을 봅니다. "여러 번에 걸쳐 가드레일을 뚫어보는 시도", "여러 계정을 동원한 공조 공격", "에이전트가 '그만하라'는 지시를 무시하고 계속 행동하는 경우" 같은 위험을 잡아내는 게 목적입니다.
- 핵심 포인트: **OpenAI 직원은 위험의 '유형과 심각도'만 담긴 제한된 신호만 받습니다.** 실제 프롬프트·응답 내용은 끝까지 열람하지 않습니다.
- 현재 **Glean, Databricks, Abridge, Microsoft** 등 초기 고객과 테스트 중이며, **9월부터 롤아웃 + 기술 백서**가 예정돼 있습니다.

이번 글에서는 이 소식의 배경과 작동 방식, 우리(사용자·개발자)에게 주는 의미를 **이슈 요약 → 상세 분석 → 영향 → 전망** 순서로 풀어 보겠습니다.

## 상세 분석 — "안전과 프라이버시, 둘 다 잡을 수 있을까"

### 1. 배경 — ZDR(제로 데이터 보존)이란 무엇인가

먼저 ZDR부터 정리하겠습니다. **ZDR은 적격 API 고객에게 "OpenAI가 프롬프트와 모델 응답을 요청 처리 후 보존하지 않는다"고 보장하는 제도**입니다. 고객 콘텐츠는 OpenAI 직원이 열람할 수 없고, 기업 데이터는 고객이 명시적으로 동의하지 않는 한 **모델 학습에도 사용되지 않습니다.**

문제는 AI가 점점 **더 길고 복잡한 작업(특히 에이전트 형태)** 을 맡게 되면서 생겼습니다. 위험한 의도는 단 한 번의 대화로는 드러나지 않는 경우가 많거든요. 예를 들어:

- 악의적 사용자가 **여러 차례에 걸쳐 안전장치를 탐색(probe)** 하는 경우
- 여러 계정을 동원해 **공조된 오용**을 벌이는 경우
- AI 에이전트가 사용자 의도와 어긋나 **"멈추라고 했는데도 계속 행동**하는 경우"

기존 ZDR 안전 시스템은 각 상호작용을 **개별적으로** 평가하기 때문에, 이런 '연결된 패턴'을 놓칠 수밖에 없었습니다. 그런데 패턴을 보려면 데이터를 모아야 하고, 데이터를 모으면 ZDR 약속이 깨집니다. 이 딜레마를 푼 게 이번 발표입니다.

### 2. 핵심 — Private Safety Processing의 작동 방식

OpenAI가 공개한 설계는 다음과 같습니다.

| 구분 | 내용 |
|:----|:-----|
| **보관 위치 (기본)** | 고객 콘텐츠는 **고객이 통제하는 인프라**에만 보관 |
| **보관 위치 (개발 중)** | OpenAI 인프라에 보관하되, **고객이 소유한 암호화 키로 암호화** — OpenAI 직원은 키 사본을 갖지 않음 |
| **탐지 범위** | 단일 상호작용이 아닌 **관련 상호작용(related interactions) 전반의 패턴** 식별 |
| **전달 정보** | 위험 감지 시 **좁게 정의된 신호(활동 유형·심각도)** 만 OpenAI에 전달 |
| **열람 불가** | 플래그가 걸려도 **프롬프트·응답 원문은 OpenAI 직원에게 공개되지 않음** |
| **고객 권한** | 고객은 자체 시스템의 정보로 알림·제재를 조사하고, 이의 제기 시 관련 자료를 선택적으로 공유 가능 |
| **예외 (CSAM)** | 아동 성착취물(CSAM)로 의심되는 이미지는 수동 검토·신고를 위해 **기존대로 보존** (ZDR 환경 포함) |

쉽게 말하면, **"자동 감시 카메라는 설치하되, 녹화본은 고객 금고에 보관하고, 경비원에게는 '누가 언제 뭘 했다'는 요약 메모만 전달"** 하는 구조입니다. OpenAI가 강조하는 포인트는 "이번 발표는 데이터 보존 없이도 **프런티어 모델의 안전 감시를 계속 제공**하기 위한 것"이라는 점입니다.

### 3. 샘 알트만의 한마디 — "we support business privacy!"

샘 알트만 CEO도 X(트위터)에서 이 소식을 **"we support business privacy!"(우리는 기업 프라이버시를 지지합니다)** 라는 다섯 단어로 압축했습니다. 그리고 OpenAI는 **Glean의 보안 책임자(CISO) 수닐 아그라왈(Sunil Agrawal)** 의 코멘트를 공식 블로그에 실었는데, "엔터프라이즈 AI 도입은 고객의 데이터 통제권에 달려 있다"며 ZDR이 기업 신뢰의 기반이 된다는 점을 강조했습니다.

### 4. 경쟁 구도 — Anthropic과의 정면 차별화

이번 발표의 속내를 더 들여다보면, **경쟁사 Anthropic을 겨냥한 측면**이 뚜렷합니다. 지난 6월 9일부터 Anthropic은 **'Covered Models'(미소스 5, 페이블 5 등 자사 최상위 모델)** 에 한해 ZDR 예외를 적용하고 있습니다. 즉, 최상위 모델을 쓰는 기업 고객은 **안전 작업을 위해 프롬프트와 출력을 30일간 보존**해야 한다는 조건을 받아들여야 했습니다.

반면 OpenAI는 이번 발표로 **"최상위 모델에서도 ZDR을 계속 지키겠다"** 는 입장을 분명히 했습니다. 영국 IT 매체 The Register는 이를 두고 **"OpenAI, 제로 데이터 보존 약속으로 Anthropic의 기업 고객을 쫓는다"** 고 평가했습니다. 데이터를 안전하게 다뤄야 하는 규제 산업(금융·의료·법률) 기업 입장에서는, 같은 성능의 모델이라도 **데이터를 안 보관해주는 쪽**을 고를 가능성이 크니까요.

참고로 OpenAI는 같은 날(8월 19일) CFO 사라 프라이어(Sarah Friar)가 직원들에게 **"2027년 또는 그 이전 IPO"** 가능성을 언급했다는 보도도 나왔습니다. 기업용 매출의 성장 스토리가 곧 IPO 밸류에이션과 직결되는 상황에서, **기업 고객 확보를 위한 프라이버시 경쟁력**은 단순한 기능 하나가 아니라 '돈이 되는 전략'이 된 셈입니다.

## 영향 — 사용자와 개발자에게는?

### 일반 사용자라면
- **ChatGPT 무료·개인 사용자에게 당장 체감되는 변화는 없습니다.** 이번 발표는 어디까지나 **기업용 API의 ZDR 고객**을 위한 안전 시스템이니까요.
- 다만 **"AI 회사가 내 데이터를 어떻게 다루는가"에 대한 기준이 한 단계 올라간** 점은 의미 있습니다. 앞으로 다른 AI 업체들도 "우리는 데이터를 보관하지 않는다"는 점을 영업 포인트로 내세우는 경쟁이 벌어질 테고, 결국 **사용자에게 유리한 방향**입니다.
- 기업에서 ChatGPT·API를 쓰는 분이라면, 지난 8월 20일 소식(RL 학습 2주 중단)과 이어서 보면 **"안전 + 프라이버시"를 모두 최우선으로 삼는 OpenAI의 방향성**이 더 선명하게 보일 겁니다.

### 개발자·기업 담당자라면
- **ZDR을 쓰는 기업 API 고객**은 그동안 "안전 감시 때문에 데이터를 보존해야 하나?"라는 고민이 있었는데, 이번 발표로 **보존 없이도 안전 감시를 받을 수 있는 길**이 열렸습니다. 다만 **9월 롤아웃까지는 테스트 단계**이므로, 실제 계약·정책 반영은 백서와 함께 확인하는 게 좋습니다.
- **의료·금융·법률 등 규제 산업**에서는 이 소식이 꽤 반가울 겁니다. 프롬프트에 민감정보를 넣어도 "AI 제공자가 보관하지 않는다"는 근거를 계약서에 넣을 수 있으니까요. 다만 **ZDR 자체가 규제 준수를 자동으로 보장하지는 않는다**는 점은 유의해야 합니다. (인도 미디어나(MediaNama)도 DPDP법상 데이터 책임자(Data Fiduciary)의 책임은 여전히 고객사에 있다고 짚었습니다.)
- **프라이버시 보존 기술(암호화 키 관리, 안전 신호 파이프라인 등)** 관련 개발 수요가 커질 전망입니다. OpenAI가 키를 고객이 관리하는 방식을 도입하면서, **KMS·키 관리·감사 로그** 분야는 오히려 기회가 될 수 있습니다.

## 전망 — '데이터를 안 보는 안전'이 표준이 될까

- **9월이 분수령**입니다. OpenAI가 예고한 **기술 백서**에서 '교차 상호작용 패턴 탐지'가 구체적으로 어떻게 구현되는지, 그리고 실제 롤아웃에서 오탐(false positive)이 얼마나 나오는지가 관전 포인트입니다.
- **경쟁 구도가 재편**될 가능성이 있습니다. Anthropic이 30일 보존 정책을 유지한다면 "프라이버시 = OpenAI"라는 인식이 기업 고객 사이에 자리 잡을 수 있고, 반대로 Anthropic이 정책을 바꾸면 **'프런티어 모델 안전 vs 데이터 보존'의 균형점이 업계 표준**으로 굳어질 겁니다.
- **에이전트 시대의 필수 인프라**가 될 수 있습니다. AI 에이전트가 장시간·다단계 작업을 수행하는 시대에는 "단일 대화로는 위험을 판단할 수 없다"는 문제가 모든 AI 회사의 과제입니다. OpenAI가 이 문제를 **프라이버시를 지키는 방향으로** 푼 첫 사례라는 점에서, 구글·메타 등 다른 빅테크의 후속 대응도 주목할 만합니다.

## 마무리 — 정리하면

이번 소식을 한 문장으로 정리하면, **"AI 안전 감시는 이제 데이터를 보관하지 않아도 가능하다"** 입니다. 솔직히 처음엔 "안전도 강화하고, 데이터도 안 모으고? 어떻게?"라는 생각이 들었는데, **고객 통제 인프라 + 고객 소유 암호화 키 + 제한된 신호 전달**이라는 설계를 보니 납득이 갔습니다. 특히 직전 글에서 다뤘던 RL 학습 중단(8.20)과 연결해서 보면, OpenAI는 **"모델이 강해질수록 안전장치도, 프라이버시 보호도 함께 고도화한다"** 는 메시지를 일관되게 던지고 있습니다.
