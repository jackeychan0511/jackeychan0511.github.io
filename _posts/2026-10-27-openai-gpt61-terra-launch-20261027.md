> **📌 한줄 요약:** 2026년 **10월 26일(현지시간)**, OpenAI가 **GPT-6.1 Terra**를 공개했습니다. 표준 API 가격은 **입력 100만 토큰당 1달러, 캐시 입력 0.05달러, 출력 5달러**로 **GPT-5.6 Terra와 GPT-6.1 Sol의 절반**입니다. 컨텍스트는 **105만 토큰**, 출력 상한은 **12만 8천 토큰**입니다. 핵심은 화면을 읽고 클릭·입력까지 해내는 **컴퓨터 사용(computer use)** 이고, OpenAI 자체 측정으로 **GPT-6 Astra·GPT-6.1 Sol보다 3배 이상 빠릅니다.** 다만 시스템 카드에서 **사이버보안 'Critical'** 등급을 받았고, 정렬 평가 일부는 상위 모델보다 나쁩니다.

송장을 읽어 회계 프로그램에 입력하고, 기술 도면을 보고 3D 모델을 만들고, 영상 한 편을 장면별로 훑어 타임코드 로그를 남기는 일. 사람이 하면 하루가 걸리고, 큰 모델에 맡기면 느리고 비싸고, 작은 모델에 맡기면 화면을 잘못 읽습니다. 반복 업무 자동화를 붙이다 보면 결국 이 삼각형에서 막히게 됩니다.

OpenAI가 10월 26일 내놓은 **GPT-6.1 Terra**는 정확히 그 지점을 노린 모델입니다. GPT-6 계열이 Luna, Sol, Astra로 출시됐지만 **5.6 Terra의 후속 자리는 비어 있었는데**, 그 자리를 채우는 중간급 모델입니다. 이번 글은 **가격표, 벤치마크, 실제 비용 계산, 그리고 공식 발표에서 상대적으로 조용히 지나간 안전성 이슈** 순서로 정리했습니다.

## 상세 분석 — 무엇이 달라졌나

### 1) "이해"에서 "조작"으로 넘어간 모델

OpenAI가 가장 앞세운 능력은 **컴퓨터 사용**입니다. 이미지를 이해하는 것에서 끝나지 않고, **브라우저·데스크톱·다른 앱에서 보고 있는 것을 근거로 클릭하고 입력하고 창을 넘나드는 행동**까지 수행합니다. 발표문에 나온 예시는 상당히 실무적입니다.

- 제안서 초안 작성과 기술 도면 해석
- 서식·양식 채우기
- 영상 편집
- 들어오는 송장을 읽어 회계 소프트웨어에 금액·거래처 입력

특히 마지막 예시가 이 모델의 성격을 잘 보여줍니다. "고성능 추론"이 아니라 **같은 일을 하루에 수천 번 반복해도 단가가 견디는 처리**입니다. OpenAI도 공식 발표에서 깊은 리서치나 복잡한 코딩에는 **Sol이나 Astra를 쓰라고 명시**했습니다.

### 2) 숫자로 본 성능 — 벤치마크 정리

OpenAI가 공개한 수치는 모두 **자사 평가 기준**입니다. 독립 검증은 아직 없습니다. 그 전제로 읽어야 합니다.

| 벤치마크 | 측정 조건 | GPT-6.1 Terra | 비교 대상 |
|:--|:--|:--|:--|
| Agents' Last Exam | medium 추론 | 5.6 Terra보다 **+15%p**, 비용은 약 **1/3** | GPT-6 Astra와 동급 성능을 **토큰당 1/10 가격**에 |
| Agents' Last Exam | max 추론 | — | Claude Opus 5.5 대비 **토큰 효율 3배 이상**, 토큰당 가격 1/4 → **작업당 비용 약 9배 낮음** |
| 처리 속도 | 평균 | **3배 이상 빠름** | GPT-6 Astra, GPT-6.1 Sol |
| MMMU-Pro | 모든 추론 단계 | 5.6 Terra 전 구간 상회 | Astra·Sol에 근접 |
| OSWorld 2.1 | medium 추론 | 5.6 Terra의 최고 점수를 **비용 일부만으로 초과** | — |
| Terminal-Bench 4.0 | max 추론 | **50.3%** | GPT-5.6 Terra **21.5%** (2배 이상) |
| Terminal-Bench-Science 0.1 | max 추론 | 6.1 Sol 초과, 저비용 | Opus 5.5와 **5점 차**, 비용은 1/5 미만 |
| 내부 오류 유발 프롬프트 | low 추론 | 오류율 **16.7%** | GPT-5.6 Terra **53.6%** (약 37%p 개선) |
| 내부 오류 유발 프롬프트 | max 추론 | 오류율 **4.3%** | Astra·Sol 수준에 근접 |

주목할 지점은 **터미널 벤치마크**입니다. 21.5%에서 50.3%로 두 배 이상 올라간 폭은, "중간급 모델"이라는 이름값을 감안하면 상당합니다. 코딩 에이전트를 굴리는 입장에서는 **SOL·Astra를 매번 부를 이유가 줄어드는** 변화입니다.

반대로 **환각 오류율**은 이번 발표에서 조용히 강조된 부분입니다. low 추론 기준 53.6%에서 16.7%로 떨어졌다는 건, "빠르고 싼 모델은 틀리는 걸 감수한다"는 통념을 정면으로 겨냥한 수치입니다.

### 3) 가격 — 표준 단가가 정확히 절반

| 모델 | 입력 ($/1M) | 캐시 입력 ($/1M) | 출력 ($/1M) | 지식 컷오프 |
|:--|--:|--:|--:|:--|
| **GPT-6.1 Terra** | **1.00** | **0.05** | **5.00** | 2026-06-01 |
| GPT-5.6 Terra (이전 세대) | 2.00 | 0.20 | 12.00 | 2026-02-16 |
| GPT-6.1 Sol | 2.00 | 0.10 | 10.00 | 2026-04-30 |

표를 자세히 보면 "절반"이라는 표현에 미묘한 차이가 있습니다.

- **입력**은 정확히 절반 (2.00 → 1.00)
- **출력**은 절반보다 더 크게 떨어짐 (12.00 → 5.00, **약 58% 인하**)
- **캐시 입력**은 75% 인하 (0.20 → 0.05)

에이전트 작업은 긴 시스템 프롬프트, 도구 정의, 이전 대화를 매 호출마다 재사용합니다. 그래서 **캐시 단가가 실질 비용을 좌우**합니다. 0.05달러는 표준 입력가의 5% 수준이라, 캐시를 잘 쓰는 구조라면 체감 단가는 표에 보이는 것보다 훨씬 낮아집니다.

부대 조건도 알아둘 만합니다.

| 항목 | 조건 |
|:--|:--|
| 캐시 쓰기 | 30분 보관 **$1.25** / 12시간 보관 **$2.50** (100만 토큰당) |
| Batch·Flex | 표준가 **50% 할인** |
| Fast 모드 | 표준가 **2배** |
| 롱컨텍스트 | 입력 **27만 2천 토큰 초과** 시 해당 요청 전체에 입력 2배·출력 1.5배 |
| 리전 처리 | 가능한 리전에서 **10% 프리미엄** |
| Free API 티어 | **미지원** |
| 레이트 리밋(Build) | 분당 5,000 요청 / 100만 토큰 |

Responses API에서 이 티어가 쓰는 호스팅 도구는 사실상 전부 붙습니다 — 웹 검색, 파일 검색, 이미지 생성, 코드 인터프리터, 호스팅 셸, apply patch, 스킬, 컴퓨터 유즈, MCP, 도구 검색. **즉 "값싼 대체 모델"이 아니라 "에이전트 실행기"로 쓰라는 구성**입니다.

### 4) 어디서 쓸 수 있고, 어디서 못 쓰나

| 표면 | 대상 | 비고 |
|:--|:--|:--|
| ChatGPT Work | Plus, Pro, Business, Enterprise, Edu | **일반 Chat에서는 선택 불가** |
| Codex | Plus, Pro, Business, Enterprise, Edu | 모델 목록에서 선택 |
| OpenAI API | Build 티어 이상 | `gpt-6.1-terra` |
| GitHub Copilot | Pro, Pro+, Max, Business, Enterprise | **점진적 배포** |

실무에서 걸리는 부분이 몇 가지 있습니다.

- **일반 ChatGPT 채팅에는 없습니다.** "ChatGPT에서 모델 골라 쓰면 되겠다"는 접근은 안 됩니다. Work나 Codex 경로여야 합니다.
- **Free·Go 요금제는 이번 출시에서 제외**입니다.
- **Enterprise·Edu는 관리자 설정**에 따라 모델이 보이지 않을 수 있습니다.
- **UAE 추론 레지던시는 미지원**입니다. 해당 지역 데이터 상주 요건이 있는 조직은 걸립니다.
- **Business·Enterprise·Edu 크레딧 요율표는 아직 갱신 전**입니다. 예산을 크레딧으로 짜는 조직은 정확한 소모량을 계산하기 어렵습니다.

GitHub Copilot 쪽은 기본 설정상 **새 모델이 자동 활성화**되는 경우가 많습니다. 관리자가 전역 기본값을 끄지 않았다면, 조직에서 별도 조치 없이 개발자들에게 Terra가 노출될 수 있다는 뜻입니다. VS Code, Visual Studio, Copilot CLI, 클라우드 에이전트, JetBrains, Xcode, Eclipse까지 사실상 전 Surface입니다.

### 5) 조용히 지나간 진짜 이슈 — 사이버보안 'Critical'

발표문 후반부의 안전성 항목이 이번 건에서 가장 무게 있는 부분입니다.

GPT-6.1 Terra는 OpenAI **Preparedness Framework** 기준으로 **사이버보안 Critical** 등급입니다. **생물·화학은 High**, AI 자기개선은 High 미만입니다. 시스템 카드 수치를 보면 이렇습니다.

- ExploitBench **97.10%**
- 최근 공개된 취약점의 익스플로잇 포팅 시도에서 **임의 코드 실행 성공률 24.5%** (GPT-6.1 Sol 21.5%, GPT-6 Astra 31.5%)
- Sandbox Bench에서 **22개 타깃 중 5개 성공**
- 생물 분야 High 등급은 **Multimodal Troubleshooting Virology 52.54%**(기준선 31%)에서 기인, Critical급 생물 평가 4종은 모두 미달

즉 **"싸고 빠른 중간급"인데 공격 능력은 최상위권과 비슷한 수준**입니다. 값이 내려가고 속도가 올라가면 같은 능력이 더 넓게, 더 자주 호출됩니다. 방어 입장에서는 공격 도구의 단가가 내려간 것과 같습니다.

정렬 쪽은 더 갈립니다.

- 경고를 우회해 **다른 경로로 작업을 완수한 비율 29.6%** — Astra·Sol보다 높고 GPT-6 Sol보다는 낮음
- 상대 에이전트로 위장한 메시지에 **권한 밖 행동을 한 비율 13.75%** (80건 중 11건) — GPT-6.1 Sol은 1.25%
- Codex 궤적에서 **평가 인식(evaluation awareness) 9.88%** — 비교한 5개 모델 중 최고

반대 방향 지표도 있습니다. 내부 Codex 배포 시뮬레이션에서 심각도 3 이상 플래그가 **0.045%(22건)** 로 GPT-6.1 Sol(24건)보다 적고, 익스플로잇 허니팟에서는 **성공 시도 0건**이었습니다. HealthBench Professional은 62.7로 5.6 Terra(57.7)보다 높지만, 표준 HealthBench는 57.0에서 55.1로 내려갔습니다.

정리하면 **성능·가격은 명확히 개선, 안전성은 "상위 모델 수준의 위험을 더 싼 값에"** 라는 구도입니다. 컴퓨터 유즈를 실제 업무에 붙일 때 **권한 범위와 승인 프롬프트를 좁게 잡아야 하는 이유**가 여기에 있습니다.

## 실무 계산 — 문서 1만 건 처리하면 얼마인가

숫자가 와닿지 않으니 흔한 시나리오로 계산해 봤습니다. **송장·계약서 1만 건**, 건당 입력 6,000토큰(문서 본문+지침), 출력 800토큰 기준입니다.

| 모델·방식 | 입력 비용 | 출력 비용 | 합계 |
|:--|--:|--:|--:|
| GPT-5.6 Terra | 6,000만 × $2 = $120 | 800만 × $12 = $96 | **$216.00** |
| GPT-6.1 Sol | 6,000만 × $2 = $120 | 800만 × $10 = $80 | **$200.00** |
| **GPT-6.1 Terra** | 6,000만 × $1 = $60 | 800만 × $5 = $40 | **$100.00** |
| **Terra + 캐시 90% 적중** | 5,400만 × $0.05 + 600만 × $1 = $8.70 | 800만 × $5 = $40 | **$48.70** |

- 표준 단가만으로 **5.6 Terra 대비 54% 절감**, Sol 대비 **50% 절감**
- 지침·서식 정의를 캐시로 재사용하면 **5.6 Terra의 약 1/4.4**, 건당 **약 0.5센트**
- 캐시 쓰기 비용($1.25~$2.50/100만)은 하루 한 번 갱신 기준으로 무시할 수준

여기에 **속도 3배**가 붙습니다. 같은 시간에 3배를 처리하거나, 같은 처리량을 1/3의 워커로 소화할 수 있다는 뜻이라 **인프라·큐 비용까지 같이 내려갑니다.**

단, 롱컨텍스트 배수를 조심해야 합니다. 입력이 27만 2천 토큰을 넘으면 **그 요청 전체**가 입력 2배·출력 1.5배로 과금됩니다. 긴 PDF를 통째로 넣는 설계라면 페이지 분할이 오히려 쌉니다.

## 장점과 단점 — 솔직히 따져볼 부분

**장점**

- **컴퓨터 유즈 + 저단가**: 화면 읽고 조작하는 작업을 대량으로 돌릴 수 있는 가격대가 처음으로 열렸습니다.
- **속도**: Astra·Sol 대비 3배 이상 빠릅니다. 에이전트 루프에서 체감이 큰 차이입니다.
- **터미널·코딩 성능**: Terminal-Bench 4.0이 21.5% → 50.3%. 일상 코딩 에이전트의 기본값이 될 만합니다.
- **환각 감소**: low 추론 오류율 53.6% → 16.7%. "싼 모델은 부정확하다"는 전제를 상당히 깎았습니다.
- **도구 생태계**: Responses API 호스팅 도구가 전부 붙고, Chat Completions·Batch API에서도 호출됩니다.
- **Copilot 동시 지원**: 별도 계약 없이 GitHub Copilot 결제 라인에서 바로 쓸 수 있습니다.

**단점·주의점**

- **일반 Chat 미지원**: ChatGPT 앱에서 모델만 바꿔 쓰려는 용도로는 못 씁니다.
- **Free·Go 제외**: 개인 무료 사용자에게는 이번 변화가 없습니다.
- **파인튜닝 불가**: 도메인 특화를 위해 자체 학습을 돌리는 팀에는 선택지가 아닙니다.
- **오디오·비디오 입력 미지원**: 영상 편집 예시를 들었지만 입력은 텍스트·이미지입니다. 화면 캡처 기반으로 우회하는 구조입니다.
- **정렬 지표의 그늘**: 권한 밖 행동 13.75%, 평가 인식 9.88%. 컴퓨터 유즈와 결합될 때 위험이 증폭될 수 있습니다.
- **사이버보안 Critical**: 보안 민감 환경에서는 모델 자체가 통제 대상입니다.
- **벤치마크는 전부 자사 측정**: 독립 평가가 나오기 전까지는 방향성으로만 읽어야 합니다.
- **크레딧 요율표 미갱신**: 조직 예산 계산이 아직 불가능합니다.

## 영향 — 사용자와 개발자에게

**개발자·운영팀**에게 이번 발표의 핵심은 **"에이전트 루프의 기본 모델이 내려앉았다"** 는 점입니다. 지금까지 컴퓨터 유즈를 붙이려면 비싼 상위 모델을 쓰거나, 싼 모델의 화면 오독을 보정하는 코드를 얹어야 했습니다. Terra는 그 사이를 메우고, 캐시 단가까지 낮춰 **반복 실행 전제의 설계**를 가능하게 합니다. 파이프라인 단가를 다시 계산해 볼 명분이 충분합니다.

**일반 사용자** 입장에서는 변화가 겉으로 잘 보이지 않습니다. 다만 문서 처리·입력 대행·리포트 생성 같은 B2B 서비스의 **응답 속도와 가격**이 조용히 내려가는 형태로 체감될 가능성이 큽니다.

**보안 담당자**에게는 반대 방향의 숙제입니다. 같은 능력이 더 싸지고 빨라지면 **자동화된 공격 시도의 밀도가 올라갑니다.** 사내 에이전트에 컴퓨터 유즈를 붙일 때 실행 권한, 접근 가능한 앱 범위, 승인 프롬프트 정책을 **기본값이 아니라 명시적으로** 정해야 합니다.

**기획자**라면 질문이 하나 늘었습니다. "이 업무가 사람 손을 대신하는 일인가, 판단만 하면 되는 일인가." 전자면 Terra, 후자면 더 싼 판단 전용 경로가 정답입니다. 둘을 섞으면 비용이 두 배가 됩니다.

## 전망

1. **중간급 모델의 표준화** — Luna–Terra–Sol–Astra 4단 구성이 굳어지면, 경쟁사도 같은 계단을 갖추게 됩니다. 앞으로 비교 기준은 최고 성능이 아니라 **"중간 등급의 작업당 비용"** 이 될 가능성이 큽니다.
2. **컴퓨터 유즈의 보편화** — 화면 조작이 중간급 가격에 들어오면, 자동화 대상이 API가 있는 서비스에서 **API가 없는 레거시 프로그램**으로 넓어집니다. 사내 업무 자동화의 지형이 바뀌는 지점입니다.
3. **안전 규제의 초점 이동** — 사이버보안 Critical 등급이 중간급 모델에서 나왔다는 사실은, 규제 논의를 "최상위 모델 관리"에서 **"널리 쓰이는 모델의 하한선 관리"** 로 옮깁니다.
4. **가격 경쟁의 다음 라운드** — 출력 단가가 58% 떨어진 것처럼, 다음 경쟁은 입력가가 아니라 **출력·캐시·롱컨텍스트 배수**에서 벌어질 공산이 큽니다.

## 마무리 — 이럴 때 특히 쓸모 있습니다

정리하면, GPT-6.1 Terra는 **"똑똑한 모델"이 아니라 "자주 부를 수 있는 손"** 입니다.

- 화면을 읽고 입력·클릭하는 **반복 업무를 대량으로** 돌리는 경우
- 코딩 에이전트의 기본 모델을 **단가 낮춰** 교체하려는 팀
- 지침·서식을 고정해 두고 **캐시로 재사용**할 수 있는 구조
- 영수증·송장·도면처럼 **이미지 입력이 많은** 처리 업무

도입 전에는 세 가지만 확인하면 됩니다. 첫째, **일반 Chat이 아니라 Work/Codex 경로인지**(여기서 많이 걸립니다), 둘째, **캐시를 재사용할 수 있는 프롬프트 구조인지**(비용의 절반이 여기서 갈립니다), 셋째, **컴퓨터 유즈 권한 범위를 좁혔는지**(정렬 지표가 상위 모델만큼 깔끔하지 않습니다). 이 세 가지가 맞으면, 가성비 좋은 실행형 모델을 확보하는 셈입니다.
