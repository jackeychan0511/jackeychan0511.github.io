## AI 에이전트에 사내 키를 물려 쓰는 분들이라면

ChatGPT 로그인이나 API 키를 에이전트에 연결해 업무 자동화를 돌리는 분들이라면, 요즘 가장 무서운 건 모델 성능이 아니라 **키가 어디로 새는지**입니다. 자동화 파이프라인을 운영하다 보면 자연스럽게 이런 상황이 생깁니다.

- 검색 스킬 여러 개를 붙여놨는데, 어느 순간 A 계정 캐시가 B 계정 결과로 채워져 있다
- 샌드박스 세션에서 만든 미리보기 이미지가, 허용 폴더 밖 파일을 읽어서 만들어져 있다
- 에이전트가 돌린 셸 명령이 allowlist에 없는 형태인데도 조용히 통과한다
- 업데이트가 중간에 끊겨서 게이트웨이가 내려간 채로 남아 있다

11월 10일 배포된 2026.11.3은 정확히 이 네 갈래를 겨냥합니다. 특히 첫 번째와 세 번째는 "성능" 문제가 아니라 **신뢰 경계** 문제라서, 11.x 라인을 쓰는 팀이라면 미루지 말아야 할 업데이트입니다.

## 이번 패치의 본체 — "자격증명이 엉뚱한 곳에 도달하는 경로" 차단

SEN-X가 정리한 표현을 빌리면, 2026.11.3 수정의 대부분은 **자격증명이 가면 안 되는 곳에 도달하는 것을 막는 일**입니다. 다른 엔드포인트, 다른 키의 캐시, 자식 프로세스, 로그 — 이 네 곳이 주요 무대입니다.

### 1) 빈 TLS 지문이 인증서 검증을 꺼버리던 문제

이게 이번 릴리스에서 가장 무거운 항목입니다.

- **워크스페이스 업로드·다운로드**: 빈 worker transfer TLS 지문이 지정되면 **인증서 검증 자체가 비활성화**되던 문제를 수정. 이제 빈 핀은 일반 CA 검증 경로를 타고, 형식이 깨진 비어있지 않은 HTTPS 핀은 거부됩니다.
- **노드 연결**: 빈 노드 TLS 지문 플래그가 같은 게이트웨이 엔드포인트에 저장된 인증서 핀을 **덮어써서 무력화**하던 문제를 수정.

정리하면 "핀을 안 걸었더니 검증이 아예 꺼졌다"는 형태입니다. 보안 설정을 비워두는 게 기본값인 환경이라면, 이 수정 전까지는 전송 구간 검증이 사실상 꺼져 있었다고 봐야 합니다.

### 2) 샌드박스 이미지 미리보기가 허용 폴더를 벗어나던 문제

필수 샌드박스(required-sandbox) 세션에서 **대화 이미지 미리보기가 허용 폴더 밖을 읽던** 문제가 수정됐습니다. Full Access 모드에서도 마찬가지였습니다. 관리자가 특정 외부 이미지를 명시적으로 허용하는 것은 여전히 가능합니다.

### 3) 검색·임베딩 자격증명이 섞이던 문제

| 영역 | 수정 내용 |
|---|---|
| Firecrawl | 검색이 **다른 API 키의 캐시 결과를 재사용**하던 문제, 검색·스크레이프가 다른 연결의 엔드포인트와 자격증명을 섞던 문제 |
| Exa / Tavily | 검색·추출이 자격증명을 넘나들며 캐시를 재사용하던 문제, 에러 메시지에 되비칠 때 활성 Exa 키 마스킹 |
| 메모리 임베딩 | 공유 엔드포인트가 아닌 다른 프로바이더로 임베딩 자격증명이 상속되던 문제 |
| 프로바이더 플러그인 | 다른 프로바이더 플러그인이 연결 대상을 **다른 오리진으로 돌리거나**, 목적지가 없을 때 임의 목적지를 공급하던 경로 차단 |
| 설정 읽기 | `env.vars`의 인라인 값이 그대로 노출되던 문제, 안전하게 마스킹할 수 없으면 원본 설정 출력을 억제 |
| Signal / 언어 서버 | 관리형 Signal 데몬과 번들 언어 서버가 **게이트웨이의 무관한 시크릿을 상속**하던 문제 |
| Twitch | IRC 파싱 에러가 수신 메시지 본문을 에러 로그로 복사하던 문제 |

Signal 쪽은 부작용도 있습니다. 프록시·트러스트 스토어·커스텀 래퍼 변수를 더 이상 상속하지 않으므로, 그동안 상속에 의존해 돌아가던 구성은 **Java 프로퍼티·래퍼·외부 데몬으로 직접 넘겨야** 합니다. 업그레이드 후 "갑자기 Signal이 안 붙는다"면 여기부터 보면 됩니다. 언어 서버도 같은 이유로 번들 설정에 허용 항목을 추가해야 할 수 있습니다.

### 4) exec allowlist의 자동 승인 우회 — 조용하지만 중요한 수정

릴리스 노트에서 가장 놓치기 쉬운 항목이 이겁니다. 원문은 이렇게 적혀 있습니다.

> "Requires normal authorization for dynamic shell `test` and `[` predicates under the Gateway allowlist, closing an automatic-approval gap."

PR #187884의 설명이 더 구체적입니다. 다이나믹 셸 프레디킷은 OpenClaw의 안전 내장 명령 검사에는 무해해 보이는데, 실제로 Bash가 나중에 **다른 피연산자를 만들어 외부 명령을 실행**할 수 있었습니다. 여기에 명령 렌더러의 따옴표 처리 버그가 겹치면, **모델이 공급한 명령이 allowlist 항목이나 운영자 승인 없이 승인 경계를 넘을 수 있었습니다.**

![OpenClaw exec 승인 정책 공식 문서](https://pub-a8e00ddf355f47339bd2e01ff3221de7.r2.dev/assets/images/posts/openclaw-2026113-security-release-20261112/openclaw-2026113-exec-approvals.jpg)
*OpenClaw 공식 문서의 exec 도구·승인 정책 페이지. mode=full / allowlist / ask 세 가지 동작을 확인할 수 있습니다. (출처: docs.openclaw.ai/tools/exec)*

부작용도 명시돼 있습니다. **메타문자가 들어간 인용된 파일명**은 이제 승인이 필요하고, 승인이 꺼진 상태에서는 거부될 수 있습니다. 기존에 "왜 되던 게 안 되지" 싶은 스크립트가 있다면 십중팔구 이 부분입니다.

## 업데이트·백업 안정성 — 그리고 미묘한 함정

보안 항목만 있는 게 아닙니다. 운영 중에 실제로 발목 잡히는 것들도 같이 고쳤습니다.

- 중단된 관리형 업데이트가 **게이트웨이를 내려간 채로 방치**하던 문제
- 느린 스토리지에서 큰 SQLite 검사가 타임아웃 나면서 **백업과 업데이트 탐색이 실패**하던 문제 → 더 작은 배치로 재시도
- Windows 게이트웨이가 부팅 정보 불일치로 락을 잃는 문제, Linux에서 이전 PID가 워커 스레드에 재사용돼 스테일 락 복구가 실패하던 문제
- macOS 관리형 게이트웨이가 업데이트 유지보수 중 재시작되던 문제
- Doctor 핸드오프 전후 DB 변경 때문에 업데이트 복구가 막히던 문제
- 큰 세션 트랜스크립트 검색 인덱스 복구가 OOM으로 죽던 메모리 압력 완화

여기에 **반드시 알아야 할 함정**이 있습니다. 릴리스 노트가 두 번이나 반복해서 적어둔 내용입니다.

> 2026.10.10 또는 2026.11.1에서 올라오는 업데이트가 이 타임아웃 때문에 막혔다면, **"더 새 버전을 선택하는 것"으로는 이 수정을 받을 수 없습니다.** 설치된 업데이터 자체가 문제이기 때문입니다.

즉 업데이트가 멈춘 상태라면 `openclaw update`를 반복하는 대신, 공식 업데이트 가이드의 **복구 절차**를 따라야 합니다.

## 곁다리지만 체감 큰 변경 — 출력 토큰 상한 폴백

2026.11.3에는 출력 토큰 관련 수정도 들어 있습니다. 그동안 **출력 한도를 모르는 모델은 8,192 토큰에서 잘리는** 문제가 있었는데, 이번에 폴백이 문맥 창을 고려하는 방식으로 바뀌었습니다(PR #193899).

| 상황 | 이전 | 이후 |
|---|---|---|
| 출력 한도를 모르는 모델 | 8,192 고정 | 최대 **32,768**까지 요청 가능 |
| 32K 창으로 알려진 모델 | 8,192 | **16,384** |
| 손으로 저장해둔 숫자 상한 | 유지 | **그대로 유지** (자동 재작성 없음) |

주의할 점도 같이 적혀 있습니다. **엄격한 프로바이더는 32,768 요청을 400으로 거절할 수 있습니다.** 8,192에서는 통과하던 요청이 실패한다면, 그 모델의 실제 `maxTokens`를 직접 지정하는 게 답입니다. 또 예전 온보딩에서 저장된 4,096·8,192 값은 **Doctor가 지적만 하고 바꾸지는 않습니다.** 업그레이드 후 Doctor를 돌려서 출력 상한 관련 안내를 읽고, 나열된 행을 직접 고치는 편이 안전합니다.

## OpenClaw ID — 키를 잃어도 기기를 전부 잃지 않게

OpenClaw ID는 게이트웨이(일명 claw)를 원격에서 접근하게 해주는 실험실(Labs) 기능입니다. 이번에 키 처리 방식이 바뀌었습니다.

- **PR #196380**: 키 파일을 잃은 claw가 **새 키를 스스로 발급하던 동작을 중단**. 예전에는 소유자가 서명한 바인딩에 없는 키로 서명해 **모든 기기가 끊기는** 결과가 나왔습니다. 이제는 원격 접근이 `keys_missing` 또는 `key_mismatch` 상태로 꺼지고, 게이트웨이는 로컬에서 계속 돕니다.
- **PR #196388**: `openclaw id rebind` 추가. **복구 키트(recovery kit)** 로 claw를 새 키로 옮깁니다. 링크 코드를 계정에서 받아 입력하고, 복구 키트는 **히든 프롬프트로만** 받습니다(인자로는 절대 허용 안 됨). 두 키가 함께 이동하고, 사람·소유자 기기·노드·초대는 유지됩니다. `rebind`는 **같은 머신의 직접 루프백 클라이언트에서만** 허용됩니다.
- **PR #196402**: 재바인딩을 클라이언트가 따라가게 해서, **훔친 게이트웨이 키가 바인딩을 폐기하지 못하게** 차단.
- **PR #196456**: Control UI에 "Move to new keys"와 키 경고 추가.

실험실 단계 기능을 만지고 있다면, 복구 키트를 오프라인에 보관해두는 게 이번 변경의 핵심 사용법입니다. 문서에 적힌 주의도 있습니다. **키 이동은 접근 권한을 재검토하지 않습니다.** 기기와 사람 목록은 따로 확인해야 합니다.

## ChatGPT Business 플랜이 OpenClaw에서 동작한다

11월 10일 오전 9시 50분(태평양시간), OpenAI 개발자 계정이 **ChatGPT Business 플랜이 "Sign in with ChatGPT"를 통해 OpenClaw를 포함한 도구에서 동작한다**고 공지했습니다.

| 항목 | 내용 |
|---|---|
| OpenClaw 쪽 명령 | `openclaw models auth login --provider openai --method siwc` (베타 방식) |
| 필수 조건 | 로그인 시 **토큰 공유 승인**. 거부하면 계정은 저장되지만 추론 권한이 없음 |
| 사용량 | 기존 플랜 한도에 **합산** (앱에 대화·메모리를 넘기지는 않음) |
| 관리자 설정 | admin.openai.com → **Tenant settings → External access**에서 앱별 허용, 멤버별 허용량 중 외부 서비스 사용 비중 상한 설정 |
| 미지원 | OpenAI 호스팅 플러그인, 이미지 생성, 전사(transcription), 실시간 음성 |
| 가시성 | OpenClaw는 **앱별 사용량을 표시하지 않음**. 워크스페이스 한도에 걸리면 Control UI가 "관리자에게 보낼 요청문 복사" 제공 |

이미 ChatGPT Business를 쓰는 팀이라면 에이전트 채팅용 API 청구서를 하나 줄일 수 있는 카드입니다. 다만 **관리자가 서비스별 상한을 먼저 걸어두는 게 안전합니다.** 앱별 사용량이 보이지 않는 구조에서 에이전트는 허용량을 빠르게 태울 수 있기 때문입니다. 이미지 생성·음성·메모리 임베딩처럼 이 자격증명이 커버하지 않는 기능은 플랫폼 API 키로 따로 두는 편이 낫습니다.

태그된 릴리스는 아니지만, 곧 11.5 라인으로 넘어갈 항목들입니다.

- **에이전트 명령의 코어 덤프 비활성화**(Linux) — 크래시 덤프가 게이트웨이의 무제한 코어 크기를 상속해 **한 번에 340MB씩** 쌓이던 것이 사라짐
- **iOS 앱이 붙여넣은 설정 코드를 저장하지 않도록** 수정 — 게이트웨이 자격증명이 평문으로 앱 환경설정과 기기 백업에 남아 있던 문제
- **도구 결과를 압축 JSON으로 전달** — 해당 결과에서 대략 **20~25% 토큰 절감** 추정
- **읽기 전용 클라이언트**에게 게이트웨이 헬스·상태의 런타임 경로 상세 노출 제한
- Claude 구독 사용자가 OpenClaw 릴리스 없이 새 모델에 도달하도록 수정, Fable 5.2의 128K 출력 상한 적용

## 솔직히, 이번 건에서 아쉬운 점

장점만 적으면 리뷰가 아니죠. 단점도 분명합니다.

- **CVE 번호가 없습니다.** GitHub 보안 권고 페이지의 최신 항목은 9월 것이고, 2026.11.3에 연결된 권고는 확인되지 않았습니다. X에서 돌던 "11.x 수정에 CVE가 붙었다"는 이야기는 **2월의 CVE-2026-25253**(2026.1.29 이전 버전의 gatewayUrl 쿼리 토큰 유출)과 섞인 것으로, 11.x 라인에는 해당되지 않습니다. 즉 "CVE가 없으니 안 급하다"가 아니라, **공식 라벨이 'Security release'라는 사실 자체가 근거**입니다.
- **부작용이 붙습니다.** Signal 데몬의 프록시·트러스트스토어 상속 중단, 언어 서버 환경 상속 축소, 메타문자 포함 인용 파일명에 대한 승인 요구. 보안을 조인 대가로 **조용히 의존하던 구성이 깨질 수 있습니다.**
- **업데이트 함정이 남아 있습니다.** 2026.10.10·2026.11.1에서 타임아웃으로 막힌 환경은 최신 버전 선택만으로 해결되지 않습니다.
- **출력 상한 폴백은 양날의 칼입니다.** 32,768을 400으로 거절하는 프로바이더도 있습니다.

---

## 업그레이드 체크리스트 — 이 순서로 하면 됩니다

1. **2026.11.3으로 올린다.** 11.x 라인이면 우선순위 업데이트로 취급.
2. **업데이트가 막혔다면 재시도 금지.** 2026.10.10·2026.11.1에서 타임아웃이 났다면 공식 업데이트 복구 가이드를 따른다.
3. **`openclaw doctor` 실행.** 출력 상한 관련 안내(4,096·8,192 같은 옛 값)를 읽고, 나열된 모델 행의 `maxTokens`를 직접 고친다.
4. **exec 정책 실태 확인.** `openclaw exec-policy show --agent main`으로 현재 모드를 본다. 게이트웨이·노드 기본값은 `mode=full`(승인 없음)이다.
5. **엄격한 신뢰가 필요하면 조인다.** `allowlist` 또는 `ask` 모드로 옮기고, `autoAllowSkills`는 끄고, `tools.exec.strictInlineEval`로 `python -c`·`node -e` 같은 형태에 검토를 요구한다.
6. **Signal·언어 서버 구성 점검.** 상속에 의존하던 프록시·트러스트스토어 변수를 명시적으로 넘긴다.
7. **OpenClaw ID 실험 중이면 복구 키트를 오프라인 보관.** 키 재바인딩 후 기기·사람 목록도 다시 확인한다.
8. **ChatGPT Business 연동 팀은 관리자 콘솔에서 앱 허용 + 서비스별 상한을 먼저 설정.**

## 마무리 — "기능 0개" 패치가 가장 비싼 패치일 때

2026.11.3은 새 기능이 하나도 없는 패치입니다. 그런데 이번 건은 **업데이트를 미루는 비용이 기능 부족보다 훨씬 큰 케이스**입니다. 전송 구간 인증서 검증, 샌드박스 폴더 경계, API 키 캐시 격리, exec 승인 경계 — 네 가지가 전부 "에이전트에게 권한을 준다는 것"의 전제 조건이기 때문입니다.

AI 에이전트를 실사용하면서 자동화 파이프라인을 운영하는 입장에서, 이번 릴리스에서 가장 값어치 있는 문장은 이거였습니다.

> "Most of its fixes stop a credential from reaching a place it should not."

(수정의 대부분은 자격증명이 가면 안 되는 곳에 도달하는 것을 막는 일이다.)

오픈소스라 구매 비용은 0원이지만, **업데이트 주기가 곧 보안 비용**인 제품입니다. 11.x 라인을 쓰면서 아직 2026.11.3 전이라면, 오늘 Doctor 한 번 돌려보는 걸 권합니다. 가성비 좋은 구성 찾는 분들께는 "최신 버전 유지 + exec 모드 명시 + 모델별 maxTokens 고정" 이 세 줄이 가장 남는 장사입니다.
