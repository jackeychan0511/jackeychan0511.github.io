요즘 저처럼 **OpenClaw 정식판(2026.8.1 stable)이 언제 나오는지 매일 npm 태그를 확인하시는 분들**, 계시죠? 어제(8/17) [OpenClaw 8월 17일 소식 글](/2026/08/17/openclaw-update-20260817/)에서 **"베타.2의 사후 검증이 실패해서 수정 후속판 없이는 정식 승격이 불가능하다"**고 말씀드렸는데 — **드디어 공식적인 출시 예고가 나왔습니다.**

OpenClaw 공동 창업자 **Hannes Rudolph(@hrudolph)**가 X(트위터)에 올린 글입니다.

> "We do not want to rush out an update that improves the experience for new users while breaking existing setups. **We expect to release on Tuesday, August 18.** Thanks for being patient with us while we finish this properly and make sure the release is worth the wait."
>
> (새 사용자 경험을 개선하면서 기존 셋업을 망가뜨리는 업데이트를 서두르고 싶지 않습니다. **8월 18일 화요일 출시를 예상합니다.** 제대로 마무리해서 기다려주신 보람이 있게 만들겠습니다. 기다려주셔서 감사합니다.)

**오늘이 바로 그 '화요일, 8월 18일'입니다.** 그래서 오늘 아침, 저는 평소보다 일찍 GitHub와 npm을 확인했습니다. 출시 직전 새벽에 어떤 커밋들이 들어왔는지, 정식판이 정말 오늘 나올지 — 지금 확인된 것까지 전부 정리해드립니다.

## 1. ⭐ 오늘의 메인 뉴스 — 2026.8.1 정식판, 8/18(화) 출시 공식 예고

먼저 다들 궁금해하실 정식판 소식입니다.

- **@hrudolph(공동 창업자) X 발표**: **"8월 18일 화요일 출시 예정"** — OpenClaw 공식 계정(@openclaw)도 같은 내용을 리포스트했습니다.
- **발표 배경**: 8/15 출시된 베타.2의 **사후 전체 검증(Full Release Validation) 실패**를 수습하는 과정에서 나온 발표입니다. 어제 글에서 말씀드린 대로 **"수정 후속판과 그린 검증 없이는 정식 승격 금지"** 상태였는데, 그 후속판(8.2 베타 또는 정식 후보)이 오늘 나올 가능성이 높다는 뜻입니다.
- **핵심 문구**: *"새 사용자 경험을 개선하면서 기존 셋업을 망가뜨리는 업데이트를 서두르고 싶지 않다"* — 신규 사용자 온보딩 개선과 기존 설치 안정성을 **동시에** 챙기겠다는 의지로 읽힙니다.

솔직히 저처럼 크론잡 자동화를 OpenClaw에 맡겨놓고 있는 입장에서는, **"출시를 서두르지 않겠다"는 발표 자체가 오히려 안심**이 됩니다. 6월에 있었던 '릴리스 사태'([OpenClaw Had a Rough Week](/2026/08/16/openclaw-update-20260816/)) 이후로 검증 프로세스를 확실히 지키고 있다는 신호니까요.

## 2. 그런데 아직 정식판은 안 나왔습니다 — 8/18 오전 npm 3트랙 실측

발표가 있었어도 **오늘(8/18) 한국시간 오전 기준, npm 정식판은 아직 배포되지 않았습니다.** 제가 방금 npm 레지스트리에서 직접 확인한 3트랙 상태입니다.

| 트랙 | 버전 | 배포 시각 (UTC) |
|:-----|:-----|:----------------|
| **latest (정식)** | `2026.7.1-2` | 2026-07-18 |
| **beta** | `2026.8.1-beta.2` | 2026-08-15 |
| **extended-stable** | `2026.6.34` | 2026-08-04 |

- 정식 트랙이 여전히 `2026.7.1-2`이고, 베타 트랙도 `2026.8.1-beta.2` 그대로입니다.
- 즉 **"오늘 출시 예고"는 한국시간 기준으로는 아직 진행 중**입니다. 미국 시간대 기준 8/18(화) 하루 중 어느 시점에 올라올 가능성이 높아요.
- 다만 **메인브랜치가 출시 직전까지 계속 움직이고 있다**는 점이 중요합니다. 마지막 푸시가 **8/18 01:19 UTC(한국시간 오전 10:19)** 였습니다. 출시 직전까지 커밋이 들어오고 있다는 건, 그만큼 마무리 작업에 공을 들이고 있다는 뜻이죠.

## 3. 출시 직전 새벽 커밋 점검 — 8/17 23:56 ~ 8/18 01:19 UTC, 30건+

출시를 앞두고 새벽에도 커밋이 쏟아졌습니다. 제가 GitHub API로 직접 확인한 **8/17 23:56 UTC ~ 8/18 01:19 UTC 사이의 커밋 30여 건** 중, 눈에 띄는 것들을 골랐습니다.

### ① 음성통화(voice-call) 안정성 3종 — Tailscale 경로 노출·재접속 유지·정리

- **`fix(voice-call): expose realtime/streaming stream paths through tailscale serve/funnel` (#125468)** — 음성통화의 실시간/스트리밍 경로를 **Tailscale serve/funnel로 노출**시킬 수 있게 했습니다. Tailscale 쓰시는 분들은 집 밖에서도 내 OpenClaw로 전화 연결이 가능해지는 셈이라 반가운 소식입니다.
- **`fix(voice-call): keep realtime calls alive through brief stream reconnects` (#125469)** — 스트림이 잠깐 끊겨도 **실시간 통화를 유지**하도록 수정.
- **`fix(voice-call): tear down realtime calls on stream close and media inactivity` (#125463)** — 반대로 스트림 종료·미디어 비활성 시 **통화를 확실히 정리**해서 리소스 누수를 차단.

저처럼 **"전화로 에이전트한테 볼일 보는" 걸 테스트해보고 싶은 분**이라면, 이 3종 세트가 이번 정식판에서 실제로 잘 작동하는지 꼭 확인해보시길 권합니다.

### ② 보안 픽스 2종 — 시크릿 노출 방지·Matrix 인증 대소문자

- **`fix(cli): avoid exposing provider env values in parse errors` (#124714)** — CLI에서 **파싱 오류가 날 때 프로바이더 환경변수(시크릿)가 그대로 출력되던 문제**를 수정했습니다. 오류 메시지에 API 키가 섞여 나가던 최악의 시나리오를 차단한 보안 픽스예요. 지난주 소개해드린 [시크릿 이그레스 호스트 바인딩](/2026/08/16/openclaw-update-20260816/)과 이어지는 행보입니다.
- **`fix(matrix): keep user ID authorization case-sensitive` (#125432)** — Matrix 채널에서 **사용자 ID 인증을 대소문자 구분**하도록 수정. `@User:example.com`과 `@user:example.com`이 서로 다른 사람인데 인증이 섞이던 문제입니다.

### ③ iOS/macOS 앱 — '플랜' 화면을 내구성 진행 카드로 이전

- **`feat(apps): migrate iOS/macOS plan surface to the durable progress card` (#125442)** — iOS/macOS 앱의 **플랜(계획) 화면을 '내구성 있는 진행 카드(durable progress card)'로 이전**했습니다. 앱을 껐다 켜도 진행 상태가 보존되는 구조로 바뀌는 거라, **모바일에서 에이전트한테 장기 작업을 시켜두는 분**들에게 체감이 클 변경입니다.

### ④ UI 편의 — 컴포저 초안 보존·대시보드 진행 타일·마크다운 정리

- **`feat(ui): preserve composer drafts across restarts` (#125332)** — **컴포저(입력창)에 쓰다 만 초안을 재시작 후에도 보존**해줍니다. 긴 메시지 작성 중 앱이 꺼져도 날아가지 않아요.
- **`feat(dashboard): add session:progress board tile rendering the live progress card` (#125438)** — 대시보드에 **세션 진행 상황을 보여주는 보드 타일**이 추가됐습니다. 어제(8/17) 소개한 '진행 카드'를 대시보드에서 바로 볼 수 있게 된 거죠.
- **`improve(ui): simplify Markdown table styling` (#125219)** / **`improve(ui): refine Markdown prose presentation` (#125242)** — 마크다운 **표 스타일 단순화·본문 표현 다듬기**. 블로거로서 이번 UI 변경이 실제로 어떻게 보이는지도 확인해볼 만합니다.

### ⑤ 게이트웨이·에이전트·Codex — 조용한 실패 없애기

- **`fix(gateway): persist session cwd in transcript` (#125484)** — 세션의 **작업 디렉토리(cwd)를 트랜스크립트에 저장**해서, 재개 시 어디서 작업 중이었는지 유지되도록 수정.
- **`fix(agents): stop silent compaction failures` (#125302)** — 에이전트 메모리 **컴팩션(압축)이 조용히 실패하던 문제를 중단**시키고 명시적으로 처리.
- **`fix(codex): degraded-engine continuity no longer projects the whole context window per turn` (#125324)** — Codex 엔진이 **저하(디그레이드) 상태에서 매 턴 전체 컨텍스트를 재투사하던 비효율**을 수정. 토큰 절약에 도움이 되는 성능 픽스입니다.
- **`fix(agents): report node exec timeouts and process kills truthfully` (#125466)** — 노드 실행 **타임아웃·프로세스 종료를 '정직하게' 보고**하도록 수정. "왜 죽었는지"가 이제 로그에 제대로 남습니다.
- **`fix(ui): keep acknowledged sends pending during stale history` (#125426)** — 오래된 히스토리 상태에서 **ACK된 전송이 pending으로 남아있던** UI 문제 수정.

### ⑥ 기타 — macOS Peekaboo 4.2.1 고정, PR 검토 복구, npm 업데이트

- **`build(macos): pin final Peekaboo 4.2.1 source` (#125464)** — 지난주 소개해드린 **macOS 컴퓨터 사용(Peekaboo)의 최종 4.2.1 소스를 고정**했습니다.
- **`fix(pr): repeated review checkout recovers partial transitions` (#125467)** — PR 리뷰 체크아웃이 반복될 때 **중간 상태에서 복구**되도록 수정.
- **`fix(update): support npm before lifecycle allowlists` (#125452)** — npm 업데이트 시 라이프사이클 허용 목록 처리 순서를 지원.
- **`fix(workboard): avoid false lifecycle warning during gateway startup` (#125470)** — 게이트웨이 시작 중 **거짓 라이프사이클 경고** 제거.
- **`fix: surface swallowed failures on action paths` (#125319)** — 액션 경로에서 **삼켜지던(무시되던) 실패를 표면화**.
- **`improve(ui): rebuild agent GitHub identity panel on settings primitives` (#125472)** — 에이전트 GitHub 신원 패널을 설정 프리미티브 기반으로 재구성.

## 5. 보안 맥락 — ClawHub 스킬 스캐닝(×VirusTotal)과 오늘의 보안 픽스

오늘 커밋의 보안 픽스(시크릿 노출 방지·Matrix 인증)를 보면서, OpenClaw가 **'에이전트 생태계 보안'을 한 축으로 계속 투자**하고 있다는 게 다시 체감됐습니다. 그 연장선에서, 공식 블로그에 정리된 **ClawHub 스킬 보안 스캐닝(×VirusTotal 파트너십)** 흐름도 짚어드립니다.

- **ClawHub에 게시되는 모든 스킬은 VirusTotal 위협 인텔리전스로 스캔**됩니다 (2월 발표, 공식 블로그에 정리).
- 스킬 번들 → **SHA-256 해시** → VirusTotal DB 조회 → **Code Insight(LLM 기반 행동 분석)** → **양성(benign) 자동 승인 / 의심(warning) 표시 / 악성(malicious) 즉시 차단**.
- **활성 스킬은 매일 재스캔**되어, "깨끗했던 스킬이 나중에 악성으로 변하는" 경우도 잡아냅니다.

솔직히 저처럼 **스킬(플러그인)을 이것저것 설치해서 쓰는 분**이라면, "설치 전에 코드가 실제로 뭘 하는지 AI가 분석해준다"는 이 파이프라인이 꽤 든든합니다. 오늘의 `fix(cli): avoid exposing provider env values in parse errors`도 같은 맥락의 방어선이라고 보시면 됩니다.

## 6. 솔직한 단점 — 짚고 넘어갈 것들

좋은 점만 나열하면 솔직한 리뷰가 아니죠. 오늘 기준으로 짚어야 할 것들입니다.

1. **정식판은 '예고' 상태** — 발표가 나왔어도 한국시간 오전 기준 npm 정식판은 아직 `2026.7.1-2`입니다. "오늘 나온다"고 해서 당장 `npm install -g openclaw@latest`가 8.1로 바뀌는 건 아니니, **업데이트는 정식판이 실제로 배포된 뒤**에 하시는 걸 권합니다.
2. **정확한 배포 시각은 미공개** — "8/18(화)"까지만 공지됐고 시각은 안 나왔습니다. 미국 시간대 기준 하루 중 언제든 올라올 수 있어요. 한국 시간으로는 **내일(8/19) 새벽까지 지켜봐야 할 수도** 있습니다.
3. **출시 직전 커밋 = 변동성** — 새벽 30건+의 커밋이 좋은 신호이기도 하지만, 그만큼 **정식판에 들어가는 코드가 마지막 순간까지 바뀌고 있다**는 뜻입니다. 출시 직후엔 역시 '관찰 모드'로 며칠 두고 보시는 게 안전합니다.
4. **베타.2 사후 검증 실패의 후속판 확인 필요** — 정식판이 나오더라도, **'그린 검증(Full Release Validation 통과)'이 실제로 확인됐는지** 릴리스 노트를 꼭 보셔야 합니다. 어제 말씀드린 "수정 후속판 없이는 승격 금지" 조건이 충족된 채로 나오는지가 핵심입니다.

## 7. 마무리 — 추천 대상과 설치 방법

정리하면, **오늘 OpenClaw의 키워드는 "2026.8.1 정식판 D-day"**입니다. 공동 창업자가 **"8/18(화) 출시"를 공식 예고**했고, 출시 직전 새벽까지 **음성통화 안정성·보안·iOS/macOS 앱·UI 편의 커밋 30여 건**이 들어왔습니다. 아직 한국시간 오전 기준 정식판은 npm에 안 올라왔지만, **하루 중 언제든 배포될 예정**입니다.

설치는 아래 한 줄이면 끝입니다.

```
# 정식판이 실제로 배포된 뒤 (권장)
npm install -g openclaw@latest

# 베타 라인으로 먼저 체험하고 싶은 분
npm install -g openclaw@beta
```

솔직히 저처럼 **메신저에서 바로 일하는 AI 비서**를 찾으시는 분, **"출시를 서두르지 않고 제대로 검증한다"는 태도**가 마음에 드시는 분이라면, 오늘 밤~내일 새벽 사이 정식판이 올라오는 걸 확인하시고 **업데이트 전 `openclaw backup sqlite create` 한 줄** 꼭 챙기시길 권합니다. 무료 오픈소스(MIT)에 38만 6천 스타가 증명하듯 **가성비 좋은 AI 에이전트 찾는 분께 추천**드립니다. 정식판이 실제로 배포되면, 릴리스 노트를 처음부터 끝까지 읽고 다시 정리해서 찾아오겠습니다.
