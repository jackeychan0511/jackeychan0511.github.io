> **📌 한줄 요약:** 2026년 8월 20일 아침 기준, Hermes Agent의 최신 정식 릴리스는 여전히 **v0.20.4(v2026.8.18)**입니다. 하지만 GitHub main 브랜치에는 v0.20.4 태그 이후 **약 352개 커밋**이 쌓여 있고, 그중 **8/18~8/19 이틀 사이에 200건 이상**이 몰려 있습니다. 커밋 로그를 뜯어보면 다음 패치(v0.20.5급)에 들어올 것으로 보이는 변경이 꽤 구체적으로 보이는데요 — **Bot Mode 그룹챗 이미지·PDF·파일 첨부(1:1과 패리티 완성)**, **봇 깨우기 약 0ms 성능 개선**, **`hermes://plugin/install` 딥링크 원클릭 플러그인 설치**, **모든 연결 게이트웨이 채팅이 보이는 통합 세션 목록**, **Ollama 네이티브 카탈로그**, **이미지 생성 라이브 카탈로그 라우팅**까지. 오늘은 그 미리보기를 실측 데이터와 함께 정리해드립니다.

## 1. 요즘 저처럼 "어제 패치했는데, 이번엔 뭐가 쌓이고 있지?" 하시는 분들

요즘 저처럼 **Hermes Agent 업데이트를 매일 쫓아가시는 분들**, 특히 이 블로그처럼 **크론잡 자동 포스팅을 Hermes에 맡기고 계신 분들** 많으시죠. 어제(8/19) 아침에 v0.20.4 정리해드렸는데, 오늘(8/20) 아침 8시쯤 출근 전에 GitHub 저장소를 열어보니 — **새 릴리스 태그는 아직 없는데 main 브랜치에는 벌써 커밋이 잔뜩 쌓여 있더라고요.**

솔직히 "릴리스가 안 나왔으면 소식이 없는 거 아니야?"라고 생각하기 쉽지만, 이 프로젝트는 **main에 먼저 쌓이고 나중에 태그로 롤업**하는 방식이라서요. 지난주 패치 릴리스 4연타(v0.20.1 → 8/13, v0.20.2 → 8/16, v0.20.3 → 8/17, v0.20.4 → 8/18)의 페이스를 보면, **이번 주 안에 다음 패치가 나올 가능성이 꽤 높습니다.** 그래서 오늘은 커밋 로그를 기준으로 **"다음 릴리스 미리보기"**를 정리해봤습니다.

## 3. ⭐ Bot Mode — 그룹챗 이미지 첨부가 드디어 완성됐습니다

이번 미리보기에서 제 기준 **가장 반가운 변경**입니다. v0.20.3에서 기본 탑재된 Bot Mode가 "그룹챗에서 이미지를 못 붙이던" 문제가 있었는데요.

- **`feat(bot-mode): group chats accept image attachments every responding bot sees`** (8/18) — 그룹룸이 **텍스트만 받던** 문제를 수정. 컴포저와 `runGroupChatMemberTurn`이 첨부 단계 없이 `prompt.submit {text}`만 보내서, **사용자가 올린 스크린샷이 멤버들의 모델에 도달조차 못 하던** 상황(커뮤니티 리포트 확인됨)을 고쳤습니다.
- **`feat(bot-mode): group chats accept PDFs, files, and drag & drop`** (8/18 밤) — 이미지에 이어 **PDF·일반 파일·드래그앤드롭**까지 추가하며 **그룹/1:1 첨부 패리티(#88983)를 완성**했습니다. 이제 1:1에서 되는 건 그룹챗에서도 된다는 뜻입니다.

저처럼 **"봇 3~4마리를 팀으로 굴려서 아침 브리핑을 만들게"** 하시는 분들께는, "그룹챗에 자료 이미지를 던져놓고 봇들이 같이 보게 하는" 워크플로우가 드디어 성립하게 된 셈입니다. v0.20.3에서 그룹챗이 생겼다면, 이번엔 **그룹챗이 실제로 일할 수 있게** 되는 변화예요.

### ① 봇 깨우기 성능 — "47~120초 부팅"이 "약 0ms 페인트"로

같은 날 **성능 커밋 2건**도 함께 들어왔습니다.

- **`perf(desktop): Bot Mode wakes paint-first`** (8/18) — 느린 Windows 머신의 콜드 프로파일 백엔드는 부팅에 **47~120초**가 걸렸는데, "전체 런타임 부팅이 끝날 때까지 기다렸다가 화면을 그리던" 방식을 **먼저 그려놓고(페이인트 우선) 부팅은 뒤에서** 마저 하도록 바꿨습니다.
- **`perf(desktop): durable transcript-tail cache — bot wakes paint at ~0ms`** (8/18) — 그 위에 **트랜스크립트 꼬리 캐시**(세션당 최대 40개 메시지·256KB, 50세션 LRU를 localStorage에 저장)를 쌓아서, **봇을 깨울 때 화면이 약 0ms 만에 그려지게** 했습니다.

솔직히 Bot Mode를 실제로 쓰다 보면 "봇 전환할 때마다 빈 화면을 몇 초~수십 초 기다리는" 답답함이 있었는데, 이 두 커밋은 정확히 그 지점을 노린 겁니다. **"기능이 생긴 것"에서 "실제로 빠르게 도는 것"**으로 넘어가는 단계라고 볼 수 있어요.

### ② blobatar — 봇 이름에서 나오는 결정적 아바타

- **`feat: Bot Mode avatars default to deterministic blob faces drawn from the agent's name`** (8/18) — 새 봇의 기본 아바타가 **이름에서 생성되는 "블롭 얼굴(blobatar)"**이 됐습니다. 같은 이름이면 영원히 같은 얼굴이고, 직접 바꿀 수도 있습니다. 봇이 많아지면 로스터에서 **"누가 누군지 한눈에 구분"**되는 게 생각보다 중요해서, 사소해 보이지만 실사용 만족도에 닿는 변경입니다.
- **`fix(bot-mode): roster age, pulse, unread, and sort now see canonical Bot Chat activity`** (8/19) — 로스터의 **활동 시각·펄스·읽지 않음·정렬**이 정식 Bot Chat 활동 데이터를 보도록 수정. "봇이 방금 활동했는데 목록에는 옛날 상태로 보이던" 문제가 줄어듭니다.

## 4. 데스크톱 — 플러그인 원클릭 설치 딥링크 + 통합 세션 목록

### ① `hermes://plugin/install` — 웹에서 클릭 한 번으로 플러그인 설치

- **`feat(desktop): one-click plugin install via hermes:// deeplinks`** (8/18) — 데스크톱이 **`hermes://` URL 스킴**을 등록해서, **웹사이트·README·채팅 메시지의 링크만 클릭하면 플러그인 설치 화면으로 직행**하게 됐습니다.

공식 문서 기준 링크 형식은 이렇습니다.

```
hermes://plugin/install?repo=owner/repo            # 기본 설치 링크
hermes://plugin/install?repo=owner/repo&enable=1   # 설치 후 에이전트 플러그인 활성화까지
hermes://plugin/install?repo=owner/repo&force=1    # 기존 설치 교체
```

클릭하면 **확인 다이얼로그**(저장소 ID·"설치 전에 확인" 안내·GitHub 링크)가 뜨고, shallow-clone으로 **에이전트 플러그인(백엔드 파이썬)인지 데스크톱 플러그인(앱 UI)인지**를 판별해 체크박스로 고르게 합니다. 중요한 건 **딥링크만으로 자동 설치되지는 않는다**는 점 — 확인을 눌러야 설치되고, 에이전트 플러그인은 기존 `hermes plugins install`과 동일한 **설치 시 보안 스캔**을 거칩니다. v0.20.4에서 들어온 SkillEvaluator 스캔과 자연스럽게 이어지네요.

같은 화면은 링크 없이도 **Settings → Plugins → Install from Git**로 열 수 있고, 웹사이트라면 그냥 HTML 앵커 하나면 됩니다.

```html
<a href="hermes://plugin/install?repo=owner/repo&enable=1">Install in Hermes</a>
```

솔직히 저처럼 **커뮤니티 플러그인을 "git clone → 폴더 복사 → 설정"**으로 설치하던 사람에게는, "README의 버튼 클릭 → 확인 → 끝"이 되는 것 자체가 큰 변화입니다. 플러그인 만드는 쪽에서도 배포 부담이 확 줄어들 거예요.

### ② 플러그인 OS 알림 + 통합 세션 목록

- **`feat(desktop): rich plugin OS notifications with deeplink activation`** (8/18) — 플러그인의 `ctx.os.notify`가 **아이콘·액션 버튼·활성화 대상(activate)**을 지원하게 됐습니다. 알림 본문/버튼을 클릭하면 **창이 포커스되고 해당 플러그인 화면으로 이동**합니다.
- **`feat(desktop): unified Sessions list shows every connected gateway's chats (#88880)`** (8/18) — 전역 세션 목록이 **원격/클라우드/SSH 게이트웨이(v2 레지스트리 연결)의 채팅까지 전부** 보여주게 됐습니다. 기존에는 로컬 프로필 + 일부 원격 오버라이드만 보여서, **"다른 PC·Hermes Cloud 세션은 목록에 안 보이던"** 문제가 해결됩니다.
- **`feat(desktop): live-preview themes from the palette highlight`** (8/18) — Cmd-K 팔레트에서 테마를 **선택하기 전에 하이라이트만으로 미리보기**가 적용됩니다.
- **`feat(desktop): add an Appearance toggle that disables the intro splash`** (8/19) — 빈 채팅에 뜨는 **인트로 스플래시(워드마크·태그라인)를 끌 수 있는 토글**이 Appearance 설정에 추가됐습니다.
- **`feat(tools): close_preview so the agent can dismiss the pane it opened`** (8/19) — 에이전트가 **연 프리뷰 페인을 닫을 수 있는 `close_preview` 도구**가 추가됐습니다. `open_preview`·`read_preview`는 있었는데 **"닫는 도구"가 없어서** 에이전트가 열어놓은 프리뷰를 사람이 직접 닫아야 했거든요. 이 블로그 포스팅 작업에서도 체감되는 변경입니다.

## 5. 모델·프로바이더 — Ollama 네이티브 카탈로그와 이미지 생성 라우팅

### ① Ollama — "로컬 모델 쓰는 분들"에게 체감 큰 변경

- **`feat(models): add native Ollama catalog semantics`** + **`feat(models): propagate native discovery across selectors`** (8/9~) — **Ollama의 네이티브 카탈로그(로컬에 받아둔 모델 목록)를 그대로 인식**하도록 모델 시맨틱스가 추가됐습니다.
- **`feat(acp): preserve native provider catalogs and identities`** (8/9) + **`fix(models): persist named custom catalog identity`** (8/18) — ACP(에이전트 통신 프로토콜) 경유 시에도 **프로바이더 카탈로그와 정체성이 유지**되고, **이름 붙인 커스텀 카탈로그의 정체성이 저장**되도록 했습니다.
- **`fix(models): keep discovery sentinels out of the user-facing models mapping`** (8/18) — 내부 탐색용 sentinel(가짜 엔트리)이 **사용자에게 보이는 모델 목록에 섞이지 않게** 정리.

솔직히 **로컬 Ollama + Hermes 조합**으로 쓰시는 분들은 "모델 목록이 가끔 이상하게 보이던" 경험이 있으실 텐데, 이번 커밋 묶음은 정확히 그 지점(탐색·정체성·표시)을 다듬는 작업입니다. 다음 패치에서 모델 선택 화면이 더 깔끔해질 것으로 기대됩니다.

### ② 이미지 생성 — 라이브 카탈로그 모델이 전용 Image API로 라우팅

- **`feat(image-gen): route live-catalog models to the Image API; merge picker catalogs; docs`** (8/19) — 라이브 `/images/models` 카탈로그에 있는 **모델 ID는 전용 Image API로 라우팅**되고, 픽커 카탈로그도 통합됩니다. 기존에는 "힌트만 로그로 남기고" 넘어가던 걸 실제 라우팅으로 승격시킨 거예요.
- **`feat(plugins): add OpenRouter Image API surface to openrouter image_gen backend`** (8/9) — OpenRouter의 **Image API 표면**이 `image_gen` 백엔드에 추가됐습니다. 블로그 썸네일·포스팅 이미지를 에이전트가 직접 만들 때 쓸 수 있는 옵션이 하나 더 늘어난 셈입니다.

### ③ reasoning-effort·Codex 와이어 정리

- **`fix: widen reasoning-effort wire translation to sibling sites (#89503 class)`** (8/19) — `chat_completions` chokepoint에서 **`ultra` → `max`**로 내려 쓰던 와이어 번역이, **gpt-5.6 한정이던 걸 모든 Responses-API 모드의 기본**으로 넓혔습니다. 모델이 지원하지 않는 추론 레벨을 보내 4xx를 받던 문제가 줄어듭니다.
- **`fix(codex): strip unsupported cache retention at wire`** (8/19) 2건 — Codex 엔진에서 **지원하지 않는 캐시 보존(retention) 필드를 와이어에서 제거**. API 호출이 조용히 실패하던 시나리오를 차단합니다.

## 6. 크론·게이트웨이 — 크론잡 도는 블로거로서 반가운 수정 3가지

이 블로그처럼 **Hermes 크론잡으로 자동 포스팅**을 돌리시는 분들께 특히 반가운 수정 3건입니다.

1. **`fix(gateway): /goal no longer lies when state.db init is slow`** (8/18) — 콜드 상태에서 state.db 초기화(스키마 DDL·FTS 테이블·최초 설정 가져오기, 빠른 머신 기준 약 300ms)가 **0.25초 부트스트랩 그레이스 윈도** 뒤에 숨어서 **거짓 결과를 보고하던** 문제를 수정. "골이 완료됐다"고 나오는데 실제로는 초기화가 안 끝난 상황이 사라집니다.
2. **`fix(dashboard): coalesce repeat gateway restarts for a short window`** (8/18) — 게이트웨이 재시작 버튼 **더블클릭으로 재시작 프로세스가 2개 뜨는 레이스**를 짧은 시간 안에 병합. 대시보드에서 재시작을 연타하던 습관이 있는 분(저요)에게 반가운 수정입니다.
3. **`fix(update): run the Windows update hand-off unattended`** (8/19) — Windows 업데이트의 re-exec 핸드오프에서, 자식 프로세스가 콘솔을 물려받아 `isatty()`가 참으로 나오면서 **로컬 변경 질문 프롬프트가 씹히던** 문제를 무인 실행으로 수정. **Windows에서 자동 업데이트를 걸어두신 분들**이라면 다음 패치에서 조용히 고쳐집니다.

## 7. 솔직한 장단점 — "미리보기"를 쓰면서

### 👍 장점

1. **Bot Mode 그룹챗 첨부 패리티 완성** — 이미지→PDF·파일·드래그앤드롭까지. "팀 봇에 자료 던져주고 일시키는" 워크플로우가 드디어 성립
2. **봇 깨우기 ~0ms 성능 작업** — 47~120초 부팅을 페인트 우선 + 꼬리 캐시로 해결하려는 방향이 명확. Bot Mode 실사용자라면 체감 큼
3. **플러그인 원클릭 설치 딥링크** — `hermes://plugin/install?repo=owner/repo` 한 줄이면 README에 설치 버튼을 달 수 있게 됨. 플러그인 생태계 성장의 분수령이 될 가능성
4. **통합 세션 목록(#88880)** — 원격·클라우드·SSH 게이트웨이 채팅까지 한 목록. 멀티 머신 유저의 오래된 불만 해소
5. **Ollama 네이티브 카탈로그 + 이미지 생성 라우팅** — 로컬 모델·이미지 생성 쓰는 사람에게 닿는 실질 개선

### 👎 단점

1. **아직 태그가 없다** — 352개 커밋이 전부 main에만 존재. 이 글이 "미리보기"인 이유이고, **일부는 다음 태그에서 빠질 수도 있음**
2. **릴리스 노트는 여전히 v0.21.0까지 대기** — v0.20.4 때와 동일. 지금은 커밋 로그로 갈음해야 함
3. **오픈 이슈 33,608개** — 프로젝트 규모가 커지면서 이슈도 함께 쌓이는 중. 이슈 처리 속도가 커밋 속도를 못 따라가는 구간
4. **Windows 성능 관련 커밋이 많은 이유** — paint-first 커밋 자체가 "느린 Windows 머신"을 전제로 하고 있어서, **macOS 사용자에게는 체감이 상대적으로 작을 수 있음**
5. **딥링크 설치가 "확인 다이얼로그" 의존** — 자동 설치는 아니라서 안전하지만, 그만큼 "클릭 한 번으로 끝"은 아님

## 8. 마무리 — 다음 릴리스 대비 사용 팁 3가지

정리하면, 오늘(8/20)의 키워드는 **"v0.20.4는 최신이지만, 다음 패치의 재료는 이미 main에 352개 쌓여 있다"**입니다. 그리고 그 재료의 중심은 **Bot Mode 그룹챗 첨부 완성 + 데스크톱 플러그인 생태계(딥링크 설치·알림) + 모델 카탈로그 정리** 세 갈래예요. v0.20.4가 "다듬기"였다면, 다음 패치는 **"팀 봇이 실제로 일하고, 플러그인이 클릭 한 번에 들어오는"** 방향으로 보입니다.

**다음 릴리스 나오기 전에 해두면 좋은 팁 3가지:**

1. **Bot Mode 팀 워크플로우를 미리 짜두세요** — 그룹챗 이미지·파일 첨부가 들어오면, "자료 스크린샷 던지기 → 봇들이 각자 역할로 분석 → 리포트" 흐름이 바로 돌아갑니다. 패치가 나오면 `hermes update` 한 줄로 바로 쓸 수 있어요.
2. **플러그인 만드는 분이라면 README에 설치 버튼을** — `<a href="hermes://plugin/install?repo=owner/repo&enable=1">Install in Hermes</a>` 한 줄이면 됩니다. 설치 다이얼로그가 저장소 ID와 소스 링크를 보여주고, 에이전트 플러그인은 기존 보안 스캔을 그대로 거치니 안심하고 걸 수 있어요.
3. **로컬 Ollama를 쓰신다면** — 다음 패치에서 모델 목록·카탈로그 동작이 바뀌니, 업데이트 후 `hermes model` 화면에서 **커스텀 카탈로그 정체성이 유지되는지** 한번 확인해보세요. (8/18 커밋들이 정확히 그 지점을 고쳤습니다.)

```bash
# 기존 설치 업데이트 (릴리스 나오면)
hermes update
# 새로 설치 (공식 인스톨러)
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```
