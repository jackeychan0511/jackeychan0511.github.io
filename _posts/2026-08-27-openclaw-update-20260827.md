## 1. 요즘 저처럼 "어제 올린 PR이 오늘은 어떻게 됐지" 매일 GitHub부터 여시는 분들

요즘 저처럼 **OpenClaw 베타 트랙(2026.8.1-beta.3)을 쓰면서 매일 아침 GitHub 저장소를 먼저 여시는 분들**, 많으시죠.

솔직히 어제(8/26)는 **Scoped Standing Grants(#129526)** 하나로 크론 승인이 1회로 끝나는 걸 보고 "이제 좀 쉬어도 되겠다" 싶었습니다. 그런데 오늘 아침 GitHub 알림을 열어보니, **창립자 피터 스타인버거(steipete)가 어제 오후부터 오늘 새벽까지 또 4개의 큰 기능을 직접 병합**해 놨더라고요. 게다가 전부 "제가 실제로 쓰는 기능"에 해당하는 것들이라 눈이 번쩍 뜨였습니다.

오늘 글은 그 4가지(IMAP 트리거, 워커 자동 일시중지, 승인 블래스트 범위, 스키마 v12)와, 지난 24시간 커밋 614건 중 눈에 띄는 것들, 그리고 GitHub·npm 실측 수치로 구성했습니다.

## 2. 오늘의 메인 뉴스 ① — IMAP 인바운드 이메일 트리거, Gmail 전용의 벽이 무너졌다

### 어떤 문제를 풀었나

어제 저녁(한국시간 8/27 새벽 4시 24분) 병합된 **PR #130230 `feat(plugins): inbound IMAP email trigger`**입니다.

그동안 OpenClaw의 "메일이 오면 자동으로 처리"는 **Gmail 전용**이었습니다. 흐름이 이랬어요.

> Gmail Pub/Sub → 외부 `gog` 바이너리 → OpenClaw의 `/hooks` 엔드포인트 → 격리된 hook 에이전트 세션

문제는 **Gmail이 아닌 메일함(Outlook, Fastmail, iCloud, 그 외 모든 IMAP 계정)은 트리거를 못 건다**는 점이었습니다. 물론 번들로 들어있는 himalaya 스킬로 "요청하면" IMAP을 조작할 수는 있지만, **아무도 감시(watch)하지 않아서** "새 메일이 도착했을 때"를 자동으로 알아차리지 못했습니다. 제 경우 회사 메일이 Outlook이라 "결재 메일이 오면 자동으로 요약해서 텔레그램으로" 같은 자동화를 만들고 싶어도 Gmail로 옮기지 않는 한 불가능했거든요.

### 어떻게 고쳤나

이번 PR로 **범용 IMAP 폴링 기반 인바운드 트리거**가 추가됐습니다. 이제 Gmail이 아니어도 **메일함을 주기적으로 확인(polling)해서 새 메일이 오면 에이전트 세션을 트리거**할 수 있습니다. PR 본문을 보면 "Gmail 전용이던 인바운드 이메일 스토리를 모든 IMAP 메일함으로 확장한다"는 게 핵심 의도로 명시돼 있습니다.

이 기능이 제게 의미 있는 이유는, **"이메일이 시작점이 되는 자동화"**가 실제 업무에서 제일 많기 때문입니다. 청구서·공지·문의 메일이 오면 → 요약 → 분류 → 필요하면 답장 초안까지, 이제 Outlook 메일함에서도 돌릴 수 있게 됐습니다.

## 3. 오늘의 메인 뉴스 ② — 유휴 클라우드 워커 자동 일시중지, 과금 걱정의 종말

### 어떤 문제를 풀었나

**PR #130242 `feat(gateway): auto-suspend idle cloud workers with suspendAfter`** (한국시간 8/27 새벽 3시 30분 병합).

얼마 전 warm images(#130087)가 들어오면서 **클라우드 워커를 멈췄다가 다시 켜는 비용이 매우 저렴**해졌습니다. 그런데 문제는 **아무도 "유휴" 워커를 안 멈춘다**는 것이었어요.

PR 본문의 표현을 그대로 옮기면, "배치된 세션(placed session)은 **누군가 Stop cloud worker 버튼을 누르기 전까지 lease heartbeat를 계속 보내며 billing이 이어진다**" — 즉, 잊어버리면 **조용히 과금**되는 구조였습니다. 클라우드 워커를 시험 삼아 켜두고 까먹는 분들, 저 포함해서 많으시죠?

### 어떻게 고쳤나

`suspendAfter` 설정으로 **일정 시간 유휴 상태면 워커를 자동으로 일시중지**시킵니다. 워머 이미지 덕에 다음 디스패치도 빠르니, "자주 켜고 끄는" 운영 방식이 이제 합리적이 됐습니다. 개인적으로 크래복스(Crabbox) 클라우드 워커를 쓰는 입장에서, **"이번 달 워커 요금 왜 이렇게 나왔지?" 하고 청구서 보고 놀라는 일**이 확실히 줄어들 것 같습니다.

## 4. 오늘의 메인 뉴스 ③ — 승인 카드에 "블래스트 범위"가 보인다 (어제의 후속)

### 어떤 문제를 풀었나

**PR #130116 `feat(approvals): typed approval scope summaries on channel cards`** (한국시간 8/27 새벽 4시 13분 병합).

어제 소개한 Scoped Standing Grants가 "크론 잡의 승인을 1회로" 줄였다면, 오늘 이 PR은 **"승인할 때 뭘 승인하는지 제대로 보여주자"**는 문제를 풉니다.

그동안 채널 승인 카드는 **명령어나 제목 텍스트만** 보여줬습니다. 그런데 결과 영향이 큰 도구 호출(메시지·이메일 발송, 결제, 외부 포스팅)의 경우, **"수신자가 몇 명인지, 금액이 얼마인지, 대상 시스템이 뭔지, 내부/외부 어디로 가는지"**를 승인자가 알 수 없었습니다.

PR 본문의 예시가 정확합니다. **"Send customer update"라는 승인 요청이 3개의 외부 이메일 주소로 발송되는지, 내부 채널로만 가는지 알 수 없는 건 나쁜 앱(App)이다** — 그래서 이번에 승인 카드에 **타입화된 스코프 요약(typed scope summary)**을 붙였습니다.

- 발송系: **수신자 수·내부/외부 구분**
- 결제系: **금액**
- 외부 포스팅系: **대상 시스템**

어제의 standing grants와 합치면, **"한 번만 승인하고 30일 안심" + "승인할 때는 뭘 승인하는지 정확히"**라는 두 축이 모두 갖춰진 셈입니다. 크론 자동화로 돈이 움직이는 작업을 돌리는 분이라면 이 조합이 꽤 든든할 겁니다.

## 5. 오늘의 메인 뉴스 ④ — 스키마 v12, 싱글톤 테이블 9개를 하나로

**PR #129876 `refactor(state): fold singleton tables into config_machine_state at schema v12`** (한국시간 8/27 새벽 5시 32분 병합).

어제 스키마 v10에서 **죽은 공유 상태 테이블 6개를 정리**했다고 말씀드렸는데, 하루 만에 **v12**까지 올라왔습니다. (v11은 중간 단계로 지나간 것으로 보입니다.)

이번엔 **SQLite 복잡도 캠페인의 Phase 3**로, shared state DB에 남아 있던 **싱글톤 테이블 9개**를 정리합니다. 이 9개는 각각 "하나의 논리적 JSON 값"을 고정 키 하나에 담고 있는데, **저마다 bespoke 스키마·접근자 모듈·형상 검증**을 갖고 있어서 유지보수가 무거웠습니다. 이를 범용 `config_machine_state` KV 하나로 통합했습니다.

**사용자 입장에서 해야 할 일은 하나** — 업데이트 후 `openclaw doctor` 한 번 돌려서 shared state DB 상태를 확인하는 것입니다. 어제(#129626)에 이어 이틀 연속 스키마 버전이 바뀌는 시점이라, **업데이트 전 `openclaw backup sqlite create` 백업은 이번에도 강력 추천**합니다.

### + 이틀 연속으로 쌓인 신기능 2건

- **Control UI 쿨톤 테마 3종 (#130232)** — 기존 내장 테마 4개(Claw 코랄 `#ff5c5c`, Knot 크림슨 `#e5243b`, Dash 초콜릿 `#b47840`, Absolutely 클레이 `#d97757`)가 **전부 웜톤**이었는데, 이번에 **Tide·Beacon·Phosphor 쿨톤 테마**가 추가됐습니다. 어두운 화면에서 장시간 작업하는 분들께는 오히려 이게 반가울 수 있어요.
- **Z.AI GLM-5.3 Flash 지원 (#130309)** — 모델 카탈로그에 `glm-5.3-flash`가 등록됐고, **thinking off 설정 시 provider가 거부하던 페이로드 문제**도 함께 수정됐습니다. Z.AI(지능형연대) 모델을 쓰는 분들은 모델 브라우저에서 바로 선택 가능합니다.

## 6. 지난 24시간 커밋 614건 — 전일의 약 1.2배, 그리고 눈에 띄는 수정들

GitHub API 실측 기준, **8/26 01:13 UTC ~ 8/27 01:13 UTC 동안 커밋이 614건** 쌓였습니다. 전일(516건)의 약 1.2배입니다. 그중 제가 눈여겨본 것들입니다.

### ① 크론·자동화를 돌리는 입장에서

- **`fix(cron): preserve authored speech in text announcements` (#130520)** — 크론 잡의 텍스트 공지에서 **작성자가 직접 쓴 문구가 유실되던 문제** 수정. 공지에 내가 쓴 말이 빠져서 "뭐라고 하려던 거지?" 하던 순간이 줄어듭니다.
- **`refactor(cron): centralize heartbeat reconciliation` (#130350)** — 어제 나온 heartbeat 자동 비활성 경고(#129560)의 뒤처리를 중앙화. 크론 잡이 "왜 조용히 꺼졌지?" 하는 문제의 원인 정리가 계속 진행 중입니다.

### ② 채널·플랫폼별 체감 수정

- **`fix(discord): a failing slash command leaves the user watching a spinner that never resolves` (#128630)** — **디스코드 슬래시 명령 실패 시 스피너가 영원히 도는** 문제 수정. 디스코드에서 OpenClaw를 쓰는 분들은 이거 생각보다 자주 겪었을 거예요.
- **`fix(telegram): preserve complete rich message edits` (#130526)** — 텔레그램 **리치 메시지 수정 시 내용이 온전히 보존**되도록.
- **`feat(buzz): bound bot-to-bot room conversations` (#130488)** — Buzz 채널에서 **봇-봇 대화가 무한히 이어지는 것**을 제한.
- **`feat(feishu): find received stickers by configured keywords` (#130498)** — Feishu(飛書)에서 **설정한 키워드로 받은 스티커 찾기**.

### ③ 모델·도구

- **`fix(github-copilot): allow xhigh and max thinking levels on claude-opus-5` (#129690)** — GitHub Copilot 채널에서 **claude-opus-5의 xhigh/max thinking 레벨** 허용.
- **`fix(ollama): retain incompletely advertised remote models` (#130240)** — Ollama 원격 모델이 **일부만 광고되어도 유지**되도록.
- **`fix(browser): hidden selectors prematurely complete waits` (#130508)** — 브라우저 자동화에서 **숨겨진 셀렉터가 대기를 조기 종료**하던 문제 수정.

### ④ 그 외

- **`feat(audit): record generic tool action decisions` (#130358)** — 감사 로그에 **일반 도구 호출 결정도 기록**.
- **`refactor(macos): automation summaries as hosted cards with clickable job rows` (#130502)** — macOS 자동화 요약이 **클릭 가능한 잡 행이 있는 카드**로 개편.
- **`fix: stop retry storms after definitive channel rejections` (#127353)** — **채널이 확정 거부한 메시지의 재시도 폭풍** 중단. 메시지 전송 실패 시 무한 재시도로 쌓이던 부담이 줄어듭니다.
- **`docs(memory): add memory provenance and deletion concepts page` (#130278)** — 메모리 **출처(provenance)와 삭제 개념** 문서화. 메모리 관리에 진심인 분들은 한번 읽어볼 만합니다.

## 8. 실제 사용감 — 장점과 아쉬운 점, 솔직하게

이틀 연속 "매일 아침 GitHub 실측"을 하면서 느낀 점을 정리합니다.

**좋았던 점 (장점)**
- **이틀 연속 내가 쓰는 기능이 고쳐진다**: 어제 크론 승인, 오늘 IMAP 트리거·클라우드 과금·승인 가시성. 베타 트랙을 타는 보람이 확실합니다.
- **오픈 이슈가 실제로 줄고 있다**: +107 스타보다 -156 이슈가 더 반가웠습니다. 기능을 "쌓는" 단계에서 "다듬는" 단계로 넘어가는 신호로 보입니다.
- **승인 UX가 드디어 성숙해진다**: 어제 "1회 승인"(standing grants) + 오늘 "블래스트 범위 표시"까지, 승인 기능이 도구 수준을 넘어 제품 수준이 되는 중입니다.

**아쉬웠던 점 (단점)**
- **여전히 베타 트랙입니다**: 모든 변경이 `2026.8.1-beta.3` 기준이고, npm latest는 `2026.7.1-2` 그대로예요. 안정 트랙을 타시는 분은 정식판까지 기다려야 합니다.
- **스키마 버전이 이틀 만에 v10 → v12**: 그만큼 DB 구조가 요동치고 있다는 뜻이라, **업데이트 전 백업이 선택이 아닌 필수**가 됐습니다.
- **커밋 614건은 역시 따라가기 벅찹니다**: 어제도 말씀드렸지만, **릴리스 노트(CHANGELOG)와 릴리스 태그만 구독**하는 걸 다시 추천합니다.

## 9. 업데이트 팁 — 지금 뭘 하면 되나요?

1. **IMAP 자동화를 기다리셨던 분** — 베타 트랙(`openclaw update --channel beta`)에서 **플러그인 목록에 IMAP 인바운드 트리거가 보이는지 확인**해보세요. Outlook·Fastmail·iCloud 메일함을 OpenClaw 자동화의 시작점으로 쓸 수 있게 됐습니다.
2. **클라우드 워커를 쓰시는 분** — 게이트웨이 설정에서 **`suspendAfter`를 지정**해 유휴 워커가 자동으로 멈추게 하세요. "켜두고 까먹고 청구서 보고 놀라는" 일이 사라집니다.
3. **승인 정책 + 크론 잡 조합** — 어제의 standing grants에 오늘의 블래스트 범위 표시까지, **Control UI의 승인 카드를 다시 한번 훑어보세요.** 이제 "뭘 승인하는지"가 카드에 보입니다.
4. **업데이트 전 백업은 이틀 연속 강조** — `openclaw backup sqlite create` → 업데이트 → `openclaw doctor`. 스키마 v12 시점이라 이 순서는 꼭 지키시길.
5. **안정 우선이시라면** — `openclaw update`로 **extended-stable(2026.6.34)** 유지. 정식판 2026.8.1이 npm latest에 올라오면 그때 올라타셔도 늦지 않습니다.

솔직히 말해서, 이틀 연속 새벽까지 기능이 병합되는 걸 보니 "베타.3가 정식판 직전의 마지막 안전벨트"라는 어제 판단이 점점 확신으로 바뀌고 있습니다. IMAP 트리거·클라우드 과금 방지·승인 가시성은 **정식판에 그대로 들어갈 "제품다운 기능"**이라, 지금 베타에서 미리 써보고 피드백을 남기시는 걸 추천합니다.

정식판 2026.8.1이 npm에 올라오는 순간, 또 바로 실측해서 정리해 찾아올게요!
