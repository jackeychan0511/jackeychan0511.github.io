> **📌 한줄 요약:** OpenAI가 **2026년 11월 17일** **GPT-6.2 Astra**와 **GPT-6.2 Sol**을 공개했습니다. Astra는 "가장 어려운 작업"용 프런티어 모델, Sol은 "일상 업무"용 효율 모델입니다. 표준 API 단가는 **Astra 입력 $8·출력 $40**, **Sol 입력 $2·출력 $10**(100만 토큰 기준)으로 **출력 단가가 4배** 차이 납니다. 독립 지표인 Artificial Analysis Intelligence Index에서는 **Astra 62(#3/92)**, **Sol 57(#11/92)** 로, 태스크당 비용은 **$4.00 vs $1.01**입니다. 핵심은 "무조건 상위 모델"이 아니라 **작업 난이도로 갈라 쓰는 구조**라는 점입니다.

## 같은 날 나온 두 모델, 이름만 다르지 값은 4배

AI 모델을 업무에 붙여 쓰는 분들이라면 요즘 가장 자주 하는 계산이 "이 작업에 가장 비싼 모델을 써야 하나"입니다. GPT-6 Astra가 나온 지 두 달 남짓, OpenAI가 **11월 17일** 후속 라인업을 내놨습니다. 이번에는 이름이 두 갈래입니다.

- **GPT-6.2 Astra** — OpenAI 표현으로 "가장 어려운 프로젝트를 위한 프런티어 모델". GPT-6 Astra를 대체합니다.
- **GPT-6.2 Sol** — "일상 업무를 위한 효율·범용 모델". GPT-6.1 Sol을 대체합니다.

두 모델의 공통점은 **같은 결과를 더 적은 출력 토큰으로 낸다**는 것입니다. 이게 생각보다 중요한 변화입니다. 구독 요금제는 대체로 토큰·메시지 한도로 잘리기 때문에, 토큰 효율이 올라가면 같은 요금으로 처리할 수 있는 작업량이 늘어납니다. 반대로 API로 쓰는 입장에서는 단가표와 캐시 할인율을 다시 계산해야 합니다.

## 스펙 비교 — 단가·컨텍스트·속도 한 표

먼저 숫자부터 정리했습니다. 가격은 모두 **100만 토큰당 USD, 표준(Standard) 처리 기준**입니다.

| 항목 | GPT-6.2 Astra | GPT-6.2 Sol |
|:---|:---|:---|
| 포지션 | 프런티어(가장 어려운 작업) | 범용·일상 업무 |
| 컨텍스트 | 최대 **100만 토큰** | 최대 **100만 토큰** |
| Codex 기본 컨텍스트 | 272,000 토큰 | 500,000 토큰 |
| 입력 단가 | **$8.00** | **$2.00** |
| 출력 단가 | **$40.00** | **$10.00** |
| 캐시 입력 | $0.40 (60% 할인) | $0.10 |
| 배치(Batch) 입력/출력 | $4.00 / $20.00 | $1.00 / $5.00 |
| 롱 컨텍스트 입력/출력 | $16.00 / $60.00 | $4.00 / $15.00 |
| Ultrafast 입력/출력 | $24.00 / $120.00 | $6.00 / $30.00 |
| AA 지능지수 | **62 (#3/92)** | **57 (#11/92)** |
| AA 태스크당 비용 | $4.00 | $1.01 |
| AA 태스크 소요 | 10.7분 | 7.9분 |
| 출력 속도 | 64 tok/s | 85 tok/s |

여기서 눈에 띄는 건 세 가지입니다.

1. **Astra는 이전 세대보다 싸졌습니다.** GPT-6 Astra가 입력 $10·출력 $50이었으니, GPT-6.2 Astra는 **입력·출력 모두 20% 인하**입니다. 캐시 입력은 $1.00 → $0.40으로 60% 할인 폭이 커졌습니다.
2. **Sol은 단가를 동결했습니다.** GPT-6.1 Sol과 같은 $2·$10입니다. 대신 "같은 값에 더 똑똑해졌다"는 쪽으로 방향을 잡았습니다.
3. **컨텍스트는 둘 다 100만 토큰**입니다. 다만 Codex에서 기본값은 Astra 272,000, Sol 500,000이고, 100만 토큰을 쓰려면 `model_context_window`를 직접 설정해야 합니다.

## Sol이 이기는 지점은 '가성비'가 아니라 '충분함'

솔직히 말하면, 이번 발표에서 더 실용적인 쪽은 Sol입니다. OpenAI가 직접 공개한 비교에서 Sol은 이렇게 나옵니다.

- **FrontierCode 2.0**(실제 코드베이스 수정): Astra와 **0.5점 차**인데 비용은 **약 1/5**
- **LifeVal**(일상 과업): **GPT-6 Astra보다 높은 점수**를 약 **1/7 비용**으로
- **GDPval v2**: GPT-6.1 Sol보다 **+5.3%p**

즉 "최고 성능이 꼭 필요한 마지막 0.5점"을 위해 5배를 지불할지, 그 지점에서 끊을지가 실제 선택의 갈림길입니다. 코딩 리뷰, 회의록 정리, 문서 초안, PR 수정처럼 **반복적으로 여러 번 돌리는 작업**이라면 Sol로도 충분한 경우가 많습니다.

Artificial Analysis의 독립 측정에서도 이 구도는 비슷합니다. Sol은 지능지수 57로 92개 모델 중 11위, 태스크당 비용은 $1.01. Astra는 62로 3위지만 태스크당 $4.00입니다. **지능 5점 차에 비용 4배**라는 뜻입니다.

## 요금제: 어디서 쓸 수 있고, 얼마나 돌릴 수 있나

가장 많이 헷갈리는 부분이 "내 요금제에서 이 모델이 보이느냐"입니다.

| 구분 | 내용 |
|:---|:---|
| 사용 가능 위치 | **ChatGPT Work**(웹·모바일·데스크톱)와 **Codex**(앱·CLI) |
| 일반 Chat | **선택 불가** — GPT-6.2 모델은 Work/Codex에만 노출 |
| 대상 요금제 | Plus, Pro, Business, Enterprise, Edu |
| Enterprise/Edu | 관리자가 워크스페이스 설정에서 **직접 활성화**해야 보임 |
| Plus 한도(대략) | 5시간마다 Astra **6~50개** 또는 Sol **17~180개** 메시지 |
| Pro | 5시간 제한 없이 사용(티어별 $100·$200·$500) |
| Ultrafast | Pro $200 → **Sol만**, Pro $500 → **두 모델 모두** |
| 기본값 | 소비자 요금제 신규 Work 채팅은 **Sol·Light 추론**, Enterprise는 **Sol·Medium** |

Pro 티어가 $100·$200·$500으로 쪼개진 것도 체크 포인트입니다. Ultrafast를 쓰려면 최소 $500 티어가 필요하고, $200 티어에서는 Sol에만 열립니다.

Ultrafast 요금은 **2027년 3월 1일부터 인상**됩니다. 표준가의 **3배**(~2027년 2월 28일)에서 **6배**로 올라갑니다. 지금 Astra Ultrafast가 $24·$120인데, 인상 후에는 $48·$240이 됩니다. 속도가 정말 급한 워크플로가 아니라면 미리 계산해 두는 게 좋습니다.

## 비용 시뮬레이션: 같은 작업, 얼마나 차이 나나

월간 사용량을 가정해 단순 계산해 봤습니다. 입력 5,000만 토큰 + 출력 1,000만 토큰을 표준 처리로 돌리는 경우입니다.

| 시나리오 | Astra | Sol | 차이 |
|:---|:---|:---|:---|
| 캐시 미적용 | $400 + $400 = **$800** | $100 + $100 = **$200** | 4.0배 |
| 입력 80% 캐시 적중 | $16 + $80 + $400 = **$496** | $4 + $20 + $100 = **$124** | 4.0배 |
| 배치 처리(50% 할인) | **$400** | **$100** | 4.0배 |
| 캐시 80% + 배치 | **$248** | **$62** | 4.0배 |

재미있는 건 **비율은 항상 4배**라는 점입니다. 단가 구조가 똑같이 4배 차이라서, 캐시나 배치를 아무리 최적화해도 격차는 줄지 않습니다. 결국 비용을 줄이는 방법은 두 가지뿐입니다. **Sol로 내려오거나, 작업 자체를 줄이거나.**

반대로 Astra를 쓸 이유도 분명합니다. 토큰을 22% 덜 쓰고 한 번에 통과하는 작업이라면, 재시도 3번 하는 Sol보다 총비용이 낮아질 수 있습니다. "단가 × 토큰"이 아니라 **"단가 × 토큰 × 재시도 횟수"** 로 봐야 하는 이유입니다.

## 실무 가이드: 어떤 작업에 무엇을 붙일까

정리하면 이렇게 갈립니다.

**Sol을 기본으로 두면 되는 작업**
- PR 리뷰, 리뷰 피드백 반영, 테스트 보강
- 회의록 → 프로젝트 브리프 변환
- 문서 초안, 이메일, 보고서 요약
- 대량 분류·추출·변환 같은 배치성 작업
- 챗봇·에이전트의 기본 응답 모델

**Astra로 올릴 만한 작업**
- 여러 서비스에 걸친 버그 추적과 수정 (원인 → 패치 → 테스트까지 한 번에)
- 템플릿을 정확히 따라야 하는 슬라이드·스프레드시트·계약서 검토
- 여러 출처를 비교·검증해야 하는 리서치
- CAD·시뮬레이션·3D 같은 시각 추론이 필요한 작업
- "한 번에 제대로"가 중요한 대외 산출물

운영 팁도 하나. 두 모델 모두 **프롬프트 앞부분(prefix)을 그대로 유지하고 뒤에 지시를 덧붙이는 방식**을 권장합니다. 추론 상태가 유지되고 캐시 적중률이 올라가서, 같은 대화를 이어가는 경우 체감 비용이 꽤 달라집니다.

## 주의할 점 — 숫자를 그대로 믿으면 안 되는 이유

세 가지는 짚고 넘어가야 합니다.

1. **벤치마크는 대부분 OpenAI 자체 발표**입니다. 경쟁 모델(Claude Fable 5.2 등)과의 비교는 특히 그렇습니다. Artificial Analysis 같은 독립 지표가 Astra 62·Sol 57로 **격차가 5점**이라는 점은 참고할 만하지만, 실제 업무 성능은 프롬프트와 도구 구성에 따라 더 크게 벌어집니다.
2. **사이버 안전장치가 강화**됐습니다. 두 모델 모두 Preparedness Framework에서 사이버 능력 **Critical**, 생물·화학 **High** 임계에 해당해, 취약점 연구 같은 일부 정당한 보안 작업도 거부될 수 있습니다. 보안 테스트가 목적이라면 Daybreak Red 같은 별도 트랙을 봐야 합니다.
3. **Astra는 AI 자기개선 능력에서 High 등급**을 처음 받은 외부 공개 모델입니다. 규제·내부 통제가 있는 조직이라면 도입 검토 시 이 부분을 함께 봐야 합니다.

## 마무리: 지금 사야 한다면

정리하면 이렇습니다.

- **Plus($20) 사용자** → 기본은 Sol. Astra는 "이번 주에 한 번 제대로 뽑아야 하는 산출물"에만 아껴 쓰기. 5시간당 6~50개라는 한도가 생각보다 빨리 닳습니다.
- **Pro 검토 중** → Ultrafast가 목적이면 $500 티어, 아니면 $200으로도 충분합니다.
- **API 사용자** → 트래픽의 80~90%는 Sol, 어려운 10~20%만 Astra로 라우팅. 배치로 돌릴 수 있는 작업은 반값, 캐시 적중률은 프롬프트 구조로 확보.
- **엔터프라이즈** → 관리자 활성화가 선행 조건이고, 데이터 레지던시는 US/EU 지원(Ultrafast는 US만)이라는 점을 확인.

가성비 좋은 조합을 찾는 분들께는 **"Sol을 기본값으로 깔고, 실패했을 때만 Astra로 승격"** 하는 구조를 추천합니다. 이번 세대의 핵심은 최고 성능이 아니라, **성능과 단가 사이에서 어디에 선을 그을지**를 직접 고를 수 있게 됐다는 점입니다.
