## 도입: "어제 8.2 정리하고 났더니, 벌써 다음 버전 릴리스 노트가?"

요즘 저처럼 **AI 에이전트 자동화에 관심이 많으신 분들**, 특히 오픈소스 에이전트 생태계를 매일 체크하시는 분들 많으시죠? 어제(9/2) 저는 OpenClaw 2.0(v2026.8.1)의 첫 후속 업데이트인 **v2026.8.2**를 정리해서 포스팅했는데요. 솔직히 "이제 좀 쉬엄쉬엄 가지 않을까" 싶었거든요.

그런데 오늘 아침, 공식 문서 사이트(docs.openclaw.ai)를 열어보니 **릴리스 노트 목록 맨 위에 v2026.9.1이 올라와 있더라고요.** 릴리스 규모를 보니 **922개 PR에 241명의 기여자**가 참여한, 8.2와는 비교가 안 되는 큰 업데이트입니다. 다만 한 가지 짚고 넘어갈 게 있어요. GitHub Releases를 실측해 보면 **아직 v2026.9.1 안정 태그는 없고**, 최신 안정판은 여전히 **v2026.8.2**(한국시간 9/2 새벽 1시 배포)입니다.

즉, 지금은 **"정식 배포 직전에 릴리스 노트가 먼저 공개된"** 상태예요. 오픈소스 프로젝트 특성상 2.0 출시 직후라 업데이트 주기가 빨라진 느낌입니다. 오늘은 공식 릴리스 노트(docs.openclaw.ai/releases/2026.9.1)와 GitHub 실측 데이터를 바탕으로 **v2026.9.1이 뭘 바꿀지** 솔직하게 프리뷰해 드릴게요.

## v2026.9.1 개요 — 9월 메이저, "쓰는 내내 아쉬웠던 부분을 통째로"

먼저 흐름부터. OpenClaw는 버전명이 **년.월** 체계(2026.9 = 9월 릴리스)라서 v2026.9.1은 **9월 메이저 업데이트**입니다. 최근 일정을 정리하면:

- **8/28(UTC)** — 2026.9 라인의 첫 베타 **v2026.9.1-beta.1** 게시로 9월 트레인 시작 (참고로 이 베타는 한때 '8.1-beta.4의 오게시'로 정정된 이력이 있음)
- **8/31** — **OpenClaw 2.0 = v2026.8.1** 안정 배포 (전면 재구축된 웹 경험·세션 연속성)
- **9/1 16:00 UTC(한국 9/2 01:00)** — **v2026.8.2** 안정 배포 (리눅스 데스크톱 앱·Home 도크 등)
- **9/3 오전(지금)** — **v2026.9.1 릴리스 노트 공개**, 안정 태그는 아직 (출시 임박)

공식 요약(summary)은 이렇게 한 문장입니다.

> "대화면 어디서나 머메이드 다이어그램, 더 완전한 안드로이드 경험, 더 안전한 업데이트 복구, 그리고 긴 대화와 대규모 설치에서 낮아진 오버헤드."
> (Mermaid diagrams across chat surfaces, a fuller Android experience, safer update recovery, and lower overhead for long conversations and large installations)

솔직히 8.2가 "2.0을 다듬은 패치"였다면, **9.1은 2.0의 새로운 기능들을 실제 일상 작업공간으로 끌어올리는 메이저**라는 느낌입니다. 웹 UI·메시징·메모리·스킬·네이티브 앱·모델·자동화·보안까지 전 영역에 걸쳐 있어서, 아래 하이라이트 순서대로 보여드릴게요.

## 하이라이트 ① 채팅 안에서 다이어그램이 그려진다 — 머메이드(Mermaid) 인라인 렌더링

이번 업데이트에서 **가장 눈에 띄는 기능**입니다. Control UI(웹)와 **Android·iPhone/iPad·Mac 앱 모두**에서, 에이전트가 답변에 포함한 **완성된 머메이드 코드 펜스가 바로 다이어그램으로 렌더링**됩니다.

- **컨트롤** — 다이어그램 옆에 소스 보기·복사·확장·줌 컨트롤이 붙고, **활성 테마를 따라가며** 나머지 답변이 도착하는 동안 제자리에 유지됩니다.
- **안전한 렌더링** — 렌더러는 lazy-loaded되고 페이지와 격리되며, 모델이 만든 출력은 표시 전에 **수동 SVG(passive SVG)** 로 변환됩니다. 플로우차트·시퀀스 다이어그램을 다른 툴로 옮기지 않고 채팅에서 바로 읽을 수 있다는 뜻이에요.
- **솔직한 한계** — "완성된 펜스"만 렌더링됩니다. 스트리밍 중이거나, 잘못됐거나, 지나치게 크거나, 외부 의존이 있는 다이어그램은 빈 박스 대신 **읽을 수 있는 소스 코드로 폴백**합니다. (PR [#134913](https://github.com/openclaw/openclaw/pull/134913), Android [#135342](https://github.com/openclaw/openclaw/pull/135342), iOS [#135470](https://github.com/openclaw/openclaw/pull/135470), macOS [#135746](https://github.com/openclaw/openclaw/pull/135746))

저처럼 "에이전트한테 플로우차트 그려달라고 하면 코드만 던져주던 경험"에 익숙하신 분들은, **그 코드가 바로 그림이 되는 순간**이 생각보다 큽니다. 다이어그램을 코드로 옮겨 붙이던 수고가 사라지거든요.

## 하이라이트 ② 안드로이드 앱, "일상 작업공간"으로 대폭 강화

두 번째 큰 축은 **Android 네이티브 앱**입니다. 2.0에서 iOS·Android가 크게 좋아졌는데, 9.1에서는 Android가 **브라우저 Control UI에 더 가까운 일상 작업공간**이 됩니다.

- **컴포저** — 풀사이즈 작성 영역에 간결한 액션, 모델 이름이 읽기 쉽게 유지
- **검색 가능한 컨트롤** — 모델·effort(추론 노력)·Fast Mode·권한을 트랜스크립트를 가리지 않고 노출
- **세션** — 네이티브 카탈로그에서 세션 탐색·생성, 사이드바를 쓰는 위치에 맞게 배치
- **테마** — 테마 패밀리·액센트가 **오프라인 변경·재연결·앱 재생성에도 올바른 프로필에 유지**
- **접근성·사전 경고** — 좁은 화면·큰 글자에서도 읽기 쉽게, 그리고 인증이 없는 모델을 명시적으로 선택해 보내려 하면 **보내기 전에 경고**

Apple 쪽도 빠지지 않습니다. iPhone/iPad는 **오프라인에서도 동작하는 벡터 프리뷰**(줌·팬·회전), macOS는 전체 채팅과 Quick Chat 양쪽에서 머메이드를 렌더링하고, 음성(보이스 노트)이 **시작한 턴에 그대로 귀속**되도록 정리됐습니다. (PR [#134939](https://github.com/openclaw/openclaw/pull/134939))

## 하이라이트 ③ 메모리 — "대화는 건드리지 않고 인덱스만 리셋" `openclaw memory reset`

이번에 **제가 가장 반가워한 부분**입니다. 2.0에서 메모리가 SQLite·LanceDB 기반으로 바뀌면서, "색인이 꼬였을 때 대화 기록까지 날릴까 봐" 망설이셨던 분들 많으시죠?

- **`openclaw memory reset`** — **색인(재구축 가능한 데이터)만 초기화**하고, 세션·트랜스크립트·메모리 소스 파일 등 영구 상태는 보존합니다. 에이전트 하나 또는 전체를 지정할 수 있고, 실행 전에 확인을 받으며 비대화형에선 `--yes`가 필요합니다.
- **불필요한 재색인 방지** — 원샷 `openclaw memory search`는 결과를 찾았으면 **인덱싱을 새로 시작하지 않고 종료**. 더티(dirty) 인덱스는 전체 재구축 대신 **증분 적용**으로 검색을 유지합니다.
- **설정 보존** — `openclaw doctor --fix`가 지식 경로·세션 메모리 선택을 조용히 기본값으로 되돌리던 문제 수정, 커스텀 OpenAI 호환 임베딩 프로바이더의 저장된 키 프로필도 해석됩니다.
- **긴 대화에서의 캡처 유지** — LanceDB 자동 캡처가 컴팩션(compaction)을 지나도 진행 위치를 유지하고, 이미 처리한 사실을 다시 임베딩하지 않습니다.

**공식 문서가 명시한 한계**도 꼭 확인하세요. 리셋은 SQLite 할당을 줄여주지 않고, 삭제된 히스토리를 복원하지 않으며, **프라이버시 퍼지(privacy purge)가 아닙니다**. (PR [#135653](https://github.com/openclaw/openclaw/pull/135653))

*OpenClaw 메모리(Memory) 공식 문서 대표 이미지 — 9.1에서 리셋 명령과 증분 색인 유지가 추가된다 (출처: docs.openclaw.ai/concepts/memory)*

## 하이라이트 ④ 스킬 — 공유 게이트웨이에서 "팀원별 개인 스킬 라이브러리"

한 대의 Gateway를 여러 사람이 쓰는 **팀·공유 에이전트 운영**이라면 주목할 기능입니다.

- **개인 스킬 라이브러리** — 로그인한 팀원이 **호스트(관리자) 접근 없이** 스킬을 만들고·가져오고(임포트)·업데이트하고·재사용할 수 있습니다.
- **비공개 시작, 선별 공유** — 라이브러리는 **비공개로 시작**하고, 공유해도 상대에게 **편집권이 넘어가지 않으며**, 스킬이 공동 작업이 되면 소유권을 팀으로 이전할 수 있습니다. "매번 관리자한테 스킬 추가해 달라고 하기"가 사라지는 구조예요.
- **불변 리비전(immutable revision)** — 각 세션이 **선택한 스킬 버전 그대로**를 지원 파일·실행 권한과 함께 유지해서, 로컬·샌드박스·클라우드·노드 워커를 오가도 같은 버전으로 작업합니다.
- **마이그레이션 안전장치** — `migrate apply claude --overwrite`가 생성된 스킬을 덮어쓸 때 **대상 디렉터리 전체를 백업**하고 복구 경로를 기록합니다. (PR [#134068](https://github.com/openclaw/openclaw/pull/134068), [#134302](https://github.com/openclaw/openclaw/pull/134302))

## 하이라이트 ⑤ 보안 — "허용을 기억하되, 전권은 아니다" (Scoped Durable Approvals)

9.1 보안의 한 줄 요약은 **"승인을 기억해 주되, 블랭킷(전체) 권한으로 만들지 않는다"**입니다.

- **범위 제한 영구 승인** — MCP 툴의 **Allow Always**가 "이 에이전트·이 서버·이 툴"에만 묶여 기억되고, 원격 Codex 배치 승인은 **그 배치·페어링·환경이 유효할 때만** 재사용됩니다. 재시작·이동·재페어링·권한 변경·만료가 생기면 **새로 승인**받아야 합니다.
- **위임 에이전트 권한 경계** — 위임 에이전트 생성 중에 **요청한 run이 끝나면**, 다음 영속 효과를 시작하기 전에 멈춥니다. "요청이 끝났는데 나중에 성공 처리"되는 일을 막는 거죠.
- **게스트 코딩 복구** — 샌드박스 필수 게스트가 `workspaceAccess: none`인 **프라이빗 워크스페이스 안에서** 파일 쓰기·코드 패치·프로젝트 로컬 명령을 다시 할 수 있습니다. 공유 에이전트 워크스페이스와 호스트 자격 증명은 여전히 경계 밖이고, 네트워킹은 운영자가 켜기 전까진 꺼져 있습니다.
- **진단 데이터 보호** — iOS 딥링크 URL을 진단에서 생략하고, 설정 응답에서 시크릿·SecretRef 값을 마스킹합니다.
- **네트워크 차단 목록 신설** — 브라우저 접근·가드 웹 페치·자동화 웹훅에 대해 **정확한 호스트명·와일드카드 서브도메인 차단**을 DNS 조회 전에 적용할 수 있습니다. (완전한 allowlist를 유지하지 않아도 된다는 뜻)

## 하이라이트 ⑥ 업데이트·자동화 — 실패해도 복구 경로가 보이고, 밀린 잡은 스킵 선택지

- **업데이트 준비 점검(Readiness Check)** — 재시작 전에 **로컬 메모리 셋업·플러그인 동의·승인 마이그레이션**을 확인하고, 문제가 있으면 재시작 전에 멈추고 구체적인 복구 경로를 제시합니다. 비치명적 경고는 **"저하된(degarded) 상태로 켜고 Doctor 안내"**를 선택할 수 있어서, 관리자 감독자가 무한 재시작하는 일이 줄어듭니다.
- **에이전트 시작 업데이트 핸드오프** — 관리형 Linux·macOS Gateway에서 에이전트가 시작한 업데이트는 **서비스가 멈추기 전에 분리된 헬퍼(detached helper)** 로 넘어가고, Windows도 Gateway 소유 재시작 경로를 타서 **옛 프로세스 트리와 함께 죽지 않습니다**.
- **더 가벼운 설치** — Sharp·ONNX 의존성 체인을 안 쓰는 설치에선 제거합니다. (단, 밈 PNG 출력은 이제 Chromium/Chrome 필요)
- **`cron.skipMissedJobs: true` (옵트인)** — 다운타임 후 밀린 알림·다이제스트·모델 호출이 싫다면 이 설정으로 **지난 반복 일정을 다음 미래 발생 시점으로 전진**시킬 수 있습니다. 기본값은 기존 catch-up 동작 유지, **1회성(one-time) 작업은 스킵되지 않습니다.** (PR [#135071](https://github.com/openclaw/openclaw/pull/135071))

## 그 외 눈에 띄는 변경점 — 모델·성능·일상 개선

- **모델 선택 UI** — 모델 변경이 **"이 세션/이 에이전트/전역 기본값" 중 어떤 범위인지 저장 전에 표시**. Defaults 카드에 메인 모델·유틸리티 모델·첫 폴백·thinking·Fast Mode가 한 곳에 모입니다. **Anthropic Fable 5.1**이 공유 API 및 Claude CLI 카탈로그에 추가됐고, xAI **SuperGrok OAuth 계정**은 상태 화면에서 사용량·리셋 시각·플랜·잔액을 볼 수 있습니다. (PR [#135638](https://github.com/openclaw/openclaw/pull/135638), [#135766](https://github.com/openclaw/openclaw/pull/135766))
- **성능** — **긴 대화와 동시 응답에서 CPU·메모리 사용량이 크게 감소**(테스트 워크로드 기준), 대규모 설치에서 헬스 체크와 세션 뷰 응답성 개선, ARM64의 768MiB·1GiB 환경 메모리 헤드룸 확보.
- **일상 개선** — 관리형 워크트리를 **다른 디스크/폴더에 저장**(체크아웃 상한 100개는 자동 정리 목표로 유지, 신규 허용 상한은 제거), 로컬 에이전트가 **기존 프로젝트 디렉터리에서 바로 작업**(unsandboxed 한정 옵션), 감독형 Codex Chat의 **"Fork from here"**(대화를 바꾸지 않고 선택한 입력을 초안으로), 대용량 파일·터미널 출력의 임시 복사본 최소화.

## 실제 사용감 — 솔직한 장단점

아직 정식 출시 전이라 **베타 기준 + 릴리스 노트 기준**으로 솔직하게 정리하면:

**👍 좋은 점**
- **2.0에서 생긴 기능들이 "매일 쓰는 도구"로 다듬어지는 방향** — 머메이드·Android·메모리 리셋 모두 실사용에서 부딪히는 지점을 겨냥합니다.
- **보안이 "편의 ↔ 안전" 균형을 구체적으로 설계** — Allow Always를 기억하되 범위를 좁히는 방식이 마음에 듭니다.
- **업데이트 실패 공포 완화** — readiness check + 복구 경로 + Doctor 연계가 8.2의 '안전한 업그레이드'를 한 단계 더 발전시켰습니다.
- **무료 오픈소스** — 이 모든 게 오픈소스 프로젝트로 계속 쌓이고 있습니다.

**🤔 아직은/주의할 점**
- **정식 출시 전** — 지금 당장 stable로 받을 수 없고, GitHub에 v2026.9.1 태그가 올라오면 `openclaw update`로 받을 수 있습니다. 급하시면 베타 채널을 쓰되 **백업 필수**.
- **머메이드는 '완성된 펜스'만** — 스트리밍 중간에는 소스 코드로 보이다가 완성되면 그림이 됩니다. 실시간으로 그려지는 걸 기대하면 살짝 다를 수 있어요.
- **memory reset은 '색인 초기화'이지 '데이터 삭제'가 아님** — 반대로 말하면 **프라이버시 퍼지 용도로 쓰면 안 됩니다.**
- **성능 개선은 측정된 특정 워크로드 기준** — 공식 문서도 "모든 브라우저·Gateway에서 같은 개선을 보장하지 않는다"고 명시합니다.
- **업데이트가 멈추는 경우** — 플러그인 동의 미해결·승인 마이그레이션 불완전 상태에선 의도적으로 재시작 전에 멈춥니다. "업데이트가 왜 안 되지?" 하기 전에 `openclaw doctor`부터.

## 정식 출시 전 체크리스트 — 지금 해두면 좋은 준비

1. **백업 먼저** — v2026.9.1은 922개 PR 규모라 마이그레이션이 큽니다. 공식 문서도 업데이트 전 **검증된 백업**(`openclaw backup` 계열 명령·자동 백업)을 강조합니다.
2. **상태 점검** — 플러그인 동의·승인 마이그레이션·로컬 메모리 셋업에 문제가 없도록 미리 확인.
   ```bash
   openclaw doctor
   ```
3. **메모리 색인이 꼬였다고 느낀다면** — 대화 기록 걱정 없이 인덱스만 리셋할 수 있게 된 점을 기억해 두세요(안정판 적용 후).
   ```bash
   openclaw memory reset
   ```
4. **자동화 운영자라면** — 다운타임 후 밀린 반복 작업을 스킵할지, 설정값 `cron.skipMissedJobs`를 미리 결정해 두세요.
5. **공유 게이트웨이 팀이라면** — 세션 가시성 설정과 함께, 9.1의 개인 스킬 라이브러리 도입 여부를 검토해 두세요.

## 마무리

정리하면, **v2026.9.1은 "2.0에서 만든 것들을 실제 일상으로 끌어올리는" 9월 메이저 업데이트**입니다. 922개 PR이라는 규모에서 느껴지듯 OpenClaw의 개발 속도는 2.0 이후 더 빨라졌고, 이번 주 안으로 안정 태그가 올라올 가능성이 높아 보입니다.
