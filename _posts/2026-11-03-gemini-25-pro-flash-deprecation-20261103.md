> **📌 한 줄 요약:** 구글이 **2026년 11월 2일**, `gemini-2.5-pro`와 `gemini-2.5-flash`를 공식 폐기 모델로 지정했습니다. **12월 1일**부터 두 모델로 들어오는 API 요청은 각각 **`gemini-3.8-flash`** 와 **`gemini-3.5-flash-lite`** 로 **자동 라우팅**되고, 과금도 새 모델 단가로 전환됩니다. 에러가 나서 멈추는 게 아니라 **조용히 다른 모델로 갈아타는** 방식이라, 코드를 안 고쳐둔 자동화일수록 위험합니다.

## 무슨 일이 있었나 — 11월 2일자 릴리스 노트

Gemini API 공식 릴리스 노트의 최신 항목은 **2026년 11월 2일**자입니다. 두 줄짜리 공지인데, 파급은 상당합니다.

> "**Gemini 2.5 Pro deprecation**: `gemini-2.5-pro` is deprecated and is no longer available to select in Google AI Studio. Effective December 1, 2026, all API requests to `gemini-2.5-pro` will automatically route to `gemini-3.8-flash` and be billed at Gemini 3.8 Flash rates."

> "**Gemini 2.5 Flash deprecation**: `gemini-2.5-flash` is deprecated... Effective December 1, 2026, all API requests to `gemini-2.5-flash` will automatically route to `gemini-3.5-flash-lite` and be billed at Gemini 3.5 Flash-Lite rates."

정리하면 이렇습니다.

| 모델 | 최초 출시 | 종료(자동 라우팅) 시점 | 대체 모델 |
|:--|:--|:--|:--|
| `gemini-2.5-pro` | 2025년 6월 17일 | **2026년 12월 1일** | `gemini-3.8-flash` |
| `gemini-2.5-flash` | 2025년 6월 17일 | **2026년 12월 1일** | `gemini-3.5-flash-lite` |
| `gemini-2.5-flash-lite` | 2025년 7월 22일 | 종료일 미정 (계속 제공) | — |

주의할 점이 하나 있습니다. 2.5 계열은 **이미 9월 18일부터 신규 사용자에게 막혀 있었습니다.** "과거에 실제로 사용한 이력이 있는 사용자"에게만 API 접근을 허용하는 방식이었고, 이번 공지는 그 남은 접근권까지 **12월 1일에 정리하겠다**는 통보입니다. 즉 이미 2.5 계열을 새로 쓰기 시작한 프로젝트는 없고, **오래전부터 돌아가던 파이프라인**이 대상입니다.

## 왜 이게 그냥 '모델 하나 없어짐'이 아닌가

세 가지가 겹쳐서 사건의 무게가 달라집니다.

### 1) Pro 티어가 Flash로 내려갑니다
`gemini-2.5-pro`는 이름 그대로 **Pro 등급** 모델이었습니다. 복잡한 추론과 코딩을 담당하던 상위 라인이고, 요청이 **Flash로 라우팅**된다는 건 등급 자체가 한 단계 내려간다는 뜻입니다. 다만 2026년 11월 기준 `gemini-3.8-flash`는 "가장 똑똑한 Flash 모델"로, 장기 소프트웨어 엔지니어링·자율 에이전트·복잡한 기업 워크플로를 겨냥해 만들어진 모델입니다. 세대 차이(2.5 → 3.8)가 워낙 커서 체감 성능이 오히려 올라가는 경우가 많지만, **"Pro였으니까 상위 모델을 쓰고 있었다"는 전제로 짜둔 프롬프트·평가 기준은 다시 봐야 합니다.**

### 2) 실패가 아니라 '조용한 교체'입니다
엔드포인트가 닫히는 방식이면 500 에러가 떨어지고 최소한 장애라도 인지됩니다. 이번 방식은 **요청은 정상적으로 200을 돌려주는데 뒤에서 다른 모델이 답하는** 구조입니다. 모니터링이 "응답 성공률"만 보고 있으면 **아무 이상 없이 지나갑니다.** 대신 결과물의 어투, JSON 준수율, 도구 호출 패턴이 슬그머니 달라집니다.

### 3) 과금 단가가 같은 날 바뀝니다
라우팅과 동시에 **새 모델 단가로 청구**됩니다. 12월 1일 이후 청구서를 열어보면 단가가 바뀌어 있고, 2027년 1월 1일에는 `gemini-3.8-flash`의 **도입 가격이 끝나면서 단가가 두 배로** 뜁니다. 이중으로 비용이 변하는 구조입니다.

## 가격은 실제로 어떻게 바뀌나

공식 가격표(2026년 11월 기준, 100만 토큰당 USD)를 나란히 놓으면 이렇습니다.

| 항목 | `gemini-2.5-pro` | `gemini-3.8-flash` (2026년 말까지) | `gemini-3.8-flash` (2027년 1월 1일~) |
|:--|:--|:--|:--|
| 입력 | $1.25 (프롬프트 ≤ 200k)<br>$2.50 (> 200k) | **$0.75** | $1.50 |
| 출력(사고 토큰 포함) | $10.00 (≤ 200k)<br>$15.00 (> 200k) | **$3.75** | $7.50 |
| 컨텍스트 캐싱 | $0.125 / $0.25 | $0.075 | $0.15 |
| 캐시 저장 | $4.50 / 100만 토큰·시간 | $0.50 | $1.00 |

숫자만 보면 **2.5 Pro → 3.8 Flash는 당장은 큰 폭의 인하**입니다. 출력 단가가 $10에서 $3.75로 떨어지니까요. 하지만 두 가지 함정이 있습니다.

1. **200k 초과 구간이 사라집니다.** 2.5 Pro는 20만 토큰을 넘기면 입력 $2.50, 출력 $15로 뛰었습니다. 3.8 Flash는 구간 구분 없이 단일가입니다. 즉 **짧은 프롬프트 위주라면 인하, 20만 토큰급 대용량 문서 처리라면 2027년부터 비슷하거나 소폭 인상**으로 체감될 수 있습니다.
2. **2027년 1월 1일에 단가가 두 배가 됩니다.** 도입 가격은 2026년 12월 31일까지입니다. 12월에 마이그레이션하고 1월에 청구서를 보면 "왜 두 배지"가 됩니다.

`gemini-2.5-flash` 쪽은 조금 다릅니다. 대체 모델인 `gemini-3.5-flash-lite`의 단가가 **입력 $0.30 / 출력 $2.50**으로 2.5 Flash와 **거의 동일**합니다. 비용은 그대로인데 모델이 바뀌는 케이스라, 오히려 **동작 변화 쪽을 더 봐야 합니다.** Flash-Lite는 "고볼륨 에이전트 작업, 번역, 단순 데이터 처리"에 최적화된 라인이라, 2.5 Flash로 복잡한 추론을 돌리던 용도라면 상위 모델로 올릴지 판단이 필요합니다.

## 코드에서 반드시 고쳐야 하는 것 — breaking changes

공식 마이그레이션 가이드가 명시한 항목입니다. 모델 문자열만 바꾸면 끝나는 게 아닙니다.

**① `thinking_budget` → `thinking_level`**
숫자로 사고 토큰을 조절하던 파라미터가 문자열 enum으로 바뀝니다. `low`, `medium`(기본값), `high` 중에서 고르는 방식이고, **`minimal`은 Gemini 3.8 Flash에서 지원하지 않습니다.**

**② 샘플링 파라미터 제거**
`temperature`, `top_p`, `top_k`가 빠집니다. Gemini 3 계열부터 적용된 변화로, 창의성 조절을 이 파라미터에 의존하던 프롬프트는 **프롬프트 문장 자체로** 그 의도를 옮겨야 합니다.

**③ `candidate_count` 미지원**
한 번에 여러 후보를 뽑아 비교하는 방식은 Gemini 3 이후 지원되지 않습니다. 후보 중 골라쓰는 구조라면 호출을 나눠야 합니다.

**④ 프리필(prefilled model turn) 제거**
모델 응답의 시작 부분을 미리 채워 넣어 형식을 강제하던 트릭이 막힙니다. JSON 강제 출력을 프리필로 처리하던 코드가 대표적인 피해자입니다. 대신 **구조화 출력(response schema)** 이나 시스템 지시문으로 옮겨야 합니다.

**⑤ 함수 호출 검증 강화**
- `FunctionResponse` 객체에 `call_id`와 `name`을 반드시 포함해야 합니다(GenerateContent API 사용 시).
- 멀티턴 대화는 서버 측 `previous_interaction_id`로 상태를 잇는 방식으로 표준화하고, **프리필 턴은 제거**해야 합니다.
- pre-tool 텍스트 때문에 `Malformed_Function_Call` 오류가 난다면, 멀티모달 자산을 응답 페이로드 안에 넣고 인라인 지시는 `\n\n`으로 구분하는 워크어라운드를 적용해야 합니다.
- 사고 과정의 `thought_signature` 보존도 확인 대상입니다. SDK를 최신 버전으로 올리지 않으면 시그니처가 깨져 도구 호출이 실패할 수 있습니다.

정리하면 **모델 ID 교체 + SDK 업그레이드 + 사고 레벨 재설정 + 프리필 제거 + 함수 호출 스키마 점검**이 한 세트입니다.

## 영향 — 사용자와 개발자

### 일반 사용자 입장
Gemini 앱을 쓰는 사람에게는 당장 체감되는 변화가 거의 없습니다. 2.5 세대는 이미 AI Studio 모델 선택 목록에서 빠져 있고, 앱은 상위 모델을 기본으로 쓰고 있습니다. 영향이 있는 건 **노코드·로우코드 도구 안에서 모델을 직접 지정해 쓰던 경우**입니다. 자동화 툴의 모델 드롭다운에 남아 있던 2.5 계열을 골라둔 워크플로가 있다면, 12월 이후 조용히 다른 모델로 돌아갑니다.

### 개발자·운영자 입장
모델 문자열이 박혀 있는 위치를 전부 찾는 게 첫 단계입니다. 생각보다 넓게 퍼져 있습니다.

- 애플리케이션 코드의 하드코딩된 모델명
- 환경변수·설정 파일·비밀 관리 저장소
- 프롬프트 템플릿이나 에이전트 정의 파일
- 배치·크론 작업 스크립트
- 평가(eval) 파이프라인의 기준 모델
- 대시보드·알림 문구에 들어간 모델 이름

그다음은 **회귀 검증**입니다. 같은 입력 20~30건을 2.5와 3.8 Flash에 각각 넣고 ① JSON 스키마 준수 ② 함수 호출 인자 정확도 ③ 응답 길이 ④ 지연시간 ⑤ 토큰 사용량을 비교하면, 12월 1일 이후에 벌어질 일을 미리 볼 수 있습니다. 특히 **출력 형식이 깨지는 케이스**가 가장 먼저 터집니다.

## 자동화 파이프라인을 운영하는 입장에서 — 12월 전에 할 일

업무 자동화 파이프라인을 돌리는 쪽이라면, 이번 공지는 "모델 교체"가 아니라 **"비용·품질·장애 지점이 동시에 이동하는 이벤트"** 로 보는 게 맞습니다. 순서를 정리하면 이렇습니다.

1. **모델 ID를 설정값으로 뺍니다.** 코드에 문자열로 박아두면 다음 폐기 때 또 같은 일을 반복합니다. `GEMINI_MODEL` 같은 환경변수 하나로 갈아끼울 수 있게 만드는 게 기본입니다.
2. **모델명을 로그에 남깁니다.** 응답 메타데이터의 실제 사용 모델을 저장해 두면, 자동 라우팅이 시작된 시점을 정확히 잡아낼 수 있습니다. 이게 없으면 "언제부터 결과가 달라졌는지"를 사후에 재구성해야 합니다.
3. **사고 레벨을 명시합니다.** 기본값이 `medium`이라 지정하지 않으면 이전보다 사고를 많이 할 수 있습니다. 지연시간과 토큰 비용에 직결되므로 용도별로 `low`/`high`를 의도적으로 골라야 합니다.
4. **비용 알림을 새 단가로 다시 겁니다.** 12월 1일(라우팅)과 2027년 1월 1일(도입가 종료) 두 번 단가가 움직입니다. 임계값을 그대로 두면 두 번째 변동에서 알림이 늦습니다.
5. **실패 시 폴백을 정합니다.** 새 모델이 특정 작업에서 계속 어긋나면 다른 모델로 우회할 경로를 미리 정해둡니다.

## 전망

이번 공지에서 읽을 신호는 세 가지입니다.

- **2.5 세대 정리는 예고된 수순이었습니다.** 2.0 계열은 2026년 6월 1일에 정리됐고, 3.5 Flash는 5월, 3.7 Flash는 8월에 각각 후속 모델로 흡수됐습니다. 구글은 **약 3개월 주기로 한 세대씩 정리**하는 리듬을 유지하고 있습니다. 2.5 Pro·Flash의 12월 1일은 그 연장선입니다.
- **Flash 라인이 사실상 기본값이 됐습니다.** 가장 똑똑한 모델이 Flash 이름을 달고 나오고, Pro 등급 요청까지 Flash로 흡수됩니다. 상위 추론이 필요한 극단적 케이스는 Gemini 4 계열(Argon 등)로 올라가는 2단 구조가 굳어지는 모양새입니다.
- **가격은 '도입가 → 정가' 패턴이 반복됩니다.** 3.8 Flash의 인상 시점이 2027년 1월 1일로 못 박혀 있습니다. 신모델을 빨리 도입한 팀일수록 **가격 인상 시점을 캘린더에 넣어둬야** 합니다.

## 정리 — 이런 경우엔 오늘 점검이 필요합니다

- `gemini-2.5-pro` 또는 `gemini-2.5-flash` 문자열이 코드·설정·노코드 툴 어딘가에 남아 있다면
- 2.5 Pro의 20만 토큰 초과 구간 단가를 전제로 예산을 잡아뒀다면
- `temperature`, `top_p`, `thinking_budget`을 프롬프트 품질 조절용으로 쓰고 있다면
- 프리필로 JSON 출력 형식을 강제하고 있다면
- 응답 성공률만 모니터링하고 있어서 모델 교체를 감지할 방법이 없다면

하나라도 해당하면 **12월 1일 전에** 모델 문자열 교체와 회귀 테스트를 끝내는 게 안전합니다. 특히 조용한 자동 라우팅은 장애로 잡히지 않기 때문에, 결과물 품질이 서서히 어긋나는 형태로만 드러납니다.
