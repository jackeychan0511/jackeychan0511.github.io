## 1. 요즘 저처럼 "어제 릴리스가 오늘은 어떻게 됐지" 매일 npm부터 여시는 분들

요즘 저처럼 **오픈소스 AI 에이전트 OpenClaw의 릴리스 소식을 매일 실측해서 정리하시는 분들**, 많으시죠. 어제(8/28)는 ClawHub 설치 전 보안 감사와 발신자 인증 등급, Daytona 클라우드 샌드박스까지 정리해드렸는데, 그 글을 쓰고 나서 **또 큰 일**이 벌어졌습니다.

어젯밤, 정확히는 **8/28 20:43 UTC(한국시간 8/29 새벽 5시 43분)**, OpenClaw의 **9월 트레인 첫 베타 v2026.9.1-beta.1**이 GitHub에 출시됐습니다. npm에는 20:04 UTC에 먼저 게시됐고, **npm의 beta dist-tag가 8/24의 2026.8.1-beta.3에서 2026.9.1-beta.1로 옮겨갔습니다.** 재밌는 타이밍이죠. **8월 정식판(2026.8.1)이 아직 npm latest에 없는 상황에서, 9월 베타가 먼저 나온** 겁니다.

그리고 이번 릴리스를 열어보면 헤드라인이 하나같이 **"재시작(re) 복구(recovery)"**입니다. Gateway 재시작 복구, config 쓰기 신뢰성, Worker 복구, 설치 신뢰성 — 마치 "8월에 쏟아낸 기능들을 **재시작에도 견디게 단단하게** 만들자"는 선언처럼 느껴집니다. 오늘은 그 내용을 npm·GitHub 실측 기준으로 낱낱이 풀어보겠습니다.

## 3. 핵심 업데이트 ② — Gateway 재시작 복구: "재시작돼도 대화가 처음부터로 안 돌아갑니다"

### 어떤 기능인가

> **"Gateway restart recovery: preserve admitted turns across repeated Gateway restarts so restart-safe runs continue through each checkpoint and deliver their final response."**
> — v2026.9.1-beta.1 릴리스 노트 (#130491, Thanks @jalehman)

번역하면 **"반복된 게이트웨이 재시작에도 승인된(admitted) 턴을 보존해서, 재시작 안전(restart-safe) 실행이 각 체크포인트를 통과하며 이어지고 최종 응답까지 전달한다"**입니다. OpenClaw에서 게이트웨이(Gateway)는 텔레그램·왓츠앱·디스코드 같은 메신저와 에이전트를 잇는 프로세스인데, 이게 재시작되면 진행 중이던 대화 턴이 날아가곤 했습니다. 이제 **승인까지 끝난 턴은 재시작을 몇 번 겪어도 체크포인트 기준으로 이어서** 최종 결과를 냅니다.

### 실제 사용감/장점

저처럼 **크론잡 자동포스팅을 게이트웨이 아래에서 돌리는 사람**에게 이건 이번 릴리스 최고의 선물입니다. 크론잡이 실패하는 흔한 시나리오가 뭐냐면, **긴 작업을 돌리는 도중 게이트웨이가 재시작(업데이트·서버 재부팅·크래시)되면서 "처음부터 다시"**가 되는 거거든요. 사람이 지켜보지 않는 새벽 크론잡은 그 순간 조용히 유실됩니다. 이제 restart-safe 실행은 **체크포인트마다 상태를 지키고, 재시작 후에도 이어서** 최종 응답을 전달합니다. "재시작 = 처음부터"라는 공식이 깨지는 순간입니다.

### 단점/주의

- 대상은 어디까지나 **"승인된(admitted) 턴"**입니다. 승인 전 단계의 턴이나 restart-safe로 표시되지 않은 실행은 기존처럼 재시작에 취약할 수 있어요. **"어떤 작업이 restart-safe로 취급되는가"**는 문서의 게이트웨이 섹션을 확인해보시는 걸 추천합니다.
- 릴리스 노트는 **체크포인트 생성 주기·보존 정책**을 상세히 적어두지 않았습니다. 장시간 실행 잡을 걸어두실 거라면 업데이트 후 실측으로 "재시작해도 이어지는지" 한 번 확인해보세요.

## 4. 핵심 업데이트 ③ — Gateway config-write 신뢰성 + Codex 0.150.1

### Gateway config 쓰기가 watcher 핸드오프를 견딘다 (#131515)

> **"Gateway config-write reliability: keep committed config writes pending through watcher handoff so same-write reloads settle against the observed generation instead of failing during source transfer."**

게이트웨이 설정(config)을 저장할 때, **watcher(설정 감시자)로 핸드오프되는 동안 커밋된 쓰기를 유지**합니다. 기존에는 같은 설정을 연달아 저장하면 소스 전송 중에 `config.patch`가 실패하는 일(#131405)이 있었는데, 이제 **관찰된 세대(generation) 기준으로 안정적으로 반영**됩니다. "설정 저장했는데 왜 안 먹히지?" 하던 미묘한 버그가 정리되는 셈이죠.

### Codex 관리형 런타임 0.150.1 (#130685)

> **"Codex managed runtime: update the bundled Codex runtime to 0.150.1 across Linux, macOS, and Windows while retaining platform-specific package resolution and current compaction behavior."**

OpenClaw에 번들된 **Codex 런타임이 0.150.1로 업데이트**됐습니다. 세 플랫폼 모두 적용되고, 플랫폼별 패키지 해석과 기존 압축(compaction) 동작은 유지됩니다. Codex 0.150.1의 **협업·상태·활동 프로토콜 추가분을 관리형 브리지로 전달**하는 호환 작업(#130685)도 함께 들어갔어요. Codex 엔진으로 작업을 돌리시는 분들은 "모델·런타임·thinking 선택이 /model에서 원자적으로 유지"되는 흐름이 더 단단해졌다고 보시면 됩니다.

### 감사 결정 기록의 실행 경계 (#130358)

> **"Audit decisions: record generic tool-action decisions at their authoritative execution boundary for clearer operator diagnostics."**

도구 실행에 대한 **감사(audit) 결정을 "실제 실행이 일어나는 경계"에서 기록**하도록 바꿔, 운영자가 진단 로그를 볼 때 **"승인은 났는데 실제로 실행된 건 언제지?"**가 명확해집니다. 보안 감사 로그를 직접 까보시는 분들께는 체감되는 변경입니다.

## 5. 핵심 업데이트 ④ — Linux 설치 신뢰성 + Worker 복구

### Linux 설치가 "호환 안 되는 Node"를 고르지 않는다 (#130369)

> **"Linux installation reliability: provision the stable Node 24 LTS stream and constrain RPM installs to the configured NodeSource repository so Linux setup cannot select an incompatible prerelease."**

리눅스 설치 스크립트가 **Node 24 LTS 스테이블 스트림**을 받도록 고정되고, **RPM 설치는 NodeSource 저장소로 제한**됩니다. 이전에는 설정 과정에서 **호환되지 않는 프리릴리스 Node를 골라 설치가 깨지는** 경우가 있었는데, 이제 그 경로 자체가 차단됩니다. 리눅스 서버에 OpenClaw를 직접 설치해 쓰시는 분(특히 RPM 계열)은 "왜 매번 설치만 하면 뭔가 하나씩 어긋나지?" 하던 원인 중 하나가 정리된 셈입니다.

### Worker 복구 — 위임된 작업이 "조용히 사라지지" 않는다 (#130446)

> **"Worker recovery: re-arm admission-deadline launches, terminalize dead-worker turns, and defer debris cleanup so interrupted delegated work settles visibly."**

클라우드 워커(Crabbox 등)로 위임한 작업이 **admission 데드라인을 넘겨 실행 기회를 잃으면 재무장(re-arm)** 되고, **죽은 워커의 턴은 명시적으로 종결(terminalize)** 되어 "위임했는데 결과도 실패도 안 오는" 상태가 사라집니다. 잔여물(debris) 정리는 뒤로 미뤄서 **진행 상황이 눈에 보이게 정리**됩니다. "어제 위임한 작업이 왜 아무 소식이 없지?" 하던 분들에게 반가운 수정입니다.

### 그 외 — Control UI 파일 안전과 모델 브라우징

- **Control UI 파일 저장 보존 (#130468)** — 파일 목록 읽기·새로고침이 겹쳐도 **확인된 저장(confirmed saves)과 파일 메타데이터가 유지**됩니다. 브라우저에서 에이전트 파일을 편집하시는 분들이 겪던 "저장했는데 덮어써졌다" 류의 문제 방지.
- **모델 브라우징 신뢰성 (#130481)** — 플러그인 자동 활성화 이후에도 **모델 탐색 카탈로그가 유지**됩니다. "플러그인 깔았더니 모델 목록이 사라졌다"는 흔한 불편이 정리되는 변경입니다.
- **Control UI 외관은 프로필별 저장 (#130340)** — 외관 설정(appearance)을 **사용자 프로필별로 저장**해서, 공유 브라우저에서도 각자 자기 설정이 유지됩니다.
- **모델 선택 스코프 (#127813)** — **모델 선택 범위(configurable model-selection scopes)**를 설정할 수 있게 됐습니다. 공식 프로바이더·런타임 정책 경로는 그대로 유지하면서, 상황별로 모델 고르는 범위를 좁힐 수 있습니다.

## 8. 실제 사용감 — 장점과 아쉬운 점, 솔직하게

**좋았던 점 (장점)**
- **"재시작에도 견디는" 방향이 또렷하다**: 이번 릴리스의 헤드라인 7개 중 5개가 복구·신뢰성입니다. 8월에 쏟아낸 기능(IMAP 트리거, 클라우드 워커, 승인 카드 등)을 **운영 환경에서 실제로 믿고 쓰게** 만드는 작업이죠. "기능이 많아서"가 아니라 "**재시작해도 안 터져서**" 쓰게 되는 단계입니다.
- **npm beta 태그가 드디어 움직였다**: 8월 내내 2026.8.1-beta.3에 머물던 베타 트랙이 9월 트레인으로 넘어갔습니다. 베타 트랙 유저는 **v2026.9.1-beta.1로 업데이트**하면 이번 안정성 패치를 바로 받을 수 있습니다.
- **Linux·Codex 사용자에게 실질적**: Node 24 LTS 고정과 RPM NodeSource 제한은 **"설치하면 왜 자꾸 깨지지"** 하던 분들의 삽질을 직접 줄여줍니다. Codex 0.150.1 번들 업데이트도 무료로 따라오는 업그레이드입니다.

**아쉬웠던 점 (단점)**
- **8월 정식판(2026.8.1)은 여전히 없습니다**: npm latest는 `2026.7.1-2` 그대로예요. 8월 트레인이 베타.3에서 멈춘 채 9월 베타가 먼저 나온 상황이라, **안정 트랙 사용자는 "8월 정식이 스킵되는 것 아닌가"** 궁금해하실 수 있습니다. 릴리스 노트 기준으로는 8월 변경분이 9.1에 포함되는 구조라, **정식판은 2026.9.x에서 통합 출시**될 가능성이 높아 보입니다(제 추측).
- **"admitted turns"의 범위가 명확하지 않다**: Gateway 재시작 복구의 대상(restart-safe로 표시되는 작업)이 어떤 기준인지는 릴리스 노트만으로 부족합니다. 장시간 실행 잡을 걸어두실 분은 **업데이트 후 직접 재시작 테스트**를 권합니다.
- **오픈 이슈 +41**: 어제 -36이었다가 다시 늘었습니다. 9월 트레인 개막 이슈가 유입되는 중이라, **베타 초기라 그런지 이슈가 요동치는** 구간입니다.

## 9. 업데이트 팁 — 지금 뭘 하면 되나요?

1. **베타 트랙을 타시는 분** — 바로 업데이트하세요. `openclaw update --channel beta`로 **v2026.9.1-beta.1**을 받을 수 있습니다. 이번 패치는 전부 "안정화" 성격이라 베타라도 부담이 적습니다.
2. **게이트웨이 아래 크론잡을 도는 분** — 업데이트 후 **게이트웨이를 일부러 한 번 재시작**해보세요. 진행 중이던 restart-safe 실행이 체크포인트를 지키며 이어지는지 실측해보시길. "재시작 = 처음부터"의 공식이 깨졌는지 직접 확인하는 게 이번 릴리스의 핵심 체크리스트입니다.
3. **리눅스에 설치하시는 분** — 이제 **Node 24 LTS + NodeSource 고정**으로 설치됩니다. 혹시 예전에 수동으로 이상한 Node를 받아두셨다면, `openclaw doctor`로 환경을 한 번 점검해보세요.
4. **Codex 엔진을 쓰시는 분** — 번들 런타임이 **0.150.1**로 올라갔습니다. 업데이트 후 `/model`에서 모델·런타임·thinking 선택이 원자적으로 유지되는지 확인해보세요.
5. **업데이트 전 백업은 나흘째 강조** — `openclaw backup sqlite create` → 업데이트 → `openclaw doctor`. 재시작 복구가 좋아졌어도 **백업 순서는 여전히 필수**입니다.

솔직히 말해서, 8월 한 달 내내 "기능이 쏟아진다"는 느낌이었다면, **이번 9월 트레인 첫 베타는 "이제 그 기능들이 재시작에도 안전하다"는 선언**처럼 느껴집니다. 정식판이 어느 버전(2026.8.1 vs 2026.9.x)으로 npm latest에 올라올지는 아직 미궁이지만, **베타 트랙에서는 이 안정성 패치를 지금 바로** 누릴 수 있습니다.

npm latest에 정식판이 올라오는 순간, 또 바로 실측해서 정리해 찾아올게요!
