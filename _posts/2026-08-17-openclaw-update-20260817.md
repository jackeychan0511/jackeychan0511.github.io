## 1. 이례적인 소식 — PR 단위 릴리스 후보 `pr-124528-profiles` 등장

먼저 다들 궁금해하실 릴리스 소식입니다. 어제 글에서 "베타.2의 사후 검증이 실패해서 **수정 후속판 없이는 정식 승격 불가**"라고 말씀드렸는데, **오늘(8/17) 아침 기준 정식판(8.1 stable)은 아직 없습니다.** npm 베타 태그도 여전히 `2026.8.1-beta.2` 그대로예요.

대신 **새로운 형태의 릴리스 후보가 하나 찍혔습니다.**

- **`pr-124528-profiles`** (2026-08-16 19:15 KST 게시, 프리릴리스)
- 내용: **PR #124528 `fix(gateway): prevent sustained-turn readiness stalls`** — 지속적인 동시 노드 턴이 돌 때 게이트웨이의 readiness(준비 상태)와 인증 연결이 **5초 넘게 멈추던 문제**를 수정
- 원인은 타임아웃을 늘리거나 캐시를 흩뿌리는 대신, **"준비된 플러그인 메타데이터 세대(generation)를 라이프사이클 소유자 안에서 재사용"**하는 구조 변경으로 해결. `/readyz` 헬스체크와 인증 연결이 4초 로드 상한 안에서 유지된다고 합니다.

솔직히 이건 **"릴리스 후보가 이제 PR 단위로도 만들어진다"**는 운영 방식의 변화라서 눈여겨볼 만합니다. 정식판 승격 전에 PR 하나하나를 자동 검증 후보로 찍어서 배포 가능성을 미리 확인하는 흐름인데, **다음 베타(8.2?)가 PR 단위 검증을 통과한 커밋들로 채워질 것**이라는 신호로 읽었습니다.

## 2. ⭐ config 안전 강화 — "설정 파일이 숫자 하나면, 이제 거부합니다" (#124945)

이번 하루 중에서 제가 **가장 반가웠던 픽스**입니다. 설정 파일 관련 두 건이 들어왔어요.

- **`fix(config): reject scalar config roots instead of loading defaults` (#124945)** — 설정 파일 루트가 **스칼라(숫자·문자열·불리언 하나)** 로 되어 있으면, 예전엔 **조용히 기본 설정을 로드**해버렸다고 합니다. YAML/JSON 문법이 잘못 꼬여서 설정이 통째로 무시돼도 "아무 일 없던 것처럼" 기본값으로 돌아가니, **"왜 내 설정이 안 먹히지?"** 하시는 분들이 생길 수밖에 없었죠. 이제는 **명시적으로 거부**하고 오류를 냅니다.
- **`fix(config): render actionable validation errors` (#124763)** — 설정 검증 오류를 **"어디가 어떻게 잘못됐고, 어떻게 고치면 되는지"** 알려주는 형태로 렌더링합니다.

저처럼 크론잡 자동화를 OpenClaw에 맡기고 **설정 파일을 자주 만지는 분**이라면, "조용히 기본값으로 리셋"되는 최악의 시나리오가 사라졌다는 점이 생각보다 큽니다. 오류가 나면 나는 대로 보여주는 게, 디버깅 시간을 훨씬 아껴주거든요.

## 3. 게이트웨이 안정성 — "턴 저장 → ACK", stale 워커 종결, 타임아웃 후유증 차단

이번 하루 커밋의 **절반 가까이가 게이트웨이·런타임 안정성**입니다. 특히 인상 깊었던 것들만 골랐습니다.

- **`fix(gateway): persist agent turns before acknowledgement` (#124857)** — **에이전트 턴을 ACK(확인 응답) 보내기 전에 먼저 저장**합니다. "응답했다"고 알려줬는데 갑자기 꺼져서 대화가 통째로 날아가는 사고를 막는 구조입니다. 블로그 자동화처럼 **긴 크론잡을 돌리는 입장에서 제일 안심되는 픽스**였어요.
- **`fix(gateway): terminalize stale worker dispatches` (#124920)** — 오래된(스테일) 워커 디스패치를 **터미널 상태로 정리**해서, 죽은 워커가 리소스를 붙잡고 있는 문제를 수정.
- **`fix: stop forked commands after Gateway timeouts` (#124081)** — 게이트웨이가 타임아웃 나면 **포크된 명령도 함께 중단**시킵니다. "타임아웃인데 프로세스는 계속 돌고 있었다"는 시나리오 차단.
- **`fix(gateway): preserve prepared plugin metadata under load` (#124844)** — 부하 상황에서 준비된 플러그인 메타데이터가 유실되지 않도록 보존.
- **`fix: honor provider timeouts during stuck-session recovery` (#123877)** — 세션이 멈췄을 때 복구 과정에서 **프로바이더 타임아웃 설정을 존중**하도록 수정.
- **`fix(gateway): stop a plugin dangerous flag from revoking desktop computer.act` (#124863)** — 플러그인의 dangerous 플래그 하나가 **macOS 컴퓨터 사용(computer.act) 권한까지 회수**해버리던 버그를 수정. 지난주 소개해드린 [macOS 컴퓨터 사용 v2(Peekaboo)](/2026/08/15/openclaw-update-20260815/)를 쓰시는 분들이라면 특히 반가운 픽스입니다.

## 4. 승인(Approval) UX 대개편 — 패시브 표시 + 카드 재설계 + 컴포저 단축키

UI 쪽에서도 꽤 큰 변화가 있었습니다. **에이전트 승인 흐름을 '사람이 덜 신경 쓰는' 방향으로** 바꾸는 작업이에요.

- **`feat(ui): surface approvals passively and redesign the approval card` (#124767)** — 승인 요청을 **방해하지 않는(패시브) 방식으로 표시**하고, **승인 카드를 전면 재설계**했습니다. 이어서 승인 페이지도 새 카드에 맞춰 정렬됐어요(#124816).
- **`improve(ui): one primary composer button, Enter-steer, Esc-stop, quiet mic, no transcript focus ring` (#124799)** — 컴포저(입력창)를 **"기본 버튼 하나"**로 정리하고, **Enter=스티어(방향 지시), Esc=중단, 마이크는 조용히** 동작하도록 개편.
- **`feat(ui): add steer-now composer shortcut` (#124826)** — 컴포저에서 바로 **"지금 이 방향으로 가라"**는 스티어를 보내는 단축키 추가.
- **`fix(mcp): make Codex approval dead ends actionable` (#124766)** — Codex 하네스에서 **승인 흐름이 막다른 길(dead end)로 끝나던 문제**를, 다음 행동을 알려주는 형태로 수정.

솔직히 저처럼 **"에이전트가 일할 때 화면을 계속 쳐다보고 있기 어려운" 분**이라면, 승인이 조용히 들어오고 Enter 한 번으로 방향을 잡아주는 이 흐름이 꽤 편해질 겁니다. 특히 **Codex 승인 데드엔드 픽스**는 "승인 창에서 아무것도 못 누르고 멈춰 있던" 경험이 있으신 분들께 체감이 클 거예요.

## 5. 에이전트·백업·doctor — 출처 기록, 백업 오류 메시지, 진단 정직성

- **`feat(agents): record agent creation provenance and add roster tree listing` (#124828)** — **에이전트 생성 출처(provenance)를 기록**하고, 에이전트 목록을 **로스터 트리(계층 구조)로 조회**하는 기능이 추가됐습니다. "이 에이전트는 누가 언제 만들었나"를 추적할 수 있게 되면서, 멀티 에이전트 운영이 훨씬 관리하기 편해집니다.
- **`fix(agents): refuse add when prompts cannot run` (#124940)** — **프롬프트가 실행 불가능한 상태면 에이전트 추가를 아예 거부**합니다. "추가했는데 왜 안 움직이지?"를 원천 차단.
- **`fix(backup): give backup create actionable output errors` (#124894)** — 어제 소개해드린 **`openclaw backup sqlite`** 의 오류 메시지를 **"다음에 뭘 하면 되는지"** 알려주는 형태로 다듬었습니다. 백업 실패 시 원인과 해결 방안이 출력됩니다.
- **`fix(doctor)` 3종** — 은퇴한 세션 스토어 분리(#124846), **유령 공유 인증 마이그레이션 보고 중단**(#124929), 마이그레이션된 세션 소유자 보존(#124928). doctor가 "문제가 있는 것처럼" 오보를 내던 케이스들을 정리했습니다.

## 6. 플러그인·브라우저·채널 픽스 — 마이그레이션, Chrome Web Store, DM 라우팅

- **`fix(plugins): keep migration metadata authoritative` (#124924)** — 플러그인 마이그레이션 시 **메타데이터가 '권위 있는 기준'**이 되도록 수정. 마이그레이션 과정에서 정보가 뒤섞이던 문제를 정리합니다.
- **`fix(browser): support Chrome Web Store native bootstrap` (#124775)** — Chrome 확장 프로그램 설치 시 **Chrome Web Store 네이티브 부트스트랩**을 지원. 브라우저 확장 셋업이 한결 매끄러워집니다.
- **`fix(channels): route direct DM replies to sender` (#124837)** — DM(다이렉트 메시지) 답장이 **보낸 사람에게 정확히 라우팅**되도록 수정. 채널이 여러 개일 때 "답장이 엉뚱한 데 갔던" 문제입니다.
- **`fix(openrouter): use dedicated /api/v1/images endpoint for image generation`** — OpenRouter로 이미지를 생성할 때 **전용 이미지 엔드포인트(`/api/v1/images`)를 사용**하도록 변경. 이미지 생성 호환성이 개선됐습니다.
- **`fix(slack): drop the tool-call receipt from finished progress cards` (#123851)** — Slack 진행 카드에서 **완료된 툴 콜의 '영수증'이 남아 지저분해지던** 문제를 정리.
- **`fix(media): bound image-optimize fetch headroom to the image cap` (#124838)** — 이미지 최적화 시 가져오는 **추가 용량(헤드룸)을 이미지 상한에 맞게 제한**해 메모리 사용을 방어.

## 7. 수치로 보는 하루 — 스타 386,471개, 하루 커밋 120건+

- **GitHub 스타 386,471개** (8/17 오전 확인) — 어제 386,406개에서 **하루 +65개**. 포크는 81,208개입니다.
- **커밋 약 120건** — 어제 글의 마지막 푸시(8/16 01:08 UTC) 이후 오늘 아침(8/17 01:25 UTC)까지 메인브랜치에 들어온 커밋 수입니다. **대부분이 fix**라는 점이 이번 하루의 성격을 잘 보여줍니다.

## 8. 솔직한 단점 — 짚고 넘어갈 것들

좋은 점만 나열하면 솔직한 리뷰가 아니죠. 오늘 기준으로 짚어야 할 것들입니다.

1. **신기능은 아직 어느 태그에도 없음** — 이 글에서 소개한 config 거부·승인 UX·에이전트 출처 기록은 **전부 메인브랜치 상태**입니다. 베타.2에 들어간 게 아니에요. 만져보려면 다음 베타(8.2?)를 기다려야 합니다.
2. **베타.2 사후 검증 실패 후속판은 아직** — 어제 말씀드린 "수정 후속판 없이는 정식 승격 금지" 상태가 그대로입니다. 오늘도 **정식판 후보 소식은 없었습니다.**
3. **문서가 여전히 안 따라옴** — **docs.openclaw.ai의 2026.8.1 릴리스 노트 페이지는 오늘(8/17) 확인해도 여전히 404**입니다. 베타.2가 나온 지 이틀이 지났는데 문서가 비어 있어서, 새 기능 확인은 GitHub 릴리스 노트로 해야 하는 상황이에요.
4. **하루 120건의 '픽스' = 안정성 모드** — 좋은 신호이기도 하지만, 그만큼 **출시 직후 버그가 많이 터졌다**는 뜻이기도 합니다. "새 기능이 폭발적으로 늘던 시기"는 한풀 꺾이고, 지금은 **다지는 시기**로 보는 게 맞습니다.

## 9. 마무리 — 추천 대상과 설치 방법

정리하면, **오늘 OpenClaw의 키워드는 "출시 다음 날의 수습(收拾) 모드"**입니다. 하루 120건이 넘는 커밋이 대부분 픽스로, **게이트웨이 안정성(턴 저장·스톨 수정)·config 안전(스칼라 설정 거부)·승인 UX 재설계**가 핵심이었고, **PR 단위 릴리스 후보**라는 새로운 운영 방식도 눈에 띄었습니다. "출시하고 나서도 바로 다음 날 이렇게 고친다"는 게, 오픈소스 프로젝트로서는 오히려 믿음이 가는 부분이기도 했어요.

설치는 아래 한 줄이면 끝입니다.

```
# 최신 안정판 (안정적으로 쓰실 분)
npm install -g openclaw@latest

# 베타 라인 (신기능 체험)
npm install -g openclaw@beta
```

솔직히 저처럼 **메신저에서 바로 일하는 AI 비서**를 찾으시는 분, **"설정이 조용히 리셋되는" 불안 없이 크론잡 자동화를 맡기고 싶은 분**이라면 이번 안정성 행보는 꽤 긍정적입니다. 다만 **신기능 체감은 다음 베타(8.2)까지 기다려야** 하니, 베타 라인을 타시는 분은 **업데이트 전 `openclaw backup sqlite create` 한 줄** 꼭 챙기시고요. 무료 오픈소스(MIT)에 38만 6천 스타가 증명하듯 **가성비 좋은 AI 에이전트 찾는 분께 추천**드립니다. 다음 소식(8.2 베타, 정식 후보 등)이 나오는 대로 다시 정리해서 찾아오겠습니다.
