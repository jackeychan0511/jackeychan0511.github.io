MCP(Model Context Protocol)가 나온 지 2년입니다. 2024년 말 "AI 에이전트를 데이터가 있는 곳에 연결하는 표준"으로 시작한 이 규약은 이제 Claude 생태계의 배관이 됐습니다. 그런데 그동안 MCP 서버가 Claude에게 줄 수 있는 건 딱 하나였습니다. **도구(tool) 목록**입니다. "이런 함수를 호출할 수 있다"까지는 알려주지만, "이 상황에서는 이 순서로 이렇게 써라"는 노하우는 서버 바깥, 사람의 프롬프트나 스킬 문서에 남아 있었습니다.

2026년 11월 24일, 앤트로픽이 그 마지막 칸을 채웠습니다. **Skills over MCP 공개 베타**, **Tasks·Elicitation 정식 출시(GA)**, **File Uploads 예고**가 한 묶음으로 나왔습니다. MCP 2주년 기념 업데이트치고는 조용한 이름이지만, 실무 관점에서는 "에이전트가 서버와 일하는 방식"이 바뀌는 변화입니다.

## 한 줄 요약 — 도구만 주던 서버가 '매뉴얼'까지 준다

이번 업데이트의 핵심은 세 가지입니다.

| 구분 | 상태 | 무엇이 달라지나 |
|---|---|---|
| **Skills over MCP** | 공개 베타 | MCP 서버가 도구와 함께 스킬(절차·베스트프랙티스·플레이북)을 배포. Claude는 필요할 때만 로드 |
| **Tasks** | 정식 출시(GA) | 오래 걸리는 작업, 심지어 전체 에이전트 루프까지 서버가 백그라운드에서 수행 |
| **Elicitation** | 정식 출시(GA) | 결제·삭제 같은 위험한 동작 전에 서버가 폼·링크로 사용자 확인을 받고 이어서 진행 |
| **File Uploads** | 순차 배포 예정 | PDF·스프레드시트·이미지를 컨텍스트 윈도우를 거치지 않고 서버로 직접 전달 |

앤트로픽은 이 변화를 "Claude가 서버를 **또 하나의 에이전트처럼** 대하게 됐다"고 표현했습니다. 배우고, 위임하고, 입력과 파일을 주고받는 관계가 된 셈입니다.

## Skills over MCP — 설치 없는 '업무 매뉴얼 배포'

기존 방식의 한계는 명확했습니다. 도구 이름과 설명은 "무엇을 할 수 있는지"만 알려줍니다. "쇼핑몰 상품 페이지를 이 순서로 만들고, 가격 표기는 이 규칙을 따르고, 재고 문구는 이 톤으로" 같은 **하는 방법**은 담기지 않습니다. 그래서 사용자는 매번 프롬프트에 절차를 다시 적거나, 별도 스킬 파일을 설치해야 했습니다.

Skills over MCP는 이걸 서버 쪽으로 옮깁니다. 서버가 도구와 함께 스킬을 게시하면, Claude는 **해당 작업이 필요할 때만** 그 스킬을 불러옵니다. 상시 로드가 아니라 조건부 로드이기 때문에 컨텍스트 소모가 적고, 스킬은 서버와 함께 업데이트되므로 사용자가 따로 설치할 것도 없습니다.

공식 발표에 소개된 실제 사례는 이렇습니다.

- **Shopify** — 판매자의 온라인 스토어를 기획부터 수정까지 엔드투엔드로 설계·반영
- **HubSpot** — 신규 고객 온보딩과 Claude 환경 설정을 스킬로 안내
- **Atlassian** — 조직의 맥락을 깊게 끌어와 업무 분석·인사이트 도출
- **Carta** — 업로드한 문서를 바탕으로 지분 초안 작성·발행(준비 중)

여기서 실무적으로 중요한 포인트는 **배포 주체가 바뀐다**는 점입니다. 지금까지 "우리 팀만의 작업 규칙"은 각 사용자의 프롬프트나 로컬 스킬 폴더에 흩어져 있었습니다. Skills over MCP에서는 그 규칙이 **서비스 제공자의 제품 일부**가 됩니다. SaaS 회사가 자기 제품의 '올바른 사용법'을 MCP 서버에 실어 보내는 구조입니다.

적용 범위는 다음과 같습니다.

- Claude 및 Claude Code에서 **공개 베타**
- Pro·Max·Ultra 플랜은 **기본 활성화**
- Team 플랜은 **관리자가 켜야** 사용 가능
- Enterprise는 **추후 지원**
- Claude Code는 **v2.1.331 이상**과 지원 모델 필요

## Tasks — "끝날 때까지 기다리는" 구조에서 벗어나기

에이전트를 실무에 쓰다 보면 가장 자주 막히는 지점이 대기입니다. 기존 MCP 도구 호출은 **끝나야만** Claude가 다음으로 넘어갈 수 있었습니다. 리서치를 30번 돌리거나, 계정 데이터를 대량으로 긁어오는 작업은 그 시간 내내 대화가 멈춰 있는 것처럼 보였습니다.

Tasks는 이 제약을 풉니다. 서버가 시간이 걸리는 연산, 혹은 **전체 에이전트 루프**를 백그라운드로 돌리고, Claude는 다른 일을 계속하다가 결과가 준비되면 받아옵니다. 공식 사례는 ZoomInfo로, 여러 번의 프롬프트가 필요했던 계정·연락처 심층 리서치를 한 번의 위임으로 처리합니다.

![Tasks — Claude가 오래 걸리는 작업을 MCP 서버에 넘기고, 계속 다른 일을 하다가 결과가 준비되면 받아옵니다.](https://pub-a8e00ddf355f47339bd2e01ff3221de7.r2.dev/assets/images/posts/claude-skills-over-mcp-20261125/02-mcp-tasks-handoff.jpg)

*이미지: Anthropic 공식 제품 업데이트 자료(2026.11.24)*

이건 단순한 속도 개선이 아니라 **에이전트 설계 패턴의 변화**입니다. 지금까지는 "한 번의 대화 안에서 끝나는 일"만 자동화 후보였습니다. Tasks가 표준이 되면 "20분 걸리는 배치 작업을 던져두고, 그동안 다른 요청을 처리"하는 구성이 기본값이 됩니다. 업무 자동화 파이프라인을 운영하는 입장에서 가장 체감이 큰 부분입니다.

## Elicitation — 위험한 동작 앞에 '확인 게이트'를 세운다

자동화에서 진짜 무서운 건 실패가 아니라 **성공적으로 잘못 실행되는 것**입니다. 결제 승인, 데이터 삭제, 서비스 제거처럼 되돌릴 수 없는 동작을 에이전트가 자신 있게 밀어붙이면 사고가 됩니다.

Elicitation은 서버가 도중에 멈춰서 사용자에게 **폼이나 링크로 입력을 요청**하고, 답을 받은 뒤 원래 지점에서 이어서 진행하는 기능입니다. 정식 출시와 함께 공개된 사례가 성격을 잘 보여줍니다.

- **Supabase** — 유료 프로젝트 생성 전, 파괴적 SQL 실행 전에 비용·영향을 확인
- **Railway** — 서비스 제거처럼 되돌리기 어려운 변경 전에 승인 요청
- **GitHub** — 에이전트가 저장소를 삭제하기 전에 저장소 이름을 직접 입력하게 함

특히 GitHub 방식은 업계 표준에 가까운 패턴입니다. "정말 삭제하시겠습니까?" 체크박스가 아니라 **이름을 타이핑하게 만드는** 확인 절차죠. 자동화 파이프라인을 설계한다면 이 세 가지 사례를 그대로 참고할 만합니다. 사람이 개입할 지점을 '에러 났을 때'가 아니라 **'위험한 동작 직전'**으로 옮기는 것이 핵심입니다.

## File Uploads — 컨텍스트를 태우지 않는 파일 전달

아직 배포 전이지만 방향은 분명합니다. 지금은 파일을 분석하려면 파일 내용이 컨텍스트 윈도우를 통과해야 합니다. 계약서 PDF 30개를 다루면 그 자체로 토큰이 녹습니다.

File Uploads 확장은 PDF·스프레드시트·이미지를 **컨텍스트를 거치지 않고** 서버로 직접 보냅니다. 서버가 파싱·인덱싱하고 필요한 결과만 돌려주는 구조입니다. Pro·Max·Ultra와 조건을 충족하는 Team·Enterprise 플랜에 순차 배포될 예정입니다.

## 숫자로 보는 MCP의 현재

앤트로픽이 함께 공개한 생태계 지표는 다음과 같습니다.

- MCP SDK **월 7억 회 이상** 다운로드
- Claude용 MCP 커넥터 **1만 개 이상**
- **툴 검색(tool search)** — 필요한 도구 정의만 로드해 멀티 서버 환경에서 컨텍스트 사용량 **85% 이상 절감**
- 최신 MCP 스펙은 **무상태(stateless)** 구조로 Claude 제품 전반에서 지원
- **Enterprise Managed Auth** — 관리자가 한 번 승인하면 사용자는 자동 연결
- **MCP Apps** — 대화 옆 또는 전체 화면으로 인터페이스를 띄우는 확장

MCP는 이제 앤트로픽 단독 소유가 아니라 **Agentic AI Foundation**이 호스팅하는 오픈 표준입니다(앤트로픽이 2026년 10월 기부). 이번 기능들도 특정 클라이언트 전용이 아니라, 확장을 구현한 서버라면 **호환되는 어느 클라이언트에서든** 동작합니다. Skills over MCP는 SEP-2640으로 표준 확장 지위를 확보한 상태입니다.

## 영향 — 사용자와 개발자에게 각각 무엇이 달라지나

**일반 사용자 입장**에서 가장 큰 변화는 "설치"가 사라진다는 점입니다. 지금은 유용한 스킬을 쓰려면 파일을 받아 넣거나 프롬프트를 복사해야 합니다. 앞으로는 쓰던 커넥터가 업데이트되면서 그 서비스의 모범 사용법이 자동으로 따라옵니다. 반대로 말하면, **어떤 스킬이 로드됐는지 확인하는 습관**이 필요해집니다. 조직 정책이나 계정 맞춤 플레이북까지 스킬에 담길 수 있기 때문입니다.

**개발자·서버 운영자 입장**에서는 배포 단위가 바뀝니다. 도구 정의만 관리하던 서버가 이제 스킬 문서, 백그라운드 작업 큐, 사용자 확인 폼, 파일 수신 엔드포인트까지 책임집니다. 앤트로픽은 이 모든 걸 오픈 스펙과 확장으로 공개했고, 지원 방법은 각 기능의 문서에 정리해 두었습니다. 기존 서버에 얹는 순서를 정한다면 **Elicitation → Tasks → Skills** 순이 무난합니다. 확인 게이트가 먼저 있어야 백그라운드 작업을 안전하게 위임할 수 있고, 그 위에 절차 지식(스킬)을 얹는 구조가 자연스럽기 때문입니다.

**운영 관점의 주의점**도 분명합니다.

- 스킬은 서버와 함께 업데이트됩니다. 즉 **공급자가 내용을 바꾸면 사용자 환경도 바뀝니다.** Team·Enterprise는 활성화 정책과 변경 검토 절차를 먼저 정해야 합니다.
- Tasks는 편리하지만 **비용과 실패 지점이 대화 밖으로** 나갑니다. 백그라운드 작업의 재시도·타임아웃·로그 정책을 서버 쪽에서 직접 관리해야 합니다.
- Elicitation은 사용자 확인을 받는 만큼 **확인 피로**가 생깁니다. 모든 동작에 게이트를 세우면 아무도 자동화를 쓰지 않습니다. 결제·삭제·권한 변경처럼 되돌릴 수 없는 지점에만 거는 것이 정석입니다.

## 전망 — '도구 연결'에서 '에이전트 협업'으로

이번 업데이트를 한 문장으로 줄이면 이렇습니다. MCP는 **"함수 호출 규격"에서 "에이전트 간 협업 규격"으로** 넘어가고 있습니다. 스킬로 지식을 주고, Tasks로 일을 위임하고, Elicitation으로 승인을 주고받고, File Uploads로 자료를 건네는 흐름은 사람과 사람 사이의 업무 위임 방식과 놀랍도록 비슷합니다.

당장의 실무 효과는 Tasks와 Elicitation 쪽이 큽니다. 반면 Skills over MCP는 생태계가 얼마나 빨리 스킬을 채우느냐에 성과가 달려 있습니다. Shopify·HubSpot·Atlassian 같은 대형 서비스가 붙었다는 건 신호가 좋다는 뜻이지만, 공개 베타이고 Enterprise 지원은 아직 남아 있습니다. 도입을 검토한다면 베타 기간의 동작 변경 가능성을 전제로, **내부 서버 한두 개에 먼저 적용해 보는 것**이 안전합니다.

AI 에이전트를 실사용하는 팀이라면, 이제 체크리스트에 한 줄이 추가됩니다. "우리 도구는 연결됐나?"가 아니라 **"우리 업무 절차는 어디에 적혀 있고, 그걸 에이전트가 읽을 수 있나?"**입니다.

> 이 글은 앤트로픽 공식 제품 업데이트(2026년 11월 24일)와 Claude Code 체인지로그, MCP 표준 문서 등 공개 자료를 정리한 것입니다. 베타 기능의 지원 범위와 동작은 변경될 수 있습니다.
