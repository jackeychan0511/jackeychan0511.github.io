> **📌 한줄 요약:** 2026년 **10월 14일, OpenAI API 디프리케이션 페이지**에 **GPT-4o·GPT-4o mini·GPT-4.1·GPT-4.1 mini**가 **2027년 1월 14일자로 API에서 제거**된다는 공지가 올라왔습니다. 넷 다 **권장 대체 모델은 gpt-6-luna** 하나로 통일됐고, **파인튜닝 버전도 원본 모델과 같은 날 함께 종료**됩니다. 가격은 100만 토큰당 **입력 0.10달러·출력 0.50달러**(gpt-6-luna)로, GPT-4o의 **2.50달러·10달러**와 비교하면 **입력 기준 25분의 1 수준**입니다. 이제 남은 시간은 약 3개월입니다.

![OpenAI 워드마크 (출처: Wikimedia Commons, 퍼블릭 도메인)](/assets/images/posts/openai-gpt4-api-deprecation-20261014/openai-wordmark-2025-wikimedia.png)

API 위에서 서비스를 굴리는 분들이라면, 모델 하나가 사라지는 공지가 **"나중에 정리해야지" 목록에 들어가는 일**이 얼마나 무서운지 아실 겁니다. 특히 **오래된 모델을 그대로 붙여둔 자동화 파이프라인**은 공지가 뜬 시점에는 아무 증상이 없다가, **종료일 다음 날 아침에 조용히 죽어 있는** 경우가 많습니다. 이번 공지는 그 시계를 다시 돌려놓았습니다.

## 🗓️ 이슈 요약 — 10월 14일, 무엇이 공지됐나

OpenAI의 API 디프리케이션 페이지에는 **2026-10-14: GPT-4 series model deprecations** 항목이 최상단에 올라왔습니다. 공식 문구는 이렇습니다.

> "2026년 10월 14일, 특정 GPT-4 계열 모델을 사용하는 개발자에게 **2027년 1월 14일부로 API에서 디프리케이션 및 제거**된다는 사실을 통지했습니다."

| 종료일 | 모델 / 스냅샷 | 권장 대체 모델 |
|:---|:---|:---|
| 2027년 1월 14일 | GPT-4o (`gpt-4o-2024-08-06`, `gpt-4o-2024-11-20`) | `gpt-6-luna` |
| 2027년 1월 14일 | GPT-4o mini (`gpt-4o-mini-2024-07-18`) | `gpt-6-luna` |

공식 문서에 함께 적힌 한 줄이 실무에서 가장 중요합니다. **"이 모델들의 파인튜닝 버전은 원본 모델과 동일한 종료 일정을 따릅니다."** 즉 **베이스 모델만 교체하면 되는 게 아니라, 그 위에 올려둔 파인튜닝 모델까지 같이 재학습**해야 합니다.

## 🔍 상세 분석 — "3개월 유예"와 "가격이 20배 넘게 낮아진 대체 모델"

### 1) 통보 기간은 약 3개월

10월 14일 공지, 2027년 1월 14일 종료 — **정확히 3개월**입니다. OpenAI는 모델별로 3~6개월 수준의 사전 통보 기간을 두고 있으며, 실제로 같은 페이지에는 **6개월 통보로 2027년 4월 1일 종료되는 `gpt-5.1`·`gpt-5.3-codex`·`gpt-5.4-nano`** 항목도 함께 올라 있습니다. 이번 GPT-4 계열은 **상대적으로 짧은 3개월**을 받은 셈입니다.

### 2) 대체 모델이 하나로 통일됐고, 훨씬 싸졌다

이번 공지에서 눈에 띄는 부분은 **네 모델의 대체 모델이 전부 `gpt-6-luna` 하나**라는 점입니다. 표준 요금(100만 토큰당 입력/출력)을 비교하면 이렇습니다.

| 모델 | 입력 | 출력 |
|:---|---:|---:|
| **gpt-6-luna** (대체 모델) | **$0.10** | **$0.50** |
| GPT-4o | $2.50 | $10.00 |
| GPT-4.1 | $2.00 | $8.00 |
| GPT-4o mini | $0.15 | $0.60 |
| GPT-4.1 mini | $0.40 | $1.60 |

출처: OpenAI API 가격 페이지 및 마이그레이션 커버리지. `gpt-6-luna`의 **입력 0.10달러 / 출력 0.50달러**는 OpenAI 공식 가격표에서 확인되는 수치입니다.

숫자만 보면 **GPT-4o 대비 입력 25분의 1, 출력 20분의 1**입니다. "모델이 사라진다"는 공지인데 **비용은 오히려 크게 내려가는 구조**라는 게 이번 건의 특징입니다. 다만 OpenAI는 **gpt-6-luna와 GPT-4o 사이의 품질 비교 자료를 함께 내놓지 않았습니다.** 그래서 "싸졌으니 그대로 갈아끼우면 된다"는 판단은 위험합니다.

### 3) 10월은 이미 '디프리케이션의 달'

이번 공지는 10월에만 나온 첫 번째 종료 공지가 아닙니다. 같은 페이지 기준으로 **10월 1일에는 텍스트-음성(TTS) 모델군이 2027년 1월 6일 종료**, **`gpt-5.1`·`gpt-5.3-codex`·`gpt-5.4-nano`가 2027년 4월 1일 종료**로 각각 공지됐습니다. 그리고 **10월 23일에는 이전에 예고된 구형 스냅샷(`gpt-4o-2024-05-13`, `o4-mini` 등)이 실제로 종료**됩니다. **10월 한 달 동안 "예고"와 "실제 종료"가 겹쳐 돌아가는 상황**입니다.

## 🛠️ 개발자 영향 — 지금 해야 할 체크리스트

### ✅ 1. 모델 ID를 코드·설정에서 전부 뽑아낸다

가장 흔한 사고는 **코드가 아니라 설정 파일에 박힌 모델 ID**입니다. 환경변수, 배포 시크릿, 프롬프트 템플릿, 평가 스크립트까지 훑어야 합니다.

```
grep -rn "gpt-4o\|gpt-4.1" ./src ./config .env* 2>/dev/null
```

### ✅ 2. `shutdown_date` 필드로 자동 감시를 건다

OpenAI는 **List models 엔드포인트(`GET /v1/models`)** 응답에 **선택 필드 `shutdown_date`**를 제공합니다. 값이 있으면 `YYYY-MM-DD` 문자열, 없으면 `null`입니다. Retrieve a model 엔드포인트에서도 같은 값을 얻을 수 있습니다. **수동으로 공지 페이지를 읽는 대신, 이 필드를 주기적으로 폴링해 알림을 거는 방식**이 훨씬 안전합니다.

### ✅ 3. 파인튜닝은 "재학습 계획"이 별도로 필요하다

파인튜닝 모델은 **원본 모델과 같은 날 종료**됩니다. 실무 마이그레이션 가이드들은 **신규 파인튜닝 작업이 그보다 앞선 시점(2027년 1월 6일)에 막힌다**고 안내하므로, 데이터셋 정리 → 재학습 → 평가까지 **최소 한 달 이상의 버퍼**를 잡는 편이 안전합니다.

### ✅ 4. 회귀 평가는 "실제 트래픽"으로

가장 조용히 깨지는 건 **구조화 출력(JSON schema)과 도구 호출(tool calls)** 입니다. 모델이 바뀌면 형식은 맞는데 **의미가 미묘하게 달라지는** 케이스가 생깁니다. 실제 트래픽 로그를 그대로 흘려보내는 **회귀 평가 세트**를 돌려보고 판단하는 게 정석입니다.

## 👥 사용자 영향 — ChatGPT는 이미 넘어갔다

ChatGPT 쪽은 이미 정리 단계입니다. GPT-6 계열은 **무료·유료 플랜 전역으로 순차 롤아웃**되어 GPT-5.6 Sol·Luna를 대체하는 흐름이고, 10월 7일자 시스템 카드에서는 **GPT-6 Sol·Luna(10월 버전)** 가 사이버보안·생물화학 영역에서 **High 역량으로 분류**된 내용도 공개됐습니다.

정리하면 이렇습니다.

- **ChatGPT 사용자:** 지금 쓰는 화면이 곧 GPT-6 계열로 이동 중이라 **직접 할 일은 사실상 없음**
- **API 개발자:** 2027년 1월 14일까지 **모델 ID 교체 + 파인튜닝 재학습 + 평가**가 필요
- **자동화 파이프라인 운영자:** 조용히 죽는 걸 막으려면 **`shutdown_date` 모니터링을 먼저 붙이는 게 가장 효율적**

## 🔭 전망 — "모델 수명"을 자산으로 관리하는 시대

이번 공지가 시사하는 건 단순히 "GPT-4가 은퇴한다"가 아닙니다. **모델 ID가 1~2년 단위의 '수명'을 가진 자산이 됐고, 그 수명이 다하면 파인튜닝까지 함께 사라진다**는 운영 원칙이 자리 잡았다는 점입니다.

앞으로 실무에서 중요한 역량은 **"가장 좋은 모델을 고르는 능력"보다 "모델이 바뀌어도 버티는 구조를 만들어 두는 능력"** 쪽으로 옮겨갈 가능성이 큽니다. 모델 ID를 설정 한 곳에서 주입하는 구조, 프롬프트와 평가 세트를 분리해 두는 구조, 그리고 `shutdown_date` 같은 신호를 자동으로 감시하는 구조 — 이 세 가지가 사실상 **기본기**가 되는 흐름입니다.
