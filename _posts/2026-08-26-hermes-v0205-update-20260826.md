## 1. 요즘 저처럼 "크론잡이 자꾸 깜빡하면" 답답하시던 분들

요즘 저처럼 **AI 에이전트에 크론잡(자동 예약 작업)을 맡겨서 블로그 포스팅을 돌리시는 분들**, 많으시죠.

솔직히 지난주까지 저도 이랬습니다. 자정에 도는 크론잡이 **이전 실행에서 배운 걸 다음 실행에서 까먹고** 매번 처음부터 다시 컨텍스트를 쌓는 게 보이니까, "메모리는 있는데 왜 크론은 기억을 못 하지?"라는 생각이 들더라고요. 어제(8/25) Hermes Agent의 **Bot Mode**를 정리해드렸는데, 오늘 아침 GitHub 릴리스를 열어보니 그 직후 또 **패치 두 개(v0.20.4·v0.20.5)가 쏟아져 나와 있었습니다.** 사흘(8/16~8/19) 사이에 무려 **약 397개 PR**이요.

특히 릴리스 노트에 **"cron jobs gaining persistent memory"** — 크론잡이 영구 메모리를 얻는다는 문구가 보이길래, 이건 꼭 파야겠다 싶어서 오늘은 8월 3주차 패치를 실측 기준으로 총정리해드립니다. 보너스로 요즘 커뮤니티에서 난리인 **펫(Pet) 기능** 설치 가이드도 같이 넣었어요.

## 3. 핵심 업데이트 ① — 키리스 웹 티어: "설치하자마자 검색이 되네?"

### 어떤 기능인가

v0.20.5 릴리스 노트에서 제가 제일 먼저 눈여겨본 문장입니다.

> **"the keyless web tier (5-vendor free rotation with ring failover, web search on fresh installs with zero keys)"**
> — Hermes Agent v0.20.5 릴리스 노트 (2026.8.19)

번역하면 **"키 없는 웹 티어 — 5개 벤더 무료 로테이션 + 링 장애조치, 신규 설치에서 키 0개로 웹검색"**입니다.

### 실제 사용감/장점

솔직히 이건 **신규 사용자 경험을 확 바꾸는 변경**입니다. 예전엔 Hermes를 깔고 나서 검색을 쓰려면 OpenRouter든 뭐든 API 키를 넣고 프로바이더를 붙여야 했잖아요. 그런데 이제 **설치 직후 별도 키 없이도 웹검색이 도는 구조**가 생겼습니다. 그것도 한 벤더가 아니라 **5개 벤더를 무료 티어로 돌려가며(로테이션), 하나가 죽으면 링처럼 다음으로 넘어가는 장애조치(ring failover)**까지요.

크론잡 자동포스팅 입장에서도 이건 큽니다. 키 만료·잔액 부족으로 검색이 죽으면 크론잡 전체가 실패했는데, 링 장애조치가 그 리스크를 나눠주니까요.

### 단점/주의

- 무료 티어는 어디까지나 **"키 없이 바로 시작"**을 위한 온보딩용입니다. 헤비하게 쓰려면 여전히 자기 키/프로바이더를 붙이는 게 맞아요.
- 릴리스 노트에 "신규 설치(fresh installs)"라고 명시돼 있어서, **기존 설치를 업데이트만 한 경우**엔 적용 범위를 한 번 확인해보시는 게 좋습니다.

## 4. 핵심 업데이트 ② — 크론잡 영구 메모리: "이제 크론도 기억합니다"

### 어떤 기능인가

> **"cron jobs gaining persistent memory and per-job reasoning effort"**
> — Hermes Agent v0.20.5 릴리스 노트 (2026.8.19)

**크론잡이 영구 메모리를 얻고, 잡마다 추론 노력(reasoning effort)을 따로 설정**할 수 있게 됐습니다.

### 실제 사용감/장점

이게 왜 크론잡 운영자에게 감동인지 설명드릴게요. 제가 매일 도는 크론잡을 보면, **각 실행이 이전 실행의 기억을 이어받지 못해서** 같은 주제라도 매번 "너는 누구고 뭘 해야 하니"부터 설명해야 하는 느낌이 있었습니다. 이제 크론잡 단위로 영구 메모리가 붙으니, **"지난번에 이 주제를 여기까지 정리했으니 오늘은 그다음부터"** 같은 이어짐이 가능해집니다.

게다가 **잡별 reasoning effort** — "이 잡은 가볍게(빠르게), 저 잡은 깊게(비싸게)"를 잡마다 지정할 수 있는 건 비용 관리에서 꽤 쓸모 있습니다. 매일 도는 요약 잡은 라이트하게, 주간 심층 리포트 잡은 헤비하게 — 이렇게 나누면 토큰 비용이 꽤 아껴집니다.

![Hermes Agent 메모리 기능 이미지](/assets/images/posts/hermes-v0205-update-20260826/hermes-feature-memory.webp)
*Hermes Agent의 메모리 기능 — 에이전트가 경험에서 스킬을 만들고, 지식을 저장하고, 과거 대화를 검색하는 학습 루프가 v0.20.5부터 크론잡 단위로도 적용된다 (출처: hermes-agent.nousresearch.com 공식 홈페이지, 2026-08-26 확인)*

### 단점/주의

- 릴리스 노트는 "v0.21.0에서 전체 큐레이티드 노트가 나온다"고 하니, **영구 메모리의 정확한 활성화 조건·설정 키는 공식 문서의 크론/자동화 섹션을 따라가며 확인**하시는 걸 추천합니다.
- 메모리가 쌓이면 잡의 컨텍스트가 커지므로, 라이트한 잡엔 오히려 메모리 사용을 끄는 게 나을 수도 있어요.

## 5. 핵심 업데이트 ③ — 업데이트 가이드: `hermes update` receipts와 worktree

### 어떤 기능인가

v0.20.5에 업데이트·작업트리 명령이 대거 다듬어졌습니다.

```bash
# 1) 업데이트 + 영수증 확인 — 뭐가 바뀌었는지 업데이트 후 바로 보여줌
hermes update

# 2) 플릿(여러 머신)을 미리 검증만 하고 싶다면
hermes update --plan

# 3) 저장소 작업트리 관리
hermes worktree list
hermes worktree prune

# 4) 문제 생기면 진단
hermes doctor
```

### 실제 사용감/장점

**`hermes update` receipts**는 업데이트 후 "무엇이 설치·변경됐는지"를 영수증처럼 남겨주는 기능입니다. 저처럼 크론잡이 돌고 있는 머신을 업데이트할 때, **"이 버전에서 뭐가 바뀌었는지"를 버전만으로는 알 수 없던 답답함**이 있었는데, 영수증이 그 공백을 메워줍니다. **플릿 `--plan`**은 여러 대의 머신(예: 집 데스크톱 + VPS)을 일괄 관리할 때 **실제 적용 전에 검증만** 해볼 수 있어서, "한 대에서 문제 터지면 전부 영향"을 피할 수 있어요.

**`hermes worktree list/prune`**은 git worktree 관리인데, 저처럼 브랜치 여러 개를 오가며 실험하다가 정리 안 된 워크트리가 쌓이는 분들에게 유용합니다.

### 단점/주의

- receipts·`--plan`은 v0.20.5에서 막 들어온 기능이라, 구버전을 쓰는 머신에선 명령이 없을 수 있습니다. **일단 `hermes update`로 최신판을 만든 뒤** 쓰시면 됩니다.
- worktree 명령은 git에 익숙한 분을 위한 기능이라, 초보자라면 굳이 안 써도 됩니다.

## 6. 보너스 — 펫(Pet) 기능: "3,200종 스프라이트를 한 줄로 입양"

### 어떤 기능인가

8월 들어 커뮤니티에서 가장 즐거운 화제였던 **펫 기능**도 이번 주 패치로 데스크톱 연동이 더 단단해졌습니다. 공식 문서 정의부터 보겠습니다.

> **"Pets are purely cosmetic. They have no effect on prompt caching, tokens, or the agent's behavior — the sprite is a display concern only."**
> — Hermes Agent 공식 문서 (Pets)

**"펫은 순수 장식이다. 프롬프트 캐싱·토큰·에이전트 행동에 아무 영향이 없다."** — Decrypt(6/24)의 표현대로 **"아무것도 안 하지만, 그래서 모두가 좋아하는"** 기능입니다.

- **3,200여 종**(petdex.dev 갤러리 기준 4,568+개)의 오픈소스 애니메이션 스프라이트
- 에이전트 상태를 **6가지 애니메이션**으로 매핑 — 도구 실행 중 `run`, 모델 사고 중 `review`, 턴 종료 `wave`, 플랜 완료 `jump`(축하), 실패 `failed`, 대기 `idle`
- **CLI·TUI·데스크톱** 모두 지원, 데스크톱에선 투명 **항상-위(always-on-top) 플로팅 창**으로 빼낼 수 있고 말풍선("working…", "thinking…")과 완료 시 메일 아이콘 표시

### 설치 가이드 (실측)

```bash
# 1) 갤러리 둘러보기 (필터 검색 가능)
hermes pets list
hermes pets list cat

# 2) 보바(boba) 입양 + 즉시 활성화
hermes pets install boba --select

# 3) 터미널에서 미리보기/애니메이션 (Ctrl+C로 종료)
hermes pets show
```

## 7. 솔직한 장단점 총정리

### 👍 이건 꼭 써보세요

- **키리스 웹 티어** — 신규 설치/세팅이 확 쉬워졌습니다. 진입 장벽이 하나 사라진 셈
- **크론 영구 메모리 + 잡별 reasoning effort** — 자동화를 오래 돌리는 사람에겐 이번 주 최고의 선물
- **`hermes update` receipts / `--plan`** — 업데이트 사고를 줄여주는 안전망

### 👎 아직은 글쎄

- 정식 큐레이티드 릴리스 노트는 **v0.21.0**에서 나옵니다. 지금은 패치 노트의 요약문으로만 판단해야 하는 부분이 많아요
- 펫 기능은 **생산성과 무관** — 감성용입니다
- 기존 설치 사용자는 키리스 티어가 자동 적용되는지 **직접 확인** 필요

## 8. 마무리 — 업데이트 한 줄이면 끝, 가성비 좋은 AI 에이전트 찾는 분께 추천

정리하면, 이번 8월 3주차 패치는 **"쓰던 사람을 더 편하게"** 만드는 업데이트였습니다. 크론잡을 돌리는 저 같은 사용자에겐 **영구 메모리**가, 새로 시작하는 분들에겐 **키리스 웹 티어**가, 관리자에겐 **update receipts·worktree**가 각각 반가웠을 겁니다.

업데이트는 아래 한 줄이면 끝입니다.

```bash
hermes update
```

Hermes Agent는 **MIT 라이선스의 무료 오픈소스**라 비용 부담 없이 시작할 수 있고, GitHub 스타 18만 개가 증명하듯 커뮤니티도 활발합니다. 다만 **"이번 주 패치로 뭐가 달라졌는지"는 v0.21.0 정식 노트가 나올 때까지 공식 문서를 함께 확인**하시는 걸 추천드려요.

솔직히 저는 이번 주에 Bot Mode(팀 기능)와 이번 패치(운영 편의)를 연달아 보고 나니, "오픈소스 에이전트가 이 속도로 달라져도 되나?"라는 생각이 듭니다. **자동화를 직접 돌려보는 재미**를 느끼고 싶은 분, 그리고 **가성비 좋은 AI 도구**를 찾으시는 분께 Hermes Agent 추천합니다.
