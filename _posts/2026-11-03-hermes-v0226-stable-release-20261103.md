밤에 배치를 걸어두고 아침에 결과만 확인하는 방식으로 자동화 파이프라인을 운영하다 보면, 릴리스 소식이 반가우면서도 한편으로는 조심스러워집니다. 기능이 늘어나는 건 좋은데, **작업이 중간에 멈췄을 때 그 사실을 어떻게 알아채는가**가 여전히 애매하게 남아 있기 때문입니다. 스케줄러가 돌긴 돌았는데 결과가 비어 있는 상황은 로그를 뒤지기 전까지 눈에 잘 띄지 않으니까요.

2026년 11월 2일, 노우스 리서치(Nous Research)가 헤르메스 에이전트 **v0.22.6 안정판**을 배포했습니다. 이름만 보면 소소한 패치 같지만, 릴리스 노트를 열어보면 성격이 다릅니다. v0.22.5 이후 쌓인 변경을 한 덩어리로 묶은 **롤업 릴리스**이고, 그 규모가 **3,448개 커밋·776개 PR·385개 이슈**입니다.

> **📌 한줄 요약:** v0.22.6은 "패치"라는 이름의 **대형 롤업 릴리스**입니다. 게이트웨이가 직접 웹앱을 서빙하고(네트워크·커스텀 URL 접속), `hermes cron cancel`과 작업별 미실행 정책이 들어왔으며, 스킬에 자율 쓰기 잠금을 걸 수 있게 됐습니다. 반면 **데스크톱 설치본(.exe/.dmg)은 이번 릴리스로 갱신되지 않습니다.** 상세 큐레이션 노트는 v0.23.0에서 나옵니다.

## 2. 업무 자동화에 실제로 영향이 있는 변경

여기부터는 자동화 파이프라인을 운영하는 관점에서, 릴리스 노트에 언급된 항목 중 **체감이 큰 것**만 골라 정리합니다.

### 2-1. 게이트웨이가 직접 웹앱을 서빙한다 — `hermes webapp`

가장 눈에 띄는 항목입니다. 게이트웨이 리스너에서 **웹앱을 직접 서빙**할 수 있게 됐고, 데스크톱에는 **Web Access 패널**이 생겼습니다. 이걸로 데스크톱 앱을 띄워둔 기기에서만 작업을 볼 수 있었던 제약이 줄어듭니다. 사내 네트워크나 직접 소유한 URL로 열 수 있고, **Nous 로그인 뒤에 두는 구성**도 지원합니다.

여기에 **데스크톱 플러그인이 브라우저 탭에서 로드**되는 변경까지 붙습니다. 원격 서버에 에이전트를 두고 노트북·태블릿에서 상태를 확인하는 구성이라면, 이번 릴리스가 실질적인 사용성 변화입니다.

### 2-2. 크론 작업을 중간에 세울 수 있다 — `hermes cron cancel`

스케줄러를 쓰는 쪽에서 오래 아쉬웠던 부분입니다.

- **`hermes cron cancel`** — 잘못 걸어둔 작업을 CLI에서 취소
- **작업별 미실행(missed-run) 정책** — 실행 시점을 놓쳤을 때 어떻게 처리할지 작업 단위로 지정
- **데스크톱 크론 편집기의 Stop 버튼** — 돌고 있는 작업을 화면에서 정지

미실행 정책이 생겼다는 건, 그동안 "놓치면 그냥 건너뛰는" 동작 하나로 고정돼 있던 부분을 **작업 성격에 따라 다르게 가져갈 수 있게 됐다**는 의미입니다. 하루 한 번 도는 집계 작업과 5분마다 도는 감시 작업은 놓쳤을 때 원하는 처리가 다르니까요.

### 2-3. 스킬에 자율 쓰기 잠금 — per-skill locks

에이전트가 스스로 스킬을 만들고 고치는 구조는 강점이지만, 검증된 스킬이 실행 중에 몰래 바뀌는 건 자동화에서는 리스크입니다. 이번 릴리스로 **스킬 단위로 자율 쓰기를 잠글 수 있게** 됐고, 데스크톱 **Capabilities 패널**에서 설정합니다.

운영 규칙을 스킬로 고정해두고 쓰는 경우라면, "내가 검증한 그 버전"이 유지된다는 보장이 생긴 셈입니다.

### 2-4. 세션 상태를 건드리지 않는 조작들

- **`/model reset`** — 세션의 모델 고정을 **히스토리 손실 없이** 해제. 모델을 잘못 골라 세션이 꼬였을 때 대화를 버리지 않아도 됩니다.
- **`/delegation` 선택 저장** — 위임 설정이 **다음 세션까지 유지**됩니다. 매번 다시 고르지 않아도 됩니다.
- **opt-in 사전 압축(`compression.prepare_ahead`)** — 컨텍스트 압축을 미리 준비해 두는 옵션. 긴 세션에서 응답이 끊기는 체감을 줄이는 방향입니다.
- **`pre_llm_call` 훅** — 추론 **전에** 턴을 차단할 수 있는 훅. 특정 조건에서 모델 호출 자체를 막는 가드레일을 코드로 걸 수 있습니다.

### 2-5. 보안·마이그레이션 쪽 변경

- **vault 키의 OS 키체인 저장(opt-in)** — macOS 키체인 등 OS 수준 저장소에 키를 둘 수 있습니다.
- **플러그인 카탈로그의 `requires_hermes` 설치·업데이트 시 강제** — 구버전에서 호환되지 않는 플러그인이 조용히 깔리는 상황을 막습니다.
- **`hermes migrate`** — Grok Bot·OpenBot 사용자를 헤르메스로 옮기는 경로가 셋업에 포함됐습니다.

### 2-6. 메신저·데스크톱 자잘한 개선

| 영역 | 변경 |
|:---|:---|
| 데스크톱 | 그룹 채팅 이름 변경·해산, 멘션, 첨부 붙여넣기 / 프로필별 사이드바 섹션 |
| Telegram | 비디오 노트 지원 |
| Slack | 스레드 컨텍스트에 이모지 반응 포함 |
| 음성 | `text_to_speech`에서 **에이전트가 ElevenLabs 목소리 선택** |
| 패키지 매니저 | 이어받기 가능한 다운로드 |

## 3. 솔직히, 이번 릴리스의 함정

장점만 적으면 반쪽짜리 정리가 됩니다. 실제로 업데이트 전에 걸리는 지점은 이렇습니다.

**첫째, 데스크톱 설치본은 이번에 안 바뀝니다.** 릴리스 노트에 명시되어 있습니다. Microsoft Store 앱은 스토어로 갱신되고, **설치 파일(.exe/.dmg)로 깐 데스크톱 앱은 다음 번들 릴리스까지 그대로**입니다. 데스크톱 UI에서 새 기능을 기대하고 업데이트를 눌렀는데 변화가 없다면, 그건 버그가 아니라 배포 방식 차이입니다.

**둘째, "패치"인데 규모가 메이저급입니다.** 776개 PR이 한 번에 들어왔다는 건, 그만큼 **동작이 미세하게 달라진 지점이 많다**는 뜻입니다. 자동화 파이프라인을 운영 중이라면 업데이트 직후 며칠은 배치 결과를 평소보다 자주 들여다보는 편이 안전합니다.

**셋째, 문서가 아직 요약 단계입니다.** 상세 노트가 v0.23.0으로 예고되어 있어, 지금 시점의 정보로 "이게 최종 스펙"이라고 단정하기는 어렵습니다. 설정 키 이름이나 기본값이 다음 릴리스에서 정리될 여지가 있습니다.

**넷째, 웹앱 노출은 설정 문제입니다.** 게이트웨이가 웹앱을 서빙하고 네트워크 접근을 허용하는 구조이므로, **인증을 켜지 않은 채 외부에 열어두는 구성은 피해야** 합니다. Nous 로그인 뒤에 두는 옵션이 제공되는 이유이기도 합니다.

## 4. 업데이트 전 확인할 것 — 실무 체크리스트

업무 자동화를 돌리는 입장에서, 이번 릴리스는 **"기능이 늘었다"보다 "운영 방식이 조금 더 통제 가능해졌다"** 로 읽는 게 정확합니다. 적용 전에 확인할 항목을 정리하면 다음과 같습니다.

1. **배포 채널 확인** — CLI는 `hermes update` 또는 설치 스크립트 재실행, Docker·클라우드는 `nousresearch/hermes-agent:stable`(또는 `:latest`). 데스크톱 설치본은 이번 대상이 아닙니다.
2. **크론 작업 목록 백업** — 미실행 정책이 작업 단위로 바뀌었으니, 기존 작업이 어떤 동작을 갖는지 먼저 확인해 두는 편이 좋습니다.
3. **스킬 잠금 대상 선정** — 운영 규칙이 담긴 스킬부터 잠그고, 실험용 스킬은 열어둡니다.
4. **웹앱 접근 범위 결정** — 내부 네트워크만인지, 인증 뒤 외부 공개인지 먼저 정한 뒤 켭니다.
5. **vault 키 저장 위치 결정** — OS 키체인 저장을 쓸지, 기존 방식을 유지할지 정합니다.
6. **업데이트 직후 배치 결과 확인** — 최소 2~3회 주기는 로그까지 확인하는 편이 안전합니다.

## 5. 정리 — v0.23.0을 기다릴 이유

이번 v0.22.6은 **"기다리던 기능이 한 번에 도착한 릴리스"** 라기보다, **v0.23.0을 위한 정리된 바닥**에 가깝습니다. 실제로 노트 자체가 "상세한 큐레이션 노트는 v0.23.0에서"라고 못 박고 있으니, 큰 그림은 다음 릴리스에서 완성됩니다.

그래도 지금 업데이트할 이유는 분명합니다. **크론 취소·미실행 정책·스킬 잠금**은 자동화를 오래 돌릴수록 아쉬웠던 통제 기능이고, **웹앱 접근**은 원격 운영의 편차를 줄여줍니다. 반대로 데스크톱 UI 변화를 기대한다면 이번엔 해당 사항이 없으니, 다음 번들 릴리스를 기다리는 게 맞습니다.

스케줄러를 돌리며 "작업이 멈췄는지 어떻게 알지"가 늘 걸렸던 분들이라면, 이번 릴리스에서 그 답이 조금 선명해졌습니다. 화면에 멈춤 버튼이 생기고, 놓친 실행을 어떻게 할지 정할 수 있게 됐다는 건 생각보다 큰 차이입니다.
