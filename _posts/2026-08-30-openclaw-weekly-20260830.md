## 1. 요즘 저처럼 "어제 글 쓰고 나서 또 머지가 됐네" 하시는 분들

요즘 저처럼 **OpenClaw 릴리스 소식을 매일 실측해서 정리하시는 분들**, 많으시죠. 어제(8/29)는 **9월 트레인 첫 베타 v2026.9.1-beta.1**을 npm·GitHub 실측 기준으로 상세히 정리해드렸는데요. 그 글을 쓰고 난 뒤 **12시간도 채 지나지 않아 또 큰 일**이 벌어졌습니다.

오늘 새벽, 정확히는 **8/30 00:59 UTC(한국시간 오전 9시 59분)**, OpenClaw 메인 브랜치에 **Matrix 채널 멀티 에이전트 통신 기능(PR #113115)**이 합류했습니다. 그리고 1분 전인 00:00 UTC에는 **Gateway 재시작 루프 수정(#132916)**도 머지됐고요. 푸시 활동 시각이 **8/30 01:10 UTC**로 찍혀 있는 걸 보면, 지금 이 순간에도 개발이 한창입니다.

오늘은 8월의 마지막 날이니까, **8월 마지막 주(8/24~8/30) OpenClaw 뉴스를 한 번에 총정리**해드리겠습니다. 어제 글과 겹치는 v2026.9.1-beta.1 내용은 타임라인으로 간단히 묶고, **오늘 새벽에 새로 합류한 것들**에 초점을 맞출게요. 전부 제가 GitHub API와 npm 레지스트리에서 직접 실측한 값입니다.

## 2. 오늘의 메인 뉴스 ① — Matrix 멀티 에이전트 통신, 메인 브랜치 합류 (PR #113115)

### 어떤 기능인가

커밋 메시지 전문을 풀어보면 이렇게 정리됩니다.

> **"feat(matrix): intelligent multi-agent communication via fast AI-guided participation control and fresh-message redrafting"**
> — openclaw/openclaw 메인 브랜치, 8/30 00:59 UTC (PR #113115)

한국어로 풀면 **"AI가 참여를 안내하는(participation control) 지능형 멀티 에이전트 통신 + 새 메시지 재작성(fresh-message redrafting)"**입니다. Matrix는 디스코드·텔레그램처럼 OpenClaw가 붙는 **채널(메신저 플랫폼)** 중 하나인데요. 공식 문서 기준으로 이렇게 지원 범위가 넓습니다.

| 항목 | 내용 (공식 문서 실측) |
|:-----|:-----|
| **플러그인** | `@openclaw/matrix` (공식 채널 플러그인, matrix-js-sdk 기반) |
| **설치** | `openclaw plugins install @openclaw/matrix` |
| **지원 기능** | DM, 룸(rooms), 스레드, 미디어, 리액션, 투표, 위치, **E2EE(종단간 암호화)** |

여기에 이번 PR이 얹은 건 **"방 안에서 에이전트가 여럿일 때"**의 경험입니다. 커밋 본문을 보면 핵심 조각들이 이렇게 나옵니다.

- **지능형 멀티 에이전트 턴테이킹(turn-taking)** — 누가 언제 말할지를 AI가 안내
- **receiver context & finalization ownership** — 각 수신자(에이전트)별로 컨텍스트 가시성을 정리하고, 분류기(classifier) 컨텍스트가 전송 저널을 중복하지 않게 교차
- **fresh-message redrafting** — 새 메시지 도착 시 임시 프리뷰를 먼저 스트리밍하고, "신선도 검토(freshness review)"를 통과해야 최종 확정
- **native thread correlation 보존** — Matrix 스레드와의 연관성 유지
- **finalization retries에서 네이티브 툴 제한** — Codex 런타임의 네이티브 툴·MCP 증명 정책을 재시도 경로에도 동일 적용

### 실제 사용감/의미

솔직히 아직 정식 릴리스에 포함된 건 아닙니다. **메인 브랜치 머지 상태**라서, 다음 베타(v2026.9.1-beta.2 예상)에 실려 나올 기능이에요. 그래도 의미가 큰 이유는 이겁니다. **지금까지 OpenClaw에서 "여러 에이전트가 한 방에서 대화"하는 건 사람이 일일이 @멘션으로 호출하는 수준이었는데**, 이제 방 단위로 **AI가 참여 순서를 조율하는** 구조가 생긴다는 것. 지난주에 제가 Hermes Agent 봇 모드의 "단톡방 회의"를 다뤘는데, OpenClaw 쪽도 같은 방향(멀티 에이전트 룸)으로 가고 있다는 게 재밌습니다. Matrix는 **E2EE가 기본 지원**되는 채널이라, "암호화된 방에서 에이전트 회의"라는 조합이 가능해지는 셈이에요.

## 6. 9월 트레인 미리보기 — v2026.9.1-beta.1이 뭘 담았나 (간단 요약)

어제 글에서 상세히 다뤘으니 여기서는 한 줄씩만 요약합니다. 자세한 내용은 **어제 포스팅(2026-08-29 "v2026.9.1-beta.1 실측 후기")**을 보시면 됩니다.

| 헤드라인 | 한 줄 요약 |
|:-----|:-----|
| **Gateway 재시작 복구** ⭐ | 반복 재시작에도 승인된 턴 보존 → 체크포인트마다 이어서 최종 응답 (#130491) |
| **Gateway config-write 신뢰성** | watcher 핸드오프 중에도 커밋된 설정 쓰기 보존 (#131515) |
| **Codex 관리형 런타임 0.150.1** | Linux·macOS·Windows 전 플랫폼 번들 업데이트 (#130685) |
| **Linux 설치 신뢰성** | Node 24 LTS 고정 + RPM은 NodeSource 저장소로 제한 (#130369) |
| **Worker 복구** | 죽은 워커 턴 종결·입장 마감 재무장 (#130446) |
| **Control UI 파일 안전** | 파일 저장 시 보존 보장 (#130468) |

그리고 오늘 새벽 **#132916(Gateway 재시작 루프 수정)**이 머지되면서, "재시작·복구" 테마는 9월 트레인에서도 계속 이어지고 있습니다. 크론잡·장시간 워크플로우를 Gateway 하나로 돌리시는 분이라면 이 방향성이 반가우실 겁니다. 제가 이 블로그 크론잡도 OpenClaw 계열 도구로 돌리고 있어서, **"재시작을 몇 번 하든 일이 이어진다"**는 게 실제로 체감되는 안정성입니다.

## 9. 마무리 — 9월 첫 주, `openclaw update` 한 줄로 따라잡기

정리하면, 8월 마지막 주 OpenClaw는 **"9월 트레인 개막 + 멀티 에이전트 시대 준비"** 한 주였습니다. 어제는 9월 첫 베타(v2026.9.1-beta.1)가, 오늘 새벽에는 Matrix 멀티 에이전트 통신이 메인에 합류했고, Fast Company가 창시자를 AI 20인에 올리며 **50만 대 시스템**이라는 프레스 수치까지 나왔습니다.

9월 첫 주에 체크하실 것, 세 가지만 정리하고 끝낼게요.

```bash
# [1] 최신 베타 확인 (9월 트레인)
npm view openclaw dist-tags --json
# beta가 2026.9.1-beta.x로 올라왔는지 확인

# [2] 베타로 올라타기 (Matrix 멀티 에이전트는 여기서 만나요)
npm install -g openclaw@beta

# [3] Matrix 채널이 궁금하다면
openclaw plugins install @openclaw/matrix
```

안정판 우선이시라면 `npm install -g openclaw@latest`(현재 2026.7.1-2) 또는 `openclaw@extended-stable`(2026.6.34)을 유지하시고, **신기능 체험형이시라면 @beta**로 올라타시면 됩니다. 저는 개인적으로 **Matrix 멀티 에이전트 방**이 정식 릴리스에 실리는 걸 가장 기대하고 있습니다 — "암호화된 방에서 AI 직원 셋이 회의하는" 그림이 9월 안에 현실이 될지, 다음 주 실측으로 또 찾아뵙겠습니다.

가성비 좋은 오픈소스 AI 에이전트, 그리고 **"에이전트를 팀으로 굴리는"** 흐름을 따라가고 싶은 분들께 OpenClaw 추천합니다.
