## AI 에이전트를 실사용하는 분들, 이번 릴리스는 체급이 다릅니다

자동화 파이프라인을 운영하거나, 서버에 상주하는 AI 에이전트를 업무에 붙여 쓰는 분들이라면 최근 흐름이 조금 답답했을 겁니다. 기능은 계속 늘어나는데, "처음 설치한 사람이 첫 대화까지 도달하는 길"과 "내 PC 안에서 모델을 돌리는 길"은 여전히 험했습니다. API 키부터 발급받고, 파이썬 환경 잡고, GPU 맞는 빌드를 찾아 헤매야 했으니까요.

그런데 2026년 10월 13일, Nous Research가 **Hermes Agent v0.22.0 — "The Threshold Release"**를 배포했습니다. 10월 14일 UTC 기준으로 각 IT 매체에 일제히 실렸고, 릴리스 노트 표현을 그대로 옮기면 **"프로젝트가 지금까지 내보낸 가장 큰 창(window)"**입니다. v0.21.0 사이클의 약 2.5배 규모라고 하니, 단순 패치가 아니라 세대 교체급입니다.

![Hermes Agent 공식 홈페이지 대표 이미지](/assets/images/posts/2026-10-15-hermes-v0220-threshold-release-20261015/hermes-v0220-official-hero.webp)

규모만 보면 이렇습니다. **약 24,200 커밋, 6,080개 머지 PR, 15,600개 파일 변경, 약 7,180개 이슈 종료, 약 2,520명 기여자.** 이번 한 번의 릴리스가 v0.21.1부터 v0.21.7까지의 패치 릴리스를 전부 흡수·문서화했습니다. 숫자만 봐도 "이슈급"이라는 게 바로 이해됩니다.

그럼 업무 자동화에 실질적으로 영향이 있는 부분만 골라 정리해 보겠습니다.

## 1. 키 없이 시작하는 첫 실행 — 가이드 온보딩과 무료 체험 모델

가장 체감이 큰 변화입니다. **한 번도 Hermes를 써본 적 없는 컴퓨터에서 데스크톱 앱을 열면, 설정 화면 대신 짧은 "설정 대화(setup chat)"가 시작됩니다.** 카드 한 장씩 이름, 강조 색, 레이아웃, 연결할 앱, 설치할 플러그인을 물어보고, 마지막에 맞춤형 첫 작업 4개까지 제안합니다.

이게 중요한 이유는 **API 키가 없어도 첫 대화가 가능**하다는 점입니다. 무료 체험 모델 `nous/welcome`(OS 사용자당 1회)로 돌아가기 때문에, 신규 사용자는 키 발급 전에 에이전트와 대화를 시작할 수 있습니다. 나중에 `hermes auth upgrade`나 채팅창의 `/login`으로 무료 신원을 정식 Nous 계정으로 승격하면, 연결해 둔 앱까지 그대로 유지됩니다.

솔직히 말하면, 온보딩 자체는 기존 설치본이나 원격(SSH·URL·Cloud) 백엔드에는 자동 적용되지 않습니다. 예전 설정 프로필 흐름과 `/initiate-setup` 명령은 삭제됐으니, 기존 사용자라면 "왜 안 뜨지?" 하고 헤매지 마시길. 데스크톱에서 **Settings → Run onboarding again**으로 다시 부를 수 있습니다.

덤으로 에이전트가 앱 테마를 직접 바꾸는 `set_theme` 도구가 생겼습니다. "보라색으로, 다크 모드" 하면 바로 반영됩니다. 사소해 보이지만 매일 쓰는 사람에겐 은근히 편합니다.

## 2. 앱 커넥터 — Linear·Notion을 에이전트가 직접 다룹니다

두 번째는 **커넥터(Connectors)**입니다. 이제 Hermes가 Nous 툴 게이트웨이를 통해 **Linear, Notion 같은 호스티드 앱 안에서 직접 동작**합니다. 앱을 요청하고 브라우저에서 한 번 로그인하면, 같은 턴 안에서 그 도구들을 바로 쓸 수 있습니다.

업무 자동화 관점에서 이게 왜 크냐면, **"이슈 만들어줘 → 노션 페이지에 정리해줘"** 같은 크로스 앱 워크플로가 별도 연동 스크립트 없이 가능해지기 때문입니다. 시작할 때 Nous 계정조차 필요 없고, 처음 앱을 쓸 때 커넥터 전용 무료 신원이 자동 생성됩니다.

데스크톱에는 호스티드 앱과 로컬 MCP 서버를 한 목록으로 보여주는 **Connectors 페이지**가 새로 생겼고(기존 MCP 탭을 대체), TUI·CLI에도 같은 설정 카드가 나옵니다. 한 앱의 **여러 계정(예: `work`·`home`)을 이름 붙여 동시 연결**하고 `/connectors` 또는 `hermes connectors`로 관리할 수 있습니다. 개인 워크스페이스와 회사 워크스페이스를 오가는 분들이라면 이게 제일 반가울 겁니다.

커넥터 도구는 로컬 파일을 첨부로 보내거나 반환된 파일을 저장할 수도 있습니다. 회사 정책상 끄고 싶다면 `tools.connectors.enabled: false`, 게스트 신원을 막으려면 `nous.guest: false`로 설정하면 됩니다.

## 3. 원클릭 로컬 모델 — 데이터를 밖으로 안 보내고 돌립니다

개인정보·보안 때문에 **"모델을 내 하드웨어 안에서만 돌리고 싶다"**는 요구는 계속 커지고 있었습니다. v0.22.0은 이걸 **클릭 한 번**으로 바꿔놨습니다.

하드웨어에 맞는 llama.cpp 엔진(CPU·CUDA·Metal·Vulkan·ROCm)을 자동으로 설치·유지하고, 카탈로그의 모든 모델을 내 GPU·RAM 기준으로 평가해 **딱 맞는 최고 품질 빌드를 골라줍니다.** 다운로드는 일시정지·재개가 되고, 서버는 Hermes와 함께 시작·종료됩니다. **계정도, API 키도 필요 없습니다.**

- 시작 경로: **Settings → Providers → Local Models** (Windows·macOS·Linux), 또는 터미널에서 `hermes model` → **Local models**
- 카탈로그: **Qwen3.8 27B, Qwen3.8 Flash Next(MTP 투기 헤드 포함), Qwen3.6 35B-A3B, DeepSeek V4 Flash**, 그리고 Hugging Face의 모든 GGUF
- GPU 지원 확대: NVIDIA(Linux)는 CUDA, AMD·Intel은 자체 메모리에 맞춘 Vulkan, 모든 백엔드가 llama.cpp b11370

추천 로직도 영리해졌습니다. **GPU 메모리에 완전히 올라가는 모델만 추천**하고, 27B는 성능이 잘 안 나오는 하드웨어에서는 아예 빼버립니다. Qwen3.8 Flash Next의 MTP 헤드는 128GB 머신에 맞춰졌습니다.

참고로 2순위/3순위 이미지 검색까지 동원해 봤지만, 이 릴리스 자체를 찍은 별도 실사진은 없고 공식 배포 자산이 가장 정확했습니다. 아래 릴리스 대표 카드도 공식 og 이미지입니다.

## 4. 테스트된 SemVer 안정 채널 — 업데이트가 "반쯤 적용"되지 않습니다

운영 관점에서 조용하지만 중요한 변화입니다. **이제 Hermes는 테스트를 통과한 SemVer 릴리스로 나옵니다.** 모든 릴리스는 소스 CI, Docker, Nix, 서명된 데스크톱 빌드, 전 OS 설치·업그레이드 검증을 통과한 뒤에야 퍼블리시됩니다.

그리고 **소스 설치본은 기본적으로 `main`의 모든 커밋을 따라가지 않고 릴리스 간 이동**합니다. 최신 개발판을 원하면 `hermes update --set-channel main` 또는 Desktop **Settings → About**의 채널 스위치를 쓰면 됩니다. 과거 릴리스로 되돌리는 건 "롤백"으로 표시되며 확인 없이는 일어나지 않습니다.

업데이트 안정성도 좋아졌습니다. **`hermes pm`이라는 통합 패키지 매니저**가 고정·해시검증된 도구(Python 3.14, uv, Node, ripgrep, FFmpeg, Chromium 등)와 파이썬 환경을 관리합니다. 새 환경을 만들어 **검증을 통과한 뒤에만 교체**하기 때문에, 업데이트가 중간에 죽어도 이전 환경이 살아 있습니다. 실제로 한 호스트에서 `hermes pm gc`로 92GB를 18GB까지 회수한 사례도 노트에 적혀 있습니다.

업데이트 시간도 줄었습니다. macOS 기준 변경분만 다시 빌드해 **32.5초 → 16.5초**, 클론은 blobless로, 하루 한 번의 GitHub API 호출로 업데이트 확인(`git fetch` 30분 주기 대체)으로 바뀌었습니다.

## 5. 서명된 데스크톱 패키지와 Microsoft Store

배포 방식도 정리됐습니다.

- **데스크톱 앱이 봉인된 서명 패키지**가 되어 자체 Python·Node를 품고 스스로 업데이트합니다. 첫 실행에서 아무것도 빌드하지 않습니다.
- **Windows는 서명된 MSIX(x64·ARM64)**로 App Installer 또는 Microsoft Store에서 설치합니다.
- **macOS는 Apple Silicon용 서명·공증(notarized) 빌드**입니다.

여기서 꼭 짚어야 할 주의사항이 있습니다. **Windows 데스크톱은 이제 MSIX 전용이고 Windows 11 22H2 이상이 필요**합니다. 기존 NSIS/MSI 설치 파일은 사라졌습니다. macOS 기본 빌드도 Apple Silicon 전용입니다. 회사 PC가 아직 Windows 10이라면 업데이트 전에 이 부분을 먼저 확인하셔야 합니다.

## 6. 플러그인 카탈로그 600개 + 코드베이스 34% 감량

이번 사이클에 **플러그인 카탈로그**가 정식 출시돼 **600개 항목**까지 늘었습니다. 각 플러그인은 리뷰된 커밋에 고정되고, 카탈로그 규칙이 Hermes 내부를 패치하거나 스캔 불가능한 바이너리를 싣는 걸 막습니다. 카테고리·별점 랭킹으로 둘러볼 수 있고 플러그인별·제작자별 페이지도 있습니다.

메모리 제공자(Honcho, Supermemory, Hindsight, Mem0, OpenViking, Holographic)와 Home Assistant, Spotify, Langfuse가 카탈로그로 옮겨졌습니다. **기존 사용자는 업데이트 또는 첫 실행 시 데이터 그대로 자동 마이그레이션**되고, 기본 설치본은 더 가벼워졌습니다.

그리고 은근히 대단한 부분 — **동작 변화 없이 코드베이스를 대폭 단순화**했습니다. 소스가 약 106만 줄에서 **69.8만 줄(−34%)**, `gateway/run.py`는 34,847줄에서 **5,512줄**로 줄었습니다. 프롬프트도 가벼워져, 거의 안 쓰는 도구 19개가 검색할 때만 로드되고 매 호출마다 나가던 데스크톱 도구 스키마는 절반 수준으로, 고정 프롬프트에서 약 2.1k 토큰이 더 빠졌습니다. **에이전트를 돌릴 때 토큰·지연이 곧 비용**인 자동화 파이프라인에서는 이게 조용한 성능 개선입니다.

## ⚠️ 업그레이드 전 반드시 확인할 것 (업무 자동화 영향)

기능만 보면 다 좋아 보이지만, **기존 파이프라인을 돌리는 분들은 아래를 먼저 점검**하셔야 합니다. 하나라도 걸리면 자동화가 조용히 멈출 수 있습니다.

1. **Python 3.14가 런타임**이 됐습니다(관리형 설치본은 패키지 매니저가 알아서 설치). 단, **KittenTTS는 3.14에서 사용 불가**입니다.
2. **Windows 데스크톱은 MSIX 전용 + Windows 11 22H2 이상.** 구형 설치 파일 없음.
3. **머신당 게이트웨이 1개가 기본**입니다. `hermes update`가 충돌이 없으면 프로필별 게이트웨이를 멀티플렉스 기본값으로 합칩니다. 프로필별로 게이트웨이를 따로 띄워 쓰던 구성이라면 여기서 한 번 확인하세요.
4. **유휴/일일 타이머로 채팅이 더 이상 리셋되지 않습니다.** `session_reset`의 idle/daily 모드가 폐지됐고(설정에 남아 있으면 경고 로그), `/new`나 `/reset`으로만 새 세션이 시작됩니다.
5. **오래된 세션이 자동 정리됩니다.** `sessions.auto_prune` 기본값이 켜짐으로 바뀌어, **종료된 뒤 90일간 비활성인 세션이 시작 시 삭제**됩니다. 고정(pinned)·열린 세션은 건드리지 않지만, 보관이 필요하면 `sessions.auto_prune: false`로 두세요.
6. **메모리 제공자가 카탈로그 플러그인으로 이동**했습니다. 기존 사용자는 자동 마이그레이션되지만, 사내 표준으로 특정 제공자를 쓰던 팀은 업데이트 후 한 번 점검을 권합니다.
7. **도구 이름 변경:** `todo` → `todo_list`, `cronjob` → `cronjob_manage`, `process` → `process_manage`. **옛 이름도 아직 동작**하지만, 스킬·스크립트에서 새 이름으로 정리해 두는 게 안전합니다.
8. **플러그인 제작자라면:** 옛 플러그인 호환 import 레이어 제거, `hermes sync`(Skill Sync) 제거, 번들 tirith 스캐너 제거.

추가로 스케줄 작업을 돌리는 입장에서 반가운 변화도 있습니다. `state.db`가 커지지 않게 **자동 프루닝이 기본 ON**(90일 초과 종료 세션 정리)이고, 오래된 크론/칸반/서브에이전트 세션도 정리하며, 25% 이상 회수 가능할 때만 VACUUM을 돌립니다. 게이트웨이도 **하나의 게이트웨이가 모든 프로필을 서비스**하게 바뀌었고, webhook 플랫폼은 `/p/<profile>/` 경로로 각 프로필을 서비스합니다.

## 정리 — 지금 업데이트할 만한가?

**결론부터 말하면, 업무 자동화에 에이전트를 붙여 쓰는 분들이라면 이번 v0.22.0은 "체크하고 올릴 가치가 있는" 릴리스입니다.** 근거는 세 가지입니다.

- **진입 장벽이 사라졌습니다.** 키 없이 무료 모델로 시작 → 로그인으로 승격 → 원클릭 로컬 모델까지, "일단 써보고 결정"이 가능해졌습니다.
- **자동화의 실질 접점이 늘었습니다.** Linear·Notion 커넥터, 프로필별 계정 분리, 게이트웨이 멀티플렉싱은 크로스 앱 워크플로를 직접 단순화합니다.
- **운영 안정성이 올라갔습니다.** 테스트된 SemVer 채널, 반쯤 적용되지 않는 업데이트, state.db 자동 관리, 코드 34% 감량에 따른 토큰·지연 절감.

업데이트는 간단합니다.

```bash
hermes update        # 안정 채널로 업데이트 (기본)
hermes doctor        # 업데이트 후 상태 진단
hermes pm status     # 패키지 매니저 환경 확인
```

최신 개발판을 쓰고 싶으면 `hermes update --set-channel main`, 로컬 모델을 붙이려면 `hermes model` → **Local models**를 실행하면 됩니다.

**가성비 좋은 자동화 스택을 찾는 분들께 추천**합니다. 다만 위의 8가지 업그레이드 주의사항 — 특히 Python 3.14, Windows 11 22H2 요건, 게이트웨이 1개 기본화, 세션 자동 정리 — 는 꼭 먼저 확인하고 올리시길. 운영 중인 파이프라인에서 이 네 가지만 체크해도 대부분의 사고는 막을 수 있습니다.
