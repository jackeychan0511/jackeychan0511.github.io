> **📌 한줄 요약:** 요즘 저처럼 **서버 한 대에 Hermes Agent를 여러 프로필로 굴리시는 분들**은 이번 업데이트가 반가울 겁니다. 9월 21일 공개된 **v0.21.4(v2026.9.21)**는 이름은 또 "패치 릴리스"인데, 실제로는 **① 게이트웨이를 호스트 전체에서 하나만 띄우는 싱글톤 락**, **② 데스크톱이 새 백엔드를 또 띄우지 않고 기존 호스트 백엔드에 접속**, **③ CLI `--format stream-json` 구조화 출력**이 들어간 구조 변경입니다. v0.21.3 이후 **1,812개 PR·5,071개 커밋·2,116개 이슈**가 한꺼번에 롤업됐습니다.

## 이 글을 읽으면 알 수 있는 것

- **게이트웨이가 왜 두 개 떠 있었는지** — 데스크톱이 백엔드를 새로 스폰하던 구조와, 그게 싱글톤 락으로 어떻게 바뀌었는지
- **CLI `--format stream-json`이 업무 자동화에 왜 중요한지** — 사람이 읽는 로그가 아니라 기계가 읽는 JSONL
- **게이트웨이 보안 동작 변화** — 허가되지 않은 DM을 거절하는 기본 동작
- **`skills.auto_load`·`mcp.discovery_concurrency`·`session_search` 기간 한정** 같은 실무형 옵션
- **규모 실측치** — 5,071개 커밋, 5,169개 파일, +312,961 / −62,855줄
- **솔직한 장단점** — "바로 업데이트" vs "이건 아직 아쉽다"
- **업데이트 방법과 주의사항(다중 프로필·NAS·Docker 사용자)**

## 도입: "저처럼 서버 한 대에 프로필 여러 개 굴리시는 분들, 프로세스 몇 개 떠 있나요?"

요즘 저처럼 **Hermes Agent를 서버에 상시 띄워두고 텔레그램·디스코드·데스크톱을 같이 붙여 쓰시는 분들** 많으시죠? 저도 이 에이전트를 실사용하면서 크론잡을 돌리고 있고, 업무 자동화 파이프라인을 여러 개 물려 놓았습니다. 그러다 보니 프로필도 자연스럽게 늘었습니다.

그런데 계속 찜찜했던 게 있었습니다. **제가 기억하는 게이트웨이는 하나인데, `ps`를 쳐보면 비슷한 프로세스가 두 개씩 보이는 겁니다.** 노트북에서 데스크톱 앱을 열면 또 하나가 올라오고요. 각자 state.db를 잡으려고 하니 지난 v0.21.2에서 크게 수습했던 세션 저장소 문제가 다시 고개를 들지 않을까 늘 조마조마했습니다.

솔직히 말하면 이건 제가 설정을 잘못한 줄 알았습니다. 그런데 v0.21.4 릴리스 노트를 보니 **"호스트 전역 게이트웨이 싱글톤 락 + 렌더부 레코드"**, **"데스크톱이 두 번째 백엔드를 스폰하는 대신 이미 돌고 있는 호스트 백엔드에 접속"** 이라고 적혀 있었습니다. 제가 이상한 게 아니라, **제품 쪽에서 그 구조를 이번에 정리한 것**이었습니다. Nous Research는 이 태그를 **v0.21.4(v2026.9.21, 9월 21일)**로 공개했습니다.

## 1. 무엇이 바뀌었나 — v0.21.4의 핵심 세 가지

### ① 게이트웨이가 '호스트당 하나'로 — 싱글톤 락과 토폴로지 정리

이번 태그의 본체입니다. 릴리스 노트 표현을 그대로 옮기면 이렇습니다.

- **호스트 전역 게이트웨이 싱글톤 락**과 **렌더부(rendezvous) 레코드**가 들어갔습니다.
- **데스크톱은 두 번째 백엔드를 새로 스폰하지 않고, 이미 돌고 있는 호스트 백엔드에 붙습니다.**

이게 왜 실무에서 크냐면, 게이트웨이가 여러 개 뜨는 순간 문제가 한꺼번에 따라오기 때문입니다. 같은 state.db에 라이터가 둘 이상 붙고, 같은 봇 토큰으로 두 프로세스가 폴링하고, 어느 쪽이 메시지를 먹었는지 알 수 없게 됩니다. 저처럼 **텔레그램 봇 + 크론잡 + 데스크톱**을 한 호스트에서 같이 쓰는 구성에서는 이게 곧 "가끔 답장이 두 번 오거나, 아예 안 오는" 증상으로 나타납니다.

이번 패치로 그 축이 **"호스트 하나 = 게이트웨이 하나"** 로 고정된 셈입니다. 저는 개인적으로 이게 v0.21.4에서 가장 중요한 변화라고 봅니다. 눈에 보이는 기능은 아니지만, 자동화를 오래 굴리는 사람에게는 **안정성의 바닥**이 되는 부분입니다.

*Hermes Agent 공식 플랫폼 아트 — 게이트웨이는 메신저·데스크톱·CLI가 같은 세션과 스킬을 공유하게 하는 허브입니다. v0.21.4는 이 허브가 호스트당 하나만 뜨도록 잠급니다 (출처: hermes-agent.nousresearch.com 공식 홈페이지)*

### ② CLI `--format stream-json` — 업무 자동화에 직결되는 변화

두 번째가 **CLI의 `--format stream-json` 구조화 JSONL 출력**입니다.

지금까지 Hermes CLI 출력을 다른 시스템에 물리려면 사람이 읽는 텍스트를 정규식으로 긁어야 했습니다. 솔직히 이게 제일 스트레스였습니다. 문구가 조금만 바뀌어도 파이프라인이 깨지니까요. 이제 **JSONL(줄마다 JSON 하나)** 로 받을 수 있으니, 결과를 DB에 넣든, 알림 서비스에 넘기든, 다른 에이전트에 전달하든 중간에서 파싱 사고가 날 여지가 확 줄어듭니다.

저처럼 **크론잡이 만든 결과를 별도 시스템으로 흘려보내는 구성**을 쓰는 분들에게는 체감이 큰 항목입니다. 참고로 이번 윈도우에는 **`hermes sessions set-journal-mode`** 도 함께 들어왔습니다.

*Hermes Agent CLI에서 활성 세션을 확인하는 실제 실행 화면 — v0.21.4부터 `--format stream-json`으로 기계가 읽는 JSONL 출력을 받을 수 있습니다 (출처: HostAdvice Hermes Agent 리뷰)*

### ③ 게이트웨이 보안·운영 옵션 — 허가되지 않은 DM 거절부터 스킬 자동 로드까지

세 번째는 운영 디테일 묶음입니다. 릴리스 노트 기준으로 이번 윈도우에 함께 들어간 것들입니다.

- **게이트웨이의 '허가되지 않은 DM 거절' 동작** — 모르는 상대가 봇에게 DM을 보낼 때의 기본 태도가 정리됐습니다. 봇을 공개 채널에 물려두는 분들은 이게 제일 신경 쓰이는 부분이죠.
- **`skills.auto_load`** — 지정한 스킬을 **모든 새 세션의 프롬프트에 고정**합니다. 매번 "이 스킬 써줘"라고 말하지 않아도 됩니다.
- **`mcp.discovery_concurrency`** — MCP 서버 탐색 시 동시 접속 수 상한을 설정으로 뺐습니다.
- **`session_search` 기간 한정(after/before) + OR 완화 재시도** — 오래된 세션에서 뭘 찾을 때 검색 범위를 좁혀 쓸 수 있습니다.
- **원 백엔드가 소유하는 커넥터 작업 하나로 통합** — 데스크톱·TUI·CLI 각각에 있던 설정 카드가 하나로 정리됩니다.
- **데스크톱 폰트 픽커, 로컬 엔진 원클릭 업데이트, 플러그인 허브에서 플러그인 삭제** — 다중 프로필 쓰는 사람에게는 플러그인 삭제가 은근 반갑습니다.
- **플러그인 카탈로그에 커뮤니티 플러그인 12종 추가** — tailscale, ssh, shodan, terminal, rss, resetwatch, done-bell, kiwi, cognee, Octen 등. 카탈로그의 모든 플러그인·작성자마다 웹 페이지가 생기고, README에 커밋 핀이 걸렸습니다.

릴리스 노트에 적힌 실측 수치입니다. 커밋 `4b8a8134009a8727a289bcabeb0019fedd353128` 기준, v0.21.3 이후 구간에:

- **비머지 커밋 5,071개**
- **변경된 파일 5,169개 (+312,961 / −62,855줄)**
- **머지된 PR 1,812개**
- **닫힌 이슈 2,116개**

지난 v0.21.3이 338개 PR이었으니, **약 다섯 배 규모**입니다. 릴리스 노트에는 "이 태그는 다운스트림(Docker 이미지, Hermes Cloud, 호스팅 배포)을 위한 안정 태그이며, **전체 큐레이션 노트는 v0.22.0에서 나온다**"고 적혀 있습니다. 즉 이번 롤업에는 **일부러 문서화하지 않은 항목이 섞여 있다**는 뜻입니다.

## 3. 실사용 체감 — 크론잡·업무 자동화 기준

제 환경은 서버 한 대에 프로필 여러 개, 텔레그램 봇, 크론잡 몇 개, 데스크톱 앱을 붙여 쓰는 구성입니다. 업데이트 후 달라진 점을 솔직하게 정리하면 이렇습니다.

**좋아진 점**
- **"왜 프로세스가 두 개지?" 하는 의문이 사라졌습니다.** 데스크톱을 열어도 백엔드가 새로 올라오지 않고 기존 게이트웨이에 붙습니다. `ps`가 깔끔해진 게 이렇게 마음 편할 일인지 몰랐습니다.
- **크론잡 결과를 다른 시스템으로 넘기는 게 편해졌습니다.** stream-json 덕분에 텍스트 긁어내는 정규식을 버렸습니다.
- **플러그인 삭제가 데스크톱에서 됩니다.** 예전엔 폴더를 직접 지웠어야 했는데, 이제 허브에서 정리됩니다.
- **`skills.auto_load`** 로 상시 스킬을 고정해 두니 매 세션마다 설명하는 품이 줄었습니다.

**아직 아쉬운 점**
- **정식 릴리스 노트가 아닙니다.** v0.22.0에서 전체 정리가 나온다고 하니, 지금은 "무엇이 바뀌었는지" 절반은 릴리스 노트의 '일부러 문서화하지 않은' 목록을 직접 읽어야 합니다.
- **싱글톤 락은 양날의 칼입니다.** 호스트당 하나로 고정된다는 건, 반대로 **기존에 게이트웨이를 두 개 띄우는 전제로 짜둔 구성은 재점검이 필요**하다는 뜻입니다. 별도 포트·별도 프로필로 분리해 쓰던 분들은 동작이 달라질 수 있습니다.
- **Docker/클라우드 사용자는 태그를 고정하세요.** 이미지가 이 태그(`nousresearch/hermes-agent:v2026.9.21`)에서 빌드됩니다. 자동 업데이트를 켜둔 환경이라면 업데이트 직후 크론잡 상태를 한 번 확인하시길 권합니다.

## 4. 업데이트 방법

```bash
# 기존 설치 (git 설치본)
hermes update

# 새로 설치하는 경우
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

- **Docker / Hermes Cloud:** 이미지가 `nousresearch/hermes-agent:v2026.9.21` 태그로 빌드됩니다.
- **전체 변경 목록:** `v2026.9.14...v2026.9.21` 비교에서 직접 확인할 수 있습니다.

## 마무리 — 이런 분께 추천합니다

정리하면 v0.21.4는 **"화려한 신기능 릴리스"가 아니라 "구조를 바로 세운 릴리스"** 입니다. 저처럼 **한 호스트에서 프로필 여러 개 + 봇 + 크론잡을 굴리는 분**, 그리고 **CLI 출력을 다른 시스템에 물려 자동화 파이프라인을 운영하는 분**에게는 지금 바로 올릴 만한 가치가 있습니다. 표기만 패치지, 실질 영향은 이슈급이라고 봅니다.

반대로 **단일 프로필로 데스크톱만 가볍게 쓰는 분**이라면 굳이 서두를 이유는 없습니다. 다만 v0.22.0에서 이 기간 전체의 정식 노트가 나오면 그때 한 번에 정리해서 올리는 것도 좋은 방법입니다.

솔직히 저는 Hermes Agent가 **MIT 라이선스에 무료**라는 점이 여전히 제일 큰 장점이라고 생각합니다. 모델만 원하는 걸 붙이면 되니, 가성비 좋은 AI 에이전트 환경 찾는 분께는 계속 추천하고 있습니다. 이번 패치처럼 **기반을 조용히 다져주는 업데이트**가 사실은 제일 고맙습니다.
