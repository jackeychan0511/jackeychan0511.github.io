요즘 저처럼 **OpenClaw 2026.8.1 정식판이 오늘(8/19)쯤이면 npm에 올라왔을까** 하고 아침부터 npm 태그를 확인하시는 분들, 계시죠? 어제(8/18) 글에서 공동 창업자 **Hannes Rudolph(@hrudolph)**가 **"8월 18일 화요일 출시를 예상한다"**고 X에 공식 예고했다는 소식을 전해드렸는데 — **그 '화요일'이 미국 기준으로 아직 안 끝났습니다.** 그래서 오늘도 저는 평소처럼 출근 전에 npm 레지스트리와 GitHub를 직접 열어봤습니다. 정식판이 나왔는지, 출시 직전 새벽에는 어떤 커밋들이 들어왔는지 — **지금 확인된 것까지 전부 실측 기준으로 정리해드립니다.**

## 1. ⭐ 오늘의 메인 뉴스 — 2026.8.1 정식판, 한국시간 8/19 오전 기준 '아직 npm에 없다'

어제 예고된 **2026.8.1 정식판** 소식부터 확인해봤습니다. **한국시간 8/19 오전 10시 30분 기준, npm 정식 트랙은 여전히 예전 버전 그대로입니다.**

| 트랙 | 버전 | 배포 시각 (UTC) |
|:-----|:-----|:----------------|
| **latest (정식)** | `2026.7.1-2` | 2026-07-18 |
| **beta** | `2026.8.1-beta.2` | 2026-08-15 |
| **extended-stable** | `2026.6.34` | 2026-08-08 |

- 정식 트랙이 **여전히 `2026.7.1-2`** 그대로이고, 베타도 `2026.8.1-beta.2`에서 멈춰 있습니다. (제가 방금 npm 레지스트리에서 직접 확인)
- 다만 중요한 건 **시간대**입니다. 현재 미국 서부(PDT) 기준으로는 **아직 8/18 저녁(오후 6시 30분 경)**입니다. 즉 @hrudolph가 약속한 **"8월 18일(화)"가 아직 끝나지 않았다**는 뜻이에요. 한국 기준으로는 8/19이지만, 미국 기준 하루가 끝나기 전에 나올 가능성이 여전히 남아 있습니다.
- 어제 말씀드린 대로 8/15 배포된 베타.2가 **사후 전체 검증(Full Release Validation)에서 실패**했기 때문에, 이번엔 "서두르지 않고 제대로" 가겠다는 입장입니다. **출시가 늦어지는 게 오히려 안심되는** 상황이죠.

솔직히 저처럼 크론잡 자동화를 OpenClaw에 맡겨놓고 쓰는 입장에서는, **"오늘 안에 안 나와도 괜찮다. 제대로 검증하고 나와라"**가 속마음입니다. 6월 '릴리스 사태'([OpenClaw Had a Rough Week](/2026/08/16/openclaw-update-20260816/)) 이후 검증 프로세스를 지키는 모습이 보이니까요.

## 2. 출시 직전, 릴리스 '검증 스킬' 자체를 만들고 있다 — 베타.2 교훈의 흔적

정식판이 아직 안 나온 이유를 커밋 로그에서 확인할 수 있습니다. **출시 준비(릴리스 프로세스) 관련 커밋 4건**이 눈에 띄었습니다.

- **`feat(release): add interactive release validation skill` (#125642)** — **"릴리스 검증 스킬" 자체를 새로 추가**했습니다. 인터랙티브하게 릴리스 검증을 수행하는 스킬이에요.
- **`fix(release): streamline validation setup` (#126055)** — 검증 셋업 절차를 간소화.
- **`fix(release): offer OCM installation` (#126019)** — **OCM(OpenClaw Manager)** 설치 옵션을 추가했습니다. OCM은 `github.com/openclaw/ocm`에서 개발 중인 도구로, **안정 릴리스·로컬 체크아웃·업그레이드·스냅샷·유지보수를 한 흐름으로 관리**해주는 매니저입니다. "설치만 하면 끝"이 아니라 **여러 셋업을 오래 관리하는 사람**을 위한 도구라, 정식판 출시와 맞물려 더 중요해질 것 같습니다.
- **`test(release): remove release-check helper barrel` (#126105)** — 검증 헬퍼 정리.

이 흐름을 해석하면, **"베타.2처럼 출시 후에 검증이 실패로 드러나는 일"을 막기 위해, 검증 절차 자체를 스킬로 표준화하고 있다**고 볼 수 있습니다. 8/18 새벽 1시 18분 UTC까지도 이 작업이 이어지고 있었어요. **"릴리스를 위해 릴리스 프로세스를 고치고 있는"** 모습이 그대로 보이는 게, 오히려 신뢰가 갑니다.

## 3. 출시 직전 24시간 커밋 점검 — 8/18 01:19 ~ 8/19 01:18 UTC, 60건+

출시를 앞두고 어제 아침(8/18 01:19 UTC)부터 오늘 새벽(8/19 01:18 UTC)까지 **60건이 넘는 커밋**이 쏟아졌습니다. 그중 눈에 띄는 것들을 골랐습니다.

### ① 보안 3종 — SSRF 차단·크레덴셜 노출 차단·Tailscale 크래시 루프

- **`fix: add ssrf protection to Beam fetches` (#123848)** — **Beam 플러그인**의 페치에 **SSRF(서버 사이드 요청 위조) 보호**를 추가했습니다. Beam은 로컬 Claude Code/Codex 세션의 정제된 스냅샷을 게이트웨이에 게시해 Control UI에서 보여주는 번들 플러그인인데, 이 스냅샷을 가져오는(fetch) 경로에 SSRF 방어를 더하고 리다이렉트 차단 동작도 명확히 정의했어요. 지난주부터 이어지는 **"네트워크 경계 강화"** 행보의 연장선입니다.
- **`fix(agents): redact reflected credentials from native PDF provider error body and reason phrase` (#125499)** — PDF·MiniMax VLM 프로바이더에서 **오류 메시지에 인증값(크레덴셜)이 그대로 반사되어 나가던 문제**를 수정했습니다. API 키가 오류 로그에 섞여 나가는 최악의 시나리오를 차단한 보안 픽스예요.
- **`fix(gateway): avoid Tailscale crash loops after upgrades` (#126069)** — 업그레이드 후 **Tailscale 크래시 루프**가 생기던 문제를 수정. 레거시 Tailscale 라우트를 업그레이드 시 마이그레이션하고, 출처 불명 라우트도 보존하도록 했습니다. **Tailscale로 집 밖에서 OpenClaw에 접속하시는 분들**이라면 꼭 반가운 수정입니다.

### ② 크론잡 쓰는 블로거로서 특히 눈에 띈 커밋 — cron aliases

- **`fix: denial gateway configuration for cron aliases` (#123847)** — **크론 별칭(cron aliases)에 대한 게이트웨이 설정 오류**를 수정했습니다. 저처럼 크론잡을 여러 개 돌리고 별칭으로 호출하는 분들이라면, 이번 정식판에서 실제로 잘 동작하는지 확인해볼 만합니다.

### ③ UI·편의 6종 — 머신 픽커 CPU/RAM 표기·세션 자동 아카이브·활동 피드 그룹핑

- **`feat(ui): show machine CPU and RAM in the cloud picker` (#125696)** — 클라우드 **머신 선택기에 "32 vCPU · 64 GB" 같은 실제 사양을 표기**하도록 변경. 기존에는 "Cheap smoke checks and small repos" 같은 문장형 설명뿐이라 뭘 고르는지 애매했는데, 이제 숫자로 보입니다.
- **`feat(sessions): keep durable work visible and auto-archive stale sessions` (#124925)** — 오래된 대시보드 세션을 **자동 아카이브**하고, 진행 중인 작업은 계속 보이게 유지. 세션 목록이 지저분해지는 걸 막아주는 변경입니다.
- **`feat(ui): activity feed automation grouping, live status, deep-link inspector` (#125981)** — 활동 피드에서 **자동화 세션을 그룹으로 접고, 실행 상태를 실시간 표시**, 실행 상세는 딥링크로만 연결. "실행이 끝난 작업인데 살아있는 것처럼 보이던" 문제(ClawSweeper P1)도 함께 수정됐습니다.
- **`feat(ui): proxy opt-in link favicons through gateway` (#121906)** — 링크 파비콘을 게이트웨이 경유로 프록시(개인정보 보호).
- **`improve(ui): make online sidebar section collapsible` (#125963)** — 온라인 목록 사이드바를 **접을 수 있게** 개선.
- **`feat(ui): add copy session id action` (#124059)** — 세션 ID 복사 버튼 추가.

### ④ 모델·MCP·Codex — "조용한 실패" 제거

- **`fix(models): seed configured provider model entries from catalog metadata` (#126068)** — 이건 꽤 중요한 버그 수정입니다. 모델 설정에서 **일부 필드만 오버라이드하면 비전(vision) 도구(특히 computer tool)가 조용히 사라지던** 문제를 고쳤어요. "분명 설정했는데 컴퓨터 도구가 안 보이던" 분들은 이 커밋이 원인일 수 있습니다.
- **`fix(mcp): retire terminal transports and process trees` (#126101)** — MCP 터미널 SSE·상태 알림 스트림과 프로세스 그룹을 제대로 정리하도록 수정. 리소스 누수 차단.
- **`fix(codex): retain terminal facts in oversized trajectories` (#126050)** / **`fix(codex): preserve native approval scope` (#125995)** — Codex 엔진에서 대형 트레이젝토리 처리와 승인 범위 보존 문제 수정.

## 5. 마무리 — 정식판 기다리는 분들을 위한 사용 팁 3가지

정리하면, 오늘(8/19)의 키워드는 **"8/18(화) 출시 예고는 아직 진행 중, 그리고 릴리스 프로세스 자체를 고치고 있다"**입니다. 정식판이 아직 안 나온 건 사실이지만, 그 시간 동안 **보안 3종(SSRF·크레덴셜 레드랙션·Tailscale), 크론 별칭 수정, UI 개선 6종**이 커밋으로 쌓이고 있어요. **늦어지는 만큼 더 단단해지고 있다**고 봐도 무방합니다.

**기다리는 동안 쓸만한 팁 3가지:**

1. **지금 당장 안정적으로 쓰고 싶다면** — `openclaw update --channel extended-stable`로 **2026.6.34(extended-stable)**를 쓰세요. 정식판 검증이 끝날 때까지 가장 보수적인 트랙입니다.
2. **정식판 출시 알림 받기** — npm에서 직접 확인하시는 분은 아래 명령으로 최신 버전을 폴링할 수 있습니다.
   ```bash
npm view openclaw dist-tags.latest
```

저는 이걸 크론잡에 걸어두고, 값이 `2026.7.1-2`에서 바뀌면 알림이 오게 해뒀습니다.
3. **업그레이드 전 체크리스트** — 정식판이 나오면 Tailscale 쓰시는 분은 **업그레이드 직후 크래시 루프가 없는지**(#126069 수정 확인), 크론 별칭을 쓰시는 분은 **별칭 호출이 정상 동작하는지**(#123847 수정 확인) 먼저 테스트해보세요.
