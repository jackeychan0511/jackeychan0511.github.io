> **📌 한 줄 요약:** 2026년 11월 12일은 OpenAI가 **Cursor(커서)에 자사 모델을 공급하는 계약을 정리하기로 예고한 날**입니다. 발단은 SpaceX의 **Anysphere(커서 모회사) 600억 달러 전액 주식 인수**였고, 이때 계약서의 **지배권 변경(change-of-control) 조항**이 발동했습니다. 오픈AI는 "계약이 허용하는 최대 통지 기간"인 11월 12일을 전환 종료일로 제시했고, **향후 모델은 커서에 공급하지 않겠다**고 못 박았습니다. 커서 안에서 GPT 계열은 **GPT-5.6에서 멈추고**, GPT-6 Astra·GPT-6.1 Sol 같은 이후 모델은 애초에 들어오지 않았습니다.

AI 코딩 도구를 업무 자동화 파이프라인에 넣어 쓰는 분들이라면, 이런 뉴스는 "경쟁사끼리 싸우나 보다"로 넘길 수 없습니다. 모델 목록 한 줄이 바뀌는 것처럼 보이지만, 실제로는 **프롬프트·평가셋·비용 계산·컴플라이언스 검토가 통째로 다시 돌아가는 일**이기 때문입니다. 이번 건은 모델 성능 뉴스가 아니라 **공급 계약 뉴스**라서, 읽는 관점을 바꿔야 합니다.

## 1. 무슨 일이 있었나 — 8월 28일 통보, 11월 12일 종료 예고

시간순으로 정리하면 이렇습니다.

| 시점 | 사건 |
|:---|:---|
| 2026년 8월 14일 | SpaceX, Anysphere(커서) **600억 달러 전액 주식 인수 완료** |
| 2026년 8월 28일 | OpenAI, SpaceX에 **모델 공급 계약 종료 통보**. 전환 종료일로 **11월 12일** 제시 |
| 2026년 8월 29일 | CNBC 등 주요 매체 보도. 커서 "OpenAI 모델 비중 약 5%" 반박 |
| 2026년 11월 12일 | **예고된 전환 종료일(오늘)** |

오픈AI가 든 근거는 계약 조항입니다. 인수로 커서의 지배 구조가 바뀌면서 **지배권 변경 조항**이 발동됐고, 오픈AI는 이 조항을 근거로 계약을 정리하겠다고 통보했습니다. 통보 당시 오픈AI가 쓴 표현은 "**우리 계약이 허용하는 최대 통지 기간**"이었습니다. 즉 11월 12일은 협상으로 늘려잡은 날짜가 아니라, **계약상 줄 수 있는 마지막 여유**라는 뜻입니다.

한 가지 짚어둘 점이 있습니다. 오픈AI 헬프센터 안내는 이 날짜를 **"제안된(proposed) 전환 종료일"**로 적고, 공식 종료일은 **양사가 확정해 별도로 공지**한다는 단서를 달았습니다. 커서가 더 일찍 끊을 수도 있다는 문구도 함께 있었습니다. 그래서 오늘 시점의 정확한 표현은 "**예고된 종료일이 도래했다**"이지, "양사가 공식 종료를 선언했다"가 아닙니다. 실제 모델 목록 변화는 커서 앱에서 직접 확인하는 게 가장 정확합니다.

덧붙여, 보도에 따르면 커서는 그 전에 오픈AI의 인수 제안을 **두 차례 거절**하고 독립 노선을 택했습니다. 그 선택이 결과적으로 경쟁 관계인 SpaceX 쪽으로 회사를 옮기는 결과가 됐고, 오픈AI 입장에서는 **경쟁 진영에 자기 모델을 대주는 상황**을 정리한 셈입니다. 감정적인 해석이 끼어들 여지가 큰 사안이라, 사실관계와 별개로 각 회사의 공식 발표를 구분해서 읽는 게 좋습니다.

## 2. 왜 이게 '이슈급'인가 — 점유율 5%보다 중요한 것

커서 CEO 마이클 트루엘은 오픈AI 모델이 **전체 트래픽의 약 5%** 수준이라고 밝혔습니다. 숫자만 보면 "5% 빠지면 별일 아니다"로 읽힙니다. 하지만 실무에서는 다릅니다.

- **5%가 평균값**입니다. 커서 전체 사용자 중 5%가 GPT를 쓴다는 뜻이 아니라, **GPT 계열에 워크플로를 고정해 둔 팀에게는 100%**입니다. 특히 코드 리뷰·리팩터링 프롬프트를 GPT 출력 기준으로 튜닝해 둔 팀은 그날부터 결과물이 달라집니다.
- **모델 세대가 끊긴 상태로 3개월 가까이 버텼습니다.** 커서의 오픈AI 라인업은 **GPT-5.6에서 멈춰 있고**, 이후 나온 **GPT-6 Astra, GPT-6.1 Sol, GPT-6.1 Terra**는 커서에 들어오지 않았습니다. 즉 "오늘 갑자기 끊긴다"기보다, **이미 성능 격차가 벌어진 상태에서 마지막 연결선까지 정리되는 날**에 가깝습니다.
- **선례가 있습니다.** 2025년 Anthropic이 Windsurf에 Claude 공급을 끊을 때 통지 기간은 **5일이 채 안 됐습니다.** 이번처럼 두 달 반을 준 경우가 오히려 예외적입니다. 업계에서는 "모델 공급 계약은 이제 **전략 자산**"이라는 해석이 힘을 얻고 있습니다.

## 3. 무엇이 끊기고, 무엇이 남나

실무에서 헷갈리는 부분이 BYOK(내 API 키 사용)입니다. 정리하면 아래와 같습니다.

| 구분 | 상태 | 비고 |
|:---|:---|:---|
| 오픈AI 모델(기본 제공) | **종료** | GPT-5.6이 마지막 세대 |
| 향후 오픈AI 모델(Astra·6.1 Sol 등) | **애초에 미공급** | 8월 통보 시 명시 |
| 내 OpenAI API 키(BYOK) | **부분 사용 가능** | 로컬 Chat·Agent 세션 한정 |
| 클라우드/백그라운드 에이전트 | **불확실** | BYOK로 커버되지 않는 영역 존재 |
| 커서 자체 모델(Composer 계열) | 유지 | 커서 1st-party |
| Claude / Gemini / Grok | 유지 | 해당 사안과 무관 |

BYOK는 "키만 넣으면 그만"이 아닙니다. 오픈AI 안내 기준으로 **내 키는 로컬 Chat과 Agent 요청에만 적용**되고, 서버에서 도는 **클라우드 에이전트는 별개**입니다. 여기에 더해 일부 정리글은 BYOK 경로가 **제로 데이터 보존(ZDR) 보장을 그대로 승계하지 않는다**는 점을 지적합니다. 사내 코드·고객 데이터를 다루는 팀이라면 기술적 가능 여부와 **계약상 보장 여부**를 따로 확인해야 합니다. 결론은 하나입니다. **BYOK는 임시 우회로, 대체재가 아닙니다.**

## 4. 개발자·사용자에게 실제로 미치는 영향

### ① 모델을 고정(pin)해 둔 워크플로
`gpt-5.6` 같은 모델 ID를 코드나 설정에 하드코딩해 둔 경우, 커서 경유 호출은 실패하거나 다른 모델로 조용히 대체됩니다. 조용한 대체가 더 위험합니다. 출력 형식이 미묘하게 달라져도 **에러가 안 나기 때문**입니다.

### ② 프롬프트·평가셋 재측정
같은 작업을 Claude·Gemini·Composer로 옮기면 프롬프트를 그대로 써도 결과가 달라집니다. 특히 **JSON 스키마 준수, 코드 diff 형식, 한국어 톤**은 모델별 편차가 큽니다. 이전에 만들어 둔 자체 평가셋이 있다면 지금이 재측정 시점입니다.

### ③ 비용 구조 재계산
모델 단가만 보면 안 됩니다. 재시도율, 출력 토큰 길이, 캐시 적중률이 모델마다 달라서 **작업당 실질 비용**이 뒤집히는 경우가 흔합니다. 표면 단가가 30% 싸도 재시도가 두 배면 손해입니다.

### ④ 컴플라이언스·감사 로그
금융·의료·공공 협업이라면 "어떤 모델이 어떤 데이터를 처리했는지"가 감사 항목입니다. 모델 공급사가 바뀌면 **데이터 처리 지역, 보존 기간, 학습 사용 여부**가 함께 바뀝니다. 도구 교체보다 이 서류 작업이 더 오래 걸립니다.

## 5. 업무 자동화 파이프라인 관점 체크리스트

자동화 파이프라인을 운영하는 쪽이라면, 이번 사안에서 뽑을 교훈은 "커서를 떠나라"가 아니라 **구조를 어디에 두느냐**입니다.

- **모델 ID 하드코딩 금지** — 라우팅 레이어 한 곳에서 모델을 결정하고, 나머지는 별칭(alias)만 참조
- **이중 경로 확보** — IDE 확장 + 직접 API 호출. 한쪽이 막혀도 작업이 멈추지 않게
- **자체 평가셋 유지** — 20~50개 대표 작업으로 모델 교체 시 회귀 확인
- **계약 조항 검토** — 지배권 변경, 공급 중단 통지 기간, 데이터 보존 조항을 계약서에서 확인
- **비용·지연 모니터링** — 모델별 작업당 비용과 p95 지연을 대시보드에 남기기
- **종속 리스크 문서화** — "이 도구가 막히면 어떤 업무가 멈추는가"를 목록으로

이 중에서도 첫 번째와 두 번째가 실제 사고를 막습니다. 나머지는 사고가 난 뒤의 복구 속도를 줄여줍니다.

## 6. 전망 — 모델 공급은 '요금제'가 아니라 '동맹'

이번 건이 남기는 가장 큰 변화는 가격표가 아니라 **계약 구조**입니다.

1. **지배권 변경 조항이 표준이 됩니다.** 모델 공급사 입장에서 경쟁사 인수는 곧 공급 중단 사유입니다. 앞으로 AI 도구 도입 계약에서 이 조항 검토가 필수가 될 가능성이 큽니다.
2. **멀티 벤더 라우팅이 기본값이 됩니다.** 한 모델에 올인하는 구성은 비용 최적화에는 유리하지만, 공급 리스크에는 취약합니다. 라우터·게이트웨이 계층을 두는 팀이 늘어날 겁니다.
3. **1st-party 모델 비중이 커집니다.** 커서는 Composer 계열을, 오픈AI는 Codex 계열을 밀고 있습니다. 자사 모델을 가진 쪽이 공급 리스크를 통제할 수 있기 때문입니다.
4. **커서의 외부 협력 구도가 재편됩니다.** Claude·Gemini·Grok 조합으로 무게가 옮겨가고, 특히 Google과의 관계가 새 시험대가 될 것이라는 관측이 나옵니다.

## 7. 오늘 확인할 것

AI 코딩 도구를 업무에 쓰는 분들이라면, 오늘 딱 세 가지만 확인해보시길 권합니다.

1. 커서 **Settings → Models**에서 지금 어떤 모델이 실제로 선택 가능한지
2. 자동화 스크립트에 `gpt-` 로 시작하는 **모델 ID가 하드코딩**돼 있는지
3. 그 모델이 막혔을 때 **대체 경로**가 문서로 적혀 있는지

솔직히, 이번 사안은 "당장 큰일"이라기보다 **경고등**에 가깝습니다. 다만 경고등이 켜진 걸 보고 지나친 팀과, 배선을 정리해 둔 팀의 차이는 다음번 공급 중단 때 확실히 갈립니다.

> **⚠️ 확인 기준일:** 2026년 11월 12일. 11월 12일은 오픈AI가 제시한 **전환 종료 예정일**이며, 양사가 확정한 공식 종료일은 별도 공지 여부를 확인해야 합니다. 실제 모델 목록과 BYOK 적용 범위는 커서 앱과 양사 공식 문서에서 최종 확인하세요.
