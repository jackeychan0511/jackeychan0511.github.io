## 도입: \"저처럼 매일 아침 9시에 같은 일을 반복하시는 분들\"

요즘 저처럼 **매일 아침 같은 시간에 똑같은 반복 업무**를 하시는 분들 많으시죠? 아침 뉴스 브리핑, 주식 시황 정리, 블로그 포스팅, 체크리스트 점검… 저도 한 달 전까지는 매일 아침 커피를 마시며 \"오늘은 무슨 소식이 있나\" 검색하고, 정리하고, 글을 쓰고, 배포하는 일을 손으로 했습니다. 솔직히 하루 2시간은 그냥 증발하는 기분이었어요.

그런데 한 달 전부터 이 블로그의 모든 포스팅이 **Hermes Agent의 크론잡(cron job)으로 자동 발행**되고 있습니다. 지금 이 글도 예외가 아닙니다. 크론잡이 새벽에 깨어나 → 최신 뉴스를 리서치하고 → 이미지를 찾고 → 스타일에 맞게 글을 쓰고 → 오타를 검증하고 → git push까지 끝내면, 제가 아침에 일어나서 할 일은 **커피 한 잔 마시며 결과 확인**뿐입니다.

오늘은 이 **30일 실사용 경험**을 바탕으로, Hermes Agent 크론잡을 처음 시작하는 분께 실제로 어떻게 쓰는지, 무엇이 좋고 무엇이 아쉬운지 솔직하게 풀어드릴게요.

## ① 크론잡이 뭔데? — \"AI 에이전트에게 알람시계를 달아주는 기능\"

Hermes Agent의 크론잡은 **\"지정한 시간에 AI 에이전트를 자동으로 깨워서 일을 시키는 스케줄러\"**입니다. 핵심은 두 가지예요.

- **자연어로 예약** — cron 표현식(`0 9 * * 1`)을 몰라도 \"매일 아침 9시에\"라고 말하면 알아서 스케줄을 만듭니다
- **완전 자율 실행** — 예약된 시각에 새 세션으로 깨어나 프롬프트만으로 작업을 끝냅니다

### 자연어 예약 3가지 방법

**① 채팅에서 `/cron` 슬래시 명령**

```
/cron add "every 2h" "서버 상태를 확인해줘"
/cron add "every 1h" "새 피드 항목을 요약해줘" --skill blogwatcher
```

**② CLI에서 `hermes cron create`**

```bash
hermes cron create "every 1h" "새 피드 항목을 요약해줘" --skill blogwatcher --name "피드 요약"
```

**③ 그냥 말하기** — 가장 신박한 방법입니다.

> \"매일 아침 9시에 해커뉴스 AI 뉴스를 확인해서 텔레그램으로 요약 보내줘\"

이렇게 말하면 에이전트가 내부의 `cronjob` 툴로 알아서 잡을 만들어 줍니다. CLI도, cron 문법도 몰라도 되는 구조예요.

### 예약된 작업이 돌아갈 때 필요한 것

크론잡은 **이전 대화 기억이 없는 새 세션**에서 실행되기 때문에, 프롬프트에 필요한 정보를 모두 담아야 합니다. 그래서 Hermes가 권장하는 조합이 바로 **프롬프트 + 스킬(skill) + 전달(deliver) 대상**입니다. 스킬을 붙이면 그 작업만의 전문 매뉴얼을 통째로 로드하고, deliver로 결과를 텔레그램·디스코드·이메일 어디로든 보낼 수 있어요.

## ② 실사용 후기: 이 블로그의 자동 포스팅 파이프라인

제가 30일째 굴리고 있는 실제 구조를 공개하면 이렇습니다. 크론잡 하나가 매일 아침 이런 순서로 일합니다.

| 단계 | 크론잡이 하는 일 | 사용하는 스킬 |
|:-----|:----------------|:-------------|
| 1 | 오늘 포스팅할 주제 리서치 (Hermes Agent 최신 뉴스·릴리스 실측) | — |
| 2 | 제품/항목별 대표 이미지 3순위 검색·추출·다운로드 (공식 홈페이지 → 웹 검색 → 이미지 검색) | image-research-subagent |
| 3 | 블로그 스타일에 맞는 글쓰기 (개인 경험 도입부, 솔직한 장단점, 구매 팁 마무리) | blogger-style-franky |
| 4 | 오타·이미지 링크·Liquid 문법·파일 존재 검증 후 PASS/FAIL 판정 | final-verification-before-report |
| 5 | git add → commit → push → GitHub Pages 배포 → 라이브 URL 보고 | — |

**핵심 포인트는 2번과 4번입니다.** 크론잡은 여러 스킬을 동시에 붙일 수 있어서, \"이 작업은 이 매뉴얼대로 해라\"를 잡 하나에 다 박아넣을 수 있어요. 스킬이 곧 **반복 업무의 표준작업절차(SOP)** 가 되는 셈이죠.

```bash
# 실제로는 이런 느낌으로 잡을 만듭니다
hermes cron create "every 1d at 6am" \
  "오늘의 블로그 포스팅을 작성하고 검증 후 git push까지 완료해줘" \
  --skill blogger-style-franky \
  --skill image-research-subagent \
  --skill final-verification-before-report \
  --name "블로그 자동 포스팅" \
  --deliver email
```

솔직히 처음에는 \"AI가 쓴 글이니 검증이 필요하겠지\" 하고 시작했는데, 한 달이 지난 지금은 **검증 스킬이 없으면 불안할 정도**입니다. 배포 직전에 깨진 이미지 링크나 Liquid 문법 오류를 잡아주니까요.

## ③ 공식 가이드의 5가지 실전 패턴

공식 문서의 'Automate Anything with Cron' 가이드에 있는 패턴 중, 제가 실제로 써보고 유용했던 것들입니다.

### 패턴 1: 웹사이트 변경 감시 (Website Change Monitor)

특정 URL이 바뀔 때만 알림을 받는 패턴입니다. 여기서 비결은 **`script` 파라미터**예요. 파이썬 스크립트가 먼저 실행돼서 fetch·diff 같은 기계적인 일을 하고, 에이전트는 \"이 변경이 흥미로운가?\"라는 판단만 합니다.

- 스크립트가 페이지 해시를 계산해서 저장해두고, 바뀌었으면 그 내용을 컨텍스트로 전달
- 에이전트는 변화가 없으면 `[SILENT]`로 응답 → **알림이 필요한 날에만 메시지가 옴**

### 패턴 2: 주간 리포트 (Weekly Report)

여러 소스를 한 번에 긁어와 정리하는 패턴입니다.

```
/cron add "0 9 * * 1" "지난주 AI 뉴스 top 5를 검색하고, GitHub 트렌드 ML 저장소와
해커뉴스 인기 글을 모아 소스별 섹션으로 정리해줘. 링크 포함, 500단어 이하" --deliver telegram
```

`0 9 * * 1`은 \"매주 월요일 9시\"라는 뜻이고, 이렇게 cron 표현식과 자연어를 섞어 쓸 수도 있습니다.

### 패턴 3: GitHub 저장소 감시 (Repository Watcher)

```bash
hermes cron create "every 6h" \
  "NousResearch/hermes-agent 저장소의 최근 6시간 내 새 이슈·PR·릴리스를 확인해줘.
   gh issue list --repo NousResearch/hermes-agent --state open --json number,title,author,createdAt --limit 10
   gh pr list --repo NousResearch/hermes-agent --state all --json number,title,author,createdAt,mergedAt --limit 10
   새로 생긴 게 없으면 [SILENT]로 응답해줘." \
  --deliver discord
```

프롬프트에 **정확한 `gh` 명령어를 통째로 적어주는 게** 포인트입니다. 크론잡은 과거 대화가 없으니 모든 걸 스펠아웃해야 해요.

### 패턴 4: 데이터 수집 파이프라인 (Data Collection Pipeline)

스크립트가 데이터를 모으고 에이전트가 분석하는 조합입니다. 예를 들어 가격 데이터를 30분마다 수집해 파일에 쌓아두고, 하루 한 번 에이전트가 추세를 분석하는 식이죠. **\"수집은 기계, 판단은 AI\"** — 이 역할 분리가 핵심입니다.

### 패턴 5: 멀티스킬 워크플로 (Multi-Skill Workflow)

한 잡에 스킬을 여러 개 붙이는 패턴입니다. 제 블로그 파이프라인이 정확히 이 케이스예요.

```
/cron add "every 1h" "두 스킬을 모두 사용해서 결과를 합쳐줘" --skill blogwatcher --skill maps
```

## ④ v0.21.0 '판테온'에서 크론잡이 달라진 점

어제(9/1) 포스팅한 v0.21.0 판테온 릴리스에서 **크론잡 관련 변경이 유독 많았습니다.** 자동화를 직접 돌리는 입장에서 체감이 컸던 것들만 추리면:

- **영구 메모리** — 크론 에이전트도 다른 에이전트처럼 메모리를 로드·업데이트합니다. 잡이 실행될 때마다 제 메모리에 \"이미 다룬 주제\"를 기록해두니까, 다음 날 같은 주제를 또 쓰는 중복이 사라졌어요.
- **연속성(continuity)** — `continuity=true`로 설정하면 이전 실행 결과가 다음 실행에 전달됩니다. \"어제 이미 보고한 건 오늘 빼기\" 같은 디듀프(중복 제거)가 구조적으로 됩니다.
- **듀러블 스크래치패드** — 잡마다 메모장을 하나씩 줘서, 여러 번에 걸친 실행에서 중간 상태를 보관할 수 있어요.
- **LLM 없는 no-agent 모드** — 스크립트만 돌리고 출력을 그대로 전달하는 '감시 전용' 잡은 **토큰을 0개 소비**합니다. 메모리 알림·디스크 알림 같은 건 이제 무료로 돌아갑니다.
- **봇 채팅(bot-chat) 전달** — 크론 출력을 특정 봇의 채팅에 넣으면, **봇이 그 결과를 읽고 실제로 응답**합니다. \"리서치 잡의 결과를 브리핑 봇이 받아서 다듬어 보내기\" 같은 2단 자동화가 가능해졌어요.
- **모델 고정(핀)** — 잡마다 모델을 고정할 수 있고, 전역 기본 모델이 바뀌어도 **실패 시 스킵+1회 알림**으로 끝나도록 방어됩니다. 자동화 잡이 조용히 유료 모델로 갈아타는 사고를 막아줍니다.
- **사전 검증(preflight)** — 잡이 실행되기 전에 API 키·스킬·전달 대상이 정상인지 확인하고, 문제가 있으면 **LLM 호출 없이** `blocked_config` 상태로 표시합니다. 잘못된 설정이 토큰을 태우는 일이 없어요.

## ⑤ 커뮤니티는 어떻게 쓰고 있나 — 실제 사례 4선

공식 'User Stories' 페이지(9/2 기준 326개 스토리)에서 크론잡 실사용 사례만 골라봤습니다.

## 솔직한 장단점

**👍 좋은 점**
- **자연어로 끝난다** — cron 문법을 몰라도 \"매일 아침 9시에\"라고 말하면 됩니다. `/cron`도, CLI도, 대화도 전부 지원해요.
- **스킬 조합이 강력** — SOP를 스킬 파일 하나로 박아두면 잡이 영원히 그 규칙을 따릅니다. 블로그 파이프라인에서 검증 스킬이 배포 사고를 두 번이나 막아줬습니다.
- **비용 제어가 체계적** — no-agent 모드는 토큰 0개, 모델 핀·드리프트 가드로 자동화 잡이 조용히 비싸지는 일이 없습니다.
- **무료** — MIT 라이선스 오픈소스이고, Nous Portal 가입 시 무료 모델(SKU)도 있습니다.

**🤔 아쉬운 점 (솔직히)**
- **프롬프트를 스스로 완결해야 한다** — 크론잡은 이전 대화 기억이 없어서 \"저번에 말한 그거\"가 통하지 않습니다. 처음에는 모든 정보를 프롬프트에 담는 습관이 필요해요.
- **출력이 길어지면 전달이 무거워진다** — 봇 채팅 전달은 대상 봇의 풀 턴을 소비하니, 잦은 스케줄에는 주의가 필요합니다.
- **잡이 많아지면 관리가 필요** — 10개가 넘어가면 어떤 잡이 뭘 하는지 정리가 필요합니다. 저는 이름에 용도를 꼭 넣고, 주간 1회 `hermes cron list`로 점검합니다.

## 이런 분께 추천합니다

- **매일 아침 브리핑·뉴스 요약을 자동화**하고 싶은 분
- **블로그·뉴스레터를 정기 발행**하는 분 (이 글의 파이프라인 그대로 가져가시면 됩니다)
- **웹사이트 변경·가격 변동을 감시**하고 싶은 분 — 변화가 있을 때만 알림
- **GitHub 이슈·PR·릴리스를 추적**하는 개발자
- **AI 직원 여러 명에게 업무를 배분**하는 분 — 봇 채팅 전달로 2단 자동화

## 시작하는 법 — 5분이면 끝

```bash
# ① 설치 (macOS/Linux/WSL2)
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

# ② 첫 예약 — 5분 뒤 테스트
hermes cron create "in 5m" "지금 시각을 알려주고 짧은 인사를 해줘" --deliver local

# ③ 확인
hermes cron list
```

데스크톱 앱(macOS·Windows)을 쓰면 설정 화면에서 잡을 관리할 수 있고, `hermes setup --portal`로 Nous Portal에 연결하면 OAuth 갱신이 자동이라 **무인 실행에 가장 안정적**입니다.
