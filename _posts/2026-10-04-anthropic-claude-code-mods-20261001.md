> **📌 한줄 요약:** **2026년 10월 1일(미국 현지시간)**, Anthropic이 **Claude Code**에 **'모드(Mods)' 시스템**을 공개했습니다. 모드는 Claude Code가 이벤트(툴 호출·프롬프트 제출·화면 그리기 등)를 낼 때 끼어들어 **프롬프트를 다시 쓰거나, 툴 호출을 막고, 화면에 새 패널·버튼을 그리거나, 내장 기능을 통째로 대체**하는 **JavaScript·TypeScript 함수**입니다. **플러그인 형태로 배포**돼 CLI와 데스크톱 앱에서 쓸 수 있고, **`/diff` 같은 내장 기능도 모드로 옮겨갑니다**. 개발자가 Anthropic의 출시를 기다리지 않고 **툴 자체를 직접 뜯어고칠 수 있게** 된 것이 핵심입니다.

코딩 에이전트를 업무에 붙여 쓰다 보면, "이 부분만 내 방식대로 바꾸면 훨씬 편할 텐데" 하는 지점이 꼭 생깁니다. 특정 조건에서 위험한 툴 호출을 자동으로 막고 싶다거나, 지금 컨텍스트가 얼마나 찼는지 보여주는 패널 하나만 더 있었으면 싶은 경우입니다. 그동안은 그런 요구가 있어도 **Anthropic이 기능을 만들어 줄 때까지 기다리는 선택지밖에 없었습니다.** Anthropic이 2026년 10월 1일 공개한 **Claude Code '모드(Mods)'** 는 정확히 이 지점, 즉 **에이전트 내부에 직접 끼어들어 동작과 화면을 바꾸는 구조**를 겨냥합니다. 무엇이 가능해졌고, 실무자에게 어떤 의미인지 정리해 보겠습니다.

## 🗞️ 이슈 요약 — 한눈에 보기

- **무엇을 발표했나:** **2026년 10월 1일**, Anthropic이 **Claude Code용 '모드(Mods)'** 를 공개했습니다. 개발자가 **툴의 동작과 인터페이스를 직접 수정**할 수 있게 하는 확장 시스템입니다
- **모드가 뭔가:** Claude Code가 어떤 작업을 할 때 내는 **이벤트에 붙는 JavaScript·TypeScript 함수**입니다. 이벤트 **앞에서 실행되거나, 뒤에서 실행되거나, 아예 대신 실행되거나, 앞뒤를 감쌀(wrap)** 수 있습니다
- **무엇을 할 수 있나:** **프롬프트를 모델에 닿기 전에 다시 쓰기**, **툴 호출 차단·재작성·재시도**, **권한 요청 승인·거부**, **툴 출력에서 비밀값(secret) 마스킹** 같은 동작 제어가 가능합니다
- **화면도 바꾼다:** 대화 옆 **패널**, 프롬프트 위 **밴드**, 탭·버튼·입력 필드를 **새로 그릴 수 있고**, Claude Code가 직접 그리는 UI(툴 호출 행·스피너·질문 다이얼로그)를 **대체·재스타일**할 수 있습니다
- **어디서 쓰나:** 모드는 **플러그인에 담겨** 배포됩니다. 따라서 **기존 플러그인처럼 설치·공유**되고, **Claude Code CLI와 데스크톱 앱** 양쪽에서 동작합니다
- **내장 기능의 모드화:** **`/diff` 같은 내장 기능이 이미 모드로 전환**됐습니다. 끄거나 자기 버전으로 교체할 수 있고, **더 많은 내장 기능을 모드로 옮길 계획**입니다
- **주의점:** 모드는 **샌드박스가 아니며 Claude Code와 같은 권한**으로 실행됩니다. **신뢰할 수 있는 출처의 모드만 설치**해야 합니다

## 🔍 상세 분석 — 모드가 정확히 무엇인가

### 1) 기존 '훅'과 결정적으로 다른 지점 — 밖이 아니라 '안'에서 실행된다

Anthropic은 모드를 **"타입스크립트(또는 자바스크립트) 이벤트 핸들러"** 로 정의합니다. Claude Code는 무언가를 할 때마다 이벤트를 남깁니다. 예를 들어 **툴을 호출할 때**, **권한을 물어볼 때**, **화면 일부를 그릴 때**가 이벤트입니다. 모드는 이 이벤트에 붙는 **함수**입니다.

기존에 있던 **설정 파일 기반 훅(settings hook)** 과의 차이가 핵심입니다.

| 구분 | 설정 파일 훅 (기존) | 모드 (신규) |
|:---|:---|:---|
| **실행 위치** | Claude Code **바깥** (셸 명령·HTTP·프롬프트) | Claude Code **안** (함수) |
| **이벤트 재작성** | 불가 | **가능** (프롬프트·툴 호출을 고쳐서 통과) |
| **UI 그리기** | 불가 | **가능** (패널·밴드·버튼 추가) |
| **내장 기능 대체** | 불가 | **가능** (예: `/diff` 교체) |
| **배포 방식** | 개인 설정에 묶임 | **플러그인으로 패키징·공유** |

정리하면, 설정 훅은 **바깥에서 스크립트를 돌리는 것**에 가깝고, 모드는 **툴 속으로 들어가 동작 자체를 바꾸는 것**입니다. 그래서 훅으로는 못 하던 **"이벤트를 다시 쓰기"와 "화면 그리기", "기능 갈아끼우기"** 가 모드에서는 됩니다.

### 2) 함수 하나로 가능한 일 — 프롬프트·툴·권한·보안을 한 지점에서

모드는 이벤트의 **앞·뒤·대신·감싸기(wrap)** 어디에든 붙을 수 있습니다. 이 하나의 구조로 다음이 가능합니다.

- **프롬프트 재작성:** 모델에 도달하기 **전에** 프롬프트를 바꿔서 보냅니다
- **툴 호출 제어:** 호출을 **막거나, 고쳐서 보내거나, 재시도**합니다
- **권한 자동화:** 권한 요청을 **코드로 승인하거나 거부**합니다
- **비밀값 보호:** 툴 출력에서 **민감 정보를 마스킹**한 뒤 Claude가 읽게 합니다

즉 사내 규칙(예: "특정 경로 접근은 항상 차단", "API 키는 로그에 남기지 않기")을 **에이전트 레벨에서 강제**하는 길이 열립니다. 그동안 이런 요구는 프롬프트 지시문이나 사람의 감시에 의존하는 경우가 많았는데, 모드는 이를 **툴 내부 동작**으로 옮깁니다.

### 3) 'Claude Code로 Claude Code를 개조한다' — 자기참조 루프

흥미로운 대목은 **모드를 만드는 일 자체를 Claude Code에게 시킬 수 있다**는 점입니다. Claude에게 모드를 만들어 달라고 하면, Claude Code가 **TypeScript를 쓰고 → 설치하고 → 세션에서 핫 리로드**까지 처리합니다. 툴을 쓰는 주체와 툴을 고치는 주체가 같아지는 구조입니다.

Anthropic이 모드를 만든 이유도 분명합니다. **"개발자들이 우리가 기능을 출시할 때까지 기다리지 않고, Claude Code가 동작하는 방식을 더 통제하고 싶어 했다"** 는 것입니다. 설정 훅으로는 이벤트 재작성·UI 그리기·기능 대체가 안 됐기 때문입니다. 회사는 **출시 전에 설계를 GitHub에 먼저 공개해 피드백**을 받았다고 밝혔습니다.

또 **내장 기능을 모드로 전환**하는 흐름도 시작됐습니다. `/diff`가 대표적인데, 이제 사용자는 이를 **끄거나 자기 버전으로 교체**할 수 있습니다. Anthropic의 구상은 **"코어는 작게 유지하고, 필요한 기능만 골라 붙이는"** 방향입니다. 여러 모드가 같은 이벤트에 걸리면 **로드 순서대로 실행**돼, 서로 다른 제작자의 모드를 **겹쳐 쌓을 수** 있습니다.

### 4) 팀·엔터프라이즈 — 통제와 감사가 함께 온다

모드는 **플러그인에 담겨 배포**되므로 **기존 플러그인 통제가 그대로 적용**됩니다. 관리자는 **마켓플레이스를 허용하거나 차단**할 수 있고, **Team·Enterprise 플랜에서는 관리 콘솔에서, Claude API·서드파티 API 플랜에서는 관리 설정을 사용자 기기에 푸시**하는 방식으로 통제합니다.

보안 측면의 설계도 눈에 띕니다. **프로덕션 설정을 건드리는 명령에는 확인을 강제**하는 안전장치, 그리고 **가장 먼저 로드된 모드가 다른 모든 모드의 호출을 기록하는 감사(audit) 로깅** 같은 패턴이 가능합니다. 반대로, 모드는 **샌드박스가 아니라 Claude Code와 동일한 권한**으로 실행되므로, **출처를 신뢰할 수 있는 모드만 설치**해야 한다는 것이 Anthropic의 명시적 경고입니다.

## 📉 영향 — 사용자·개발자에게 뭐가 달라지나

**일반 사용자 입장에서는** 당장 눈에 보이는 요금·성능 변화는 아닙니다. 다만 **툴의 생김새와 동작이 팀·사용자 취향에 맞게 바뀔 수 있는 토대**가 마련됐습니다. 불필요한 내장 기능을 걷어내고, 사내 규칙에 맞는 화면·동작을 얹는 식입니다. 에이전트가 **회사 규정을 코드로 강제**하기 쉬워지면, 결과물의 일관성에도 간접적으로 영향이 갑니다.

**개발자·운영자 입장에서는** 네 가지가 실무 포인트입니다. 첫째, **자동화의 자유도**가 올라갑니다. 민감정보 마스킹, 위험 명령 차단, 승인 자동화를 **프롬프트가 아니라 툴 내부 로직**으로 구현할 수 있습니다. 둘째, **배포·표준화**입니다. 모드를 플러그인으로 패키징해 **디렉터리로 공유**하면, 팀 단위로 같은 동작을 강제하기 쉬워집니다. 셋째, **보안 책임이 함께 커집니다.** 샌드박스가 아니라는 점은 곧 **모드가 곧 코드 실행**이라는 뜻이므로, 도입 전 검토가 필요합니다. 넷째, **커스터마이징 역량이 차별점**이 됩니다. 코딩 에이전트를 사내 업무에 맞게 뜯어고치는 팀과, 기본 설정 그대로 쓰는 팀의 격차가 벌어질 수 있습니다.

## 🔭 전망

짚어볼 지점은 세 가지입니다. 첫째, **'작은 코어 + 모드' 구조의 확산**입니다. 내장 기능이 모드로 계속 옮겨가면, Claude Code는 **사용자가 자기에게 필요한 것만 조립하는 툴**로 진화합니다. 둘째, **생태계·거버넌스가 관건**입니다. 모드가 쏟아지면 **디렉터리 품질 관리와 악성·과도한 권한 모드의 위험**이 커지므로, 관리자 통제와 감사 도구의 완성도가 채택을 좌우합니다. 셋째, **경쟁 축의 이동**입니다. 모델 성능·요금 다음의 경쟁력이 **"툴이 얼마나 개방적이고 확장 가능한가"** 로 옮겨가는 신호로 읽힙니다. 개발자 입장에서는 **"기다리는 사용자"에서 "만드는 사용자"로** 역할이 바뀌는 셈입니다.

## 🧭 정리 & 참고 팁

- **핵심 한 줄:** **Anthropic이 Claude Code 안에 '모드'라는 확장 지점을 열어, 개발자가 에이전트의 동작·화면·기능을 직접 바꿀 수 있게 했다** — 모델 뉴스가 아니라 **툴 확장성 뉴스**입니다
- **개발자라면:** 위험 명령 차단·비밀값 마스킹·권한 자동화처럼 **프롬프트로 하던 통제를 모드로 옮길 수 있는지** 점검해 볼 만합니다. 단, 샌드박스가 아니므로 **검토 없이 설치하지 않는 것**이 원칙입니다
