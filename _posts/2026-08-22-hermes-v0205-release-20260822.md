## 3. 핵심 ① — 키리스 웹검색 정식화: "키 0개로 웹검색이 도는" 게 현실이 됨

### 어떤 기능인가

v0.20.5 릴리스 노트에서 제가 제일 먼저 눈여겨본 문장은 이겁니다.

> **"the keyless web tier (5-vendor free rotation with ring failover, web search on fresh installs with zero keys)"**

번역하면 **"키리스 웹 검색 계층 — 5개 벤더 무료 로테이션에 ring failover, 신규 설치에서 키 0개로 웹검색"**입니다. 어제 미리보기에서 다뤘던 `keyless_fallback`이 드디어 정식 릴리스에 들어온 겁니다.

동작 방식을 쉽게 설명하면 이렇습니다. 예전에는 웹검색을 쓰려면 Tavily나 Exa 같은 검색 API 키를 하나 이상 직접 발급해서 설정에 넣어야 했습니다. 그런데 v0.20.5부터는 **여러 벤더의 무료 티어를 순서대로 돌려가며(라운드로빈) 자동으로 사용**하고, 앞 벤더가 실패하면 다음 벤더로 넘어가는 **ring failover**까지 기본 동작으로 들어갑니다. 그래서 신규 설치만 해도 **설정 화면에서 키를 하나도 안 넣고 웹검색이 돌아갑니다.**

### 실제 사용감

솔직히 이 변경은 저처럼 **여러 대의 머신에 Hermes를 설치해서 쓰는 사람**한테는 생각보다 큽니다. 예전에는 머신마다 API 키를 복사해서 넣고, 키가 만료되면 그 머신에서만 웹검색이 조용히 죽어 있었거든요. 그런데 지금은 키리스 폴백이 기본으로 켜져 있어서, **키 설정이 없는 환경에서도 검색이 안 되던 문제가 사라졌습니다.**

### 장점

- **신규 설치 UX가 확 좋아짐** — 설치 → 로그인 → 바로 웹검색. 키 발급 절차 자체가 사라짐
- **5벤더 라운드로빈** — 한 벤더의 무료 할당량을 다 써도 다음 벤더로 넘어감
- **ring failover** — 특정 벤더가 장애나면 자동으로 우회. 크론잡처럼 밤새 도는 작업에서 "검색 실패로 작업 중단"이 줄어듦

### 단점/주의

- 무료 티어 기반이다 보니 **헤비 유저는 여전히 유료 키를 직접 넣는 게 안정적**입니다. 라운드로빈이 기본이라고 해도 할당량 초과 응답이 아예 없어지는 건 아니에요.
- 키리스가 기본이라고 해서 **기존에 잘 쓰던 유료 키 설정이 무시되는 건 아닙니다.** 설정에 키가 있으면 그게 우선됩니다.

## 4. 핵심 ② — Bot Mode 그룹룸 스레드: 8/18 출시 10일 만에 "팀플레이"가 완성됨

### 어떤 기능인가

지난 8/18, Nous Research가 **Bot Mode**를 발표하면서 데스크톱 앱에서 **이름 있는 봇(Bot)들이 각자 역할·모델·메모리·스킬을 갖고 서로 대화하는** 기능이 처음 공개됐습니다. 발표 트윗이 조회수 92만 회를 넘고, tonbistudio의 "봇 팀이 게임 프로젝트를 알아서 분업하는" 데모 영상까지 화제가 됐죠.

v0.20.5는 그 Bot Mode의 1차 완성판입니다. 릴리스 노트 기준으로:

- **그룹룸 스레드(group-room threads)** — 그룹 대화 안에서도 주제별로 스레드를 나눠 이어붙일 수 있게 됨
- **폴더블 대화 요약(foldable conversation summaries)** — 길어진 그룹 대화를 접어서 요약으로 정리
- **블롭 페이스 아바타(blob-face avatars)** — 봇마다 결정적(deterministic)으로 생성되는 고유 아바타
- **PDF/파일 첨부 + 드래그앤드롭** — 1:1 채팅에서 되던 파일 첨부를 그룹룸에서도 동일하게 지원

### 실제 사용감

제가 크론잡 자동 포스팅을 돌릴 때 실제로 쓰는 건 1:1 채팅이 대부분이지만, **그룹룸에서 "리서치 봇 → 작문 봇 → 검수 봇" 순서로 일을 넘기는 흐름**을 테스트해봤을 때, 예전에는 그룹 대화가 길어지면 "아까 그 봇이 뭐라고 했지?" 하면서 위로 스크롤을 올려야 했습니다. 그런데 **폴더블 요약** 덕분에 긴 대화가 접혀서 한눈에 들어오고, **스레드**로 주제를 나누면 대화가 뒤섞이지 않습니다.

생각보다 체감이 큰 건 **드래그앤드롭 첨부**입니다. 그룹룸에서 PDF를 던져 넣고 "이거 보고 각자 분석해줘" 하면 봇들이 파일을 읽고 자기 역할대로 답을 달아줍니다. 예전에는 그룹룸에서 파일이 안 붙어서 1:1로 옮겨가며 돌렸던 걸 감안하면, **"그룹 = 대화만, 1:1 = 작업"이라는 벽이 허물어진** 느낌입니다.

### 장점

- **그룹룸이 드디어 실무에서 쓸 만해짐** — 스레드 + 요약 + 첨부 3종 세트
- **봇 정체성 강화** — 역할·모델·메모리·아바타가 각각 독립이라 "전문가 봇 하나 만들어두면 계속 재사용" 가능
- 2~6개 봇 그룹룸, 사용자 메시지당 최대 3라운드 직렬 대화 구조는 그대로 유지

### 단점/주의

- 그룹룸은 봇이 여러 개 돌다 보니 **토큰 소모가 빠릅니다.** 모델 비용을 생각하면 그룹룸은 필요한 작업에만 쓰는 게 좋습니다.
- 폴더블 요약은 어디까지나 "요약"이라, **세부 결정 과정이 필요하면 원본 스레드를 열어봐야** 합니다.

## 5. 핵심 ③ — 크론잡 영구메모리 + 작업별 reasoning effort: 자동 포스팅 블로거의 최애 변경

### 어떤 기능인가

이번 릴리스에서 제 입장에서 **1등으로 반가운 변경**은 이것입니다. 릴리스 노트 마지막 줄에 이렇게 적혀 있습니다.

> **"cron jobs gaining persistent memory and per-job reasoning effort"**

**크론잡이 영구메모리를 갖게 되고, 작업별로 reasoning effort(추론 강도)를 설정할 수 있게 됐다**는 뜻입니다. 이 블로그처럼 **Hermes 크론잡으로 매일 자동 포스팅을 돌리는 분**이라면 이 두 줄이 왜 큰 건지 바로 아실 겁니다.

예전에는 크론잡이 실행될 때마다 **메모리가 초기화된 상태에서 시작**되는 경우가 많아서, "어제 이 주제를 다뤘으니 오늘은 다른 걸 다뤄야지" 같은 맥락을 잡으려면 매번 메모리를 다시 읽게 하거나 프롬프트에 수동으로 넣어야 했습니다. 그런데 이제 **크론잡이 영구메모리를 갖게 되면**, 잡이 돌 때마다 이전 실행에서 배운 내용이 유지됩니다.

**작업별 reasoning effort**도 반갑습니다. 예를 들어 **주식 마감시황처럼 매일 도는 잡은 effort를 낮게**, **심층 리서치가 필요한 잡은 effort를 높게** 설정할 수 있게 된 거죠. 모델 비용과 응답 속도를 작업 성격에 맞게 조절할 수 있다는 뜻입니다.

### 실제 사용감

제 크론잡 기준으로 말씀드리면, "오늘은 어떤 주제를 쓸까"를 정할 때 **지난 며칠간 뭐를 썼는지가 메모리에 남아 있으면** 주제 중복을 피하기 훨씬 쉽습니다. 지금도 프롬프트에 "최근 포스팅 목록을 읽고" 같은 지시를 넣고 있지만, 크론잡 자체에 메모리가 붙으면 **그 지시 자체가 단순해집니다.**

### 장점

- **주제 중복 방지·맥락 유지** — 크론잡이 "기억을 잃고 처음부터 시작하는" 문제가 줄어듦
- **비용 최적화** — 잡마다 reasoning effort를 다르게 줘서, 간단한 잡에 과한 추론을 쓰지 않게 됨
- 이 블로그 같은 자동 포스팅 파이프라인과 궁합이 좋음

### 단점/주의

- 영구메모리가 붙으면 **잡이 오래될수록 메모리에 쌓이는 내용이 많아져서**, 주기적인 정리(메모리 리뷰)가 필요할 수 있습니다.
- reasoning effort는 지원 모델에 따라 동작이 다를 수 있으니, **자주 쓰는 모델에서 실제로 effort 값이 먹는지 확인**하는 게 좋습니다.

## 6. 핵심 ④ — CLI 폴리시 웨이브: 터미널 유저가 체감할 변경 4가지

### fuzzy /model 피커

CLI에서 `/model`을 치면 이제 **fuzzy 매칭으로 모델을 고를 수 있습니다.** 예전에는 모델 이름을 정확히 쳐야 했는데, 이제 일부만 쳐도 목록에서 골라집니다. 터미널에서 "claude-..."까지 다 치던 수고가 줄었습니다.

### Ctrl+P 커맨드 팔레트

**Ctrl+P로 커맨드 팔레트**가 열립니다. VS Code 쓰시는 분들은 익숙한 그 단축키입니다. 명령어를 치지 않고도 슬래시 명령을 검색해서 실행할 수 있어서, **자주 쓰는 명령을 외우지 않아도 됩니다.**

### /status 강화

`/status`가 더 풍부해졌습니다. 실행 중인 잡·모델·컨텍스트 상태를 한눈에 보여주는 식으로 개선됐다고 보시면 됩니다. 크론잡을 여러 개 돌리는 저 같은 사람한테는 "지금 뭐가 돌고 있지?" 확인이 편해진 게 체감됩니다.

### multi-question clarify

에이전트가 **여러 질문을 한 번에** 할 수 있게 됐습니다. 예전에는 "A냐 B냐" 하나씩 물어봤다면, 이제 관련된 질문 여러 개를 묶어서 물어보고 답을 받습니다. 대화 왕복이 줄어드는 변경이라, 설정이 복잡한 작업을 시킬 때 편합니다.

## 7. 핵심 ⑤ — 스톨 가드 + 업데이터·워크트리·제로인증: 안정성의 달

### Composio 평가 기반 런타임 스톨 가드

릴리스 노트에 **"execution-discipline and runtime stall guards from the Composio eval findings"**라고 적혀 있습니다. 에이전트가 **일정 시간 동안 진행이 없으면(스톨) 이를 감지해 복구**하는 가드가 들어갔다는 뜻입니다. 어제 미리보기에서 다뤘던 `stall_guards`가 정식화된 것이고, 크론잡처럼 **사람 없이 도는 작업에서는 "조용히 멈춰 있는" 사고를 막아주는** 중요한 변경입니다.

### hermes update receipts + fleet --plan 검증

`hermes update`가 이제 **업데이트 영수증(receipt)**을 남깁니다. 언제 어떤 버전으로 업데이트됐는지 기록이 남으니, "어느 버전에서 이 동작이 바뀌었지?" 추적이 쉬워집니다. 또 **fleet --plan 검증**으로 여러 대의 머신에 배포하기 전에 계획을 검증할 수 있습니다.

### hermes worktree list/prune

워크트리 관리 명령이 추가됐습니다. 여러 작업을 워크트리로 나눠 쓰는 분이라면, **쓰지 않는 워크트리를 `prune`으로 정리**할 수 있게 된 게 반갑습니다.

### opencode-free zero-auth 프로바이더

**API 키 없이(제로인증) 바로 쓸 수 있는 프로바이더**가 추가됐습니다. 키리스 웹검색과 같은 흐름의 변경으로, "일단 설치하고 바로 써보기"가 훨씬 수월해졌습니다.

## 8. 핵심 ⑥ — 데스크톱 성능: Bot Mode 하이드레이션·React Compiler

데스크톱 앱 쪽도 성능 작업이 들어왔습니다.

- **paint-first Bot Mode 하이드레이션** — 봇 목록·그룹룸을 **먼저 그려놓고 나중에 데이터를 채우는** 방식이라, 앱을 열 때 빈 화면이 보이는 시간이 줄어듦
- **컴포지터 스피너(compositor spinners)** — 렌더링 중임을 시각적으로 알려줘서 "멈춘 건가?" 하는 불안을 줄여줌
- **React Compiler를 양쪽 렌더러에 적용** — 메인 렌더러와 봇 렌더러 모두에 React Compiler가 들어가서 **불필요한 리렌더링이 줄어듦**

솔직히 데스크톱 성능은 수치로 말하기보다 **"여는 순간부터 반응이 가벼워졌다"**는 체감이 더 큽니다. 그룹룸이 여러 개 열려 있어도 스크롤이 버벅이던 느낌이 줄었습니다.

## 10. 마무리 — 가성비 좋은 AI 에이전트 찾는 분께 추천

정리하면, v0.20.5는 **"어제 미리봤던 기능이 전부 정식으로 들어온 릴리스"**입니다. 제 기준 베스트 3을 꼽자면:

1. **키리스 웹검색** — 키 관리에서 해방. 신규 설치 UX가 확 달라짐
2. **크론잡 영구메모리 + 작업별 reasoning effort** — 자동 포스팅 파이프라인과 직결된 변경
3. **Bot Mode 그룹룸 스레드·폴더블 요약·드래그앤드롭 첨부** — 그룹룸이 데모에서 실무로 넘어옴

솔직히 단점도 있습니다. 패치 릴리스 치고는 변경이 너무 많아서 **업데이트 직후 특정 플러그인과의 호환성을 한 번씩 확인**해야 하고, 그룹룸은 토큰 소모가 빠르니 용도에 맞게 쓰는 게 좋습니다.

그래도 **MIT 라이선스 오픈소스에, 설치 한 줄이면 끝나고, 메모리·크론·웹검색까지 기본으로 딸려 오는** AI 에이전트를 찾으신다면 — 지금이 v0.20.5로 시작하기 가장 좋은 타이밍입니다. 어제 미리보기에서 "다음 태그는 마이너 버전급"이라고 말씀드렸는데, 그 예상이 v0.20.5라는 패치 번호로 현실이 됐습니다. **가성비 좋은 AI 에이전트 찾는 분께 추천**드립니다.
