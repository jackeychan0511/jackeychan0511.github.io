> **📌 한줄 요약:** 2026년 8월 21일 아침 기준, Hermes Agent의 최신 정식 릴리스는 여전히 **v0.20.4(v2026.8.18)**입니다. 하지만 GitHub main 브랜치는 어제 실측(352커밋)보다 하루 만에 **약 688커밋**까지 늘었고, 작성일 기준 **8/18 206건 → 8/19 259건 → 8/20 279건**으로 사흘 연속 커밋이 증가했습니다. 오늘은 그중 제 기준 체감이 큰 것만 골라 정리했는데요 — **① API 키 없이 웹검색이 도는 키리스 5벤더 라운드로빈(keyless_fallback/keyless_rescue)**, **② 데스크톱 테마 대개편(GitHub 테마·Nous 블루·글래스 기본 ON·플러그인 테마 SDK)**, **③ Bot Mode 그룹룸 UX 클러스터**, **④ max_turns 무제한 기본값 전환 + 실행 예산·스톨 가드**, **⑤ Windows 데스크톱 업데이트 'Updating Hermes' 멈춤 수정**까지입니다.

## 이 글을 읽으면 알 수 있는 것

- v0.20.4(8/18) 이후 **main에 688커밋**이 쌓인 실측 근거와, 커밋 페이스가 사흘 연속 빨라지고 있는 이유
- **키리스 웹검색** — `keyless_fallback: true`가 기본으로 켜지며 무슨 일이 벌어지는지, 5개 벤더 라운드로빈과 원샷 리스큐 동작 방식
- **데스크톱 테마 대개편** — GitHub 테마 2종·Nous 블루·글래스 기본 ON·액센트 피커 플러그인, 그리고 **플러그인이 테마를 바꾸는 SDK(theme surface)** 공개
- **Bot Mode 그룹룸 UX 클러스터** — Shift+Enter 개행·최신 메시지로 열기·늦은 답변 수확·로스터 그룹 삭제가 뭘 고쳤는지
- **max_turns 무제한 기본값** — \"조용한 중간 절단(silent mid-task truncation)\"을 없앤 이유와, 실행 예산(`run_budget_seconds`)·스톨 가드(`stall_guards`)의 실제 동작
- **Windows 데스크톱 업데이트 수정** — \"Updating Hermes\"에 멈춰 있던 문제(#90937)가 고쳐진 내용
- 크론잡 자동화 관점에서 반가운 수정과, 다음 릴리스(v0.21.0 예상) 대비 사용 팁

## 3. ⭐ 키리스(keyless) 웹검색 — API 키 없이 5벤더 라운드로빈, 이게 오늘의 1등 소식

제 기준 **오늘 가장 반가운 변경**입니다. 웹 검색·추출 툴이 **API 키가 하나도 없어도 무료 티어로 알아서 돌아가게** 됐습니다.

- **`feat: keyless web tier becomes a 5-vendor round-robin ring (adds Tavily, Firecrawl, Keenable)`** (8/20) — 키리스 무료 티어가 **Exa / Parallel / Tavily / Firecrawl / Keenable 5개 벤더 라운드로빈**이 됐습니다. 하나가 막히면 다음 벤더로 넘어갑니다.
- **`feat: keyless web traffic splits 50/50 between Exa and Parallel like opencode`** (8/20) — 검색 트래픽을 **Exa·Parallel 50/50**으로 분산.
- **`feat: keyless free-tier failover + Tavily/Firecrawl salvage integration`** (8/20) — 키리스 실패 시 **Tavily·Firecrawl 무료 티어로 샐비지(salvage)**.
- **`feat: keyed web backends get a one-shot keyless rescue on failure — never sticky`** (8/20) — **키를 넣어둔 백엔드**라도 호출이 실패하면 **그 호출 한 번만 키리스 링으로 재시도**. 다음 호출은 원래 백엔드로 돌아갑니다(절대 고착되지 않음).

공식 문서(llms-full, 8/21 확인)에도 이미 반영돼 있어서, 설정값까지 그대로 옮겨봅니다.

```yaml
web:
  backend: firecrawl    # firecrawl | searxng | parallel | tavily | exa
  # 용도별로 따로 섞는 것도 가능 (예: 무료 검색 + 유료 추출)
  search_backend: "searxng"
  extract_backend: "firecrawl"

  # 키리스 무료 티어 폴백 (기본: true)
  # 백엔드 설정도 키도 없으면 Exa/Parallel/Tavily/Firecrawl/Keenable
  # 무료 티어를 돌아가며 사용. false로 끌 수 있음.
  keyless_fallback: true

  # 원샷 키리스 리스큐 (기본: true)
  # 선택한(키 있는) 백엔드가 실패하면 그 호출만 키리스 링으로 재시도.
  # 다음 호출은 다시 원래 백엔드 (never sticky).
  keyless_rescue: true

  # Exa/Parallel 티어 고정 (hermes tools의 Free/Paid 행에서 설정)
  # free = 항상 익명 엔드포인트, paid = 항상 키드 SDK, unset = 자동
  provider_tier:
    parallel: free
    exa: paid
```

| 백엔드 | 환경변수 | 검색 | 추출 |
|:-------|:---------|:----:|:----:|
| **Firecrawl** (기본) | `FIRECRAWL_API_KEY` | ✔ | ✔ |
| **SearXNG** | `SEARXNG_URL` | ✔ | — |
| **Parallel** | `PARALLEL_API_KEY` (선택 — 키리스 무료 티어) | ✔ | ✔ |
| **Tavily** | `TAVILY_API_KEY` (선택 — 키리스 지원) | ✔ | ✔ |
| **Exa** | `EXA_API_KEY` (선택 — 키리스 무료 티어) | ✔ | ✔ |

솔직히 저처럼 **블로그 리서치를 Hermes에 맡기는 분**이라면, \"웹 검색 키가 만료됐는데 조용히 실패하던\" 스트레스가 꽤 컸거든요. 이제는 키가 없어도 돌고, 키가 있어도 실패하면 한 번은 키리스로 살려주니, **크론잡이 새벽에 돌다가 백엔드 장애로 죽는 일이 확 줄어들** 것 같습니다. `hermes tools` 화면에서 Free/Paid 행으로 티어까지 고정할 수 있는 것도 좋고요.

- **`feat(desktop): an accent picker plugin, off by default`** (8/20) — **액센트 컬러 피커가 플러그인**으로 분리(기본 OFF). 원하는 사람만 켜는 구조.

- **`fix(desktop): off means off when glass is turned down`** (8/20) — 글래스 OFF는 진짜 OFF. 반투명 잔상이 남던 문제 수정.

### ② ⭐ 플러그인이 테마를 바꾼다 — theme surface SDK (#91018)

- **`feat(desktop): let plugins switch the theme, and document the theme surface (#91018)`** (8/20) — **플러그인이 데스크톱 테마를 바꿀 수 있는 SDK 표면(theme surface)**이 공개됐습니다.
- **`docs: document the desktop plugin SDK theme surface`** (8/20) — 문서화까지 완료.
- **`feat(desktop): let plugins switch the theme from outside React`** (8/20) — React 외부에서도 테마 전환 가능.

이건 사소해 보이지만 **플러그인 생태계에 꽤 큰 변화**입니다. \"다크 모드 플러그인\", \"세피아 테마 플러그인\" 같은 게 **설치만 하면 앱 전체 테마를 바꾸는** 구조가 되거든요. 어제 정리해드린 `hermes://plugin/install` 딥링크 원클릭 설치와 합쳐지면, \"테마 플러그인을 웹에서 클릭 한 번으로 설치\"가 성립합니다.

## 5. Bot Mode — 그룹룸 UX 클러스터, \"그룹챗이 실제로 일할 수 있게\" 다듬는 중

어제 그룹챗 이미지·파일 첨부 패리티를 정리해드렸는데, 오늘은 **그룹룸을 실제로 쓰면서 부딪히는 UX 문제**를 한꺼번에 고치는 커밋들이 몰려왔습니다.

- **`fix(bot-mode): group-room UX cluster — Shift+Enter newlines, open-at-latest, late replies harvested (#89884, #89894)`** (8/20) — 그룹룸에서 **Shift+Enter 개행**, 방을 열 때 **최신 메시지로 스크롤(open-at-latest)**, **늦게 도착한 답변 수확(late replies harvested)**까지. 멀티턴 그룹 대화에서 \"답변 순서가 꼬이던\" 문제가 줄어듭니다.
- **`fix: retained group panes re-anchor to the latest message on reopen`** (8/20) — 보존된 그룹 패널을 다시 열면 **최신 메시지에 재정렬**.
- **`fix(desktop): expose group deletion from roster rows`** (8/19) — **로스터에서 그룹 삭제**가 가능해짐. (어제까지는 어디서 지우는지 찾기 어려웠습니다.)
- **`fix: disband tombstones no longer hold the group name or leak into storage`** / **`fix: disbanded group chats no longer resurface as empty roster rows`** (8/20) — 해산한 그룹이 **이름을 붙들고 있거나 빈 로스터 행으로 되살아나던** 문제 수정.
- **`fix(bot-mode): recreating a same-name group mints fresh member sessions`** (8/19) — 같은 이름으로 그룹을 다시 만들면 **새 멤버 세션이 깨끗하게 생성**.
- **`fix(bot-mode): group chat opens as one room pane, not two (#89788)`** (8/20) — 그룹챗이 **메인 탭 옆에 두 개로 열리던** 문제 수정.
- **`fix(bot-mode): group-chat members' clarify questions surface in the room and are answerable (#90694)`** (8/20) — 멤버 봇의 **질문(clarify)이 방에 표시되고 답변 가능**.
- **`fix(bot-mode): group-chat command approvals surface in the room too`** (8/20) — **명령 승인 요청도 방 안에서** 처리.

## 6. 에이전트 런타임 — max_turns 무제한 기본값 + 실행 예산 + 스톨 가드

### ① ⭐ `agent.max_turns` 기본값이 \"무제한\"으로 바뀜

- **`feat(config): default agent.max_turns to unlimited; accept inf/infinity/null spellings`** (8/20) — 기본값이 **무제한**으로 전환되고, `none`/`null`/`unlimited`/`inf`/`infinity`/`infinite`/`0`/`-1` 표기를 모두 인정.

공식 문서에 이유가 명확히 적혀 있습니다. **\"턴 제한이 문제를 해결하기보다 더 많이 만들었다(silent mid-task truncation — 작업 중간에 조용히 잘려나감).\"** 그래서 이제는 기본이 끝까지 달리는 쪽이고, 제한을 걸고 싶은 사람만 양의 정수로 걸면 됩니다.

```yaml
agent:
  max_turns: none   # 대화 턴당 반복 횟수 (기본: none = 무제한)
                    # 양의 정수로 제한. none/null/unlimited/inf/infinity/infinite/0/-1 = 무제한
```

### ② wall-clock 실행 예산 — `run_budget_seconds`

- **`feat: wall-clock run budget — wrap-up injection at 80% and deadline-scaled stale timeouts (agent.run_budget_seconds)`** (8/19) — 원샷/평가 하네스 실행처럼 **외부 상한(예: 태스크당 900초)** 아래에서 도는 경우를 위한 **벽시계 예산**.

```yaml
agent:
  run_budget_seconds: null   # 기본: 꺼짐
```

```bash
hermes chat --run-budget 850 -q "..."
```

동작은 두 가지입니다. **① 예산의 80%**가 지나면 \"새 조사·검증을 멈추고 지금 가진 상태로 최종 결과물을 내라\"는 **원타임 공지**를 주입하고, **② 암묵적 stale 타임아웃**(기본 90초, 추론 모델은 600초+)을 **max(60, 남은 예산 × 0.5)**로 조여서, **한 번의 멈춘 provider 호출이 실행 전체를 삼키지 못하게** 합니다. \"거의 다 끝내놓고 마지막 한 줄 생성 직전에 타임아웃\" 나던 크론잡/배치가 확 줄어들 시나리오입니다.

### ③ 스톨 가드 — `stall_guards` (기본 ON)

- **`feat: runtime stall guards — identical-call loop breaker and continue-intent recovery (agent.stall_guards)`** (8/19) — 두 가지 가드를 켭니다.

1. **동일 호출 루프 브레이커** — 같은 툴을 **같은 인자로 3회 연속** 호출하고 **결과까지 동일**하면, 그 결과에 \"이 호출을 반복하지 말라\"는 한 줄 공지를 덧붙임(호출 자체는 차단 안 함). `process`·`*_poll` 같은 정당한 폴러는 예외.
2. **계속-의도 복구(continue-intent recovery)** — 모델이 툴 호출 없이 턴을 끝내면서 **\"Let me now update the file…\"처럼 행동을 예고만 하고 끝나면**, 턴당 최대 2회까지 **행동하도록 재프롬프트**.

덤으로 **결과-참조 스터빙**도 붙었습니다. **`feat: identical re-calls enter context as reference stubs, not duplicate payloads`** (8/20) — 재발행된 동일 호출의 바이트 동일 결과는 **중복 페이로드 대신 짧은 참조 스텁**으로 컨텍스트에 들어가서, 토큰 낭비와 컨텍스트 비대를 줄입니다.
