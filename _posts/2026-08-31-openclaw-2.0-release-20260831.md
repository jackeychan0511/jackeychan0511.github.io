> **📌 한줄 요약:** 오늘(8/31) 오픈클로(OpenClaw) 공식 문서에 **v2026.8.1, 일명 'OpenClaw 2.0' 릴리스 노트 초안**이 공개됐습니다. 가장 큰 변화는 **세션·트랜스크립트 저장을 SQLite로 전환**하는 것과, **QMD 메모리를 퇴역시키고 빌트인 메모리로 통합**하는 것입니다. 여기에 **개인 대화 간 회상(Recall) 기본 활성화**, **세션 리와인드·포크·브랜치 전환**, **Codex/ChatGPT/Claude 로그인 재사용 온보딩**, **GPT-5.6 기본 모델**까지 포함된 대형 업데이트입니다. 릴리스 노트에는 'Draft(초안)' 배너가 붙어 있고, 'OpenClaw 2.0, Accidentally(우연히)'라는 에디토리얼이 함께 링크돼 있어 **안정판 출시가 정말 임박**했음을 시사합니다. 오늘 실측 기준 GitHub 스타는 **388,096개(+80)**, npm 베타 채널은 **2026.9.1-beta.1**입니다.

## 1. 도입 — 요즘 저처럼 "어제 글 쓰고 나서 또 큰일 났네" 하시는 분들

요즘 저처럼 **OpenClaw 릴리스 소식을 매일 실측해서 정리하시는 분들**, 많으시죠. 어제(8/30)는 **Matrix 멀티 에이전트 통신 머지**와 **9월 트레인 첫 베타 v2026.9.1-beta.1**을 정리해드렸는데요. 그 글을 쓰고 난 뒤 하루도 안 돼서 **또 큰 소식**이 터졌습니다.

오늘 아침 공식 문서 사이트(docs.openclaw.ai)를 열어보니, **v2026.8.1 릴리스 노트 페이지가 통째로 새로 올라와 있더라고요.** 그런데 제목이 무려 **"v2026.8.1 (AKA OpenClaw 2.0)"**입니다. AKA, 즉 '일명 OpenClaw 2.0'이라는 뜻이죠. 솔직히 처음엔 "어? 8.1은 8월 트레인이잖아? 벌써 2.0이라고?"라는 생각이 들었습니다.

그런데 자세히 보니 이게 단순한 버전 넘버링이 아니었습니다. **세션 저장을 SQLite로 바꾸고, QMD 메모리를 퇴역시키고, 개인 대화 간 회상을 기본으로 켜는** — 지금까지의 OpenClaw와는 '저장 구조가 다른 프로그램'이 되어버린 수준의 변화라서, 팀에서도 이걸 2.0이라고 부르기로 했다는 거죠. 게다가 페이지 상단에는 **"OpenClaw 2.0, Accidentally"**라는 에디토리얼이 링크돼 있었습니다. "2.0이 우연히 되었다"니, 이건 좀 제대로 파봐야겠다 싶어서 오늘도 GitHub·npm을 실측하고, 릴리스 노트 초안을 구석구석 정리해봤습니다.

이번 글에서는 **핵심 뉴스 → 실측 데이터 → 타임라인 → 장점 → 단점 → 업그레이드 팁** 순서로, 지금 OpenClaw를 쓰고 있거나 써보려는 분들께 솔직하게 풀어볼게요.

## 2. 핵심 뉴스 — v2026.8.1 릴리스 노트 초안 공개, "일명 OpenClaw 2.0"

### 2-1. 릴리스 노트 초안과 "OpenClaw 2.0, Accidentally"

오늘(8/31) 확인한 docs.openclaw.ai의 [v2026.8.1 릴리스 노트 페이지](https://docs.openclaw.ai/releases/2026.8.1)는 이렇게 시작합니다.

> "Warning: Draft release notes — This page is under active editorial review and does not represent the final v2026.8.1 release notes."
> (초안 릴리스 노트 — 현재 편집 검토 중이며 최종 v2026.8.1 릴리스 노트가 아닙니다.)

아직 '초안' 단계지만, **이미 정식 페이지로 공개**됐다는 것 자체가 출시가 임박했다는 신호입니다. 그리고 "이번 릴리스의 스토리가 궁금하면 **'OpenClaw 2.0, Accidentally'**를 읽어보라"고 안내하고 있는데, 제목에서 풍기는 뉘앙스대로 **처음부터 2.0을 계획한 게 아니라, 변경이 워낙 커지다 보니 2.0이 '우연히' 되어버렸다**는 스토리로 보입니다.

릴리스 노트 초안은 이렇게 요약하고 있습니다.

> "This update touches every part of OpenClaw, including installation, messaging, memory, skills, models, automations, the browser and native apps, plugins, security, and many smaller fixes."
> (이번 업데이트는 설치·메시징·메모리·스킬·모델·자동화·브라우저·네이티브 앱·플러그인·보안 등 OpenClaw의 모든 부분을 건드립니다.)

### 2-2. 가장 큰 변화 1 — 세션·트랜스크립트 저장이 SQLite로

릴리스 노트 초안에서 가장 눈에 띄는 건 **저장 구조의 전환**입니다.

> "This release changes how sessions and transcripts are stored by moving them into SQLite."
> (이번 릴리스는 세션과 트랜스크립트 저장 방식을 SQLite로 전환합니다.)

그리고 이렇게 경고도 붙어 있습니다.

> **Storage and downgrade warning**: Before downgrading to an older file-backed release, use the current CLI to restore archived legacy transcript artifacts; sessions created after the migration will not appear in older releases.
> (다운그레이드 경고: 구버전(파일 기반)으로 내리기 전에 현재 CLI로 레거시 트랜스크립트를 복원하세요. 마이그레이션 이후 생성된 세션은 구버전에서 보이지 않습니다.)

즉, **한번 SQLite로 넘어가면 예전 버전으로 돌렸을 때 새 세션이 안 보일 수 있다**는 뜻입니다. 그래서 공식 문서도 **업그레이드 전 verified backup(검증된 백업)을 만들고, 다운그레이드 절차를 먼저 검토하라**고 강조합니다. 개인적으로 이건 "2.0은 진짜 저장 엔진까지 바꾸는 큰 건"이라는 방증이라고 봅니다.

### 2-3. 가장 큰 변화 2 — QMD 퇴역, 빌트인 메모리로 통합

메모리 쪽도 대격변입니다. 그동안 OpenClaw 커뮤니티에서 많이 쓰던 **QMD(Queryable Memory Database) 방식이 퇴역**하고, **빌트인 메모리가 검색·회상의 핵심 경로를 전담**하게 됩니다.

- **개인 대화 간 회상 기본 활성화**: "eligible personal Claw"에서는 같은 에이전트의 다른 비공개 대화에서도 관련 맥락을 회상할 수 있습니다. 물론 그룹·채널·공유 알리어스·삭제된 기록·정책상 차단된 소스는 제외되고, DM 격리 설정이 있으면 그게 우선입니다.
- **마이그레이션**: QMD를 쓰던 분들은 `openclaw doctor --fix`로 퇴역 설정을 정리하고, 지원되는 경로·인덱싱 설정을 이전하며, 호환되는 기존 행은 유지한 채 **캐노니컬 Markdown에서 인덱스를 재구축**합니다. 다만 QMD 전용 reranking·쿼리 확장·에이전트 간 트랜스크립트 검색은 퇴역합니다.
- **세션 연속성**: reset 정책이 없는 세션은 **며칠이 지나도 열린 채 유지**되고, SQLite 기반 채팅(웹·macOS·iOS·Android)은 **아무 사용자 메시지에서나 리와인드(rewind)하고, 포크(fork)하고, 보존된 브랜치를 전환**할 수 있습니다. 리와인드는 트랜스크립트 브랜치만 바꾸지, 파일이나 보낸 메시지 같은 부수 효과를 되돌리진 않습니다.
- **검색 개선**: 파일명·전체/부분 유니코드 경로·설정된 추가 경로를 이해하고, 임베딩 제공자가 못 뜨더라도 키워드 결과는 유지됩니다.

솔직히 이 "리와인드/포크" 기능은 **"아, 이거 AI 에이전트 대화를 실수로 망쳤을 때 되돌릴 수 있구나"** 싶어서 개인적으로 제일 반가운 부분이었습니다.

### 2-4. 온보딩·설치 — "이미 있는 로그인 그대로 쓰세요"

- **AI 연결**: 온보딩이 **Codex·ChatGPT·Claude CLI 로그인, API 키, Ollama·LM Studio 로컬 모델** 중 이미 쓰고 있는 걸 그대로 재사용하는 방식으로 바뀝니다. 그리고 **그 모델이 실제로 답변할 수 있는지 검증한 뒤에야** 저장합니다. OpenAI 신규 설정의 기본 모델은 **GPT-5.6**입니다.
- **로컬 모델**: node-llama-cpp를 걷어내고 **관리형 llama-server**로 전환, RAM 상황에 따라 **Gemma 4**가 기본이고 기본 컨텍스트는 **64K**로 상향됐습니다.
- **설치**: Mac 앱이 Downloads/디스크 이미지에서 열리면 **Applications로 옮길지 제안**하고, Linux/Unix는 셸 시작 파일을 직접 고치지 않아도 새 터미널에서 `openclaw` 명령이 바로 잡힙니다. 그리고 **인증 없이 네트워크에 노출되는 Gateway 설치는 아예 차단**됩니다.

### 2-5. GPT-5.6 풀 패밀리 지원

8.1 트레인에는 이미 **GPT-5.6 Sol·Terra·Luna·Ultra 리즈닝을 OpenClaw와 Codex 런타임 전반에 추가**한 내용(beta.3, 8/24)이 포함돼 있습니다. 2.0 안정판에는 이 모델 지원이 그대로 담길 예정입니다.

### 3-3. 오늘 새벽 메인 브랜치 커밋 실측 (8/31 01:03~01:18 UTC)

오늘 새벽(한국 시간 오전 10시쯤) 메인 브랜치에 머지된 커밋 중 눈에 띄는 것들입니다.

- **feat(workers): snapshot prepared projects before session enrollment (#133447)** — 워커가 세션에 등록되기 전에 준비된 프로젝트를 스냅샷. 클라우드 워커 세션의 신뢰성 개선으로 보입니다.
- **fix: prevent cloud session lifecycle actions from hanging behind worker moves (#133551)** — 워커 이동 중 클라우드 세션 수명주기 작업이 멈추지 않도록 수정
- **fix(sessions): keep failed deletions in cleanup accounting (#133668)** — 실패한 세션 삭제도 정리 대상으로 유지

## 5. 솔직한 장단점 — "이건 주목해야 해" vs "아직은 기다려도 되는"

### ✅ 주목해야 할 것

1. **세션 리와인드·포크·브랜치 전환**: 대화를 실수로 꼬아도 되돌릴 수 있는 기능. AI 에이전트를 실무에 쓰는 사람일수록 이게 얼마나 큰 구원인지 체감할 겁니다.
2. **빌트인 메모리 + 개인 대화 간 회상**: QMD 같은 별도 도구 설정 없이도 "아까 그 대화에서 했던 얘기"를 기억해주는 구조로 바뀝니다. 물론 격리·정책 설정이 우선한다는 점이 마음에 듭니다.
3. **온보딩 간소화**: 이미 있는 Codex/ChatGPT/Claude 로그인을 그대로 쓰고, 로컬 모델도 **검증 후 저장**. "설치하고 모델 연결하다 포기하는" 초보자가 확 줄어들 것으로 보입니다.
4. **인증 없는 네트워크 Gateway 설치 차단**: 보안 측면에서 "안전한 기본값"이 강해진 건 언제나 좋은 소식입니다.

### ⚠️ 아직은 기다려도 되는 것 / 조심할 것

1. **SQLite 마이그레이션은 되돌리기 어렵다**: 릴리스 노트가 직접 경고하듯, **마이그레이션 후 구버전으로 다운그레이드하면 새 세션이 보이지 않습니다.** 2.0이 나오자마자 무작정 올리기보다, **먼저 verified backup을 만들고** 여유 있을 때 올리는 걸 추천합니다.
2. **Matrix 멀티 에이전트는 아직 베타**: 어제 머지된 기능이라 안정판 기준으로는 더 지켜봐야 합니다.
3. **릴리스 노트가 아직 '초안'**: 오늘 공개된 문서는 편집 검토 중입니다. 최종 노트는 내용이 조금 달라질 수 있으니, **안정판이 실제로 나온 뒤 공식 노트를 다시 확인**하는 게 좋습니다.
4. **9월 트레인(2026.9.1)과 병행 주의**: 8월 트레인(2.0)과 9월 트레인이 동시에 돌고 있는 상황이라, 어떤 채널을 쓸지(베타/안정/연장 안정) 먼저 정하고 올라타는 게 편합니다.

## 6. 마무리 — OpenClaw 2.0, 업그레이드 준비는 이렇게

정리하면, 오늘의 OpenClaw는 **"2.0 안정판 출시 직전"**입니다. 지금 OpenClaw를 쓰고 계신 분이라면 이렇게 준비하시는 걸 추천합니다.

2. **백업부터** — 릴리스 노트가 강조한 대로 업그레이드 전 **verified backup** 생성
3. **QMD 쓰시는 분은** — 2.0 적용 후 `openclaw doctor --fix`로 빌트인 메모리로 마이그레이션
4. **안정판 나오면 공식 릴리스 노트 확인 후 적용** — 초안이 아니라 최종본 기준으로

저도 2.0 안정판이 npm 'latest'에 올라오는 순간, SQLite 마이그레이션 실측 후기로 다시 찾아오겠습니다. 그때까지 이 글이 OpenClaw 2.0 준비에 조금이라도 도움이 되길 바랍니다. 🦞
