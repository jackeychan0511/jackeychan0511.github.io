## 1. 요즘 저처럼 "업데이트를 따라가기 벅차신" 분들

요즘 저처럼 **오픈소스 AI 에이전트 Hermes Agent로 블로그 크론잡(자동 예약 작업)을 돌리시는 분들**, 많으시죠. 지난주(8/26) v0.20.4·v0.20.5 패치를 정리해드렸는데, 그 글을 쓰고 나서도 **패치가 멈출 줄을 모릅니다.**

8/13부터 8/27까지 딱 2주 동안, Hermes Agent는 **v0.20.1 → v0.20.2 → v0.20.3 → v0.20.4 → v0.20.5 → v0.20.6, 무려 6번의 롤업(rollup) 패치**를 연속으로 쏟아냈습니다. 그리고 재밌는 게, **이 6개 릴리스 전부가 릴리스 노트에 같은 문장을 적어놨습니다.**

> **"Full curated release notes for this window will ship with v0.21.0."**
> — Hermes Agent v0.20.6 릴리스 노트 (v2026.8.27)

번역하면 **"이번 구간의 전체 큐레이티드 릴리스 노트는 v0.21.0에서 배송됩니다."** 즉 지금 나오는 패치들은 전부 **"큰 그림은 v0.21.0에서 보여줄 테니, 일단 안정판 먼저 깔아둔다"**는 성격이라는 거죠. 솔직히 이렇게 빠르게 달라지는 프로젝트를 보면 "따라가다 지치는 게 정상"이라는 생각이 듭니다. 그래서 오늘은 그 마지막 롤업인 **v0.20.6(v2026.8.27)**을 GitHub API 실측 기준으로 낱낱이 파헤쳐보겠습니다. 보너스로 지난주 CryptoBriefing이 실측한 **OpenRouter 토큰 점유율 1위** 소식도 같이 정리했어요.

## 3. 핵심 업데이트 ① — TTL 웹검색 캐싱: "크론잡이 드디어 같은 걸 두 번 검색 안 합니다"

### 어떤 기능인가

> **"TTL result caching for web_search/web_extract"**
> — Hermes Agent v0.20.6 릴리스 노트 (2026.8.27)

**web_search와 web_extract 결과에 TTL(Time-To-Live, 유효시간) 기반 캐싱**이 붙었습니다. 같은 검색어·같은 URL을 일정 시간 안에 다시 요청하면, 네트워크를 새로 타지 않고 저장해둔 결과를 재사용한다는 뜻입니다.

### 실제 사용감/장점

솔직히 이 변경은 **저처럼 크론잡을 매일 도는 사람에게 이번 패치 최고의 선물**입니다. 크론잡 자동포스팅의 흔한 패턴이 뭐냐면, 여러 잡이 **비슷한 키워드를 비슷한 시간대에 검색**하는 거거든요. 예를 들어 아침 8시 뉴스 잡과 오후 코인 브리핑 잡이 둘 다 "OpenRouter"를 검색한다고 치면, 예전엔 잡마다 매번 네트워크를 타고 검색 API를 소비했습니다. 이제 TTL 안에 들어오는 중복 요청은 **캐시에서 즉시 응답**되니, 토큰 비용과 검색 벤더 호출량(rate limit)이 동시에 아껴집니다.

게다가 **lean-tail 압축이 기본값**이 된 것도 컨텍스트 관리에 좋습니다. 긴 문서를 읽을 때 앞부분(head)과 꼬리(tail)를 압축해서 담는 방식인데, "문서 전체를 통째로 컨텍스트에 넣어 토큰이 터지는" 일이 줄어듭니다. 멀티쿼리 tool_search(여러 검색어를 한 번에)와 형태소 분석까지 합쳐지면, **도구를 "찾는" 단계 자체가 빨라집니다.**

### 단점/주의

- TTL 캐싱은 **뉴스처럼 매번 달라지는 정보에는 주의**가 필요합니다. 캐시 유효시간을 길게 잡으면 "방금 나온 속보"를 놓칠 수 있어요. **속보성 잡은 캐시를 끄거나 TTL을 짧게** 설정하시는 걸 추천합니다.
- 릴리스 노트는 요약만 있고 **설정 키·기본 TTL 값은 v0.21.0 정식 노트에 예고**된 상태라, 실사용 전에 공식 문서의 설정 섹션을 확인해보시는 게 좋습니다.

## 4. 핵심 업데이트 ② — 동의 기반 실제 프로필 브라우징: "브라우저 자동화가 로그인을 기억합니다"

### 어떤 기능인가

> **"consent-gated real-profile browsing (use your default Chromium profile for local browsing, with Windows close-with-approval flow)"**
> — Hermes Agent v0.20.6 릴리스 노트 (2026.8.27)

**로컬 브라우징에 기본 Chromium 프로필을 사용**하는 기능이 추가됐습니다. 지금까지는 브라우저 자동화가 **격리된 임시 프로필**에서 돌아서, 로그인이 필요한 페이지(웹메일·관리자 콘솔·마이페이지)를 자동화하려면 매번 세션을 처음부터 만들거나 쿠키를 우회해서 넣어야 했습니다. 이제 **사용자가 동의하면 평소 쓰는 Chromium 프로필(로그인·확장 프로그램·쿠키 포함)을 그대로 사용**할 수 있습니다. Windows에서는 브라우저를 닫을 때 **close-with-approval(닫기 전 승인)** 절차가 들어가서, "에이전트가 내가 쓰는 브라우저를 함부로 닫지 못하게" 막아줍니다.

### 실제 사용감/장점

이 기능의 가치는 두 가지입니다. 첫째, **"로그인이 필요한 웹 자동화"가 현실화**됐다는 점. 예를 들어 "내 블로그 관리자 페이지에 접속해서 통계를 가져와" 같은 잡이 이제 실제 세션으로 동작할 수 있습니다. 둘째, **프라이버시 통제**가 기능에 처음부터 설계로 들어갔다는 점. 이름부터 **consent-gated(동의 기반)**이고, Windows엔 닫기 승인 절차가 붙어 있습니다. "에이전트가 내 브라우저를 맘대로 써도 되나?"라는 불안을 **동의 → 사용 → 승인** 3단계로 나눠서 관리하는 구조인 거죠.

같이 발표된 **데스크톱 브라우저의 독립 OS 창**도 체감이 큽니다. 에이전트가 브라우저를 열면 이제 Hermes 창 안에 갇히지 않고 **맥/윈도우의 일반 앱 창처럼** 뜨니까, 옆에 두고 진행 상황을 눈으로 확인하기 편합니다.

### 단점/주의

- **동의 기반이라 기본은 꺼져 있습니다.** 기능을 쓰려면 설정에서 실제 프로필 사용에 동의하는 절차를 거쳐야 하고, **평소 프로필에 로그인된 모든 사이트가 에이전트에 노출된다**는 점을 인지하셔야 해요. 민감한 사이트는 별도 프로필을 만들어 쓰는 걸 추천합니다.
- 리눅스/맥의 구체적인 프로필 선택 UI·권한 화면은 **플랫폼별로 조금씩 다르게 배포**되고 있으니, 자기 OS 기준으로 한 번 확인해보세요.

## 5. 핵심 업데이트 ③ — 리모트 MCP 카탈로그 50개+와 운영 안전장치

### 50개 이상 실측 검증된 리모트 MCP 서버

v0.20.6에서 **원격 MCP(모델 컨텍스트 프로토콜) 서버 카탈로그가 대폭 확장**됐습니다. 핵심은 "벤더가 직접 호스팅하는 MCP 서버를 **라이브로 검증(live-verified)**해서 50개 이상 모아뒀다"는 점입니다. Cloudflare, Grafana Cloud, Better Stack, Railway 같은 서비스가 이름을 올렸어요.

이게 왜 좋냐면, **MCP 서버를 직접 띄우는 수고가 사라지기 때문**입니다. 예전엔 "Grafana 데이터를 에이전트한테 물어보게 하려면" 로컬에 MCP 서버를 설치·설정해야 했는데, 이제 카탈로그에서 고르면 벤더 호스팅 서버로 바로 연결됩니다. 헬스체크까지 끝난 서버만 올라가 있으니 **죽은 서버에 연결하는 삽질**도 줄어듭니다.

### 크론·설치·보안 안전장치

이번 패치에서 제가 눈여겨본 운영 쪽 변경입니다.

- **크론 durable-incident ack** — 크론잡이 실패했을 때 **"이 사고는 처리됨"을 영구히 기록**할 수 있게 됐습니다. 자동포스팅을 돌리다 보면 "어제 실패했던 그 잡이 오늘은 왜 조용하지?" 싶을 때가 있는데, ack가 남아 있으면 **놓친 실패가 묻히지 않습니다.**
- **업데이터의 컨트롤 소켓 일시정지** — 예전엔 업데이트가 게이트웨이(메신저 연동 프로세스)를 **트리 킬(강제 종료)** 하는 경우가 있었는데, 이제 **컨트롤 소켓으로 정중하게 일시정지**했다가 재개합니다. 저처럼 텔레그램·디스코드 게이트웨이를 켜두는 분에겐 체감되는 변경입니다.
- **선택형 OS 키체인 암호화** — 맥에서 **실행할 때마다 뜨던 키체인 프롬프트가 사라집니다.** 보안을 원하면 OS 키체인에 암호화해서 저장하고, 아니면 기존 방식도 유지 가능한 옵트인 구조예요. "보안 vs 편의"를 직접 고를 수 있다는 게 좋습니다.
- **안전하지 않은 인플레이스 업데이트 거부** — 이미지/패키지로 설치한 환경에서 **위험한 즉석 업데이트를 거부**합니다. 크론잡이 도는 머신을 밤새 업데이트했다가 아침에 깨져있는 사고를 막아주는 장치죠.

```bash
# 최신 버전 확인 + 업데이트 (v0.20.6, v2026.8.27)
hermes update

# 업데이트 후 문제가 생기면 진단
hermes doctor

# 크론잡 목록 확인 — durable-incident ack는 여기서 처리
hermes cron list
```

## 7. 그럼 v0.21.0은 언제? — 6연속 롤업이 남긴 숙제

이번 2주간의 롤업 6연속은 전부 **"정식 체인지로그는 v0.21.0에서"**라는 메모를 달고 나왔습니다. v0.20.6 노트에도 **"Nothing in this window is skipped"** — "이번 구간에서 빠지는 건 없다"고 못 박아뒀어요. 즉 v0.21.0은 v0.20.0(Herald) 이후의 **모든 변경을 큐레이티드로 정리한 대형 노트**가 될 예정입니다.

솔직한 예상(공식 확인 전)을 덧붙이면:

- **v0.20.1~v0.20.6에서 미리보기로만 나온 기능들의 공식 설정 문서**가 가장 기대됩니다. 특히 **TTL 캐싱 설정·실제 프로필 브라우징의 권한 체계**는 노트 요약만으로는 부족했거든요.
- **기여자 크레딧**도 v0.21.0에서 전부 공개된다고 예고되어 있습니다. 525개 PR이면 기여자 수가 상당할 텐데, 오픈소스 프로젝트의 건강함을 보여주는 자리라서 저는 개인적으로 이 부분이 궁금합니다.
- 릴리스 주기로 보면 **v0.21.0이 9월 첫째 주 안에 나올 가능성**이 높아 보입니다. 다만 이건 제 추측이고, 정확한 일정은 공식 발표를 따라가시는 게 맞습니다.

## 8. 솔직한 장단점 총정리

### 👍 이건 꼭 써보세요

- **TTL 웹검색 캐싱 + lean-tail 기본화** — 크론잡 자동포스팅을 돌리는 저 같은 사람에겐 **비용·속도·레이트리밋 3관왕** 변경
- **동의 기반 실제 프로필 브라우징** — 로그인 필요한 웹 자동화를 시도해보고 싶던 분은 이제 시작점이 생김 (Windows는 닫기 승인 절차까지)
- **리모트 MCP 카탈로그 50개+** — Grafana·Cloudflare 같은 서비스를 에이전트에 붙이는 진입 장벽이 확 낮아짐
- **크론 durable-incident ack** — 자동화 실패를 놓치지 않게 해주는 운영 안전망
- **맥 키체인 프롬프트 종료(옵트인)** — "실행할 때마다 암호 묻던" 답답함이 사라짐

### 👎 아직은 글쎄

- **모든 게 "요약만"** — 525개 PR의 상세 내용은 v0.21.0 정식 노트까지 기다려야 함. 지금은 릴리스 노트 요약 + 커밋 로그로만 판단해야 하는 구간
- **실제 프로필 브라우징은 동의 기반이라 기본 off** — "켜면 편하지만 켜는 순간 내 로그인 세션이 에이전트에 노출"되는 트레이드오프를 각자 판단해야 함
- **TTL 캐싱은 속보성 잡에 독** — 캐시 설정을 잘못 잡으면 "방금 나온 뉴스"를 놓칠 수 있음
- **신규 모델(GLM-5.3-Flash 등)은 픽커 추가 수준** — 성능 검증은 직접 해봐야 함

## 9. 마무리 — `hermes update` 한 줄이면 끝, 가성비 좋은 AI 에이전트 찾는 분께 추천

정리하면, 이번 6연속 롤업 패치는 **"v0.20.0 Herald 대형 업데이트의 후폭풍을 안정화하면서, 동시에 다음 대형 업데이트(v0.21.0)의 뼈대를 깔아두는"** 구간이었습니다. 그중 v0.20.6은 **크론잡 운영자(캐싱·ack)·브라우저 자동화 사용자(실제 프로필)·서비스 연동을 원하는 분(MCP 카탈로그)** 각각에게 줄 선물이 뚜렷한 패치였어요.

업데이트는 아래 한 줄이면 끝입니다.

```bash
hermes update
```

Hermes Agent는 **MIT 라이선스 무료 오픈소스**라 비용 부담 없이 시작할 수 있고, GitHub 스타 23만 개·OpenRouter 토큰 점유율 1위가 말해주듯 **"실제로 계속 쓰는 사람들"**이 많습니다. 다만 지금은 **v0.21.0 정식 노트가 나오기 전의 과도기**라, "이 기능의 정확한 설정법"은 공식 문서(hermes-agent.nousresearch.com/docs)를 함께 확인하시는 걸 추천드려요.

솔직히 저는 이번 주도 **"오픈소스 에이전트가 이 속도로 달라져도 되나?"**라는 생각이 들었습니다. 하지만 그 빠른 변화를 **크론잡이 매일 아침 자동으로 따라잡아주는** 지금의 구조 덕분에, 저는 그냥 `hermes update` 한 줄만 치면 됩니다. 자동화의 재미를 직접 느껴보고 싶은 분, 그리고 **가성비 좋은 AI 도구**를 찾으시는 분께 Hermes Agent 추천합니다.
