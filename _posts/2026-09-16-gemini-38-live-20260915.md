요즘 저처럼 **고객 문의 응대나 예약 확인, 주문 조회 같은 "말로 하는 업무"를 AI로 넘기려는 분들** 많으시죠? 솔직히 저도 음성봇을 한번 붙여보려고 STT → LLM → TTS를 줄줄이 이어 붙이는 이른바 **캐스케이드 구조**를 직접 만들어봤는데, 말이 자꾸 끊기고, 상대가 말을 거는 타이밍에 끼어들지도 못하고, 뒤에서 뭘 조회하는 동안 봇이 멍하니 침묵하는 게 제일 답답했습니다. "이건 결국 음성 자체를 네이티브로 다루는 모델이 나와야 한다"고 생각하고 있었는데, 구글이 정확히 그걸 내놨습니다.

**2026년 9월 15일(현지시간), 구글이 공식 블로그 "Build real-time voice applications with Gemini 3.8 Live and 3.5 Transcribe"를 통해 `Gemini 3.8 Live`와 `Gemini 3.8 Live Extended Thinking`을 Gemini API와 Google AI Studio에 공개**했습니다. 이름만 보면 상·하위 버전처럼 보이지만, 실상은 **"대화를 잘하는 모델"과 "일을 끝내는 모델"로 음성 라인을 둘로 쪼갠 것**이라 성격이 꽤 다릅니다. 오늘은 이 소식을 **이슈 요약 → 상세 분석 → 영향(사용자·개발자) → 전망** 순서로 정리해 드립니다.

> **📌 한줄 요약:** 구글이 **네이티브 음성(speech-to-speech) 모델 두 개를 동시에 공개**했다. **3.8 Live Extended Thinking은 Artificial Analysis 음성 대화 품질 지수 1위(82.6)** 로 OpenAI의 GPT-Live-1 Astra(81.5)를 제쳤고, **기본형 3.8 Live는 오디오 입력 시간당 $0.84 수준의 저가형**으로 라인을 나눴다. 핵심은 벤치마크 1위가 아니라 **"말하면서 동시에 일을 처리하는" 구조가 API로 열렸다**는 점이다.

## 🗞️ 이슈 요약 — 한눈에 보기

- **무엇:** Google DeepMind가 **Gemini 3.8 Live**·**Gemini 3.8 Live Extended Thinking**을 **Gemini API·Google AI Studio·Live API**에 공개 (2026년 9월 15일, 구글 공식 블로그)
- **모델 ID:** `gemini-3.8-live`, `gemini-3.8-live-extended-thinking` (모델 카드는 `gemini-3-8-audio`로 공개)
- **핵심 기능:** **비동기 함수 호출**(API·도구 호출을 백그라운드에서 처리하면서 오디오 응답은 계속 스트리밍), **시각적 컨텍스트**(카메라·화면 입력을 대화 근거로 사용), **97개 언어** 대화 중 자동 전환, **알파뉴메릭 정확도**(확인 코드·청구 번호 파싱)
- **가격:** **오디오 입력 분당 $0.005 / 오디오 출력 분당 $0.018** (공식 표기, 대략 입력 $3/1M 토큰·출력 $12/1M 토큰 기준)
- **벤치마크:** Extended Thinking — **Speech to Speech Quality Index 82.6 (1위)**, **τ-Voice 68.6%**, **Sierra τ-Voice-banking 35.1%**, **Big Bench Audio 97.7%**
- **기본형 3.8 Live:** 동일 지수 **76.0(5위)**, τ-Voice **30.1%**, **Speech Agent Arena 2위**, 첫 오디오 응답 **1.18초**
- **함께 발표:** 전용 음성인식 모델 **Gemini 3.5 Transcribe** — 85개 이상 언어, 평균 WER **4.0%(스트리밍)·2.6%(비스트리밍)**
- **적용처:** **Gemini Live**, **Gmail Live**, **Docs Live**, **Keep Live**, 그리고 **AI 모드의 Search Live**에 순차 반영
- **워터마크:** 생성된 모든 오디오에 **SynthID** 워터마크 적용

## 🔍 상세 분석 — 무엇이 실제로 달라졌나

### 1️⃣ "둘로 쪼갰다"는 게 이번 발표의 본질

구글의 프레이밍이 유난히 명확합니다. **3.8 Live는 "규모와 비용 효율을 위해 만들어진, 유창한 대화 + 시각적 그라운딩"** 모델이고, **3.8 Live Extended Thinking은 "고복잡도 작업을 위한, 향상된 지능과 멀티스텝 추론"** 모델입니다.

이건 단순한 크기 등급(size tier) 분리가 아니라 **"음성 에이전트의 직무가 무엇인가"에 대한 서로 다른 답**입니다. 하나는 **대화형 인터페이스**이고, 다른 하나는 **말을 할 줄 아는 추론 시스템**입니다.

- **Gemini 3.8 Live** — 근실시간 시각 입력 처리, 대화 중 97개 언어 자동 전환, **백그라운드 도구/API 실행**(요청을 접수해 두고 계속 대화)
- **Gemini 3.8 Live Extended Thinking** — **추론과 발화를 동시에** 수행. "잠시 확인해 볼게요…" 같은 **초기 발화 신호**로 자연스럽게 응답을 잇고, 멀티스텝 백그라운드 작업 진행 상황을 **실시간으로 나레이션**
- **공통** — 모델 카드 공개, API 모델 ID 문서화, **SynthID 워터마크**

특히 **3.8 Live Extended Thinking이 "3.8 Live에 사고 예산(thinking budget)을 더 얹은 것"이 아니라는 점**이 중요합니다. 이 모델은 **대화와 작업 계획을 동시에 유지하면서 대화가 멈추지 않게 하는 것**이 목적입니다. 실무에서 음성 에이전트가 실패하는 지점이 정확히 여기입니다. 사용자는 봇이 뭘 찾는 동안 **침묵**하는 걸 원하지 않습니다. 계속 말을 걸어주길 원합니다.

### 2️⃣ 벤치마크 — 지수는 6.6점 차, 실제 격차는 38점

구글이 강조한 숫자는 **Artificial Analysis의 Speech to Speech Quality Index 1위, 82.6**입니다. 2위는 **GPT-Live-1(Astra 백엔드, medium effort) 81.5**, 3위는 **Grok Voice Think Fast 2.0 High 81.3**입니다.

그런데 **지수만 보면 두 모델의 차이가 6.6점(82.6 vs 76.0)으로 작아 보입니다.** 항목별로 뜯어보면 이야기가 달라집니다.

| 항목 | 3.8 Live Extended Thinking | 3.8 Live |
|:---|:---|:---|
| Speech to Speech Index | **82.6 (1위)** | 76.0 (5위) |
| τ-Voice 에이전트 작업 완수 | **68.6%** | 30.1% |
| Big Bench Audio (음성 추론) | **97.7%** | 92% |
| 대화 역동성 | 91.9% | **96.1%** |
| Arena 선호도(Elo) | 990 | **1083** |
| 작업 성공률 | 89.1% | **93.2%** |
| 첫 오디오까지 걸리는 시간 | 1.35초 | **1.18초** |
| 입력 오디오 시간당 비용 | $3.50 | **$0.84** |

솔직히 표를 정직하게 읽으면 **8개 항목 중 4개는 기본형 3.8 Live가 이깁니다.** 첫 응답이 더 빠르고, 아레나 평점이 더 높고, 대화 역동성이 더 좋고, 가격은 **4분의 1 이하**입니다.

**기본형이 못 하는 단 하나는 "단계가 있는 일을 끝내는 것"** 입니다. **30.1% 대 68.6%** 는 이번 릴리스에서 가장 큰 격차이고, 그게 바로 **음성 인터페이스와 음성 에이전트를 가르는 축**입니다.

![Artificial Analysis Speech to Speech Quality Index — Gemini 3.8 Live Extended Thinking 82.6, 1위](/assets/images/posts/2026-09-16-gemini-38-live-20260915/gemini-38-live-bench-s2s.png)
*Artificial Analysis Speech to Speech Quality Index 비교 — Gemini 3.8 Live Extended Thinking이 82.6으로 1위, 기본형 3.8 Live는 76.0 (출처: Google 공식 블로그 벤치마크 차트, 2026.9.15)*

한 가지 짚고 갈 점은, **GPT-Live-1과의 격차(68.6% vs 67.9%)는 0.7점 차**로 사실상 노이즈 수준이라는 겁니다. 반면 **두 Gemini 모델 사이의 38점 차는 노이즈가 아닙니다.** 즉 "1위"라는 헤드라인보다 **"같은 회사 안에서 직무가 이렇게 갈린다"는 쪽이 더 읽을 거리**입니다.

### 3️⃣ 개발자에게 진짜 중요한 건 가격표보다 이 한 줄

성능보다 실무에 크게 영향을 주는 건 **비동기 함수 호출**입니다. 공식 문서가 이렇게 경고합니다.

> 비동기 추론을 쓰는 모델에서는 **`turnComplete: true`가 더 이상 "모델이 유휴(idle)"라는 뜻이 아니다.** 서버는 이후에도 백그라운드 추론이나 도구 호출을 계속 처리할 수 있다.

그래서 클라이언트는 `turnComplete` 이후에도 **추가 서버 메시지(도구 호출·오디오 프레임)를 계속 수신**해야 하고, `interaction_status` 필드로 **IN_PROGRESS / IDLE** 을 구분해야 합니다. **"말이 끝나면 턴이 끝난 것"이라는 기존 가정이 깨지는 것**이라, Live API로 이미 서비스를 만들고 있는 팀은 상태 관리 로직을 손봐야 합니다.

**비용 감각**도 짚어둘 만합니다. Extended Thinking은 **입력 오디오 시간당 $3.50**로 기본형($0.84)의 **4배 이상**입니다. Artificial Analysis 기준 **"6.6 지수 포인트를 위해 4배를 낼 것인가"** 가 곧 설계 결정이 됩니다.

### 4️⃣ Gemini 3.5 Transcribe — 조용하지만 실무형

같이 발표된 **Gemini 3.5 Transcribe**도 실무에서는 반가운 물건입니다.

- **85개 이상 언어**, 평균 WER **4.0%(스트리밍) / 2.6%(비스트리밍)**
- **자동 코드스위칭** — 한 문장 안에서 언어가 섞여도 설정 없이 처리
- **커스텀 어휘 바이어싱** — 최대 **1,000개 용어**를 넘겨 사내 용어·브랜드명 인식 보정
- **스마트 전사 모드** — 군더더기 제거·자기 정정 반영으로 읽기 좋은 텍스트 생성
- **Interactions API**로 **최대 1시간 오디오** 일괄 전사 + 타임스탬프·화자 분리

콜센터 녹취, 실시간 자막, 통화 분석처럼 **"음성을 텍스트로 바꿔 쌓아두는" 업무**에 바로 쓸 수 있는 구성입니다.

## 🧭 영향 — 사용자와 개발자에게 무엇이 바뀌나

**일반 사용자 입장에서는:**
- **Gemini Live의 체감 품질이 달라집니다.** 3.8 Live Extended Thinking이 Gemini Live에 순차 반영 중이고, **Gmail Live(대화형 검색)·Docs Live(초안 작성·편집)·Keep Live(노트 생성)** 가 이 모델로 돌아갑니다. AI 모드의 **Search Live**는 기본형 3.8 Live가 맡습니다.
- **"봇이 침묵하는 시간"이 줄어듭니다.** "잠시 확인해 볼게요"라고 말한 뒤 백그라운드에서 일을 처리하고, 끝나면 다시 말을 거는 흐름이 API 차원에서 지원됩니다.
- 다만 **한국어 품질·억양은 직접 써봐야 압니다.** 97개 언어 지원과 "한국어가 좋아졌다"는 건 다른 문제입니다.

**개발자·운영자 입장에서는:**
- **캐스케이드(STT→LLM→TTS)를 걷어낼 수 있습니다.** 구글도 이번 모델을 **"캐스케이드 아키텍처의 간소화된 대안"** 이라고 표현했습니다. 지연·끼어들기·말 끊김 문제의 상당 부분이 구조적으로 사라집니다.
- **통합 파트너가 넓습니다.** **Agora, Fishjam, LiveKit, LangChain, Pipecat, Vercel, Vision Agents**가 미디어 스트리밍 인프라를 처리해 주니, WebSocket을 직접 만지지 않고도 붙일 수 있습니다. Simon Willison은 **라이브러리 없이 Web Audio API + WebSocket만으로 동작하는 테스트 UI**를 하루 만에 올렸는데, 진입 장벽이 그만큼 낮아졌다는 뜻입니다.
- **단점은 분명합니다.** ① **비동기 상태 관리로의 코드 전환 비용**, ② **Extended Thinking의 4배 가격**, ③ **여전히 프리뷰(preview) 단계**라 프로덕션 의존은 리스크, ④ 벤치마크는 **자사 인용치**라는 점. 그리고 τ-Voice 0.7점 차 선두는 **다음 릴리스에서 뒤집힐 수 있는 숫자**입니다.

## 🔭 전망 — 음성 AI 경쟁의 축이 옮겨간다

구글은 **3.7 Flash(8월 중순) → 3.8 Flash(9월 2일) → 3.8 Live(9월 15일)** 로 **한 달에 세 번** 모델을 내놨습니다. 이 속도 자체가 신호입니다. 음성은 이제 **데모용 기능이 아니라 에이전트의 입력·출력 인터페이스**로 취급되고 있습니다.

앞으로의 관전 포인트는 세 가지입니다.

1. **"말하면서 일하기"가 표준이 되는가** — 비동기 함수 호출 + 진행 나레이션 조합이 업계 기본값이 되면, 음성 에이전트의 평가 기준은 "목소리가 자연스러운가"에서 **"끝까지 해내는가"** 로 완전히 이동합니다.
2. **가격 경쟁** — 기본형이 **입력 오디오 시간당 $0.84**까지 내려온 건, 음성봇을 대량으로 돌리는 콜센터·예약 시스템 시장을 정면으로 겨냥한 가격입니다.
3. **프리뷰 졸업 시점** — 정식(GA) 전환과 요금 확정이 나와야 실제 도입 판단이 가능합니다. 구글은 3.8 Flash의 도입가가 **2026년 12월 31일**까지라고 명시해 둔 상태라, 음성 라인도 비슷한 일정이 나올 가능성이 큽니다.

## 💡 어떤 걸 골라야 할까 — 실사용 기준 팁

제가 이번 발표를 보고 정리한 **선택 기준**은 이렇습니다.

- **예약 접수·주문 조회·단순 안내처럼 "대화가 곧 업무"인 경우 → `gemini-3.8-live`**
  빠르고(첫 오디오 1.18초), 대화 역동성이 좋고, **가격이 4분의 1**입니다. 여기서 Extended Thinking을 쓰는 건 돈 낭비에 가깝습니다.
- **여러 단계를 넘나드는 업무(조회 → 조건 비교 → 변경 → 확인)를 맡길 경우 → `gemini-3.8-live-extended-thinking`**
  τ-Voice 68.6% 대 30.1%는 실사용에서 체감 차이가 큽니다. **"침묵 없이 일을 끝내는 것"** 에 값을 매길 수 있다면 이쪽입니다.
- **녹취·자막·통화 분석처럼 텍스트가 목적이면 → `gemini-3.5-transcribe`**
  스트리밍 WER 4.0%에 커스텀 어휘 1,000개, 1시간 배치 전사까지 필요 충분합니다.
- **아직 프리뷰라는 점은 꼭 감안하세요.** 실서비스에 넣기 전 **폴백 모델과 요금 변동 시나리오**를 먼저 정해두는 걸 추천합니다.

솔직히 저는 이번 발표에서 **"1위"라는 타이틀보다 두 모델로 갈라진 구조**가 더 반갑습니다. 그동안 음성봇은 "예쁘게 말하는 인터페이스"에 머물렀는데, 이제 **말로 시키면 뒤에서 알아서 처리하고 돌아와 보고하는 쪽**으로 넘어가고 있으니까요.

**실시간 음성 상담이나 예약 자동화를 검토 중이고, 가성비 좋은 음성 모델을 찾는 분께 추천합니다.** 특히 캐스케이드 구조로 삽질해 보신 분들이라면, 이번 3.8 Live 라인은 한 번 테스트해 볼 가치가 충분합니다.
