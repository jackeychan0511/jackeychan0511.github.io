> **📌 한줄 요약:** 2026년 **10월 29일(현지)**, **Cursor 확장 마켓플레이스**에서 **Anthropic 공식 계정으로 배포되는 Claude Code 확장 프로그램**(`anthropic.claude-code`) **2.1.312·2.1.313** 버전에 **SSH 백도어 코드가 삽입된 채 약 11시간** 유통됐습니다. 영향 범위는 **최대 5,000명**, 확장 프로그램은 **자동 업데이트가 기본값**이라 손대지 않아도 감염될 수 있는 구조였습니다. Cursor는 마켓플레이스를 전면 폐쇄하고 키를 교체했고, Anthropic은 **2.1.314**를 배포했습니다. 그런데 **확장을 삭제해도 지속성 파일은 남습니다.**

AI 코딩 도구를 업무에 붙여 쓰는 분들이라면 한 번쯤 확인해 보셔야 할 사건입니다. 이번 건은 "AI가 나쁜 짓을 했다"는 이야기가 아니라, **AI 개발 도구의 배포 경로 자체가 공격 표면이 됐다**는 이야기입니다. 모델 성능이나 프롬프트 인젝션 문제가 아니라, **확장 프로그램 마켓플레이스의 게시자 계정**이라는 아주 평범한 지점에서 뚫렸습니다.

이 글은 **① 무슨 일이 있었나(타임라인) → ② 상세 분석(공격 체인·신뢰 구조·피해 범위) → ③ 영향(사용자·개발자) → ④ 지금 확인할 것 → ⑤ 남은 의문과 전망** 순서로 정리합니다.

## 2. 상세 분석

### 2-1. 공격 체인 — 5단계로 본 실제 동작

Microsoft 위협 인텔리전스가 주입된 자바스크립트를 분석한 결과, 확장 모듈이 로드되는 **가장 먼저** 악성 함수가 실행됩니다. 정상 초기화 코드보다 앞섭니다. 그리고 이 함수는 외부 실행 파일을 내려받지 않고, **Node.js 기본 API와 운영체제 내장 도구만으로** 끝까지 진행합니다.

| 단계 | 동작 | 수집·생성되는 것 |
|:---|:---|:---|
| ① 정찰 | 호스트·사용자 정보 수집 | 호스트명, 사용자명, OS, 아키텍처, 홈 경로, 작업 디렉터리, Git 전역 이메일, 공인 IP |
| ② SSH 키 삽입 | `authorized_keys`에 공격자 공개키 추가 시도 | `svc-telemetry` 라벨의 Ed25519 공개키 |
| ③ 역터널 | `ssh -N -R '*:0:localhost:22'` 로 원격 포트 포워딩 | 별도 개인키를 `.stk_<hex10>` 임시 파일로 기록 |
| ④ 지속성 | macOS LaunchAgent / Linux cron / Windows 작업 스케줄러 | `com.apple.sysmond.plist`, `@reboot` 항목, `SysMon` 작업 |
| ⑤ 지연 보고 | 앞 단계가 끝난 뒤 호스트 정보 전송 | `134.209.82.225:8099/beacon` 으로 HTTP POST |

![역방향 SSH 터널을 구성하는 실제 명령줄 — 호스트 키 검증 비활성화, 60초 간격 재시도](/assets/images/posts/anthropic-claude-code-extension-cursor-backdoor-20261031/reverse-ssh-tunnel-command.jpg)
*원격 서버가 할당한 포트를 워크스테이션의 로컬 22번 포트로 포워딩하는 명령. `-N`은 원격에서 명령을 실행하지 않겠다는 뜻이고, 호스트 키 검증과 known_hosts 사용을 꺼서 중간 확인 절차를 우회합니다 (출처: Microsoft Security Blog, 2026.10.30, Figure 2)*

몇 가지 디테일이 이 코드의 성격을 잘 보여줍니다.

**환경변수는 "이름"만 훔쳐갑니다.** 로더는 `KEY`, `TOKEN`, `SECRET`, `PASS`, `AWS`, `GCP` 같은 문자열이 들어간 환경변수 이름을 최대 40개까지 골라 담습니다. 값이 아니라 **이름**입니다. Microsoft는 이를 "민감한 설정 범주의 존재를 드러내는 수준이며, 변수에 저장된 비밀값 자체의 탈취를 입증하지는 않는다"고 정리했습니다. 다만 Cursor는 "제한적인 환경변수 수집이 **나중에 백도어를 통해 자격증명에 접근하지 않았다는 것을 배제하지는 않는다**"고 명시했습니다. 이름만 보고 다음 표적을 고를 수 있다는 뜻입니다.

**이름은 그럴듯하게 위장했습니다.** SSH 키 라벨은 `svc-telemetry`, macOS 지속성 파일은 `com.apple.sysmond.plist`, Windows 작업 이름은 `SysMon`입니다. 얼핏 보면 애플 시스템 서비스나 모니터링 에이전트처럼 읽힙니다. 실제 동작은 60초 간격으로 SSH 터널을 다시 여는 스크립트입니다.

**실패해도 흔적은 남깁니다.** 역터널은 공격자 서버 설정과 로컬 권한에 따라 실패할 수 있습니다. Cursor는 "관리자 권한으로 Cursor를 실행한 매우 이례적인 상황이 아니면, 악성 코드의 오류 때문에 이 단계는 실패했을 것"이라고 밝혔습니다. 그런데 **키 삽입과 지속성 파일 생성은 터널이 실패해도 그대로 진행**됩니다. 그래서 "터널이 안 열렸으니 괜찮다"는 판단이 위험합니다.

### 2-2. 왜 하필 이 지점이 뚫렸나 — 신뢰 체인의 구조

이 사건의 본질은 **서명된 배포 채널**이 뚫렸다는 데 있습니다.

일반적으로 확장 프로그램 보안은 "공식 마켓에서 받았는가"로 판단합니다. 게시자 인증, 버전 서명, 다운로드 수, 리뷰 — 이 신호들은 모두 **"그 게시자 계정이 곧 그 회사"** 라는 전제 위에 서 있습니다. 이번에는 그 계정 자체가 공격자 손에 들어갔습니다.

그래서 기존 방어 논리가 흔들립니다.

- **"공식 계정이니까 안전하다"** → 이번엔 공식 계정이 공격 경로였습니다.
- **"리뷰와 다운로드 수를 보면 된다"** → 11시간짜리 공격에는 리뷰가 쌓일 시간이 없습니다.
- **"수동으로 설치하니까 괜찮다"** → 자동 업데이트가 기본값이면 수동 설치자도 갱신 시점에 노출됩니다.

Microsoft는 이와 별개로, **마이크로소프트 Visual Studio 마켓플레이스와 npm `@anthropic-ai/claude-code` 패키지는 이번 사건과 무관**하며 악성 패키지가 배포된 적이 없다고 확인했습니다. Anthropic도 Microsoft에 **자사 시스템이 침해된 것은 아니며 악성 패키지를 개발하지 않았다**고 확인했습니다. 즉 현재까지 증거는 **Cursor 마켓플레이스 범위**에 머뭅니다. 확장 하나가 뚫린 것이지, Claude 모델이나 Claude Code 본체가 오염된 것은 아닙니다. 이 구분은 과잉 대응을 막는 데 중요합니다.

### 2-3. 피해 범위 — 숫자보다 구조를 봐야 합니다

Cursor가 밝힌 영향 규모는 **"최대 5,000명"(at most 5,000 users)** 입니다. Ars Technica는 이 수치를 그대로 인용하면서, 다운로드와 자동 업데이트 양쪽을 합친 결과일 것으로 해석했습니다.

숫자만 보면 크지 않아 보입니다. 하지만 세 가지를 같이 봐야 합니다.

**첫째, 대상이 개발자입니다.** Cursor 확장은 IDE 권한으로 실행됩니다. 로컬 파일, 소스코드, 개발 도구, 그리고 개발 환경에 붙어 있는 각종 토큰과 세션에 접근할 수 있는 위치입니다. 일반 사용자 5,000명과 개발자 5,000명은 무게가 다릅니다.

**둘째, 자동 업데이트가 기본값입니다.** "내가 설치한 기억이 없다"가 면책이 되지 않습니다. Cursor 사용 중 백그라운드에서 갱신됐을 수 있습니다.

**셋째, 공격자 서버가 내려갔다는 사실이 안심 근거가 되지 않습니다.** Cursor가 호스팅 업체와 협의해 C2를 오프라인 처리한 것은 **추가 통신을 끊은 것**이지, **이미 단말에 남은 키·스크립트·시작 항목을 지운 것이 아닙니다.** Microsoft도 이 점을 명시적으로 못 박았습니다 — "Cursor의 서버 셧다운은 이미 기기에 존재하는 아티팩트를 제거하지 않는다."

## 3. 영향 — 사용자와 개발자·보안 담당자

### 3-1. 개인 개발자·소규모 팀

가장 현실적인 위험은 **"확장 지웠으니 끝"이라고 믿는 것**입니다. 악성 코드가 만든 파일은 확장 폴더 밖에 있습니다.

- `~/.ssh/authorized_keys` 의 `svc-telemetry` 키
- `~/.config/.smt`, `~/.config/.smtk` (터널 재구성 스크립트·키)
- macOS: `~/Library/LaunchAgents/com.apple.sysmond.plist`
- Linux: 사용자 crontab의 `@reboot` 항목
- Windows: `SysMon` 예약 작업, 시작 프로그램 폴더의 `sysmon.cmd`

이 파일들이 남아 있으면 확장을 지우고 2.1.314로 올려도 **재부팅 때마다 터널 재시도**가 돌아갑니다. 그래서 순서가 중요합니다. **삭제보다 확인이 먼저**입니다. 흔적을 지우고 나서 "감염됐는지"를 확인하면 증거가 사라집니다.

또 하나, **터널이 실패했어도 자격증명 교체를 미루면 안 됩니다.** Cursor는 "영향받은 호스트에서 접근 가능한 자격증명과 세션은 **신뢰할 수 있는 다른 시스템에서** 교체하라"고 권고합니다. 감염 의심 단말에서 비밀번호를 바꾸면 새 비밀번호가 그 단말을 거쳐 갈 수 있기 때문입니다.

### 3-2. 개발자·플랫폼 운영 담당자

조직 입장에서 이번 사건이 남기는 교훈은 **"확장 프로그램도 소프트웨어 공급망이다"** 라는, 조금 뒤늦은 확인입니다.

Microsoft가 제시한 완화책은 화려하지 않지만 실효적입니다.

| 통제 | 내용 | 왜 효과가 있나 |
|:---|:---|:---|
| 게시자 제한 | 승인된 게시자의 확장만 허용 | 계정 탈취 시에도 화이트리스트 밖이면 차단 |
| 설치 쿨다운 | 신규 게시 버전의 설치를 일정 기간 지연 | 11시간짜리 공격 창을 그대로 회피 |
| 설치 기록 보존 | 확장 설치·업데이트 텔레메트리 유지 | 사후 추적의 유일한 단서 |
| 자동 업데이트 정책 검토 | 팀 단위로 갱신 시점 통제 | "모르는 사이 갱신" 차단 |

특히 **설치 쿨다운(cooldown)** 은 이번 사건의 성격에 정확히 맞는 통제입니다. 공격 노출 창이 짧을수록, 갱신을 조금 늦추는 것만으로 피해를 비껴갑니다. 반대로 자동 업데이트를 무조건 켜 두는 관행은, 신뢰할 수 있는 게시자에게도 **즉시 실행 권한을 위임**하는 것과 같습니다.

## 4. 지금 확인할 것 — 체크리스트

이미 지나간 사건이지만, 노출 창(10월 29일 02:27~13:35 PDT, 한국시간 10월 29일 18:27 ~ 10월 30일 05:35)에 Cursor를 켜 두고 Claude Code 확장을 쓰고 있었다면 확인이 필요합니다.

**1) SSH 키 흔적 확인 (macOS·Linux)**

```bash
grep -s svc-telemetry ~/.ssh/authorized_keys && echo "svc-telemetry 키 발견" || echo "키 없음"
```

**2) 지속성 파일 확인**

```bash
ls -la ~/.config/.smt ~/.config/.smtk 2>/dev/null
ls -la ~/Library/LaunchAgents/com.apple.sysmond.plist 2>/dev/null   # macOS
crontab -l 2>/dev/null | grep -i smt                                # Linux
```

**3) 터널 프로세스 확인**

```bash
ps aux | grep -E "ssh -N -R|autossh" | grep -v grep
```

**4) 네트워크 흔적** — `134.209.82.225` (SSH 22, HTTP 8099)와의 연결 기록. 방화벽·프록시·EDR 로그에서 최근 30일 범위로 조회합니다.

**5) 확장 버전 확인** — Cursor에서 Claude Code 확장이 **2.1.314 이상**인지 확인합니다. 다만 **버전이 올라간 것과 단말이 깨끗한 것은 별개**입니다.

**주의할 점 두 가지.** 첫째, `svc-telemetry` 문자열이 없다고 완전히 안전한 것은 아닙니다. Microsoft는 "마커 부재만으로는 설치·프로세스·네트워크·지속성 증거 검토를 대체할 수 없다"고 했습니다. 둘째, 반대로 `SysMon`이나 `sysmond`라는 이름이 있다고 무조건 악성은 아닙니다. **이름이 아니라 실제 실행 동작**을 봐야 합니다. 정리 스크립트를 돌리기 전에 아티팩트를 보존하는 이유도 여기에 있습니다.

## 5. 남은 의문 — 아직 답이 없는 세 가지

**① 공격자는 어떻게 공식 게시자 계정에 접근했나.** 이게 이번 사건의 핵심인데, 아직 공개 설명이 없습니다. Ars Technica는 "Cursor도 Anthropic도 공격자들이 어떻게 계정 통제권을 얻었는지 설명하지 않았다"고 전했습니다. 토큰 탈취인지, 내부자 접근인지, 마켓 게시 파이프라인의 취약점인지에 따라 **재발 방지책이 완전히 달라집니다.** 이 부분이 설명되지 않으면 같은 경로로 다시 뚫릴 수 있습니다.

**② Anthropic의 커뮤니케이션 공백.** Ars는 보도 시점 기준으로 **Anthropic이 고객에게 공개 경고를 하지 않았다**고 지적했습니다. 2.1.314를 조용히 배포하고 Cursor가 공지를 낸 형태입니다. 영향받은 개발자가 스스로 확인해야 하는 상황에서, **당사자의 안내 부재**는 사후 대응 속도를 떨어뜨립니다.

**③ 11시간 동안 몇 명이 실제로 실행됐나.** "최대 5,000명 노출"은 **다운로드·자동 갱신 규모**이고, "백도어가 실제로 동작한 수"는 아닙니다. 권한 문제로 터널 단계가 대부분 실패했다는 설명이 있지만, 키 삽입과 지속성 파일 생성은 별개로 진행됐습니다. 이 구분이 정리되지 않으면 피해 규모는 계속 과소평가됩니다.

## 6. 전망 — 이 사건이 남길 것

솔직히, 이번 사건의 기술적 난이도는 그렇게 높지 않습니다. 외부 바이너리를 내려받지도 않고, 흔한 SSH 키·cron·LaunchAgent 조합을 씁니다. **눈에 띄지 않는 평범한 기법**이라는 점이 오히려 무섭습니다. 탐지 제품이 잡아내기 어려운 형태이고, 확장 프로그램이 정상 동작을 계속하기 때문에 사용자는 아무 이상을 못 느낍니다.

앞으로 벌어질 일은 대략 이렇게 예상됩니다.

- **확장 마켓플레이스의 게시 파이프라인 보안이 심사 항목이 됩니다.** 2단계 인증, 게시 권한 분리, 게시 후 서명 검증, 신규 버전 지연 배포 같은 장치가 기본값으로 올라올 가능성이 큽니다.
- **엔터프라이즈 쪽은 "확장 화이트리스트 + 쿨다운"을 기본 정책으로 가져갈 것입니다.** 이미 Microsoft가 권고 목록에 넣었으니, 보안 검토 항목으로 빠르게 자리 잡을 겁니다.
- **AI 코딩 도구의 신뢰 모델이 "모델 성능"에서 "배포 경로"로 옮겨갑니다.** 프롬프트 인젝션·모델 오남용 논의는 계속되겠지만, 실제로 단말을 장악하는 경로는 한동안 **플러그인·확장·MCP 서버** 쪽일 가능성이 높습니다.

업무 자동화 파이프라인을 운영하는 입장에서 이번 건은 각별합니다. 자동화는 본질적으로 **여러 도구에 권한을 넘기는 구조**입니다. 에이전트에 저장소 접근권을 주고, CLI에 API 키를 물리고, IDE 확장에 로컬 파일 접근을 허용합니다. 그 권한이 정당한 도구에만 흘러간다는 보장이 없으면, 자동화는 편의가 아니라 **공격면 확장**이 됩니다.

AI 코딩 도구를 팀 단위로 쓰시는 분들이라면, 이번 주에 한 번은 확장 목록과 자동 업데이트 정책을 같이 열어 보시길 권합니다. 모델을 바꾸는 일보다 이쪽이 지금은 더 급합니다.
