## 도입: "저처럼 원격에서 클라우드로 자동화 돌리시는 분들, 새벽에 세션 끊기셨죠?"

요즘 저처럼 **Hermes Agent를 서버에 올려두고 원격 데스크톱과 클라우드로 같이 쓰시는 분들** 많으시죠? 저도 8월부터 이 에이전트를 실사용하면서 크론잡을 돌리고 있고, 자동화 파이프라인을 운영하다 보니 하루에도 몇 번씩 원격 대시보드에 붙습니다.

그런데 지난주에 좀 이상한 일이 있었습니다. 노트북을 뚜껑 열어 깨우면 **대시보드가 로그인 화면으로 튕겨 있는 겁니다.** 한두 번이면 "뭐 그럴 수도 있지"인데, 아침에 몰아서 몇 번 겪고 나면 예약 작업 상태를 확인하려던 흐름이 계속 끊깁니다. `hermes doctor`를 돌려도 특별한 건 안 잡히고요.

알고 보니 **저만 그런 게 아니었습니다.** 원격 게이트웨이에서 새로고침 요청이 몰리는 순간, 이미 교체된(refresh rotate) 토큰이 다시 한번 재사용으로 잡히고, 그게 "토큰 탈취 의심"으로 판정돼 **세션을 통째로 revoke**해버리는 구조였습니다. 방어 로직이 정상 사용자를 공격한 셈이죠. Nous Research는 **v0.21.3(v2026.9.14, 9월 14일)**에서 이 경로를 닫았습니다. 태그가 존재하는 이유 자체가 "클라우드 에이전트가 최신 릴리스 태그로 자동 업데이트되니, 이 수정을 그 경로로 밀어 넣기 위해서"라고 릴리스 노트에 적혀 있습니다.

## 1. 무엇이 바뀌었나 — v0.21.3의 핵심 두 가지

### ① 새로고침 폭주로 세션 전체가 로그아웃되던 문제 (#110061)

이번 태그의 본체입니다. 릴리스 노트를 그대로 옮기면 이렇습니다.

- 게이트웨이의 **양쪽 리프레시 경로**(쿠키 게이트 + 데스크톱의 네이티브 베어러 라우트)가 **같은 회전 토큰을 들고 오는 동시 요청을 하나로 병합(coalesce)** 합니다.
- 그래서 데스크톱이 깨어나며 몰아치는 요청(wake burst)이 **이미 회전된 토큰을 다시 재사용 감지에 밀어 넣어 세션을 revoke하는 일이 사라졌습니다.**
- 리프레시가 **이벤트 루프 밖에서** 돌아가므로, 아이덴티티 프로바이더가 느려져도 `/api/status`가 얼어붙지 않습니다.
- 포털 쪽 짝 패치(`hermes-portal#1209`)로 **슬라이딩 30일 유휴 기한 + 회전 토큰 5분 유예**가 함께 적용됐습니다.

제가 겪은 "뚜껑 열면 로그인 화면"이 정확히 이 항목입니다. 생체 인식처럼 30일 유휴 기한이 생긴 것도 실사용에서 체감이 큽니다. 매일 붙는 사람은 사실상 다시 로그인할 일이 없어졌습니다.

### ② state.db 쓰기 핸들 누수 정리 (#110934)

두 번째가 **롱리빙 프로세스의 중복 state.db 쓰기 핸들 누수**입니다.

- 게이트웨이, 대시보드/데스크톱 백엔드, ACP, CLI 리더가 전부 **읽기 전용으로 붙고**, 같은 프로세스 안의 라이터는 **레지스트리 핸들을 공유**하도록 정리했습니다.
- 결과적으로 **정상 토폴로지에서 "N live SessionDB handles" 경고가 더 이상 뜨지 않습니다.**

이게 왜 중요하냐면, 지난 v0.21.2가 state.db 손상 사고를 수습한 릴리스였다면 **이번 건은 그 사고의 잔불을 끄는 작업**입니다. 저처럼 서버 한 대에서 여러 프로필을 굴리는 환경에서는 `sessions list`나 대시보드가 가끔 느려지는 원인이 이런 핸들 누수였습니다.

## 2. 규모 — "패치"라는 말이 무색한 롤업

릴리스 노트에 적힌 실측 수치입니다. 커밋 `9b419a2d3c2657c192008e732149d61170b32c01` 기준, v0.21.2 이후 구간에:

- **비머지 커밋 1,036개**
- **변경 파일 2,642개** (+131,690 / −37,096)
- **머지된 PR 338개**

이 정도면 사실상 마이너 릴리스 하나 분량입니다. 다만 릴리스 노트는 이 구간의 기능을 **의도적으로 문서화하지 않았습니다.** 전체 큐레이션 노트는 **v0.22.0**에서 v0.21.0 이후 전체를 한 번에 정리해 나온다고 하니, 지금은 "무엇이 들어갔는지"가 일부만 공개된 상태입니다. 솔직히 이게 이번 릴리스의 가장 아쉬운 점입니다.

그래도 노트에 이름이 올라온 것만 추려도 업무 자동화에 영향이 큽니다.

- **OpenRouter OAuth PKCE 로그인** — API 키를 붙여넣는 대신 OAuth로 연결
- **모델 픽커 전반의 reasoning effort 선택** — 데스크톱 컴포저 필과 보조 모델별 제어까지
- **MCP OAuth 리프레시 토큰을 발급자(issuer)에 바인딩** — 토큰이 다른 발급자로 새지 않게
- **데스크톱의 일일 MCP 재인증 넛지** — 만료된 MCP 인증을 놓치지 않게
- **HEIF/HEIC/AVIF 이미지 디코딩** — 아이폰 사진을 그대로 물려도 읽힙니다
- **Slack 붙여넣기 표 + Agent Sessions API**
- **TUI/데스크톱 게이트웨이용 server→client JSON-RPC + Pydantic 와이어 계약 레지스트리**(TS/OpenRPC 생성)
- **FAL 카탈로그에 Wan 3.0, Kling 3.0 / Kling Image v3, MiniMax H3 Max Turbo, Gemini Omni Flash 1.1, Meta Muse 추가**
- **멀티플렉스 프로필 격리 및 게이트웨이 생존성(liveness) 수정**
- **크로스 VM 파일시스템에서 state.db WAL 거부** — 네트워크 공유 볼륨에 DB를 두지 않도록 강제

## 3. 실제 사용감 — 업데이트 후 달라진 점

**가장 크게 체감한 건 세션 유지입니다.** 예전에는 노트북을 닫았다 열거나, 여러 창에서 대시보드를 동시에 새로고침하면 가끔 세션이 날아갔습니다. 지금은 그 패턴이 재현되지 않습니다. 크론잡을 돌리는 입장에서 이건 단순 편의가 아니라 **운영 안정성**입니다. 새벽에 예약 작업 결과를 확인하려고 대시보드에 붙었는데 로그인 화면이 뜨면, 그 순간 알림 파이프라인이 끊긴 것과 같으니까요.

**두 번째는 로그인 피로 감소입니다.** 슬라이딩 30일 유휴 기한과 5분 유예 덕분에, 매일 쓰는 사람은 사실상 한 번 로그인하면 계속 유지됩니다.

**세 번째는 reasoning effort 제어입니다.** 모델 픽커마다 추론 강도를 고를 수 있게 되면서, 크론잡마다 모델을 갈아끼우는 게 편해졌습니다. 대량 요약처럼 빨라야 하는 작업은 낮게, 코드 수정이나 리서치는 높게 두는 식으로 나눠 쓰고 있습니다. 생각보다 차이가 큽니다.

**MCP 쪽도 조용히 좋아졌습니다.** MCP OAuth 리프레시 토큰이 발급자에 묶이면서, 여러 MCP 서버를 붙여 쓰는 환경에서 자격증명이 엉킬 여지가 줄었습니다. 데스크톱이 재인증을 하루 한 번 알려주는 것도 실사용에서는 꽤 고맙습니다.

## 4. 업데이트 방법과 주의사항

업데이트는 늘 그렇듯 간단합니다.

```bash
# git 설치본
hermes update

# 또는 설치 원라이너 재실행
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

- **Docker / 헤르메스 클라우드**: 이미지가 이 태그로 빌드됩니다 (`nousresearch/hermes-agent:v2026.9.14`). 클라우드 에이전트는 최신 릴리스 태그로 자동 업데이트되므로, 세션 로그아웃에 시달렸다면 별도 조치 없이 해결됩니다.

**여기서부터는 솔직한 주의사항입니다.**

1. **다운스트림 템플릿을 쓰는 분들은 CLI 플래그를 먼저 확인하세요.** Docker 이미지나 템플릿 저장소에서 핀을 올릴 때, `start.sh`에 쓰인 `hermes dashboard`, `hermes gateway run` 같은 플래그가 바뀌었으면 컨테이너가 크래시루프에 빠질 수 있습니다. 실제로 업스트림 동기화를 하는 저장소들이 이번 태그에서 그 점검을 명시적으로 안내하고 있습니다.
2. **state.db를 NAS·네트워크 공유 볼륨에 두신 분들은 경로를 로컬로 옮기세요.** 이번 구간에서 **크로스 VM 파일시스템에서는 WAL을 거부**하도록 바뀌었습니다. SQLite를 네트워크 볼륨에 두는 게 원래 위험한 구성이긴 한데, 이제는 아예 막히니 미리 옮겨두는 게 좋습니다.
3. **무엇이 바뀌었는지 전체 목록은 아직 없습니다.** 위에서 말했듯 큐레이션 노트는 v0.22.0에서 나옵니다. 특정 기능에 의존하는 자동화가 있다면 업데이트 후 한 번씩 수동 실행해 보시길 권합니다.

## 5. 솔직한 장단점 정리

**바로 업데이트하세요 (장점)**

- 원격·클라우드에서 **세션이 통째로 날아가던 사고가 닫혔습니다.** 이건 기다릴 이유가 없는 수정입니다.
- **state.db 핸들 누수 정리**로 롱리빙 게이트웨이 운영이 한결 안정적입니다.
- OpenRouter **OAuth PKCE 로그인**, **reasoning effort 제어**, **MCP OAuth issuer 바인딩**, **AVIF/HEIF 디코딩** 등 자동화에 바로 쓰이는 변화가 한 번에 들어왔습니다.
- MIT 라이선스에 무료입니다. Nous 무료 티어를 쓰는 분들은 비용 부담도 없습니다.

**이건 아직 아쉽습니다 (단점)**

- 릴리스 노트가 기능을 **의도적으로 비워둔 채** 나왔습니다. 338개 PR을 롤업했는데 "무엇이 들어갔는지"는 v0.22.0까지 기다려야 합니다.
- 릴리스 이름이 **"패치 릴리스"**라서, 겉만 보면 넘겨버리기 쉽습니다. 실제로는 마이너 릴리스급 변경입니다. 문서와 실제가 어긋나는 셈이죠.
- 다운스트림(Docker 이미지·템플릿)과 **NAS/네트워크 볼륨 사용자는 별도 조치**가 필요합니다.
- 여전히 **SQLite(state.db) 기반**이라는 구조적 제약은 그대로입니다. 세션 저장소를 별도 DB로 분리하는 건 아직 로드맵상 멀리 있습니다.

## 마무리: 이런 분들께 추천합니다

정리하면, **v0.21.3(v2026.9.14)는 이름만 패치고 내용은 이슈급**입니다.

- **원격 대시보드나 클라우드로 Hermes Agent를 쓰시는 분** → 세션 강제 로그아웃 사고가 닫혔으니 오늘 바로 업데이트하세요.
- **서버 한 대에서 게이트웨이를 롱리빙으로 돌리시는 분** → state.db 핸들 누수 정리만으로도 체감 차이가 있습니다.
- **MCP 서버를 여러 개 붙여 업무 자동화를 하시는 분** → MCP OAuth 토큰 issuer 바인딩과 재인증 넛지가 반갑습니다.
- **이제 막 시작하시는 분** → 굳이 이 릴리스부터 쫓아갈 필요는 없습니다. 설치 원라이너로 최신 버전을 받으면 자연스럽게 이 태그가 들어갑니다. 무료(MIT)라 진입 부담도 없고요.

**구매 팁 하나 더 드리자면**, 이 제품은 "돈 주고 사는" 물건이 아니라서 할인 정보는 없습니다. 대신 **API 비용이 실제 지출**입니다. 저처럼 여러 작업을 크론잡으로 돌리는 경우에는 저렴한 모델을 기본으로 두고, 꼭 필요한 작업에만 reasoning effort를 올리는 조합이 가장 가성비가 좋았습니다. 이번 업데이트로 그 조합이 훨씬 편해졌고요.

**가성비 좋은 자동화 환경 찾는 분께 추천합니다.** 오픈소스라 직접 뜯어볼 수 있고, 릴리스 주기가 빠른 것도 장점입니다. 다만 빠른 만큼 이렇게 "이름과 내용이 다른" 릴리스가 나오니, 저처럼 **업데이트 전 릴리스 노트 한 번 읽고 하는 습관**만 들이시면 됩니다.

궁금한 점은 댓글로 남겨주세요. 저도 실사용 중이라 아는 범위에서 답변드리겠습니다.
