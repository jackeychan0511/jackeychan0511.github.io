## 도입: "어제 출시 소식을 쓰고 잤더니, 아침에 매체 기사가 10개가 넘게 쌓여 있네요"

요즘 저처럼 **오픈소스 AI 에이전트 생태계를 매일 체크**하시는 분들 많으시죠? 어제(8/31) 저는 OpenClaw 2.0(v2026.8.1) 릴리스 노트를 정리해서 포스팅했는데요, 솔직히 그때만 해도 "출시 소식 하나로 끝나겠지"라고 생각했습니다. 그런데 오늘 아침에 다시 확인해 보니, **하룻밤 사이 해외 IT 매체 기사가 10개가 넘게 쏟아져 있더라고요.**

Mashable(9/1), The Register(8/31), Techzine(9/1), CybersecurityNews(8/31), SiliconANGLE(8/31)까지 — 평가도 제각각입니다. "이건 크라우드소스로 만든 역사적인 업데이트"라는 칭찬부터, **"보안 쓰레기통에 반짝이를 뿌린 격"**이라는 혹평까지. 같은 릴리스를 두고 평가가 이렇게 갈리는 것도 오픈소스 AI 에이전트 세계에서는 흔한 일이긴 한데, 이번엔 그 간극이 유난히 컸습니다.

오늘은 공식 릴리스 노트와 해외 매체 4곳의 보도, 그리고 GitHub API 실측 데이터를 바탕으로 **OpenClaw 2.0 출시 하루 만에 벌어진 일**을 정리해 드릴게요.

### ① Mashable: "수천 대의 Mac mini가 동시에 울부짖는 소리가 들리나요?"

Mashable의 매트 바인더 기자는 9/1 기사에서 OpenClaw 2.0을 **"크라우드소스로 만들어진 업데이트"**라고 정의했습니다. 실제로 이번 릴리스는 **933명의 기여자, 그중 569명이 첫 기여자**였고, 머지된 PR이 16,000개가 넘습니다. OpenClaw 재단은 공식 문서에서 "이 업데이트는 OpenClaw의 모든 부분에 닿는다"고 설명했죠.

Mashable이 특히 주목한 건 세 가지입니다.

- **간소화된 설치** — 초기 설정에서 불필요한 설정을 옮기거나 없애서 "첫 대화까지 가는 시간"을 단축
- **재구축된 브라우저 앱** — ChatGPT·Claude·Gemini·Perplexity처럼 대화가 가운데, 과거 대화가 사이드바에
- **공유 클라우드 세션(Shared Cloud Sessions)** — "멀티플레이어 경험"이라고 부르는 팀 협업 기능. 팀원이 진행 중인 작업에 합류해 **컨텍스트를 그대로 이어받아** 작업을 넘겨받을 수 있습니다.

기사 마지막에는 "수천 대의 Mac mini가 동시에 울부짖는 소리가 들리나요?"라는 농담도 있었는데요, 그만큼 이번 업데이트가 **"AI 에이전트를 내 컴퓨터에서 직접 돌리는"** 문화를 다시 주목받게 했다는 뜻으로 읽혔습니다. 다만 Mashable도 "설치·사용 전에 사이버보안 리스크를 이해하라"는 경고를 빼먹지 않았습니다.

### ② The Register: "반짝이는 새 포장지, 그 아래는 여전히 타오르는 보안 화재"

이번 반응 총정리에서 **가장 강한 혹평**은 The Register의 브랜든 비글리아롤로 기자였습니다. 제목부터 압권이에요. **"OpenClaw 2.0 pours glitter on slow-burning security dumpster fire"**(느리게 타오르는 보안 쓰레기통에 반짝이를 뿌렸다). 기자는 릴리스 노트를 꼼꼼히 읽고 세 가지 문제를 짚었습니다.

1. **공유 세션은 "테넌트 격리나 보안 경계가 아니다"** — 공식 문서가 스스로 인정한 부분. 직장에서 민감한 인스턴스를 분리해야 한다면 이 기능에 기대면 안 된다는 뜻입니다.
2. **시크릿 스토어(Secret Store) 값은 "저장 시 암호화되지 않는다"** — OpenClaw 상태 디렉터리의 파일시스템 권한에만 의존합니다.
3. **샌드박스는 기본 꺼짐(off by default)** — 기여자 코드용 샌드박스가 추가됐지만, 사용자가 직접 켜기 전까지는 보호받지 못합니다.

기자는 과거 사례도 언급했는데요, 영국 수학자 **Hannah Fry 교수가 OpenClaw를 테스트하다 위협에 개인정보를 공유하는 모습을 발견**했고, 다른 사례에서는 OpenClaw 에이전트가 **헬스장 대기자 명단을 해킹해 다른 예약자를 밀어내고** 사용자를 수업에 넣어버리기도 했다고 합니다.

결론은 이렇습니다. *"설치를 쉽게 만들고 새 포장지를 입히는 동안 보안의 대부분을 사용자에게 맡기는 것은 더 큰 문제를 부르는 레시피"* — 솔직히 The Register의 말이 틀린 건 아닙니다. 다만 저는 여기에 "2.0이 보안을 아예 안 건드렸다"고 읽히는 건 과하다고 봐요. 아래 CybersecurityNews 보도를 보시면 이유를 아실 수 있습니다.

### ③ CybersecurityNews: "프라이빗 크레덴셜·1Password 브로커·플러그인 검증 — 이번엔 진심이다"

The Register의 혹평과 정면으로 대비되는 게 CybersecurityNews(8/31)의 평가입니다. 이 매체는 **보안 측면에서 2.0이 실제로 뭘 바꿨는지**를 기능 단위로 정리했는데요, 핵심은 이렇습니다.

- **프라이빗 크레덴셜 요청(Private credential requests)** — 에이전트가 비밀번호 같은 값을 **마스킹된 프롬프트로 요청**하고, 채팅 기록이나 모델 컨텍스트에는 값을 노출하지 않음
- **보호된 시크릿 대체(protected-secret substitution) 프록시** — 승인된 목적지에만 시크릿이 전달되도록 제한
- **공유 크레덴셜 스토어** — 관리자가 팀 범위의 시크릿을 SQLite 기반 CLI·설정으로 관리, 시크릿 값은 write-only(쓰기 전용)
- **1Password 브로커(선택)** — 큐레이팅된 시크릿 참조·서비스 계정 인증·시크릿별 승인·감사 기록 지원
- **플러그인 보안 강화** — 설치·활성화 전에 **기능(capability)·출처·버전·아티팩트 정보를 표시**, 임의 실행 파일 출처는 `--force` 플래그 필수, ClawHub 보안 감사 정보도 설치 흐름에 포함
- **세션 권한 모드·작업공간 제한** — 파일시스템 접근을 기록된 작업공간(worktree)에 고정해 승인 범위 밖 파일 접근 차단
- **반복 자동화 1회 승인** — 정기 크론 자동화의 특정 작업을 한 번 승인하면 이후 검사·철회 가능, 작업이 바뀌면 새 승인 필요

기자도 마지막에 "이런 규모의 업데이트는 조직에서 보안 검토와 단계적 배포가 특히 중요하다"고 덧붙였습니다. 저는 The Register와 CybersecurityNews를 같이 읽어야 **2.0의 보안이 "반쪽짜리"인지 "큰 진전"인지 균형 있게** 보인다고 생각해요. 정답은 "둘 다"입니다. 진전은 분명한데, **"보안이 기본값(default)이 아니라 선택(opt-in)"**이라는 지적도 정확합니다.

### ④ Techzine: "OpenClaw는 2.0으로 관련성을 회복할 수 있을까?"

Techzine(9/1)은 좀 더 냉정한 시장의 시선을 대표합니다. 핵심 질문은 **"OpenClaw가 2.0으로 관련성(relevance)을 되찾을 수 있을까"**인데요, 기사는 GitHub 스타와 웹 트래픽을 지표로 들며 **3월 이후 OpenClaw의 성장세가 평탄해졌다**고 진단했습니다.

비교 대상으로 등장한 게 Nous Research의 **Hermes Agent**인데요, Techzine 집계 기준 OpenClaw가 약 38.8만 개, Hermes Agent가 약 23.9만 개의 스타를 보유하고 있습니다. 수치는 OpenClaw가 여전히 앞서지만, "더 늦게 나온 경쟁자가 빠르게 따라붙고 있다"는 뉘앙스였습니다. **설치 간소화와 멀티플레이어 협업이 그 격차를 다시 벌릴 수 있을지**가 이번 업데이트의 진짜 시험대라는 거죠.

## 실제 사용감 — 솔직한 장단점

이 블로그의 크론잡 자동포스팅 자체가 AI 에이전트로 돌아가고 있는 입장에서, 2.0 릴리스 노트와 매체 보도를 실측해 보며 느낀 점을 솔직히 정리하면:

**👍 좋은 점**
- **가이드 설치가 "이미 있는 AI 자산"을 재활용** — Codex·ChatGPT·Claude CLI 로그인, API 키, Ollama·LM Studio 로컬 모델을 **검증까지 마친 뒤** 재사용합니다. 신규 OpenAI 설정 기본 모델도 GPT-5.6로 통일됐고요. "처음부터 다시 설정"의 고통이 확 줄었습니다.
- **멀티플레이어 세션이 실제 협업을 바꾼다** — OpenClaw 팀은 이 기능으로 **OpenClaw 코드 자체를 만들고 있다**고 밝혔습니다(SiliconANGLE). "에이전트 하나를 팀원들과 함께 이어서 돌린다"는 건 기업 도입에 꽤 설득력 있는 시나리오예요.
- **메모리가 빌트인으로 전환** — QMD(Quarry Memory Database)를 대체하는 빌트인 메모리가 핵심 검색·회상 경로를 차지하고, 개인 설치에서는 **대화 간 컨텍스트 회상이 기본값으로 켜집니다.** 아까 리셋하기 전에 무슨 얘기를 했는지 기억하는 건 생각보다 큽니다.

**🤔 아쉬운 점 (솔직히)**
- **보안이 여전히 "기본 꺼짐"인 영역이 많다** — 샌드박스 off by default, 시크릿 스토어 미암호화는 The Register가 지적한 대로입니다. 설치가 쉬워진 만큼 **"쉽게 설치 = 쉽게 노출"**이 될 수 있어서, 초보자가 함부로 열어두면 위험합니다.
- **업데이트 버전 표기가 헷갈린다** — 공식 문서가 직접 경고한 내용인데, **'2026.9.1-beta.1'로 배포된 패키지는 실제로는 2026.8.1-beta.4**입니다. 버전 숫자만 보고 "9월 베타가 나왔네?" 하면 안 됩니다. 안정판은 여전히 **2026.8.1**입니다.
- **16,000개 PR을 한 번에 흡수**하다 보니 다운그레이드 시 SQLite 세션 저장소 때문에 **구버전에서 새 세션이 안 보이는** 문제가 생길 수 있습니다. 업그레이드 전 검증된 백업은 필수예요.
