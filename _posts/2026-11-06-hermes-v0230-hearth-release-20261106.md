자동화 파이프라인을 운영하다 보면 릴리스 소식이 반갑기만 하지는 않습니다. 기능이 늘어나는 건 좋은데, **이미 잘 돌아가던 것이 조용히 바뀌는 순간**이 더 신경 쓰이기 때문입니다. 특히 에이전트를 여러 창구에서 동시에 쓰는 구성이라면 "지금 이 대화가 어디에 저장되고 있는가"라는 질문이 늘 따라다닙니다.

2026년 11월 5일, 노우스 리서치(Nous Research)가 헤르메스 에이전트 **v0.23.0**을 배포했습니다. 코드네임은 **'히어스 릴리스(The Hearth Release)'** 입니다. v0.22.0이 "문턱을 넘는" 릴리스였다면, 이번은 **문 안쪽에 화로를 놓는** 릴리스라는 설명입니다. 규모부터 범상치 않습니다. v0.22.0 이후 **약 10,080개 커밋, 1,950개 PR, 8,720개 파일 변경, 약 850개 이슈 종료, 666명 기여자**가 한 번에 묶였습니다. v0.22.1부터 v0.22.7까지의 패치 릴리스도 이 문서에서 전부 정리됩니다.

![헤르메스 에이전트 공식 사이트 대표 이미지](/assets/images/posts/hermes-v0230-hearth-release-20261106/hermes-hearth-hero.webp)
*헤르메스 에이전트 공식 사이트 대표 아트워크 (출처: Nous Research 공식 홈페이지)*

> **📌 한줄 요약:** v0.23.0의 핵심은 **"표면(surface)을 하나로 모으는 것"** 입니다. 데스크톱 워크스페이스가 브라우저 탭으로 열리고, CLI·TUI·데스크톱·에디터·봇·크론이 각자 에이전트를 띄우던 구조가 **게이트웨이 1개 = 세션 1개**로 통일됩니다. 여기에 터미널 인라인 이미지, 대화 되감기(`/rewind`), 그룹챗 자동 라우팅, 크론 실행 중단, 유료 MCP 도구의 가격·지출 한도가 더해졌습니다. 대신 **구형 브라우저 도구 제거, macOS 13 미만 지원 종료**라는 파괴적 변경이 함께 왔습니다.

## 1. 숫자로 보는 릴리스 규모

먼저 릴리스 노트에 적힌 사실만 정리합니다.

| 항목 | 내용 |
|:---|:---|
| 릴리스 | **v0.23.0 '히어스(The Hearth)'** (2026년 11월 5일) |
| 기준점 | v0.22.0 이후 누적 |
| 커밋 | **약 10,080개** |
| PR / 이슈 | **약 1,950개 PR 머지**, 약 850개 이슈 종료 |
| 변경 파일 | **8,720개** (+725,200 / −201,400) |
| 기여자 | **666명** |
| 포함 범위 | v0.22.1 ~ v0.22.7 패치 릴리스 전체 문서화 |

숫자만 보면 "한 달 반 동안 쌓인 걸 한 번에" 수준입니다. 실제로 v0.22 계열은 10월 중순부터 거의 매주 패치를 냈고, 그 상세 노트를 모아둔 것이 이번 문서입니다. 즉 **v0.22.6, v0.22.7에서 "다음 릴리스에서 설명한다"고 미뤄둔 항목들의 정체가 여기서 전부 공개**된 셈입니다.

## 2. 업무 자동화 관점에서 체감이 큰 변경

### 2-1. 웹앱 — 데스크톱 워크스페이스가 브라우저 탭으로

이번 릴리스의 간판입니다. `webapp.enabled: true`를 켜면 **게이트웨이가 자기 리스너에서 데스크톱 워크스페이스를 그대로 서빙**합니다. 채팅, 그룹챗, 플러그인, 설정까지 동일하고, 접속 방법은 세 가지입니다.

- `hermes webapp` 명령으로 열기
- 데스크톱 **Settings → Web Access**에서 같은 네트워크에 공개
- 로그인 뒤 공개 URL로 노출

중요한 건 **기본값이 꺼져 있다**는 점입니다. 설정을 켜기 전까지는 브라우저에 아무것도 서빙되지 않습니다. 그리고 **단일 사용자** 모델입니다. 로그인한 탭은 곧 "나"이고, 그 탭의 세션과 그룹챗은 네이티브 데스크톱이 보여주는 것과 **같은 것**입니다. 별도 저장소가 생기는 게 아니라 같은 화로를 다른 창에서 들여다보는 구조입니다.

Docker 이미지와 Nix 패키지에도 웹앱 번들이 포함됩니다. 데스크톱 플러그인도 브라우저 탭에서 로드되기 때문에, 원격 서버에 에이전트를 두고 노트북·태블릿에서 같은 작업 화면을 보는 구성이 현실적으로 가능해졌습니다.

### 2-2. 게이트웨이 하나가 모든 세션을 소유한다

개인적으로 이번 릴리스에서 가장 중요한 구조 변경입니다. 이전에는 **CLI, TUI, 데스크톱, 에디터(ACP), 메신저 봇, 크론이 각자 에이전트 사본을 띄워 같은 채팅에 접근**할 수 있었습니다. 그 결과가 "메시지가 두 번 써지거나, 표면 사이에서 사라지는" 문제였습니다.

v0.23.0부터는 **머신당 게이트웨이 1개가 모든 세션을 소유**하고, 모든 표면은 클라이언트로 붙습니다. 어디서 열어도 같은 채팅, 같은 큐, 같은 히스토리입니다. 데스크톱에서 대기 중인 프롬프트를 수정해도 두 번 실행되지 않습니다.

크론과 봇을 함께 쓰는 구성이라면 이 변화가 곧 **중복 실행 리스크의 제거**입니다. 다만 구조가 바뀐 만큼, 게이트웨이가 살아 있어야 모든 표면이 동작한다는 전제도 함께 생깁니다.

### 2-3. 터미널에 이미지가 그려지고, 대화를 되감을 수 있다

터미널 쪽 변화도 실사용 체감이 큽니다.

- **인라인 이미지** — 이미지를 붙여넣거나 도구가 스크린샷을 찍으면, 파일 경로를 출력하는 대신 **채팅 안에 실제 픽셀로** 그려집니다. kitty·Ghostty(CLI·TUI), iTerm2·WezTerm·Konsole(CLI)는 실제 이미지, 나머지는 컬러 블록, VS Code 터미널은 이미지 지원이 켜져 있으면 원본 해상도로 표시됩니다.
- **`/rewind`** — TUI나 클래식 CLI에서 **Esc 두 번** 또는 `/rewind`로 이전 메시지 목록을 열고, 그 지점에서 수정 후 재전송하거나 **새 세션으로 분기**할 수 있습니다. 원본 세션은 그대로 남습니다.
- **턴 중 `/new`** — TUI에서 작업이 돌고 있는 중에 새 세션을 열 수 있고, 기존 작업은 백그라운드에서 계속됩니다.

에이전트가 스크린샷을 검증 자료로 쓰는 워크플로라면, "파일 경로 확인 → 뷰어 열기" 단계가 사라지는 것만으로도 손이 꽤 줄어듭니다.

### 2-4. 그룹챗이 스스로 굴러가고, 크론을 중간에 세울 수 있다

봇 모드(Bot Mode) 그룹챗이 운영 도구다워졌습니다.

- **리드 봇 또는 `auto` 라우팅** — 이름이 지정되지 않은 메시지에 누가 답할지 자동으로 정합니다.
- **크론 → 룸 전달** — `deliver: room:<id>@<profile>` 형식으로 스케줄 작업 결과를 룸에 바로 게시합니다. 멘션된 봇만 깨어납니다.
- **룸의 목적·공유 노트** — 룸 단위로 맥락을 유지합니다.
- **봇 간 무한 루프 종료** — 마지막 사람 메시지 이후 교환 횟수를 `max_hops`(기본 4)로 제한합니다.

크론 쪽은 v0.22.6에서 예고됐던 기능이 정식 문서로 확정됐습니다. **`hermes cron cancel`, 데스크톱 Stop 버튼, API, `cronjob_manage`로 실행 중인 작업을 중단**할 수 있고, 작업마다 **미실행(missed-run) 정책**을 `--catch-up on|off`로 지정합니다. 수동 실행이 원샷(one-shot) 작업을 소모하지 않는 것도 실무에서 반가운 부분입니다.

### 2-5. 플러그인이 스스로 업데이트되고, 유료 도구에 가격표가 붙는다

- **`hermes plugins update`** — 이름 없이 실행하면 업데이트가 있는 플러그인을 모두 나열하고 한 번에 갱신합니다. 자동 업데이트 스위치(`plugins.auto_apply`, 기본 꺼짐)도 CLI·TUI·데스크톱·대시보드에 생겼습니다. **설정을 깨뜨릴 업데이트는 적용하지 않고 보류**합니다.
- **카탈로그 확장과 Verified 등급** — 600개 → 1,050개 이상. 벤더가 직접 만든 플러그인에 **Verified 등급**이 붙습니다(Cua Spaces, NVIDIA App, NVIDIA Broadcast, TinyFish, CoreWeave Inference가 첫 사례).
- **유료 MCP 도구의 가격 표시·지출 한도** — 3D·미디어 생성처럼 호출당 비용이 있는 도구가 **호출 가격과 채팅 누적 금액**을 승인 화면에 표시합니다. 한도를 넘으면 **YOLO 모드에서도** 먼저 묻습니다.
- **위임(delegation) 백엔드 교체** — `delegation.backend`로 서브에이전트 실행 방식을 고르고, 공식 `advanced-delegation` 플러그인으로 **작업별 모델 지정·프로필 라우팅**이 가능합니다. `/delegation`으로 전환합니다.
- **스킬 잠금** — `hermes curator lock <skill>`을 걸면 `skill_manage`, 파일 편집, 터미널 쓰기 어느 경로로도 해당 스킬을 바꿀 수 없습니다. `--yolo`에서도 마찬가지입니다.

### 2-6. 조용하지만 체감이 큰 비용·속도 개선

릴리스 노트에서 눈에 띄는 수치들입니다.

- **같은 크론 작업은 프롬프트 캐시 키를 공유** — 반복 실행에서 캐시 적중률이 올라갑니다.
- **원샷 실행당 프롬프트 토큰 약 1,570개 절감**, 도구 스키마 4종은 319토큰 짧아짐.
- **`patch`·`write_file`이 LSP 켜진 상태에서 밀리초로 복귀** — TypeScript 편집 10.1초 → 약 0.06초.
- **데스크톱 사이드바** — 크론 실행 3만 5천 건이 쌓인 저장소에서 새로고침이 **121초 → 즉시**.
- **게이트웨이 메모리** — 1분에 한 번씩 걸리던 메모리 정리 프리즈가 사라지고, 닫힌 세션이 메모리에서 해제됩니다.

에이전트를 하루 종일 띄워두는 구성일수록 이런 항목이 누적효과를 냅니다.

## 3. 업데이트 전 반드시 확인 — 파괴적 변경 5가지

좋은 것만 적으면 반쪽짜리 정리입니다. 이번 릴리스는 **메이저**이고, 실제로 기존 구성을 깨는 변경이 명시돼 있습니다.

**첫째, 구형 브라우저 도구가 사라졌습니다.** 브라우저 자동화는 이제 **`browser_exec` 단일 경로**입니다. `browser_navigate`, `browser_click` 등 10종의 `browser_*` 도구와 agent-browser가 제거됐습니다. 프롬프트, 스킬, 도구 목록에 옛 이름이 남아 있다면 **`browser_exec`로 바꿔야** 합니다. Camofox를 쓰던 환경은 `camofox` 플러그인이 자동 설치됩니다.

**둘째, 데스크톱은 macOS 13 이상, 64비트 Windows만 지원합니다.** Electron 40 → 44로 올라가면서 **macOS 11·12와 32비트 Windows 지원이 종료**됐습니다. 오래된 미니PC나 구형 맥을 자동화 전용기로 쓰던 경우라면 이번이 교체 시점입니다.

**셋째, `hermes mcp serve`가 `hermes mcp-serve`로 바뀌었습니다.** 플러그인으로 이동하면서 이름이 바뀌었고, **자동으로 고쳐주지 않습니다**. 헤르메스를 MCP 서버로 띄워 다른 클라이언트에서 붙이던 구성은 클라이언트 쪽 명령을 직접 수정해야 합니다.

**넷째, Word·PowerPoint·Excel 스킬이 `microsoft-office` 하나로 통합**됐습니다. 기존 사본은 디스크에 남아 있으니, 참조 경로가 있다면 정리해야 합니다.

**다섯째, 웹앱은 기본적으로 꺼져 있습니다.** 반대로 말하면 **켤 때 노출 범위를 반드시 정해야** 합니다. 웹앱은 단일 사용자 모델이라 로그인한 탭이 곧 사용자 권한입니다. 인증 없이 외부에 열어두는 구성은 피하고, 사내망이면 사내망까지만 두는 편이 안전합니다.

> **⚠️ 참고:** 릴리스 노트에는 `hermes gateway stop`/`restart`가 **세션이 살아 있으면 거부**하도록 바뀌었다는 항목도 있습니다. 자동화 스크립트에서 게이트웨이를 재시작하던 로직이 있다면 이 동작 변경을 확인해야 합니다.

## 4. 솔직히, 아쉬운 점

**첫째, "하나의 게이트웨이"는 편리함과 단일 장애점을 함께 가져옵니다.** 세션이 한 곳에 모인다는 건, 게이트웨이가 죽으면 CLI도 데스크톱도 크론도 같이 멈춘다는 뜻입니다. 릴리스 노트에 "모든 플랫폼이 시작에 실패하면 게이트웨이는 degraded 상태로 유지된다"는 보완이 들어간 이유이기도 합니다. 모니터링을 붙여두는 편이 좋습니다.

**둘째, 내장 스킬이 58개에서 44개로 줄었습니다.** 12개의 틈새 스킬이 선택 설치로 빠졌고, 벤더 저장소나 카탈로그 MCP가 커버하는 스킬은 제거됐습니다. 쓰던 스킬이 조용히 사라진 것처럼 보일 수 있으니, `hermes skills browse`에서 다시 설치해야 하는 항목이 있는지 확인하는 게 좋습니다.

**셋째, 카탈로그가 두 배로 커진 만큼 검증 비용도 커졌습니다.** 1,050개 항목 중 무엇이 내 워크플로에 맞는지 판단하는 건 여전히 사람 몫입니다. Verified 등급이 생긴 건 도움이 되지만, "Verified = 내 환경에서 안전"은 아닙니다.

**넷째, 웹앱은 아직 1인용입니다.** 팀 단위로 같은 워크스페이스를 공유하는 용도가 아니라, 한 사용자가 여러 기기에서 접속하는 모델입니다. 협업을 기대했다면 그 부분은 아직 아닙니다.

## 5. 업데이트 체크리스트

적용 전에 확인할 항목을 순서대로 정리하면 다음과 같습니다.

1. **백업** — `state.db`와 스킬·플러그인 목록을 먼저 백업합니다.
2. **브라우저 도구 이름 치환** — 프롬프트·스킬·도구셋에서 `browser_*`를 `browser_exec`로 교체합니다.
3. **MCP 클라이언트 명령 수정** — `hermes mcp serve` → `hermes mcp-serve`.
4. **OS 요건 확인** — 데스크톱 자동화 기기가 macOS 13+ 또는 64비트 Windows인지 확인합니다.
5. **웹앱 노출 범위 결정** — 끄고 쓸지, 사내망만 열지, 인증 뒤 공개할지 먼저 정합니다.
6. **크론 미실행 정책 지정** — 작업 성격별로 `--catch-up on|off`를 정합니다. 집계 작업은 켜고, 감시 작업은 끄는 식입니다.
7. **스킬 잠금 대상 선정** — 운영 규칙이 담긴 스킬부터 `hermes curator lock`으로 고정합니다.
8. **업데이트 직후 2~3회 주기 관찰** — 특히 크론·봇·웹앱 조합의 로그를 확인합니다.

설치 채널별로는 **CLI는 `hermes update`**(신규 설치는 이제 `main` 최신이 아니라 **최신 안정판**을 체크아웃), Docker·클라우드는 `nousresearch/hermes-agent:stable`, 데스크톱은 Electron 44 기반 새 번들입니다.

## 6. 정리 — "표면이 늘어난 릴리스"가 아니라 "표면이 합쳐진 릴리스"

v0.23.0을 한 문장으로 줄이면 **"여러 개로 흩어져 있던 작업 창구를 하나의 게이트웨이로 모은 릴리스"** 입니다. 기능 목록만 보면 웹앱, 인라인 이미지, 되감기, 그룹챗 라우팅, 플러그인 자동 업데이트, MCP 가격표까지 화려하지만, 그 아래를 받치는 건 **세션 소유권을 한 곳으로 모으는 구조 변경**입니다.

업무 자동화를 오래 돌리는 입장에서 실제로 와닿는 부분은 세 가지입니다. **크론 작업을 중간에 세울 수 있게 된 것**, **미실행 정책을 작업별로 정할 수 있게 된 것**, 그리고 **유료 도구에 지출 한도가 붙은 것**. 화려하진 않지만, 파이프라인을 "돌아가면 되는 것"에서 "통제되는 것"으로 옮겨주는 변화입니다.

반대로 업데이트를 서두를 이유가 없는 경우도 분명합니다. **구형 맥이나 32비트 Windows로 데스크톱을 돌리고 있거나, 프롬프트에 옛 `browser_*` 도구 이름이 잔뜩 박혀 있다면** 먼저 정리하고 올리는 편이 안전합니다. 메이저 릴리스는 항상 "언제 올릴까"보다 **"무엇을 먼저 고쳐둘까"** 의 문제입니다.

스케줄러를 돌리면서 "작업이 멈췄는지 어떻게 알지"가 늘 걸렸던 분들이라면, 이번 릴리스에서 답이 꽤 선명해졌습니다. 멈춤 버튼이 생기고, 놓친 실행을 어떻게 처리할지 정할 수 있게 됐다는 건 생각보다 큰 차이입니다.
