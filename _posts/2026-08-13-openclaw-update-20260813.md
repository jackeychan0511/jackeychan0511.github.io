요즘 저처럼 **오픈소스 AI 에이전트 OpenClaw**의 커밋과 릴리즈를 매일 같이 챙겨보시는 분들, 계시죠? 어제 [v2026.8.1-beta.1 상세 노트 정리 글](/2026/08/12/openclaw-v202681-beta-details-20260812/)에서 "다음 베타(8.1-beta.2+)에서 Kimi K3 비디오 입력을 확인하자"고 말씀드렸는데, **오늘(8/13) 기준으로 그 다음 베타가 정말 코앞까지 와 있습니다.**

솔직히 오늘 아침에 GitHub 저장소를 열어보고 깜짝 놀랐습니다. **v2026.8.1-beta.2가 이미 코드 프리즈(Code Freeze) 상태로 8번째 검증 라운드를 돌고 있더라고요.** 게다가 어제 오후부터 오늘 아침 사이 메인브랜치에는 **웹 세션을 터미널에서 그대로 이어받는 기능, 페어링된 기기로 세션을 넘겨주는 워커 파운데이션** 같은 알찬 기능들이 줄줄이 들어왔습니다. 오늘은 이 두 축을 중심으로, 제가 GitHub API와 공식 사이트에서 직접 확인한 **8월 13일자 OpenClaw 소식**을 정리해드립니다.

## 1. v2026.8.1-beta.2, 코드 프리즈 완료 — 검증 라운드 8회차 진행 중

어제 글에서 "8.1 라인의 다음 베타는 기능보다 안정화"라고 말씀드렸는데, 예상보다 빨리 움직이고 있습니다.

- GitHub 저장소에 **`release/2026.8.1-beta.2-code-frozen-r8`** 브랜치가 떠 있습니다. 이름 그대로 **코드 프리즈(기능 동결)가 끝난 상태**이고, `-r8`은 **8번째 검증(Validation) 라운드**를 뜻합니다.
- `chore(release): prepare 2026.8.1-beta.2` 커밋은 **8/10(월) 저녁(UTC 18:21)** 에 이미 올라와 있어서, 베타.1 출시 직후부터 다음 베타 준비가 병행된 셈입니다.
- 다만 **npm 최신 베타 태그는 아직 `2026.8.1-beta.1`**(8/13 오전 확인)입니다. 검증 라운드가 끝나고 태그가 찍히면 정식 배포가 시작될 텐데, **출시 시점은 말 그대로 "몇 시간~며칠 안"**으로 보입니다.

> 저처럼 **베타 라인을 직접 타보시는 분**이라면 `npm install -g openclaw@beta` 상태로 두시고, 며칠 안에 찍힐 **beta.2 태그**만 기다리시면 됩니다. 검증 라운드를 저렇게 여러 번 도는 릴리즈일수록 실제로는 더 믿을 만하더라고요.

## 2. 메인브랜치 신기능 — 8/12 오후~8/13 아침 커밋 기준

어제 글에서 정리한 Kimi K3 비디오 입력(#122337), 세션 환경설정 동기화(#121816)에 이어, **8/12 오후(한국시간 8/13 새벽)부터 8/13 아침까지 들어온 커밋** 중 눈에 띄는 것만 추렸습니다.

### ① 웹(Control UI) 세션을 터미널에서 그대로 이어받기 (#122870) ⭐

제가 이번 주 메인브랜치 소식 중 **제일 반가웠던 기능**입니다.

- `feat: continue web sessions in the terminal` — 브라우저(Control UI)에서 시작한 세션을 **터미널에서 그대로 이어서** 작업할 수 있게 됐습니다.
- `openclaw resume` 명령이 **자격증명 없이(credential-free)** 동작하도록, 셸별 따옴표 이슈를 피한 **base64url 핸드오프** 방식으로 바뀌었습니다.
- 보안도 꼼꼼합니다. 검증된 핸드오프에 대해서만 기존 인증 재사용을 허용하고, **바이트 단위로 정확히 일치하는 설정된 Gateway 대상**이 아니면 로컬 인증을 물려주지 않습니다.

솔직히 저처럼 **낮에는 브라우저, 밤에는 SSH로 같은 세션을 붙잡고 싶은 사람**한테는 딱 필요한 기능입니다. 지금은 베타.2에 실릴지 다음 베타에 실릴지가 관건인데, 코드 프리즈 전에 올라온 커밋이라 **베타.2에 들어갈 가능성이 꽤 높아 보입니다.**

### ② 페어링 기기 워커 파운데이션 (#122769, #122724)

- `feat: add paired-device worker provider foundation` — **페어링된 기기(노드)에 세션을 디스패치**하는 워커 프로바이더의 기반이 추가됐습니다. 기기 임대(device lease) 코어 로직과 설치 준비 지연 처리까지 포함됩니다.
- `feat(gateway): observe paired node desktops` — 페어링된 노드의 **데스크톱 스트림을 관찰**하는 기능도 함께 들어왔습니다. 스트림이 세션 생명주기에 묶여서(lifetime-bound) 끊김이 관리됩니다.

"PC에서 시작한 작업을 **옆에 있는 다른 기기(워커)**로 넘겨서 돌린다"는 구도인데, 지난주 [7.2 베타의 원격 코딩 세션(클라우드 워커)](/2026/08/11/openclaw-update-20260811/)과 맞물려 **"내 기기들이 하나의 클러스터가 되는" 방향**으로 가고 있다는 게 느껴집니다. 아직 파운데이션 단계이니, 실제 사용감은 다음 베타들에서 확인해보겠습니다.

### ③ 자동화·관리 편의 개선

- **자동화 이름 편집 (#122702)**: CLI에서 크론잡·자동화의 **표시 이름(display name)을 수정하거나 삭제**할 수 있게 됐습니다. 이름을 잘못 지어서 헷갈렸던 분들께 반가운 소식입니다.
- **제한된 브라우저의 관리자 권한 요청 (#121459)**: 제한된 접근(live device scope) 상태의 브라우저에서 **관리자 권한 상향을 요청하는 플로우**가 추가됐습니다. 요청 시 기한(deadline)도 적용돼서, 권한 요청이 무한정 대기하지 않습니다.
- **Cloudflare 배포 템플릿 (실험적, #122768)**: `@cloudflare/containers` 기반 **Worker + Durable Object 배포 템플릿**이 추가됐습니다. 실험 단계지만, 게이트웨이를 **서버리스로 올려보고 싶은 분**이라면 다음 릴리즈에서 꼭 만져볼 만합니다.
- **Linux 절전 연동 (#122719)**: macOS에 있던 **호스트 절전 시 게이트웨이 일시중단 → 복귀 시 재연결** 동작이 Linux(logind `PrepareForSleep`)에도 추가됐습니다. 노트북을 덮고 자는 분들께 체감이 큰 변경입니다.

## 4. 아키텍처 변화 — 멀티에이전트 소유권 명시화 (H2-1)

눈에 띄는 대형 리팩토링도 하나 있었습니다. `refactor(agents): make multi-agent ownership explicit (H2-1 core)` (#114388)인데요.

- 에이전트 **로스터(roster) 소유권을 명시화**하고, 레거시 에이전트 역할을 설정으로 **자동 구체화(materialize)** 합니다.
- **에이전트 범위 권한 부여(agent-scoped authorization)**가 강화되고, **소유권이 애매한 세션은 실패로 처리(fail closed)** 합니다.
- 크론잡의 레거시 소유자도 **시작 시 자동 마이그레이션**됩니다.

겉으로는 안 보이는 변경이지만, **여러 에이전트를 한 게이트웨이에서 같이 돌리는 분**이라면 "내 에이전트가 남의 세션/잡을 건드리는" 문제가 이제 원천적으로 줄어듭니다. 코드 구조가 커지면서 꼭 필요한 정리라고 봅니다.

## 5. 수치와 관전 포인트 — 스타 386,091개, Grok 4.6은?

40만 개 돌파가 정말 눈앞입니다. 하루 100개 안팎으로 꾸준히 늘고 있으니, **이번 달 안에는 충분히 넘어설** 속도입니다.

### Grok 4.6 관전 포인트

어제(8/12) xAI가 롱러닝 에이전트 특화 모델 **Grok 4.6**을 공개했고, 같은 날 **Hermes Agent가 당일 지원 커밋**을 올린 건 [오늘 오전 글](/2026/08/13/hermes-grok46-migration-20260813/)에서 말씀드렸죠. 그런데 OpenClaw 메인브랜치에는 **8/13 아침 기준 아직 Grok 4.6 전용 커밋이 보이지 않습니다.** (마지막 xAI 관련 커밋은 7/29의 OAuth 기본 모델 추적 수정)

다만 OpenClaw는 **모델 카탈로그(models.dev) 기반**으로 프로바이더를 잡는 구조라, 모델 ID만 등록되면 별도 커밋 없이도 쓸 수 있을 가능성이 있습니다. **베타.2가 나오면 Grok 4.6이 바로 잡히는지**를 직접 테스트해서 다음 글에서 확인해드리겠습니다.

## 마무리 — 오늘 소식 핵심 정리

1. **v2026.8.1-beta.2 코드 프리즈 완료** — 8번째 검증 라운드 진행 중, npm 태그만 기다리면 됩니다
2. **웹 세션 → 터미널 연동 (#122870)** — `openclaw resume`으로 브라우저 세션을 SSH에서 그대로 이어받기 (자격증명 없는 안전한 핸드오프)
3. **페어링 기기 워커 파운데이션 (#122769)** — 세션을 페어링된 기기로 디스패치하는 기반 완성, "내 기기 = 클러스터" 구도로 진화 중
4. **운영자용 픽스** — 게이트웨이 재시작 후 세션 자동 재개, 세션 리셋 후 이전 대화 기억, 크론잡 기록 보존 등
5. **멀티에이전트 소유권 명시화 (H2-1)** — 에이전트 범위 권한 강화, 애매한 소유권은 fail closed
6. GitHub 스타 **386,091개** (+126) — 40만 개 돌파 눈앞

**업데이트 팁** 하나만 드리면, 지금 운영 중이신 분은 서두르지 마세요. **안정판(`openclaw@latest`, v2026.7.1-2)은 그대로 두시고**, 새 기능을 미리 보고 싶은 분만 `openclaw@beta`로 올려서 **며칠 안에 나올 beta.2**를 기다리시는 걸 추천합니다. 특히 **브라우저와 SSH를 오가며 세션을 쓰시는 분**이라면, 베타.2 릴리즈 노트에서 `openclaw resume` 항목을 꼭 확인해보세요.

```bash
# 안정판 유지
npm install -g openclaw@latest

# 베타 라인 (beta.2 태그 대기)
npm install -g openclaw@beta

# 버전 확인
openclaw version
```
