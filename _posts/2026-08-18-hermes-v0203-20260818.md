## 1. 요즘 저처럼 "크론잡이 조용히 죽으면 어쩌지" 고민이신 분들

요즘 저처럼 **Hermes Agent로 크론잡 자동화를 돌리시는 분들**, 특히 이 블로그처럼 **매일 아침 자동 포스팅**을 맡기고 계신 분들 많으시죠. 저도 그런데, 지난주에 이어 계속 업데이트가 쏟아지고 있습니다. 8월 3일 v0.20.0 Herald 릴리스 → 8월 13일 v0.20.1 → 8월 16일 v0.20.2에 이어, **8월 17일(한국시간 8/18 새벽) v0.20.3**까지. 이번엔 전날 나온 v0.20.2 이후 **단 하루 만에 ~125개 PR**이 롤업됐습니다.

솔직히 "또 패치?" 싶을 수도 있는데, 이번 v0.20.3을 자세히 뜯어보니 **자동화를 실제로 돌리는 사람 입장에서 반가운 내용이 유독 많았습니다.** 크론잡이 파일 디스크립터 고갈(EMFILE)로 조용히 멈추던 문제를 스스로 고치고, 데스크톱엔 '봇 모드(Bot Mode)'가 기본 탑재되고, MCP는 2.x SDK로 넘어가면서 stateless 프로토콜을 지원합니다. 하나씩 정리해 봤습니다.

숫자부터 보시면, **v0.20.2(8월 16일) → v0.20.3(8월 17일)이 하루**인데 커밋 250개·PR 125개입니다. 릴리스 노트 표현을 빌리자면 "v0.20.2 이후 병합된 약 125개 PR을 안정 태그로 롤업"한 것으로, 기능 추가보다는 **견고함과 생태계 포팅에 집중한 패치**라는 점이 특징이에요.

### ② 실사용자가 체감할 만한 포인트 7가지

릴리스 노트에서 짚어보면 이번 패치의 핵심은 이렇습니다:

1. **MCP 2.x SDK 마이그레이션** + 2026-07-28 stateless 프로토콜 지원
2. **Bot Mode(hermes-bots) 플러그인 기본 번들** — 핵심 팀메이트 프로토콜 포함
3. **CommandCode 프로바이더 플러그인**
4. 서브프로세스 **Python 런타임 소유권 하드닝** (PYTHONHOME/PYTHONPATH 격리)
5. **Cua Driver 0.20** 런타임 계약 지원 (컴퓨터 사용 자동화)
6. 칸반 worktree/dispatch 수정, **크론 연속성(continuity) 플래그**
7. **크론 스케줄러 자가 복구** (EMFILE 회복·고아 클레임 정리·wedged 잡 재무장)
8. 데스크톱 **원격 게이트웨이 헤더·연결 셀프힐**, 세션 핸드오프 데이터 손실 수정

이 중에서 저처럼 자동화를 돌리는 사람에게 가장 중요한 **크론 셀프힐**과, 이번에 기본 탑재된 **Bot Mode**를 중심으로 자세히 풀어보겠습니다.

## 3. Bot Mode — 데스크톱에 기본 탑재된 '봇 부대' (별도 설치 불필요)

### ① 이게 왜 중요하냐면 — 이제 그냥 켜져 있습니다

Bot Mode는 원래 **별도 저장소(NousResearch/Hermes-Bot-Mode, 600+ 스타)**로 개발되던 데스크톱 플러그인이었습니다. 그런데 이번 v0.20.3에서 **PR #87886으로 Hermes Desktop에 기본 내장(bundled, default-on)**됐습니다. 별도 설치, 별도 패치 없이 데스크톱 앱을 업데이트하면 **Sessions 옆에 'Bots' 탭**이 그냥 생깁니다.

핵심 컨셉은 간단합니다. **"봇 = 프로필"**이라는 것. Hermes의 프로필(격리된 설정·메모리·스킬·자격증명·대화 이력, `~/.hermes/profiles/<name>/`)을 그대로 '봇'이라는 이름의 로스터로 보여주는 UI입니다. 그래서 데스크톱에서 만든 봇은 CLI에서도 그대로 보입니다.

```bash
hermes -p <bot> chat        # CLI로 같은 봇과 대화
hermes cron list            # 봇 루틴도 그냥 크론잡으로 표시
hermes profile create/list  # 프로필 관리로도 가능
```

![Hermes Bot Mode 로스터 스크린샷](/assets/images/posts/hermes-v0203-20260818/botmode-roster.png)
*Bot Mode 로스터 — 프로필별 아바타·최근 메시지·Active now 프레즌스 스트립 (출처: github.com/NousResearch/Hermes-Bot-Mode 공식 저장소, 2026-08-18 확인)*

### ② 봇 만들기 — 3개 필드면 끝, 고급 설정은 그 뒤에

**New Agent** 클릭 → **이름(Name)·직책(Title)·설명(Description)** 세 개만 넣으면 몇 초 만에 봇이 생기고, 자기소개 메시지와 함께 전용 'Bot Chat' 대화가 자동 생성됩니다. **Advanced**를 열면:

- 기존 프로필/봇에서 **클론** (설정·스킬·SOUL.md·메모리까지)
- **모델 고정** — 봇마다 다른 프로바이더/모델을 나란히 사용 가능
- **SOUL.md 커스텀** — 페르소나와 상시 지시사항
- **스킬·툴셋·MCP 서버별** 활성화 체크리스트
- 자격증명은 기본적으로 메인 프로필과 **키 풀 공유** (리프레시 충돌 방지)

아바타도 취향대로 고를 수 있는데, 이번에 기본 탑재되면서 **픽셀 펫(PetDex)** 갤러리도 함께 들어왔습니다. 터미널에서 `hermes pets`라고 치면 갤러리를 구경할 수 있어요. 봇이 일하는 동안 펫이 아바타 옆에서 깡충깡충 뛰는 게 꽤 귀엽습니다.

![Hermes Bot Mode PetDex 아바타](/assets/images/posts/hermes-v0203-20260818/botmode-petdex.png)
*PetDex 픽셀 펫 아바타 갤러리 — 봇이 작업 중일 때 아바타 옆에서 움직이는 펫 (출처: github.com/NousResearch/Hermes-Bot-Mode 공식 저장소, 2026-08-18 확인)*

### ③ 루틴·그룹챗·봇 간 메시징 — '팀'이 됩니다

- **Routines(루틴)** — "매일 아침 인박스 요약해 줘" 같은 반복 작업을 담당 봇에 바로 부착합니다. 실체는 Hermes 크론잡이고, 이름이 `[bot:<name>] <루틴>`으로 네임스페이스돼서 `hermes cron list`에 그대로 보입니다. 실행 결과는 그 봇의 채팅 기록에 쌓여요.
- **그룹챗** — 로스터를 그룹으로 묶고(2~6봇) **Open chat**을 누르면 공유 방이 열립니다. 내 메시지에 대해 최대 3라운드까지 봇들이 돌아가며 답하고, `@name`으로 서로를 호출하며, 판단이 필요한 건 `@user`로 나에게 올립니다(헤더에 'needs you' 배지). 하드캡(턴당 10메시지·3라운드)으로 무한 루프는 차단됩니다.
- **봇 간 메시징** — 어떤 채팅에서든 `@researcher 이거 한번 봐줘`라고 멘션하면 활성 봇이 메시지를 넘겨주고, 답변을 기다렸다가 보고합니다. 멀티 머신 환경이면 **@name-device** 핸들로 다른 PC·Hermes Cloud의 봇에게도 전달됩니다.

솔직히 아직 한계도 있습니다. **봇 간 메시지 수신이 '다음 실행 시' 방식**이라, 대화 중인 봇을 실시간으로 끼어들게 하는 건 future work라고 공식 문서에 명시돼 있어요. 그래도 "봇 3개가 아침에 모여 브리핑을 만들고, 하나는 검증하고, 하나는 출판하는" 구조는 지금도 충분히 만들 수 있습니다.

### ④ 끄고 싶다면? — Settings → Plugins → Bots

기본 내장이지만 **Settings → Plugins → Bots**에서 언제든 끌 수 있고, 끄면 로스터·루틴 패널·컴포저 미들웨어만 빠지고 **프로필·세션·크론잡은 그대로** 유지됩니다. "Bot Mode는 데이터를 소유하지 않고 그려줄 뿐"이라는 표현이 인상적이었어요.

## 4. 크론 셀프힐 — "조용히 죽던 잡"이 스스로 일어납니다

제가 이번 패치에서 제일 반가웠던 부분입니다. 자동화를 돌려보신 분들은 아시겠지만, **크론잡이 실패하는 것보다 더 짜증나는 건 '조용히 멈추는 것'**입니다. 로그를 뒤져야 겨우 발견하거든요. 이번 v0.20.3은 그런 시나리오를 겨냥한 수정이 대거 들어왔습니다.

| 시나리오 | 수정 내용 |
|:----|:------|
| **EMFILE(파일 디스크립터 고갈)** | 스케줄러가 조용히 멈추던 문제 → **자가 복구** (PR #87644) |
| **stale in-flight claim** | 실행 원장(ledger)과 대조해 **고아 클레임 정리** |
| **last_status=error로 멈춘 반복 잡** | 영속 상태 복구 시 **자동 재무장** |
| **wedged job(꼬인 잡)** | **다음 합법 실행 시점으로 re-arm** + 주기 캐시 |
| **misfire(실행 놓침)** | 외부 크론 프로바이더용 **misfire catch-up** |
| **게이트웨이 의도적 중지** | **재시도 스톰 방지** (OOF-266) |

여기에 **크론 '연속성(continuity)'** 기능도 새로 생겼습니다. `context_from='self'` 방식으로 **반복 잡이 실행 간 컨텍스트를 이어받는** 건데, 사용자 입장에서는 `hermes cron create/edit`에 **`--continuity` / `--no-continuity` 플래그**로 켜고 끕니다. 대시보드·Bot Mode 루틴·TUI 크론 화면에도 토글이 함께 들어갔어요. "어제 정리하던 그 맥락에서 오늘 이어서"가 되는 거라, **다단계 자동화 파이프라인**을 크론으로 짜신 분들께 특히 유용합니다. 추가로, **반복 실패하는 잡은 리뷰를 넛지(알림)** 해주는 기능도 들어왔습니다(Poke 프로젝트에서 영감).

![Hermes Agent 공식 자동화 기능 이미지](/assets/images/posts/hermes-v0203-20260818/feature-automation.webp)
*Hermes Agent 공식 사이트 'Automation' 기능 소개 이미지 — 크론·루틴 기반 자동화 컨셉 (출처: hermes-agent.nousresearch.com, 2026-08-18 확인)*

저처럼 "매일 아침 잡이 죽었는지 안 죽었는지 확인하러 로그 보는" 사람에겐, 이 셀프힐들이 **"그 걱정을 시스템이 대신 하게 된"** 변화입니다.

## 5. MCP 2.x + stateless 프로토콜 — "세션 없는" MCP의 시대

이번 릴리스는 **MCP(Model Context Protocol) 2.x SDK로의 마이그레이션**과 **2026-07-28 MCP 스펙 릴리스 후보의 stateless 프로토콜 지원**을 포함합니다. 이게 뭔지 쉽게 설명하면:

- 기존 MCP는 `Mcp-Session-Id` 헤더로 **서버와 세션을 고정**해야 했습니다. 그래서 같은 서버 인스턴스에 요청이 몰리고, Redis 같은 세션 고정(스티키 세션) 꼼수가 필요했어요.
- **stateless 프로토콜**은 프로토콜 코어에서 세션 상태를 아예 걷어냅니다. **어떤 요청이든 아무 서버 인스턴스에나 떨어져도** 되는 구조라, **라운드로빈 로드밸런싱**이 그냥 됩니다. 대규모로 MCP 서버를 돌리는 팀에겐 운영 부담이 확 줄어드는 변화입니다.

v0.20.3에서는 이 마이그레이션과 함께 **스트리밍 HTTP 트랜스포트 2세대 호환**(`MCP-Protocol-Version`을 핸드셰이크 버전에서 시드), 그리고 생태계 스카우트 포트로 **보이지 않는 유니코드 TAG 문자 제거**(goose에서), **MCP 툴 결과 `_meta` 노출**(kimi-code에서) 같은 보안·가시성 개선도 묶여 들어왔습니다.

## 6. /worktree & /rollback — "에이전트가 만든 변경, 되돌릴 수 있어야죠"

에이전트가 파일을 마구 바꾸는 시대에 **되돌리기 안전망**은 선택이 아니라 필수인데, 이번에 두 가지가 의미 있게 개선됐습니다.

### ① /worktree — 세션 중에 작업 공간 분리

**Copilot CLI에서 영감**을 받아 추가된 `/worktree` 명령입니다. 세션 도중에

```
/worktree new my-experiment
```

라고 치면 저장소 안에 `.worktrees/my-experiment/`(브랜치 `hermes/my-experiment`)가 만들어지고, **터미널·파일 툴이 재시작 없이 즉시 그 트리로 리타깃**됩니다. 실험적인 리팩터링을 메인 브랜치와 완전히 분리해서 진행하고 싶을 때 딱입니다. `/worktree list`로 목록 확인, `/worktree`만 치면 현재 활성 트리 표시. 원격 게이트웨이 백엔드에서도 동작하도록 수정됐고(f8f43c9), 칸반도 작업 완료 시 워크트리 워크스페이스를 정리하도록 바뀌었습니다.

### ② /rollback — 손으로 고친 건 지켜주는 복원

역시 **Copilot CLI에서 영감**을 받아, **기본 동작이 '사용자 수동 편집(hand-edits) 보존'**으로 바뀌었습니다(bd4b709). 즉 `/rollback <N>`으로 복원해도 **내가 직접 고친 부분은 남아있고**, 에이전트가 만든 변경만 되돌아갑니다. 완전 복원은 `/rollback <N> --all`, 미리 보기는 `/rollback diff <N>`, 단일 파일 복원은 `/rollback <N> <file>`입니다.

주의할 점 하나 — 체크포인트는 **v2부터 opt-in(기본 off)**입니다. 섀도우 저장소(`~/.hermes/checkpoints/store/`) 용량이 무시할 수 없어서인데, 쓰실 분은 세션 시작 시 `hermes chat --checkpoints` 또는 `config.yaml`에 `checkpoints: enabled: true`를 넣으면 됩니다. 파괴적 작업(write_file·patch·rm·mv·git reset 등) **전에 자동 스냅샷**을 찍어주고, 실제 프로젝트 `.git`은 건드리지 않습니다. `hermes checkpoints status/prune`으로 관리할 수 있어요.

## 7. 기타 — CommandCode 프로바이더·Python 하드닝·데스크톱 연결 셀프힐

- **CommandCode 프로바이더 플러그인** — Command Code AI의 **네이티브 `/alpha/generate` API**로 채팅을 라우팅하는 모델 프로바이더 플러그인이 번들됐습니다. Command Code의 **$1 플랜과 프로모 딜(4× DeepSeek V4 Pro, 2× Qwen 3.7 Max 등)은 Provider API가 아닌 네이티브 API에서만** 적용된다고 하니, 초저가로 모델을 굴리고 싶은 분은 눈여겨볼 만합니다.
- **Python 런타임 하드닝** — Hermes 자체 venv의 site-packages가 터미널 서브프로세스의 PYTHONPATH에 섞여 **크로스 버전 ABI 충돌**을 내던 문제를 차단(PYTHONHOME/PYTHONPATH 격리). 파이썬 스크립트를 자동화에 돌리는 분에게는 꽤 실제적인 수정입니다.
- **Cua Driver 0.20** 런타임 계약 지원 — 컴퓨터 사용(computer use) 자동화 드라이버가 최신 계약을 따릅니다.
- **데스크톱 연결 셀프힐** — 원격 게이트웨이 헤더 지원, 끊긴 SSH/HTTP 연결 자가 복구, 오프라인 게이트웨이 상태바 재연결, sleep/wake 후 세션 타일 재개. Hermes Cloud·원격 게이트웨이·로컬을 함께 쓰는 분들께 반가운 수정들입니다.

1. **Bot Mode가 그냥 켜져 있음** — 별도 설치 0단계. 게다가 '봇 = 프로필'이라 CLI·크론과 완전히 호환되는 게 최고의 설계 포인트

3. **/rollback이 손편집을 보존** — "에이전트가 고친 것만 되돌리고 내 수정은 남기는" 기본 동작이 실용적

1. **큐레이티드 릴리스 노트는 여전히 v0.21.0까지 대기** — v0.20.0부터의 전체 하이라이트 정리가 다음 메이저에서 나오니, 지금은 릴리스 노트 원문과 커뮤니티 분석으로 갈음해야 합니다
2. **봇 간 메시징이 '다음 실행 시 수신'** — 실시간 인터럽트는 아직 future work. "지금 당장 답해!"형 협업은 안 됩니다
3. **체크포인트가 기본 off** — /rollback을 기대하려면 `--checkpoints` 활성화가 선행돼야 하는데, 이 사실을 모르면 "왜 롤백이 안 되지?" 하기 쉽습니다
4. **패치 주기가 하루로 단축** — v0.20.2→v0.20.3이 하루 만입니다. 빠른 건 좋지만, 변경 추적과 검증 부담은 따라옵니다
5. **CommandCode는 타사 생태계 플러그인** — 번들됐지만 공식 문서화는 아직 얕습니다

## 9. 마무리 — 업데이트 방법과 사용 팁

정리하면, v0.20.3의 키워드는 **"봇(Bot Mode 기본 탑재) + 자가 치유(크론 셀프힐·연결 셀프힐) + 안전망(/worktree·/rollback) + 차세대 표준(MCP 2.x stateless)"**입니다. 지난주 Herald 릴리스가 '기능의 폭'을, v0.20.1·v0.20.2가 '견고함'을 넓혔다면, 이번엔 **"여러 에이전트를 팀처럼 굴리는 운영"**으로 무게중심이 옮겨가는 느낌이에요.

기존 설치자라면 업데이트는 이 한 줄이면 끝입니다.

```
# 기존 설치 업데이트
hermes update
# 새로 설치 (공식 인스톨러)
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

**사용 팁 3가지:**

1. **크론 자동화를 돌리신다면** — 업데이트 후 `hermes cron edit <잡>`에서 **`--continuity`를 켜보세요.** 다단계 작업의 맥락 유지가 확 달라집니다.
2. **/rollback을 쓰실 거라면** — 지금 바로 `hermes chat --checkpoints`로 체크포인트를 켜두세요. 기본 off라서 모르고 지나치기 쉽습니다.
3. **여러 봇을 팀으로 굴리고 싶다면** — 데스크톱의 Bots 탭에서 봇 2~3개를 만들고 그룹챗을 열어보세요. `@user`로 판단을 요청하는 구조가 실제로 꽤 쓸 만합니다.

솔직히 저처럼 **"크론잡이 조용히 죽지 않았으면"**, **"에이전트가 바꾼 파일을 안심하고 되돌리고 싶은"** 분들, 그리고 **여러 AI 에이전트를 팀처럼 운영**해 보고 싶은 분들께 이번 v0.20.3 업데이트를 추천드립니다. 가성비 좋은(사실상 무료인 MIT) AI 에이전트 찾는 분께 특히요. 다음 메이저 v0.21.0에서 v0.20.0 이후의 전체 큐레이티드 노트가 나오면 또 정리해 올게요!
