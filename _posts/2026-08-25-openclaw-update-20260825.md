## 1. 요즘 저처럼 "OpenClaw 정식판 언제 나오나" 매일 npm부터 여시는 분들

요즘 저처럼 **오픈소스 AI 에이전트 OpenClaw의 2026.8.1 정식판이 언제 npm에 올라오나** 매일 아침 `npm view openclaw dist-tags`부터 확인하시는 분들, 많으시죠.

솔직히 지난주 내내 좀 답답했습니다. 8/20에 정리했듯이 공동 창업자가 예고한 **"8월 18일(화) 출시"**가 미뤄지면서, "이번 주도 latest는 그대로겠지" 하는 마음으로 확인하는 게 일상이 됐거든요. 그런데 어제(8/24) 저녁, GitHub 알림이 울리더라고요. **2026.8.1-beta.3 게시.** 그것도 8/22 커뮤니티 공지에서 "8/25(화)쯤 나올 예정"이라고 했던 로드맵보다 **하루 일찍**입니다.

그래서 오늘(8/25) 아침, **npm 레지스트리와 GitHub 저장소, 릴리스 노트, CHANGELOG를 전부 실측**하고 — 크론잡 자동 포스팅을 실제로 돌리는 제 입장에서 "이번 베타, 받아볼 만한가"를 기준으로 정리해 봤습니다.

## 2. 오늘의 메인 뉴스 — 2026.8.1-beta.3, 어제 저녁 출시 (npm 실측)

오늘 아침 기준 **npm dist-tags 실측 결과**입니다.

| 트랙 | 버전 | 비고 |
|:-----|:-----|:-----|
| **latest (정식)** | `2026.7.1-2` | 7/18 배포 그대로 — **아직 미출시** |
| **beta** | `2026.8.1-beta.3` | **8/24 게시 — 신규!** (종전 beta.2) |
| **extended-stable** | `2026.6.34` | 8/8 배포, 보수적 트랙 유지 |
| **alpha** | `2026.5.19-alpha.1` | 변동 없음 |

- **beta 트랙이 `2026.8.1-beta.2` → `2026.8.1-beta.3`으로 이동**했습니다. GitHub 릴리스 페이지에도 `v2026.8.1-beta.3` 태그가 게시돼 있고, 게시 시각은 **8/24 04:40 UTC(한국시간 8/24 오후 1시 40분)**입니다.
- 다만 **latest는 여전히 `2026.7.1-2`** — 정식판 2026.8.1은 아직 안 나왔습니다. 베타.3은 "정식판 직전의 마지막 검증" 성격으로 보는 게 맞아요.
- 재미있는 점: 8/22에 유지보수자 커뮤니티 공지에서 **"베타.3은 8/25쯤 출시 예정, fresh-install 및 v2026.7.1 업그레이드 시 DB 문제를 고치고 permission-file 기본 게이트를 하드닝한다"**고 예고했는데, 실제로는 **하루 먼저 나왔습니다.** "늦어지던 출시가 드디어 빨라졌다"는 느낌이 들어서 기분 좋았습니다.

### 왜 베타.3이 필요한가 — 로드맵 배경

베타.2(8/15)가 **fresh install과 v2026.7.1 업그레이드 과정에서 데이터베이스 문제**가 보고됐고, **퍼미션 파일(permission-file)의 기본 게이트**가 생각보다 약하다는 지적도 있었습니다. 베타.3은 신기능보다 **이런 실사용 문제를 먼저 고치는 유지보수 릴리스**예요. 정식판 직전에 "설치한 사람이 바로 이상한 DB를 만나지 않도록" 다지는 단계라고 이해하시면 됩니다.

## 3. 베타.3 하이라이트 6가지 — CHANGELOG 실측

릴리스 노트와 CHANGELOG(약 340만 자)를 커밋 단위로 까보니, 체감이 큰 순서대로 6가지가 나옵니다.

### ① Puppeteer 호환 CDP 릴레이 — 이번 베타의 진짜 하이라이트 🎯

이번 베타.3에서 **가장 눈에 띈 신기능**입니다. 이름이 좀 어려운데, 쉽게 풀면 이렇습니다.

> **Puppeteer 같은 브라우저 자동화 도구가 OpenClaw의 paired Chrome을 "원격 디버깅 권한 프롬프트 없이" 직접 제어할 수 있게 해주는 릴레이.**

- **`Target.getBrowserContexts` 응답**: Puppeteer 기반 클라이언트(대표적으로 **chrome-devtools-mcp**)가 paired Chrome을 드라이브할 때, 원래 뜨던 **remote-debugging 권한 프롬프트가 사라집니다.**
- **DevTools 스타일 `/json/list` 타겟 디스크립터** 제공: 외부 CDP 클라이언트가 마치 DevTools 프로토콜에 붙은 것처럼 타겟 목록을 읽을 수 있습니다.
- **`openclaw browser extension cdp` 명령**: 릴레이 엔드포인트와 인증 헤더를 한 번에 출력해 줍니다. 외부 CDP 클라이언트를 붙일 때 이 출력값을 그대로 쓰면 됩니다.

저처럼 **"AI 에이전트가 크롬을 열어서 직접 작업하는" 자동화를 짜보시는 분들**이라면, 이 권한 프롬프트 하나가 생각보다 큰 걸림돌이었어요. 자동화 스크립트 중간에 사람이 "허용" 버튼을 눌러야 하면 의미가 없으니까요. 이번 변경으로 **완전 무인 브라우저 자동화의 마지막 관문이 하나 사라졌다**고 봐도 됩니다.

### ② GPT-5.6 Sol/Terra/Luna/Ultra 추론 지원

베타.2에서 GPT-5.6 **Ultra와 Sol/Terra/Luna 런타임 전환**이 확정됐었는데, 베타.3에서는 **추론(reasoning) 지원 범위가 OpenClaw 엔진과 Codex 런타임 양쪽으로 확장**됐습니다. 모델·런타임·thinking 선택이 `/model` 명령으로 원자적으로 함께 바뀌는 것도 그대로 유지됩니다. GPT-5.6 계열을 메인 모델로 쓰시는 분이라면 이번 업데이트에서 체감이 있을 겁니다.

### ③ Control UI 첫 실행 셋업 — Custodian 연계

베타.2에서 개선됐던 첫 실행 흐름이 한 단계 더 이어집니다. **검증된 모델 셋업을 Custodian(커스토디언)으로 이어가고**, 채널 셋업은 선택(닫을 수 있는) 경로로 제공됩니다. "설치하고 나서 뭐부터 해야 하지?" 하는 첫인상이 계속 좋아지고 있어요.

### ④ 외부 게이트웨이 라이프사이클 감독

**`OPENCLAW_SUPERVISOR_MODE=external`** 환경 변수로, OCM 같은 외부 라이프사이클 관리자가 OpenClaw 게이트웨이를 감독할 수 있는 **명시적 모드**가 추가됐습니다. 핵심은 **검증된 재시작 핸드오프(verified restart handoff)** — 외부 감독자가 게이트웨이를 재시작할 때 "정말 재시작됐는지"를 확인하는 절차가 들어갔고, 이 모드에서는 **네이티브 서비스 변형과 자체 업데이트가 차단**됩니다. 여러 대의 머신을 한꺼번에 관리하시는 분들께 유용한 기능입니다.

### ⑤ SQLite 스냅샷 백업/복원

베타.2에서 확정된 `openclaw backup sqlite create|list|verify|restore`가 베타.3에서도 **compact(작게 압축) + verified(검증된)** 아티팩트로 이어집니다. 전역 DB와 에이전트별 DB를 각각 지원하고, 복원은 **fresh-target 전용**이라 실수로 지금 쓰는 DB를 덮어쓸 일이 없습니다. 베타 트랙을 타시는 분들은 **업데이트 전에 이 명령으로 백업 한 방** 해두시면 안심입니다.

### ⑥ 채널 플러그인 공유 인그레스 모니터

IRC·Synology Chat·Google Chat이 공유 플러그인 SDK 모니터(durable admission·polling·pruning·claim identity 검증·adoption handoff·shutdown)로 이전됩니다. "채널이 조용히 죽어 있는" 문제를 공통 인프라로 잡는 작업이에요.

### + 출판 증거 (이번엔 특별히 꼼꼼합니다)

베타.2 때와 달리 베타.3 릴리스 노트에는 **출판 검증 기록이 통째로** 들어있습니다.

- **89개 공식 npm 플러그인 전부**가 `beta` 선택자로 `2026.8.1-beta.3`에 맞춰 read-back됐고, 타르볼 무결성 메타데이터까지 확인됐습니다.
- `@openclaw/codex@2026.8.1-beta.3`은 **관리형 `@openai/codex@0.149.1` 런타임을 정확히 탑재**합니다.
- 코어 npm 사전 점검(preflight)·게시·플러그인 동기화 GitHub Actions 실행 링크까지 공개돼 있습니다.

6월 릴리스 사태 이후 **"검증된 것만 배포한다"는 원칙을 계속 지키고 있다**는 게, 직접 확인할 때마다 든든합니다.

## 4. 지난 24시간 커밋 점검 — 283건 (8/24 00:00 UTC ~ 8/25 00:51 UTC)

출시와 별개로 커밋도 멈추지 않았습니다. GitHub API 실측 기준 **24시간 동안 283건**이 쌓였는데(8/24 00:00 UTC~8/25 00:51 UTC), 제가 눈여겨본 것들입니다.

### ① 크론잡 쓰는 블로거로서 제일 반가운 커밋 2건
- **`fix(cron): honor updated recurring schedule anchors` (#128893)** — 반복 스케줄의 **앵커(기준점)가 갱신되면 새 기준을 따르도록** 수정. "스케줄을 바꿨는데 예전 기준으로 도는" 문제를 정리해 줍니다.
- **`fix(cron): route script notifications to their owning agent` (#128856)** — 스크립트 알림이 **그 작업을 소유한 에이전트에게 정확히** 전달되도록 수정. 멀티 에이전트 환경에서 "알림이 엉뚱한 데 간다"는 문제가 줄어듭니다.

### ② 보안 — `$-패턴 인젝션` 수정
- **`fix: prevent $-pattern injection in prompt template and approval substitution` (#123015)** — 프롬프트 템플릿과 승인 치환 과정에서 **`$` 패턴 인젝션을 차단**합니다. 프롬프트 인젝션 공격의 한 갈래를 구조적으로 막는 수정이라, 에이전트를 믿고 쓰는 입장에서 반가웠습니다.

### ③ UI — 커맨드 팔레트에서 세션·카탈로그 검색
- **`feat(ui): search sessions and catalogs from command palette` (#128356)** — Control UI 커맨드 팔레트에서 **세션과 카탈로그를 바로 검색**할 수 있게 됐습니다. 세션이 많이 쌓이는 분들에게 유용한 기능이에요.

### ④ 그 외 주목할 커밋들
- **GitHub 연동**: `fix(agents): preserve GitHub capability at attempt dispatch` (#128937) — 에이전트가 작업을 실행할 때 GitHub 능력이 유실되지 않도록 수정.
- **게이트웨이**: `fix(gateway): publish cloud placement changes` (#128914), `refactor(gateway): unify bounded chat history across transports` (#128844).
- **채널 스레드 보존**: Slack 편집/삭제 메시지 원 스레드 유지 (#128768), MSTeams 채널 스레드 컨텍스트 보존 (#128901), Matrix 편집 메시지 스레드 반영 (#128763), Discord 포럼 첨부 첫 스레드 유지 (#128765). **채널별 "메시지가 원래 대화 맥락에서 사라지는" 문제를 일제히 고치는** 물결입니다.
- **로컬/성능**: `perf(sqlite): avoid unnecessary snapshot workers` (#128884), macOS paired-node Codex 카탈로그 수정 (#126811), Twitch 계정 셧다운 후 커넥션 펜싱 (#128909).

## 6. 실제 사용감 — 장점과 아쉬운 점, 솔직하게

이 블로그처럼 **에이전트 + 크론잡으로 자동 포스팅을 돌리는** 제 입장에서, 이번 베타.3의 체감을 정리하면 이렇습니다.

**좋았던 점 (장점)**
- **CDP 릴레이는 "와, 이제 됐다" 싶었습니다**: 브라우저 자동화를 짜다 보면 remote-debugging 권한 프롬프트가 진짜 골칫거리인데, `openclaw browser extension cdp` 한 줄로 엔드포인트가 나오고 Puppeteer 클라이언트가 바로 붙는 흐름은 생각보다 편합니다.
- **출판 검증이 꼼꼼해졌다**: 89개 공식 플러그인 read-back + 무결성 메타데이터까지 릴리스 노트에 박혀 있어서, 베타여도 "깨진 패키지를 받는" 걱정이 줄었습니다.
- **크론 수정 2건이 바로 내 일이었습니다**: 스케줄 앵커 갱신(#128893)과 알림 라우팅(#128856)은 크론잡을 여러 에이전트로 돌리는 저 같은 사람에게 직접 체감되는 수정이에요.

**아쉬웠던 점 (단점)**
- **여전히 베타입니다**: npm latest는 `2026.7.1-2` 그대로. "8/18 출시" 약속은 8/25인 지금도 안 지켜졌습니다. 솔직히 조금 답답하지만, 그만큼 검증을 더 한다고 생각하면 납득은 됩니다.
- **CDP 릴레이는 아직 "환경"이 따라와야 합니다**: paired Chrome이 이미 셋업돼 있어야 하고, 외부 CDP 클라이언트 쪽도 새 엔드포인트를 지원해야 합니다. "설치만 하면 바로 되는" 건 아니에요.
- **릴리스 주기가 여전히 빠릅니다**: 베타.2(8/15) → 베타.3(8/24) 간격이 9일. 쫓아가는 재미는 있지만, 매번 CHANGELOG를 볼 시간이 없는 분이라면 릴리스 노트 구독을 추천합니다.

## 7. 업데이트 팁 — 지금 받아도 될까?

결론부터 말하면, **용도별로 나눠서 판단하시면 됩니다.**

1. **베타 기능 체험(브라우저 자동화 하시는 분)** — `openclaw update --channel beta`로 **2026.8.1-beta.3**을 받아보세요. CDP 릴레이와 GPT-5.6 Ultra 추론을 미리 쓸 수 있습니다. 단, **업데이트 전에 `openclaw backup sqlite create`로 백업부터** — 이번에 확정된 신기능이니 꼭 써보세요.
2. **안정 우선(추천)** — `openclaw update`로 **2026.6.34(extended-stable) 라인** 유지. 크론잡/자동화를 실서비스처럼 돌리는 분은 정식판 2026.8.1이 npm latest에 올라올 때까지 이쪽이 안전합니다.
3. **업데이트 후 습관** — 베타든 정식이든 **업데이트 후엔 항상 `openclaw doctor` 실행.** fresh-install/업그레이드 DB 이슈가 베타.3에서 고쳐졌다고는 하지만, 자기 환경은 자기가 확인하는 게 제일 확실합니다.
4. **정식판 출시 알림** — npm 폴링 크론을 걸어두면 됩니다. 저는 아래 명령을 30분 간격 크론으로 돌려서 값이 바뀌면 알림이 오게 해뒀습니다.
   ```bash
   npm view openclaw dist-tags.latest
   ```

솔직히 말해서, 베타.3이 **"정식판 직전의 마지막 안전벨트"**라는 느낌이 강합니다. fresh-install DB 문제를 고치고, 권한 게이트를 하드닝하고, 89개 플러그인 read-back까지 마친 상태니까요. **"정식판이 이제 진짜 곧 나온다"**는 확신이 선 하루였습니다. 가성비 좋은(완전 무료·MIT) 오픈소스 AI 에이전트를 찾으시는 분, 그리고 브라우저 자동화에 관심 있으신 분께 OpenClaw 한번 써보시길 추천합니다.

정식판 2026.8.1이 npm에 올라오는 순간, npm 태그 실측부터 어떤 변경이 들어왔는지 바로 정리해서 다시 찾아올게요!
